## Concrete ABI and immutable excerpt source

`HarnessForgeWeb.Company.Analysis.report/1` already receives the FULL `claim` map through required `attr :claim, :map`; required `id` is a string, and `goals` is a list defaulting to `[]`. It derives `basis = assigns.claim["basis"]` internally (`lib/harness_forge_web/components/company/analysis.ex:422–447`). Add exactly `attr :sources, :list, default: []`. No workspace argument or new expected-workspace authority is needed.

The original citation rendered beside a finding is **`claim["basis"]["report"]["findings"][i]["citations"][j]`**, not the separately persisted `claim["citations"]` record. Existing HEEx uses its original `snippet`, `source_id`, `revision_id`, `start_byte`, `end_byte` (`analysis.ex:473–484`). The finding has string keys `kind`, `statement`, `citations`. A report citation has exactly `source_id`, `revision_id`, `start_byte`, `end_byte`, `snippet`; it has no citation ID or body hash. Its bounds are UTF-8 byte offsets with exclusive end; the validator checks exact snippet bytes against the selected revision body (`lib/harness_forge/models/company_analysis.ex:6–17,136–154`). Keep this excerpt and full ID/span display untouched.

A distinct persisted citation record carries `id`, `workspace_id`, `revision_id`, byte offsets, `snippet`, `snippet_hash`; it does not carry `source_id` (`lib/harness_forge/evidence/records.ex:50–60`). Persistence derives these records from original report spans and canonicalizes them (`lib/harness_forge/company/analysis.ex:299–326`). Do not join metadata by a citation-record ID, shortened ID, snippet text, title or snippet hash.

The body-hash reference is **`claim["basis"]["context"]["sources"]`**, a string-keyed list of maps `{source_id, revision_id, body_hash}`. `context` also contains `profile` and `project` ID/content-hash pins; `basis` contains exact goal ID/content hash, context digest, report, current guidance, provider/model/config/run/request attribution and saved resolution. Accepted provenance includes uncited context. Existing origin validation requires2–4 ordered refs with unique source IDs and exact UUID/digest fields (`lib/harness_forge/evidence/origin.ex:6,53–98`). Retain the existing included-context disclosure and hashes (`analysis.ex:487–502`). Do not recalculate or rewrite claim/report/context authority while displaying metadata.

## Actual loaded DTO and authenticated provenance

`Evidence.list_sources/0` uses `Store.scoped(Source)`; `list_claims/0` uses `Store.scoped(Claim)` (`lib/harness_forge/evidence.ex:51–54,331–338`). `Store.scoped/1` binds the active workspace; `Store.get/2` is scoped too (`lib/harness_forge/evidence/store.ex:6–26`). `Store.dto/1` drops ONLY `__meta__`, stringifies schema field keys and converts `DateTime` to ISO8601 text. **Real `workspace_id` fields remain present** (`store.ex:28–36`). They are not invented component inputs.

Source DTO fields from the schema include `id`, `workspace_id`, `connection_id`, `provider`, `external_id`, mutable CURRENT `title`, `latest_revision_id`, string `status`, timestamps, plus added `latest_revision`. Revision DTO fields include `id`, `workspace_id`, `source_id`, `body`, `body_hash`, integer `revision`, ISO8601 `captured_at`, `source_url`, `source_updated_at`, `metadata` (`records.ex:19–47`). There is **no `active` boolean**. `source_dto/1` exposes `latest_revision` only when source status is `"active"` and its scoped connection is active; otherwise it is nil. Its revision read follows the current latest ID; it supplies no historical title or historical-revision collection (`evidence.ex:597–615,681–689`). `source_updated_at` is not capture time.

The portal is behind the authenticated router pipeline/live-session mount. `OperatorSession.valid?/1` binds workspace, process epoch and age; events recheck validity (`lib/harness_forge_web/router.ex:14–30`; `lib/harness_forge_web/plugs/operator_session.ex:28–57`; `lib/harness_forge_web/live/portal_live.ex:960–963`). It passes those same workspace DTOs into CompanyPanel (`:1615–1629`); the panel validates authentication before accepting/reloading state (`lib/harness_forge_web/components/company_panel.ex:36–61`). Profile/project assignment UNION constrained original analysis capture (`lib/harness_forge/company/analysis.ex:188–218`). Company report metadata should receive the existing full workspace `@sources`, not a newly selected project or re-filtered picker list.

These upstream callers establish access provenance. Pairwise equality of actual claim/source/revision `workspace_id` values can reject inconsistent DTOs; it **does not authenticate an arbitrary standalone component call**. A coherent foreign bundle is not made authorized by equality. Keep the existing authenticated scoped loading path, with no domain call inside the renderer, no caller-supplied trusted workspace promise and no new route.

## Minimal pure projection and failure rules

A small private helper in the existing component can take `(full_claim, original_citation, loaded_sources)` and return either a small metadata map or `:unavailable`. It must return fallback on malformed relevant input instead of raising or fetching. The entire pre-existing report renderer remains based on admitted reports; this iteration does not claim to repair every possible malformed report envelope.

For enrichment, require all of the following:

1. The citation has nonblank valid source/revision IDs; `basis.context.sources` is a list of valid string-keyed source refs. Reject duplicate source IDs, even identical duplicate refs, rather than letting `Enum.find` or `Map.new` choose one. Exactly one ref names this citation's source, with the same revision and a valid body hash.
2. Exactly ONE loaded source DTO has that full source ID. Duplicate candidates are ambiguous even when their displayed fields match. Require its `status == "active"`, a map `latest_revision`, and `source.latest_revision_id == latest_revision.id == ref.revision_id == citation.revision_id`.
3. Require `latest_revision.source_id == source.id == ref.source_id == citation.source_id` and `latest_revision.body_hash == ref.body_hash`. Reject missing/wrong-type/blank/hash-mismatched fields. Require actual nonblank string `claim.workspace_id == source.workspace_id == latest_revision.workspace_id` as consistency only. Missing older/synthetic caller fields fail closed; no extra report attribute is required.
4. Return only validated display values: qualified current name, matched capture timestamp and separately safe stored URL. Do not add a body, new revision, inferred title or network-derived metadata to the display projection.

Hash equality never selects an identity: two sources/revisions with identical body hashes must remain distinct. A wrong source/revision with the same hash cannot satisfy the joins; a same-ID/wrong-hash DTO cannot enrich. Do not claim mathematical SHA256 collision detection or recompute authority in the UI. Existing validated original span/excerpt is authoritative display data; a link/name does not prove semantic support or complete coverage. Malformed/unrelated list entries may conservatively invalidate enrichment without affecting the excerpt. Repeated citations in separate original findings remain separate; do not deduplicate away original report content.
