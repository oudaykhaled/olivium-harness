Read-only Principal UI/UX advice, 2026-11-02. Root accepted ADR10; programme count is 9/50. This brief specifies the selected presentation benefit and its falsifiers. It is not implementation, runtime verification or approval authority. Root executes all checks and owns any CSS change. No Figma, new design file, hook, modal, route or general redesign is needed for this standalone OSS application.

## Reuse and data truth

Reuse `Company.Analysis.report/1` and its existing findings disclosure (`lib/harness_forge_web/components/company/analysis.ex:425–506`). Add an optional `sources` list defaulting to `[]`; pass the already-loaded list from Company’s report call at `analysis.ex:341` and Evidence’s call at `lib/harness_forge_web/live/portal_live.ex:1661–1666`. The same renderer must supply both locations, including the exact Evidence approval surface.

The actual source DTO has `id`, `title`, `status`, `latest_revision_id` and nested `latest_revision`; the latter has `id`, `source_id`, `body_hash`, `captured_at` and `source_url`. `Source.title` is current mutable metadata, not a captured title (`lib/harness_forge/evidence/records.ex:19–48`). `list_sources/0` is workspace-scoped; `source_dto/1` exposes only the latest revision and hides it for unavailable sources/connections (`lib/harness_forge/evidence.ex:51–54,681–689`; `lib/harness_forge/evidence/store.ex:16–37`). Portal already loads this list at `portal_live.ex:913–952`. Do not add a historical query, scope bypass, inferred title or extra body disclosure.

For each original citation, require an unambiguous exact reference in `basis.context.sources`, matching the citation’s source/revision IDs. Require an active supplied source with matching source ID, latest revision ID, nested revision ID/source ID and context body hash. Missing, malformed, ambiguous or mismatched data produces the whole-pin fallback below. A matching excerpt or name is insufficient. No mutable metadata may substitute for an old pin. The domain context really contains source references, not captured titles (`lib/harness_forge/company/analysis.ex:207–222,235–253`).

## Minimal HEEx hierarchy and frozen copy

Keep the current report heading, original recommendation status, uncertainty, goal rationale, saved goal/fallback, structural-coverage warning, resolution requirement and saved human resolution in their current order. Keep “Original findings and excerpts” open by default and retain the separate closed attribution disclosure. Current guidance stays in the existing Company editor; approval/rejection stays in Evidence. Added metadata must not look like a current guidance edit, a saved human resolution or an approval.

Inside each finding, retain its heading/statement and each unchanged excerpt. A small per-citation wrapper may hold the existing `<blockquote><p>{snippet}</p></blockquote>` plus a sibling metadata block, so added UI labels are not presented as quoted source words. Read order within that wrapper is excerpt → full source/revision/UTF-8 span → qualified metadata. Preserve `UTF-8 bytes {start_byte}–{end_byte} (exclusive end)`. Source IDs, revision IDs and spans remain visible and selectable; retain context hashes and exact claim/goal revisions in the existing attribution disclosure. No ellipsis, line clamp, tooltip-only authority or hidden replacement text.

| State | Visible copy and behavior |
|---|---|
| Exact match; nonblank name | **Current source name (may have changed):** `{source["title"]}`. Always use this qualifier, including an unchanged revision. Never say “captured title.” |
| Exact match; name absent/blank/unusable | **Current source name unavailable.** Do not derive one from the URL or report. Other independently available matched fields may remain. |
| Exact match; capture date available | **Captured at:** the stored timestamp. Preserve its actual timezone/date information; avoid relative-age or “current policy” claims. A semantic `<time datetime={...}>` is suitable for a valid stored timestamp. |
| Exact match; capture date missing/unusable | **Capture date unavailable.** Do not borrow the source update date or today’s date. |
| Exact match; safe stored URL | **Open stored source link (opens in a new tab)**. Nearby text: **This link was stored with the capture. Its destination may have changed.** The explanation may appear once before the findings if it clearly applies to all report links. |
| Exact match; URL missing/unsafe | **Source link unavailable.** Render no anchor and no raw unsafe URL. Do not disable a fake link or explain the rejected URL by echoing it. |
| Changed/latest-only, missing, unavailable/revoked, ambiguous or mismatched pin | **Pinned capture details unavailable or changed. The original excerpt and pin are retained.** Omit all added name/date/link, preserving the immutable excerpt and exact references. This state is distinct from an individually missing name/date/URL after a successful match. |

Render imported labels, snippets and attributes through escaped HEEx. Factor/reuse the existing pure `source_url/1` policy (`analysis.ex:536–548`) so picker and report agree. The current helper checks only scheme/host/userinfo and needs the ADR’s additional malformed-text/whitespace/control/backslash checks. Guardrail/interface owns the exact numeric URL cap and parser policy; this brief introduces no competing number. Accept only bounded valid absolute HTTP(S) text with host and no userinfo, with no preview, fetch, prefetch or automatic opening.

## Link, keyboard and draft behavior

Use an ordinary `<a href={validated_url} target="_blank" rel="noopener noreferrer">` without a Phoenix event, LiveView navigation attribute or new hook. The visible new-tab warning must also be in the accessible name. Distinguish repeated links using their finding/excerpt ordinal in the accessible name or associated metadata; retain the visible words “Open stored source link.” Derive any association IDs from the existing unique report `@id` plus finding/citation indices, preventing collisions between reports. Do not make static metadata an extra Tab stop. Native summary controls and links retain DOM order, normal Enter activation and visible focus.

Returning from the new browser tab should leave the original application tab, selected report, disclosure state and any dirty guidance untouched, with the source link still a usable focus/continuation point. Root must observe the browser’s actual return behavior; do not invent a focus-restoration hook or claim it passed from source inspection.

Preserve two different existing contracts. The explicit **Review exact revision in Evidence** continuation is disabled while dirty, and a forged `company_navigate` is refused with Save/discard feedback (`analysis.ex:388–416`; `company_panel.ex:239–246`; `test/harness_forge_web/company_analysis_test.exs:125–142`). Ordinary navigation away from Company clears analysis and rotates event/reset generations (`company_panel.ex:36–58,104–116`; `portal_live.ex:965–981`). Therefore new-tab return can preserve the mounted draft; application departure, reset, auth loss or remount must not revive it. Do not add a global navigation fence or promise draft preservation across departure. Existing JS reset/fixed focus handling remains unchanged (`assets/js/app.js:29–87,138–160`).

## CSS recommendation bounded by existing evidence

Existing `.company-record`, report and `code` rules already provide `min-width: 0` and wrapping (`assets/css/app.css:22,232,255–260`). Use those before introducing layout rules. Keep prose at the existing report scale; avoid picker-only `.field-help` reducing new text to 10px in Company (`app.css:107,181–182`). Long current names, source/revision IDs, hashes and byte spans must wrap in both containers.

One code-supported gap is new report anchors: global `a` removes decoration (`app.css:15`), while the underlined `--company-target` link treatment applies only to `.company-analysis-source a` (`:254`). If the author adds a report-specific link class, root may extend that existing selector to it, reusing `--company-target`, `--green-dark` and existing spacing; constrain width/wrapping only if the actual matrix needs it. Global focus already covers anchors (`:16`); verify its visibility/contrast in the real containers. If insufficient, scope the existing `var(--green)` outline treatment to these links. Do not restyle unrelated cards/navigation or declare focus contrast passed from a screenshot. No CSS has been edited by this adviser.

## Root acceptance and falsifiers

- **Positive:** reopen the same synthetic report derived from at least two selected historical sources and a saved goal in Company and Evidence. Recognizable matched metadata accompanies unchanged original excerpts/IDs/spans; original findings, current guidance, saved resolution and exact approval remain distinguishable. Change only the current name with the same revision: the qualifier remains. Malicious name/snippet markup stays data.
- **Negative:** after deliberately changing a synthetic source and using supported refresh/reopen, old pins show the whole-pin fallback with no latest name/date/link. Cover wrong source ID, same revision/wrong body hash, absent/ambiguous context, absent source, loaded unavailable/revoked source or connection, and individual missing name/date/URL. Unsafe URI fixtures produce no anchor/raw unsafe URL. Missing optional `sources` remains safe. Auth/reset paths clear the existing data; no new query supplies it again.
- **Responsive and keyboard:** root records both locations at actual CSS viewport widths **320 and 390**, each at actual browser zoom **100% and 200%**. Use long names/IDs/hashes/spans plus link-available and unavailable states. Record post-zoom dimensions and native zoom evidence; CSS transforms alone are insufficient. Require no unintended page/report horizontal overflow, clipping or ellipsis; full selectable authority; visible nonobscured focus; logical Tab order; keyboard opening of a synthetic local link and return. Test return with dirty guidance and separately exercise the existing dirty continuation refusal, ordinary departure reset and queued old-event refusal. Restore prior browser state.
- **Noninterference:** root compares immutable report/context pins, exact claim/plan decision projections and request/build/export counts before/after view-only opening, disclosure, link/return. Separate these observations from deliberate fixture mutations and their subsequent reload. Viewing must select, infer, resolve, approve, reject, build or export nothing. Existing separately approved guidance-to-plan/export semantics and current-data refusals remain; unavailable-model reopening needs no fallback/download/new inference. Root owns focused component/integration checks and final canonical checks; this adviser ran none.

Any current-to-old substitution, unqualified historical-name claim, unsafe anchor, cross-scope disclosure, hidden authority, inaccessible link in the measured matrix, draft resurrection or view-induced authority/inference/artifact change falsifies delivery.
