## Exact selected behavior

1. Keep existing digest-keyed export row forms. Replace global `export_path` with **one ephemeral active export outcome/draft**, bound to a validated full digest and current form generation. Every accepted export submission supersedes the previous export outcome, including A→B; no A result can appear under B. Readiness selection is independent. No per-keystroke state, auto-export, automatic retry, new export selector or persistent history is required.
2. Use `Harnesses.export/2` as the only write/admission authority. For success, accept its returned digest/path only after checking their expected shape, exact digest equality with the submitted package and **exact path equality with the submitted validated target**. A shape-valid but different path is completion-unconfirmed, never success. Show an operation-labeled result beside that exact package, with name/version, exact destination and full digest available. Use escaped text. Clear the submitted target after success. Export confirms written files; evaluation and release remain separate.
3. On known destination refusal, preserve the entered target only in the attempted row for correction; remove earlier success. Use fixed export-specific copy, never arbitrary error `message`/`details`. `export_conflict`: choose a new directory; existing destination was not replaced by this refused attempt. `unsafe_artifact_path`: use an absolute new directory under an existing real parent, without symlinks or traversal; do not pretend to know which condition failed. `artifact_io_error`: **completion unconfirmed**, inspect destination first, then check access/storage as possibilities. Unknown/error-shape/returned-identity anomalies also say **“Export completion could not be confirmed. Inspect the destination before retrying with a new directory.”** Do not diagnose permissions or assert universal absence of output. Known integrity/eligibility/workspace-quarantine refusals give current package/evidence/Company review remedies, not a path-only fix.
4. Export outcomes are local to Packages and do not write/clear generic flashes. Existing direct Packages build outcomes gain a clear **“Package build:”** prefix at production of the message; retain their existing lifecycle and actionable content. This is the sole non-export presentation adjustment needed to distinguish the observed neighboring failure. Do not call blanket `clear_flash`, relabel unrelated failures as resolved, or introduce a generic notice framework. A later export success is not a successful rebuild.
5. Introduce mount/reset generation validation for export envelopes **before domain invocation**. Missing, malformed, foreign/unavailable digest or stale generation is safely refused without echoing submitted private paths/metadata or exporting. Keep the domain's own current eligibility checks. Rotate generation and clear all export draft/outcome on privacy cache reset (including sibling-tab broadcast), revocation/lock, fresh mount and removal/unavailability of the active artifact. Replace generation-keyed input DOM on privacy reset so a focused unsent browser value is actually removed. Ordinary reload/reorder with the artifact still present may preserve the exact bound result; cannot transfer it. Leaving Packages clears the ephemeral export state; returning starts clean. No reset is a claimed deletion of already exported files.
6. Failure focuses the matching corrective target input with an associated visible error (`aria-describedby`, `aria-invalid` where applicable); next Tab reaches its export action. Success focuses a programmatically focusable local result with status semantics. Use fixed-purpose focus handling with validated digest/generation and known target types; no arbitrary client selector/HTML or focus into hidden tabs. Preserve existing fixed Company destinations. Reset/revocation must not leave a delayed focus action restoring private UI.
