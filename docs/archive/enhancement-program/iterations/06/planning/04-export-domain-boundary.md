# 06 proposal: truthful Packages export recovery

**Finding.** `Harnesses.export/2` checks workspace, artifact and current eligibility before `Artifacts.export/3`, then appends audit (`lib/harness_forge/harnesses.ex:122-130,135-170`). `Artifacts` requires a fresh absolute target and existing nonsymlink parents (`artifacts.ex:61-69,245-288`); occupied targets return `export_conflict`, unsafe/missing-parent paths return `unsafe_artifact_path`, and stage/write/rename failures return `artifact_io_error` (`artifacts.ex:291-347`). No separate `SafePath` module exists. Occupancy/no-overwrite tests cover races (`test/harness_forge/artifacts_test.exs:69-117`); revoked evidence/plan blocks export (`test/harness_forge/company_harnesses_test.exs:125-155`).

Portal stores the submitted target as success without using the returned result; failure uses generic `finish`, leaving prior `export_path` intact (`portal_live.ex:432-443,733-741`). Success sits after all package rows without identity (`portal_live.ex:1948-1976`). Most `Contracts.Error` codes fall through to provider-import advice (`portal_live.ex:1162-1185`). An occupied retry can display stale success beside an unrelated error.

**Decision (UI only).** Give each export attempt a result owned by its artifact digest. Clear its prior result when retrying; on success show the returned digest/path beside that package. On `export_conflict`, retain the entered target and ask for a new directory. On `unsafe_artifact_path`, explain absolute path, existing parent and no symlink/traversal. On `artifact_io_error`, suggest checking filesystem access and destination state. Eligibility/integrity failures retain their own review remedies. For unknown errors, including an audit failure after files were written, say completion is unconfirmed and ask the operator to inspect the destination before retrying with a fresh path. Never claim that failure proves no bytes exist. Reset private draft/result on privacy reset, revocation and package removal. Domain admission, immutability and audit order stay unchanged.

**Acceptance.** Positive: eligible fresh target yields exact digest/path and matching exported files. Negative: occupied/unsafe targets preserve existing bytes, entered value and a focused correction with accurate copy; stale success disappears. Edge: unwritable/unknown failure does not assert absence, changed eligibility never suggests a path-only fix, and reset/another package cannot show the prior result. Cover LiveView events plus keyboard and 320/390px/200% visual checks; these do not establish operator comprehension or WCAG conformance.

**Alternatives.** A shared flash-copy fix is smaller but cannot bind feedback to a package or clear stale success. A filesystem preflight adds a race and duplicates `Artifacts` authority; reject.
