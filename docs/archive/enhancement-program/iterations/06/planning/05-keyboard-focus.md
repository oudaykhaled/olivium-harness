# 06 proposal: keyboard handoff from Goals to rule proposal

**Facts.** Saving a goal uses the generic `finish/3` flash and reload (`lib/harness_forge_web/live/portal_live.ex:420-422,733-738`). The Goals card has no onward action (`:1856-1889`); the Evidence form is a separate, unselected goal-rule proposal (`:1446-1505`). Ordinary tab navigation changes `@tab` without focus routing (`:59-61`). Existing fixed `company-focus` targets include `evidence-panel`, but not `goal-rule-proposal` (`assets/js/app.js:110-129`). Existing success/error flash uses `role=status`/`role=alert` (`portal_live.ex:1288-1295`). Iteration05 native evidence observed BODY after Save goal and Goal input on the next Tab; it did not establish destination focus or speech (`docs/enhancement-program/iterations/05/verification.md:55`). Its goal-only flow then required manual Evidence navigation (`test/harness_forge_web/goal_claims_test.exs:33-51`).

**Hypothesis and value.** A saved-card button labelled “Propose a rule from this goal” reduces memory and keyboard navigation in the newly delivered goal-origin journey. Keep the goal chooser blank: the operator must still choose the current goal, author rule text, approve that exact claim, and separately approve the plan. This is a narrow UI handoff, not a new authority path. UX05 favors this; product/architecture/trust favor export recovery and quality favors notice ownership. Those alternatives remain distinct, not bundled or selected by votes.

**Acceptance.** After a successful save, existing status text identifies success. Activating the card button opens Evidence and focuses a `tabindex=-1` `goal-rule-proposal` region with an accessible heading; the next Tab reaches the blank **Saved goal** select. The button does not preselect a value, create/approve a claim, or alter export/approval bytes. If the goal list is unavailable, show the existing unavailable message and withhold the handoff; failed save retains its alert and stays on Goals. A privacy reset, lock or remount leaves no queued focus or private draft; a delayed old event cannot restore one. Preserve the fixed destination allowlist, using only the static proposal ID. Verify LiveView event/DOM assertions plus native keyboard active element, next Tab, status/alert presence and visible controls at 320/390 CSS px and actual 200% zoom. Observe announcements only as DOM live-region semantics; speech, WCAG certification and first-time comprehension need separate evidence.

**Ownership.** Web owner: `portal_live.ex` and focused web tests; root: shared `assets/js/app.js`, native/browser execution and board. No domain admission or persistence change.
