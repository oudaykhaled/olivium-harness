# Goal authority clarity: a direct, non-authorizing handoff

**Finding.** Saving a goal currently reports only that it was saved (`lib/harness_forge_web/live/portal_live.ex:420-422`); the Goals panel presents saved cards without a next action (`lib/harness_forge_web/live/portal_live.ex:1856-1889`). The operator must remember to return to Evidence. Evidence already says saving or selecting a goal does not approve a rule and starts with a blank goal choice (`lib/harness_forge_web/live/portal_live.ex:1446-1497`). Company separately requires an approved exact claim, deliberate goal selection, and a distinct exact plan decision (`lib/harness_forge_web/components/company/plan.ex:62-65,150-164,262-274,609-639`). The goal-only web test proves those gates and direct-build refusal (`test/harness_forge_web/goal_claims_test.exs:28-119`). The gap is wayfinding, not missing authority checks.

**Recommend one UI unit.** Add a plainly labeled “Open Evidence to propose a rule” action beside saved goals, available only when the current goal list loaded and is nonempty. Explain beside it: “A saved goal is intent. Write a separate rule, approve its exact revision, then select both in a Company plan and approve that plan.” The action navigates to the existing Evidence proposal and focuses its heading using the existing `company-focus` event (`assets/js/app.js:122-128`). Carry no goal ID, title, hash, or approval state in the event; leave the goal select blank. This keeps the action an orientation aid rather than implied rule or plan authority. **Owner:** Portal LiveView UI and its focused web test; no domain, approval, or export contract change.

**Acceptance.** Positive: after saving a goal, keyboard activation opens Evidence, focuses the proposal heading, and the next Tab reaches the blank Saved goal select; the four stages remain legible. Negative: the action creates no claim, decision, selection, plan, or package; no build becomes eligible. Edge: a removed/stale goal is unavailable on refreshed Evidence, while a foreign goal never appears or leaks its label; existing forged-version refusal remains (`test/harness_forge_web/goal_claims_test.exs:169-191`). Privacy: source/workspace purge, lock, reload, and stale form events clear private draft/selection as existing tests require (`test/harness_forge_web/goal_claims_test.exs:261-379`); the handoff retains no private payload. Verify readable, operable layout at 320/390 CSS pixels and actual 200% zoom. Native observation and operator comprehension need separate evidence; this proposal claims neither.
