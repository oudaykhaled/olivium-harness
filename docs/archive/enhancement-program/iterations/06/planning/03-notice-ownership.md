# 06 proposal: own package-operation feedback

**Fact.** [Direct build](../../../../../../lib/harness_forge_web/live/portal_live.ex#L424) uses `finish/3`, whose failure branch clears flash and sets a global error ([lines 733–741](../../../../../../lib/harness_forge_web/live/portal_live.ex#L733)). [Export success](../../../../../../lib/harness_forge_web/live/portal_live.ex#L432) sets `export_path` and an info flash without clearing that error; `reload/1` leaves flash intact ([line 784](../../../../../../lib/harness_forge_web/live/portal_live.ex#L784)). The page renders both flash kinds above every tab ([lines 1288–1293](../../../../../../lib/harness_forge_web/live/portal_live.ex#L1288)), while `export-result` displays only a path after the package list ([lines 1948–1976](../../../../../../lib/harness_forge_web/live/portal_live.ex#L1948)). Thus a failed direct build can appear beside a successful export of another built package. [Native 05 verification](../../05/verification.md) observed this; it did not establish how operators interpreted it. Export failure goes through `finish/3`, leaving an older `export_path` intact. Privacy cache reset rotates Company state but does not clear `export_path` ([lines 769–774](../../../../../../lib/harness_forge_web/live/portal_live.ex#L769)). The Company component separately owns its notice/error and clears them on cache reset ([company panel lines 50–85](../../../../../../lib/harness_forge_web/components/company_panel.ex#L50)).

**Recommendation.** Give *direct Package build* and *each export attempt* local, labeled outcomes in the existing Package panel. Keep a build failure beside its build form; keep export outcome beside the submitting artifact, keyed by digest and attempt, with exact destination on success. A new attempt replaces only that operation's prior outcome; failure removes its former success. Other actionable notices keep their own owner. Clear these ephemeral outcomes on privacy reset/revocation and fresh mount. This is a bounded UI change in `PortalLive`; filesystem recovery design is a separate choice. The current `export/2` contract remains authoritative: fresh contained directory, exact package, no overwrite. No new persistence or authority is needed.

**Acceptance.** Positive: after a build refusal, exporting a previously built package shows “Exported” with that package digest/path and a clearly labeled build refusal, never two unqualified global results. Negative: occupied/unsafe destination reports failure only for that attempted digest, preserves the typed target for correction and does not touch existing bytes. Edge: retry of A, export of B, tab change, reload, reset and lock cannot present A's stale success as B's; unrelated failure remains identifiable. Keyboard users can reach and perceive the local status/error; verify reflow at 320/390 CSS pixels and actual 200% zoom. Test the event sequence and reset/remount behavior; native comprehension and screen-reader speech remain unmeasured.
