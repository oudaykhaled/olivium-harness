# Iteration 08 — test-oracle proposal

**Recommendation: recover from an invalid package name in the build form.** The schema accepts a package name beginning with a lowercase letter followed by lowercase letters, digits, `_` or `-` ([schema:24](../../../../../../priv/schemas/harness-v1alpha1.json)); `Harnesses.build/1` compiles the submitted name ([Harnesses:93](../../../../../../lib/harness_forge/harnesses.ex)), but `PortalLive` sends the resulting `invalid_harness` through generic connector advice ([PortalLive:425](../../../../../../lib/harness_forge_web/live/portal_live.ex), [PortalLive:1258](../../../../../../lib/harness_forge_web/live/portal_live.ex)). A user correcting a package name is therefore told to inspect provider-import status. The form currently hardcodes its name value ([PortalLive:2008](../../../../../../lib/harness_forge_web/live/portal_live.ex)).

**Benefit and decision.** Give fixed, name-specific correction beside the package-name field; retain submitted build values for correction. Keep the authoritative compiler validation and immutable digest unchanged. This is a UI recovery change, not a new eligibility rule.

**Oracles.** Positive: with otherwise eligible approved evidence, submit `Bad Name`; the page identifies the name rule, retains the entered name and other form values, places keyboard focus at the correction, and leaves artifact and build-audit counts unchanged. Correct to `good-name`, submit, and observe one immutable artifact with its exact digest. Negative: a connector error still receives connector-specific advice; neither schema detail strings nor hostile submitted content appear as raw HTML in the notice. Edge: leading digit, uppercase, whitespace and overlong names receive a bounded correction; a valid name with another contract failure must not be misclassified as a name error. Reset or expired operator session cannot restore a private draft. Check complete label, message and focus at 320/390 CSS pixels and actual 200% zoom.

**Delivery and evidence.** UI owner: `lib/harness_forge_web/live/portal_live.ex` and, only if focus needs it, `assets/js/app.js`; QA owner: focused LiveView regression in `test/harness_forge_web/`, plus browser keyboard/zoom evidence. Root alone schedules Mix/browser execution and records machine results. No tests ran for this planning proposal.

**Tradeoff and limit.** Goals-to-Evidence continuation ([PortalLive:1980](../../../../../../lib/harness_forge_web/live/portal_live.ex)) may improve more of the author journey, but its comprehension benefit needs an unperformed operator study and it leaves demonstrated wrong recovery advice. A broader operation-owned notice system could cover more errors but expands scope. Passing these oracles proves this recovery path, not novice comprehension, full WCAG conformance or company/model fitness.
