**Problem and evidence.** The build form accepts a package name at [`portal_live.ex:2008`](../../../../../../lib/harness_forge_web/live/portal_live.ex#L2008). The frozen schema requires 1–64 characters, starting with a lowercase letter and followed only by lowercase letters, digits, `_`, or `-` ([`harness-v1alpha1.json:20`](../../../../../../priv/schemas/harness-v1alpha1.json#L20)). `Harnesses.build/1` passes that name to `Compiler.compile/1` ([`harnesses.ex:93`](../../../../../../lib/harness_forge/harnesses.ex#L93), [`harnesses.ex:194`](../../../../../../lib/harness_forge/harnesses.ex#L194)); validation returns `invalid_harness` with a `$.metadata.name` detail ([`contracts.ex:323`](../../../../../../lib/harness_forge/contracts.ex#L323)). The build handler routes that contract error through `connector_error/1`, whose fallback says the provider page could not be imported ([`portal_live.ex:425`](../../../../../../lib/harness_forge_web/live/portal_live.ex#L425), [`portal_live.ex:1258`](../../../../../../lib/harness_forge_web/live/portal_live.ex#L1258)). Fixed input values at line 2013 can also erase the rejected draft on rerender.

**One benefit.** Give the operator an actionable, truthful correction in the existing build error notice: “Package name: use 1–64 characters. Start with a lowercase letter; then use lowercase letters, numbers, `_` or `-`.” Match only the trusted `$.metadata.name` validation path, never interpolate validator details or user input into copy. Keep other build-contract refusals build-specific; retain connector-specific remedies on connector operations.

Correct to `bad-name` and build the immutable package under existing approval rules. Negative: an unrelated `invalid_harness` detail does not claim a name problem or show provider-import advice. Edge: mixed validation details give bounded generic build guidance without leaking detail strings; empty/overlong names remain correctable; reset clears the draft. Inspect full copy and focus at 320/390 CSS widths and actual 200% browser zoom.
