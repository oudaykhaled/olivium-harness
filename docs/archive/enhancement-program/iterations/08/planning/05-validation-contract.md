# 08 proposal: recover from an invalid package name

**Problem and evidence.** The package form accepts arbitrary text for `package[name]` and hardcodes `my-harness` on render ([PortalLive:2008–2014](../../../../../../lib/harness_forge_web/live/portal_live.ex#L2008)). `Harnesses.build/1` passes that name into the specification and only publishes after compilation ([Harnesses:93–116](../../../../../../lib/harness_forge/harnesses.ex#L93), [194–204](../../../../../../lib/harness_forge/harnesses.ex#L194)). The frozen schema requires 1–64 characters matching `^[a-z][a-z0-9_-]*$` ([schema:20–24](../../../../../../priv/schemas/harness-v1alpha1.json#L20)). Validation returns `%Contracts.Error{code: "invalid_harness", details: [...]}` ([Contracts:43–52](../../../../../../lib/harness_forge/contracts.ex#L43), [323–330](../../../../../../lib/harness_forge/contracts.ex#L323)); the build event maps that error through the generic connector fallback, claiming a provider page could not be imported ([PortalLive:425–446](../../../../../../lib/harness_forge_web/live/portal_live.ex#L425), [1258–1281](../../../../../../lib/harness_forge_web/live/portal_live.ex#L1258)). This is demonstrated misleading recovery, not a measured comprehension failure.

**Decision.** Give the build form a fixed, name-specific correction: “Start with a lowercase letter; use 1–64 lowercase letters, numbers, underscores or hyphens.” Classify only the existing typed `invalid_harness` error with a `$.metadata.name` validation detail as `:invalid_package_name`; never render raw details. Preserve bounded submitted form values after refusal and connect the notice to `package-name` for keyboard and screen-reader correction. Keep other build errors and connector remedies distinct. This is an interface contract, not a new approval or compiler authority.

**Acceptance.** Positive: an approved-evidence build with a valid name still yields the same immutable digest behavior. Negative: `Bad Name` refuses with the fixed correction, retains the draft, and creates no artifact or build audit event. Edge: an overlong name and a concurrent second validation fault remain bounded; fixing the name exposes the remaining fault without provider-import advice. Connector import failure retains its own remedy. Verify focused field, announced notice, complete copy and no horizontal clipping at 320/390 CSS pixels and actual 200% zoom. Test corrected resubmission.

**Expected ownership and verification.** Elixir author owns `portal_live.ex` and focused LiveView tests; root owns serial Mix and native browser verification. No schema, domain, export or migration change is proposed. The strongest alternative, Goals-to-Evidence continuation, improves discovery of the next step but needs an unperformed first-time-operator comprehension study and leaves this confirmed wrong instruction. Neither option proves company/model fitness, complete WCAG conformance or publication completion; prior 05/06 coherence, outcome and portable-authority dissent survives.
