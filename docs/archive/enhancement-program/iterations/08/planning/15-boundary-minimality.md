# 08 proposal — continue from a saved goal to evidence review

**Context.** Saved goal cards end at owner, title and acceptance text ([PortalLive:1980](../../../../../lib/harness_forge_web/live/portal_live.ex#L1980)); the separate goal-rule form is on Evidence ([1542](../../../../../lib/harness_forge_web/live/portal_live.ex#L1542)). Current tab navigation ([60](../../../../../lib/harness_forge_web/live/portal_live.ex#L60)) and allowlisted focus event ([app.js:113](../../../../../assets/js/app.js#L113)) provide a contained seam. Existing goal form generations and blank selection enforce deliberate authority ([PortalLive:935](../../../../../lib/harness_forge_web/live/portal_live.ex#L935), [goal_claims_test:28](../../../../../test/harness_forge_web/goal_claims_test.exs#L28)).

**Decision and benefit.** Add a “Continue to evidence review” action on each saved goal card. It changes to Evidence and focuses the goal-rule heading; it carries no goal ID or draft payload. This exposes the next step while retaining explicit goal selection, separate proposal and exact-revision approval. Reuse `company-focus`; add only the heading target to its fixed allowlist. This is a UI navigation change, with no schema, contract, artifact or authority change.

**Acceptance.** Positive: keyboard activation on a card reveals the form, focuses its heading, and the next Tab reaches the blank Saved goal selector. Negative: no claim, approval, build, export or selected goal is created by navigation. Edge: unavailable/deleted goals, privacy reset, lock and stale events cannot restore a prior draft or preselect a goal; visible controls and focus work at 320/390 CSS pixels and actual 200% zoom. A five-person first-time comprehension check may measure whether at least four continue unassisted and distinguish save from approval; that target is **unperformed**, not a present claim.

**Blast radius and verification.** UI owner: `lib/harness_forge_web/live/portal_live.ex` for the card, event and heading. Frontend owner: `assets/js/app.js` for one focus allowlist entry. QA owner: `test/harness_forge_web/goal_claims_test.exs` for no-mutation and reset cases. Root alone schedules Mix and native browser checks, including keyboard/focus/zoom evidence. No migration or shared router edit. Failure recovery is reverting the navigation action; persisted goal/claim bytes remain immutable.

**Strongest alternative.** Correct invalid package-name refusal: the build handler maps generic `invalid_harness` through connector advice ([PortalLive:425](../../../../../lib/harness_forge_web/live/portal_live.ex#L425), [1258](../../../../../lib/harness_forge_web/live/portal_live.ex#L1258)). It repairs a confirmed misleading message with narrower user reach. The error code covers more than names, so safe classification and preserving entered fields after reload add work. The continuation offers broader workflow reach, but its human benefit remains unmeasured. Neither option qualifies company/model outcomes or resolves earlier coverage, coherence and portable-authority dissent.
