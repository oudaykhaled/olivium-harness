# 08 proposal — carry a package digest into own-MCP inspection

**Problem and source.** The Packages card displays an immutable digest but offers only export beside it ([PortalLive:2042–2115](../../../../../../lib/harness_forge_web/live/portal_live.ex#L2042)). The separate [MCP guide:54–80](../../../../../mcp.md#L54) asks operators to supply that exact 64-character digest to `harnessforge_inspect_package`. The tool verifies stored bytes and reports *current* eligibility, while explicitly returning `qualification: "not_assessed_by_this_tool"` ([Tools:248–263](../../../../../../lib/harness_forge/mcp/tools.ex#L248)). This cross-surface handoff is currently left to the operator.

**One benefit.** Add a compact, keyboard-accessible “Inspect with MCP” disclosure to each built-package card. It presents the exact tool name and copyable JSON arguments for that card’s digest, links to the existing setup guide, and says MCP is disabled by default, read-only, and requires separately configured bearer access. It does not report live MCP status or initiate a request. This helps a client user move from a built artifact to bounded current inspection without mistyping identity or confusing inspection with qualification.

**Acceptance.** Positive: opening the disclosure for package A exposes only A’s full lowercase digest in valid `{"digest":"…"}` arguments; keyboard activation and focus are clear. Negative: opening it creates no approval, build, export, evaluation, MCP request or credential exposure; disabled access is described as setup-required, not as package failure. Edge: two cards retain distinct digests; after privacy reset/removal, obsolete arguments disappear with their card; 64-character text and guidance remain readable without horizontal clipping at 320/390 CSS pixels and actual 200% zoom. Existing exact-digest/current-eligibility/Not-assessed language persists.

**Ownership and verification.** Product author: `lib/harness_forge_web/live/portal_live.ex`; documentation author if needed: `docs/mcp.md`; focused LiveView test owner: existing portal test module. Root alone schedules Mix and native browser checks, including keyboard/zoom and reset. No runtime or tests were executed for this planning proposal.

**Tradeoff and limit.** Confirmed invalid-package-name advice currently points to generic provider-import recovery ([PortalLive:1258–1282](../../../../../../lib/harness_forge_web/live/portal_live.ex#L1258)); fixing that is smaller and may deserve priority. Goals-to-Evidence continuation may improve the author journey but has an unperformed 4/5 comprehension target. This MCP handoff’s user benefit is likewise unmeasured. Historical 01 SDK compatibility does not establish fresh 07 or current client compatibility, company/model fitness, or portable approval authority.
