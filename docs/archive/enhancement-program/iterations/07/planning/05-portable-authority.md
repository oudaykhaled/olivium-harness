# 07 proposal: recipient-verifiable approval receipt

**Finding.** Exact claim and plan decisions record a free-text `actor` and revision hash ([`lib/harness_forge/decisions.ex:7`](../../../../../lib/harness_forge/decisions.ex), [`lib/harness_forge/company.ex:111`](../../../../../lib/harness_forge/company.ex)); neither proves the actor's company authority to a recipient. Current export rechecks local eligibility before writing ([`lib/harness_forge/harnesses.ex:122`](../../../../../lib/harness_forge/harnesses.ex)), but exports runtime files alone ([`lib/harness_forge/artifacts.ex:62`](../../../../../lib/harness_forge/artifacts.ex)); [`docs/mcp.md:79`](../../../../../docs/mcp.md) expressly denies portable approval verification. Restore deletes decisions and quarantines the workspace ([`lib/harness_forge/privacy/snapshot.ex:236`](../../../../../lib/harness_forge/privacy/snapshot.ex), [`test/harness_forge/privacy_test.exs:269`](../../../../../test/harness_forge/privacy_test.exs)). Thus copying hashes or local actor strings into a package would manufacture authority.

**Recommendation (one bounded benefit).** Add an *optional, separate* versioned approval receipt for an exported package, verified by a recipient with an independently provisioned company trust policy. A receipt binds exact artifact digest, workspace/company identifier, approved plan and claim revision hashes, signer key ID, issuance/expiry, and policy version. Issue only after current local eligibility and exact decisions pass; sign canonical bytes with a configured Ed25519 key whose custody is outside exported files and backups. Recipient verification requires its configured trusted public key, company scope, valid time window and current revocation-policy snapshot. Missing policy, stale revocation data or offline freshness yields **Not assessed**, never “approved.” Preserve v1alpha1 package bytes/digest; receipt is an adjacent file, not compiler input. A restore cannot issue from quarantined decisions. Receipt proves authorization at a bounded time, not policy completeness, model quality or current local eligibility.

**Trade-off.** The original 05 trust dissent ([`docs/enhancement-program/iterations/05/handoff-to-06.md`](../../05/handoff-to-06.md)) is substantial: recipient trust is a distinct missing capability. Yet keys, rotation and revocation distribution make this larger than the 06 retrospectives' validated route-snapshot proposal ([`docs/enhancement-program/iterations/06/handoff-to-07.md`](../handoff-to-07.md)); route consistency has a smaller implementation/verification surface and more direct qualification value now. Astra should select the receipt only if an explicit recipient/trust-policy owner is available; otherwise select route consistency and retain this gap.

**Falsifiers / ownership.** Positive: trusted, scoped, fresh receipt verifies exact exported digest/revisions. Negative: altered digest, unknown key, wrong company or revoked key refuses. Edge: expired/unavailable revocation state reports Not assessed; restored workspace cannot sign. Root owns schema/export integration and key-configuration boundary; one domain author owns canonical receipt/verifier and focused synthetic-key tests. Root verifies fresh export, tamper/revocation/restore cases and unchanged package bytes; no live recipient trust is claimed from fixtures.
