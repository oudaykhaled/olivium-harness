# 07 proposal — account for declared goal acceptance before plan approval

**Recommendation.** Add an approval preflight for *new* company-plan revisions: every selected goal must appear in a milestone with nonblank acceptance and evaluation method. Return uncovered goal IDs for correction; derive coverage from the immutable plan revision. This checks only selected goals. It cannot discover missing company obligations or certify model quality.

**Why this unit.** `Company.resolve/1` verifies selected approved claims, sources and goal scope, but does not inspect milestone coverage (`lib/harness_forge/company.ex:234-261,340-344`). Milestones are optional and validate each milestone's goal membership without requiring every selected goal to be covered (`lib/harness_forge/company/validation.ex:37-70,79-94`). The current test approves a plan with one goal and no milestones (`test/harness_forge/company_test.exs:39-50,108-123`). Thus an approved plan can omit an acceptance route for its declared goal. The evaluator has two synthetic Go tasks and objective outputs (`lib/harness_forge/evaluation/task_suite.ex:1-76`); task success does not measure company obligations. `Evaluations.compare/2` reports one finite observation, not productivity (`lib/harness_forge/evaluations.ex:166-184`). Iteration 06 delivered export recovery, not company/model qualification (`docs/enhancement-program/iterations/06/handoff-to-07.md`).

**Decision trade-off.** This is a narrow, offline accounting prerequisite with no inference cost and no new execution path. The route-snapshot alternative fixes repeated transport discovery and a failed-discovery Unix fallback (`lib/harness_forge/execution/coding.ex:28-38,127-150,427-450`), improving identity for later task evidence, but still cannot detect a missing acceptance obligation. Declared-conflict admission would address contradictory policies, a separate and larger lifecycle. Existing approved revisions remain historically valid; the new rule applies at new approval, with a correction through a superseding revision.

**Falsifiers.** Positive: a plan with two selected goals and two covered milestones can be approved; its exact coverage survives reload. Negative: one uncovered selected goal refuses approval without a decision or artifact. Edge: a milestone referencing an unselected/stale goal cannot satisfy coverage; a goal with no claimed milestone remains visibly uncovered. Zero selected goals retain the existing valid behavior. No result is labeled “company qualified.”

**Ownership/verification.** One Company/validation author plus focused plan admission tests, with root integrating any UI copy. Root runs the canonical suite and reviews preservation of old approved revisions; no model calls or private imports are needed.
