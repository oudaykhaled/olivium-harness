# 07 proposal: named, scoped local MCP clients

**Recommendation.** Give each local MCP client its own secret reference and allowlist of the three read-only tools. Revoking one entry must deny that client while another continues. This supports multiple recipients without sharing one all-access bearer. Received information remains outside revocation.

**Evidence and risk.** [Auth](../../../../../../lib/harness_forge/mcp/auth.ex) compares one `mcp_token_env` bearer; [runtime configuration](../../../../../../config/runtime.exs) supplies one reference. [Protocol](../../../../../../lib/harness_forge/mcp/protocol.ex) lists and calls all tools after authentication. [Tools](../../../../../../lib/harness_forge/mcp/tools.ex) returns catalogue owner/name, plan name/status/digests and package bindings. [Documentation](../../../../../mcp.md) says logout does not revoke MCP. A catalogue-only recipient given that bearer can read plan/package metadata. This is conditional exposure, not an observed leak; loopback, origin, no-store, response limits and the purge fence already constrain it. [HTTP tests](../../../../../../test/harness_forge_web/mcp_test.exs) cover global rotation and fenced reauthentication, not client-specific revocation.

**Decision and trade-off.** Extend `MCP.Auth` to return client policy from a bounded registry of secret references; pass it through fenced dispatch to `tools/list` and `tools/call`. Recheck membership and secret under the fence before reading. Reject duplicate credentials and ambiguous matches; give unknown tool names fixed errors. Retain single-bearer configuration as an explicit legacy full-read policy. Remove a client entry and restart the owner to revoke; this briefly interrupts MCP. Dynamic revocation storage adds migration and consistency risk.

**Acceptance.** Positive: two synthetic clients with disjoint allowlists see only permitted definitions/results; revoking one leaves the other usable. Negative: revoked, malformed or wrong-scope credentials return fixed errors without company data or secret echoes. Edge: a request queued behind the purge fence is denied after its entry is removed; purge still holds through response send. Verify HTTP/protocol tests, `mix test`, and one native local MCP client check in root's runtime window.

**Why this unit.** Route snapshot repairs execution identity and may be more urgent for qualification; coherence checks address approved content; portable receipts require signer/freshness/key management. This closes a per-recipient MCP boundary without a new endpoint, schema or write capability.
