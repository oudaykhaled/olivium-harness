# 10 — Failure injection and test accounting

**Recommend one validated, attempt-owned coding route snapshot.** `Coding.profile/0` discovers transport three times (`lib/harness_forge/execution/coding.ex:28-39`); `run/2`, proxy setup and verification rediscover (`:128-145`, `:444-451`, `:661-663`). `transport/0` maps every nonexact Docker Desktop result, including timeout and malformed output, to Unix (`:427-432`). `Evaluations.applicability_identity/2` computes another profile digest (`lib/harness_forge/evaluations.ex:72-94`). Changing observations can produce inconsistent execution identity. This is source-derived, not an observed exploit.

Have one typed discovery result feed relay mode, proxy config, network verification and persisted profile digest; reject failed or unrecognized discovery before resource creation. Recheck route and model configuration for later applicability. Cleanup uses original run/workspace labels. Keep readiness command-free and abstaining (`test/harness_forge/readiness_test.exs:24-44`).

**Why now:** Tests assert two profile fields and execute pinned OpenCode against a synthetic HTTP model (`test/harness_forge/coding_evaluation_test.exs:128-135,186-223`). Docker cases are opt-in; fixtures prove protocol and containment, not model quality or company fitness. Iteration 06 recorded 495 canonical passes, 15 default Docker skips and 111 repeated focused passes; CSS-only candidate 03 had no fresh canonical run (`docs/enhancement-program/iterations/06/handoff-to-07.md`). Coverage, flake rate and longitudinal reliability remain unmeasured. Alternative conflict admission requires a wider resolution/invalidation lifecycle; recipient receipts require signer/revocation contracts. Route consistency is a falsifiable prerequisite for qualification.

**Acceptance:** Positive: injected stable Desktop and Unix observations each yield exactly one discovery per attempt and identical route in relay/proxy/network checks and persisted identity. Negative: timeout, nonzero, malformed and unknown observations return a fixed unavailable result with zero relay/container creation and no invented Unix profile. Edge: route or configuration drift makes the saved run inapplicable; cleanup uses original ownership and synchronous readiness invokes no discovery. Instrument the command boundary in focused tests, then run the canonical machine-counted suite and one guarded Docker path under root's Mix window. Report unique passes, skips, failures and fixture versus live provenance separately. Minimal ownership: coding route and evaluation identity integration, focused coding/readiness tests; root coordinates shared integration and execution.
