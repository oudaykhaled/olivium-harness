# Goal-origin task evaluation compatibility

**Recommendation (07, one bounded benefit).** Admit an eligible, approved, plan-bound **goal-only** OpenCode artifact to the existing local synthetic task evaluator with an empty source-ID scope. Today that artifact can build and export with exact goal provenance and no citations ([goal admission test](../../../../../test/harness_forge/goal_claim_admission_test.exs#L62)), but `Coding.artifact_sources/1` rejects every empty revision set before relay creation ([Coding](../../../../../lib/harness_forge/execution/coding.ex#L761)). This prevents a task observation even with a local model. No live outcome is claimed.

Keep the exception narrow: require at least one rule; every rule must have a non-null goal ID and empty evidence; rely on the existing `Harnesses.eligible/1` and `Compiler.verify/1` admission before evaluation ([Evaluations](../../../../../lib/harness_forge/evaluations.ex#L109), [origin/binding checks](../../../../../lib/harness_forge/harnesses.ex#L148)). Source-bearing artifacts still resolve every revision to active workspace sources and fail closed when a revision is missing. The relay receives `source_ids: []` only for the admitted goal-only case. Coding evaluation already accepts only local Ollama; cloud authorization requires a nonempty consented source set ([Coding](../../../../../lib/harness_forge/execution/coding.ex#L108), [configuration](../../../../../lib/harness_forge/models/configuration.ex#L92)). Preserve that boundary and never synthesize a source citation or infer consent from a goal. A passing synthetic Go suite remains a finite runtime observation, not evidence that the company goal was met ([TaskSuite](../../../../../lib/harness_forge/evaluation/task_suite.ex#L1)).

**Trade-off.** The 06 handoff favors validated route identity for 07 ([handoff](../../06/handoff-to-07.md)); it addresses profile/dispatch consistency for all coding runs. This exception opens a blocked path; route drift remains unresolved and applicability must refuse changed identities. Declared-conflict admission is also valuable but adds a separate policy lifecycle; it cannot make this evaluation path usable.

**Acceptance.** Positive: a zero-source, approved goal-only fixture reaches the existing local task path; recorded result retains exact artifact/suite/model identities, and only observed protected checks can qualify it. Negative: mixed or source-origin rules with missing revisions, unapproved/stale plans, and caller-supplied outcomes refuse before relay/resource creation. Edge: a goal/plan change or privacy reset makes the prior run inapplicable; cancellation/cleanup remains run-owned, and no cloud dispatch becomes possible. Own `Coding.artifact_sources/1` plus focused goal/evaluation tests; root coordinates any shared integration and one Mix window. Verify positive/negative/edge with synthetic fixtures, canonical `mix test`, and explicit unavailable-model behavior; live company fitness remains unverified.
