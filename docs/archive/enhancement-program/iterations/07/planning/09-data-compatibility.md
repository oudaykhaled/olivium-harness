# Planner 09 — persisted evaluation identity and historical compatibility

**Recommend one bounded improvement: validated, run-owned transport identity for new OpenCode task evaluations.** `Evaluations.create/2` persists identities before execution; `Coding.profile/0`, `Coding.run/2`, and `Coding.start_proxy/2` independently discover transport, with failed discovery interpreted as Unix. Recorded and executed routes can differ: a source-derived risk, not an observed incident. See `lib/harness_forge/evaluations.ex` (`applicability_identity/2`, `create/2`), `lib/harness_forge/execution/coding.ex` (`profile/0`, `run/2`, `transport/0`, `start_proxy/2`), and `test/harness_forge/evaluations_test.exs`.

**Decision.** Validate one Desktop or Unix observation before task execution resources; pass its typed route through relay/proxy construction and derive the persisted profile digest from it. Version only the task coding profile (`v2`), so legacy `v1` cannot prove the new guarantee. Keep the route in the string-keyed `evaluation_runs.result` map (`lib/harness_forge/evaluation/run.ex`): no migration, backfill, lock, or historical rewrite. Static/smoke identities retain separate contracts. Release admission recomputes validated current identity and rejects old/drifted task digests (`lib/harness_forge/releases/validation.ex`, `lib/harness_forge/evaluations.ex`). `Readiness` continues abstaining from live OpenCode identity (`lib/harness_forge/readiness.ex`); saved route grants no current authority.

**Alternative:** preserve `v1` and add only a result field. This minimizes digest churn but leaves historical ambiguous runs apparently applicable. A SQL column adds migration cost without strengthening identity. `v2` invalidates historical task qualification while retaining readable results and same-generation comparison.

**Acceptance:** Positive: each recognized route yields matching persisted profile, relay/proxy configuration, and execution. Negative: timeout, nonzero, malformed, or unknown discovery blocks before relay/container/network creation, never defaulting to Unix. Edge: drift refuses release applicability; cleanup uses original run/workspace ownership; old `v1` rows remain readable but inapplicable. Verify both routes, malformed discovery, old/new rows, compare, release validation, and command-free readiness with focused tests; root schedules `mix test`. Ownership: Elixir author owns `coding.ex` and focused tests; root integrates shared evaluation/release code. Rollback disables v2 release admission before restoring v1 code; no data rollback or database lock.
