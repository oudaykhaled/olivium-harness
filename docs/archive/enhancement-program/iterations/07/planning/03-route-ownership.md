# Proposal 03 — attempt-owned route and daemon identity

**Recommendation (07 functionality).** Admit a coding attempt only after one validated local Docker observation yields a supported route (`Docker Desktop` or recognized Linux/Unix) and a local Unix daemon endpoint. Bind that observation to the attempt. Use its route for relay socket choice, proxy configuration/network, container verification and recorded profile. Use its daemon endpoint for every attempt-owned Docker command, including cleanup, or refuse cleanup as pending when that endpoint cannot be safely re-established. Do not infer Unix from discovery failure.

**Evidence.** `lib/harness_forge/execution/coding.ex:28-50` calls `transport/0` three times while constructing one profile; `:128-157` chooses relay mode, `:444-468` discovers again for proxy, and `:653-676` discovers again during verification. `:427-431` maps every non-exact Desktop result, including timeout and malformed output, to Unix. `lib/harness_forge/execution/command.ex:6-40` resolves Docker's endpoint on every call, so a route-string-only patch still lets later commands and `coding.ex:802-910` cleanup target a changed daemon. Relay already owns its process/capability and socket cleanup (`lib/harness_forge/execution/relay.ex:12-16,44-59,180-195`); container cleanup checks workspace/run/profile labels (`coding.ex:680-695,865-905`). Preserve these checks and the existing command-free OpenCode readiness abstention (`lib/harness_forge/readiness.ex:105-111`). These are source-derived risks; no drift exploit or live company qualification was observed in 06 (`docs/enhancement-program/iterations/06/handoff-to-07.md`).

**ADR sketch.** Context: route and daemon discovery are mutable. Decision: one attempt-owned validated snapshot, with a bounded explicit endpoint argument at the Command boundary and durable non-secret cleanup identity. Consequence: discovery/drift may block an attempt or leave cleanup pending until the original local daemon is available. Alternatives: changing only `transport/0` leaves command drift; redesigning all Docker runtimes expands scope beyond coding attempts.

**Falsifiers.** Positive: Desktop and Linux fixtures each produce one consistent relay/proxy/profile route and commands aimed at the same local endpoint. Negative: timeout, nonzero, malformed or unknown discovery creates no relay/container and records no invented route. Edge: context/config drift before proxy or cleanup cannot touch a different daemon, cannot qualify a passed run, and retains original run/workspace/profile cleanup identity for recovery. Test with injectable command observations plus guarded synthetic Docker integration; root owns the sole Mix/Docker window. Proposed ownership: one Elixir author for `Command`, `Coding` and focused tests; root integrates evaluation identity persistence if required.
