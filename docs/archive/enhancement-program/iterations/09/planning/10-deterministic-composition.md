# Cross-source candidate composition with deterministic approval

**Recommendation.** Add one analysis run for two to four selected, current, consented revisions of company guidance, plans and history, plus one saved goal. A configured model proposes candidate rules, exact cross-source citations, rationale distinguishing practice, decision, exception or changed guidance, uncertainty, and suggested check/evaluation wording. The operator edits, rejects or approves candidates. An approved company plan selects exact claim revisions; the compiler exports the company-specific harness. Model output grants no authority.

**Why this seam.** `Models.propose/2` currently sends one source revision and `Proposal.validate/2` binds every model citation to that one revision (`lib/harness_forge/models.ex:150`, `lib/harness_forge/models/proposal.ex:49`, `lib/harness_forge/models/proposal.ex:109`). `Evidence.create_claim/1` already accepts validated citation lists and records immutable claim revisions (`lib/harness_forge/evidence.ex:289`, `lib/harness_forge/evidence.ex:429`). Portal separates proposal and exact-revision decision (`lib/harness_forge_web/live/portal_live.ex:215`, `lib/harness_forge_web/live/portal_live.ex:407`). `Company.build_inputs/1` requires an approved exact plan, and `Harnesses.build_plan/2` rechecks it before publication (`lib/harness_forge/company.ex:138`, `lib/harness_forge/harnesses.ex:10`). `Compiler.assemble/3` binds deterministic file bytes and digest (`lib/harness_forge/compiler.ex:78`).

**Bounded contract.** Cap input bytes, output tokens, candidates and citations; pin revision hashes and recheck before storing. Preserve consent/budgets and visibly refuse unavailable local inference. Keep rationale/uncertainty in review metadata, outside approved instructions. Let the operator edit text/citations, then decide. Existing finite skills and synthetic evaluation suite remain labelled generic; suggested checks are review guidance until approved as rule text. Independently generated checks or company-specific skills need later schema work.

- Positive: a synthetic policy, superseding decision and incident history yield a cited candidate whose conflict/exception rationale is visible; operator edits and approves, approves a selected plan, then exports the verified digest with the edited rule and pinned provenance.
- Negative: stale citation, missing consent, malformed output or rejected candidate creates no approved rule or package.
- Edge: reversed source selection yields the same canonical prompt order; the same approved revisions produce byte-identical exports regardless of proposal order. Changed source invalidates eligibility.

**Trade-off.** Semantic assistance can identify changed policy that keyword matching misses, at local-model and review cost. Three seams: model/validation, portal review, end-to-end tests. Falsifier: unreviewed model text reaches exported instructions or identical approved inputs yield differing digests. Synthetic success proves neither real-company completeness nor model quality.
