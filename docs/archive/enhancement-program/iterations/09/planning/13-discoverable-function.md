# 13 — Review a cross-source company brief into a package

**Gap and trigger.** An owner has captured policy, project plans, incident history and a future goal, and asks what the harness should contain. `Models.propose/2` extracts from one revision (`lib/harness_forge/models.ex:150-189`); Company requires manual claim, goal, preset and milestone selection (`lib/harness_forge_web/components/company/plan.ex:87-242`). Its guide counts records without analyzing agreement, conflicts or change (`lib/harness_forge_web/components/company/guide.ex:15-81`).

**One functional slice.** Add `Company.analyze_project(project_id, opts)` as an operator-triggered brief over assigned current revisions and goals. Reuse metered `Models.infer/2` with source authorization, consent, request IDs and budgets (`lib/harness_forge/models.ex:81-148,229-250`); no fallback. Return candidate rules with exact citations, goal relevance, check/acceptance text and conflict/outdated/unknown notes. Validate cited ranges against selected revisions, reject invented IDs, and cap inputs/output. In Company, each candidate has editable text, accept-as-proposed-claim or dismiss; exact Evidence rejection/approval remains mandatory (`lib/harness_forge/decisions.ex:7-48`). The human selects approved revisions, goals, fixed presets and milestones, then approves, builds and exports through existing authority (`lib/harness_forge/company.ex:71-95,110-169`; `lib/harness_forge/harnesses.ex:8-65`). Persisted claims and plan snapshots form the handoff; the brief confers no approval.

**Acceptance.** Positive: a synthetic three-source corpus contains a repeated practice, later exception, conflicting older instruction and a goal. One explicit analysis produces grounded recommendations and uncertainty; the operator edits one, dismisses another, rejects/approves exact claims, creates a scoped plan, and exports a package whose selected rules match the approved revisions. Negative: fabricated citation, unassigned source, unavailable model or missing consent creates no claim/plan/package. Edge: source revision changes between analysis and acceptance refuse the stale candidate; retry requires fresh analysis. A dismissed candidate never enters the package; an approved historical plan retains its own immutable bytes.

**Tradeoff, ownership, falsifier.** Model/validator and Company/Portal authors fit two lanes; estimate 3–5 days. Keyword summaries cannot reliably resolve exceptions; generic chat lacks a reviewed handoff. Falsify delivery if export contains an unapproved candidate, loses the edited rule, or presents conflict as settled. Synthetic success does not establish real-company semantic quality, comprehension, connector scopes, managed runtime or portable authority.
