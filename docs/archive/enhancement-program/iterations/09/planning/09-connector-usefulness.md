# 09 — Cross-source company analysis into a reviewed harness

**Trigger and gap.** An operator captures a company plan, decision log and incident history, then wants a harness reflecting practice and future goals. `Models.propose/2` accepts one revision (`lib/harness_forge/models.ex:150-184`); its validator requires citations from that source (`lib/harness_forge/models/proposal.ex:49-55,109-122`). Portal queues from one source card (`lib/harness_forge_web/live/portal_live.ex:215-220,1694-1708`). It cannot compare a plan with a later exception. Connector sync records provenance; revocation removes eligibility (`lib/harness_forge/evidence.ex:148-172,561-570`; `test/harness_forge/connectors_test.exs:58-112,360-385`). Live account listings are metadata, never imported evidence (`lib/harness_forge/accounts.ex:1-7,252-264`).

**Decision candidate.** Add “Analyse selected sources for this goal” for 2–4 current revisions and one saved goal. Show scope links, freshness and missing coverage. Reuse metered `Models.infer/2` with consent/budgets (`lib/harness_forge/models.ex:89-147`; `lib/harness_forge/models/configuration.ex:92-103`). Return a dossier: recurring practice/failure, applicable decision/exception, changed/outdated or conflicting guidance, goal connection, suggested skill/check/evaluation criterion, and 1–5 proposed rules with exact cross-source byte citations. Suggestions are advisory; export uses reviewed rules, goal acceptance and existing fixed skill templates (`lib/harness_forge/harnesses.ex:194-266`). Unresolved conflicts cannot silently become approved rules. Validate membership, freshness, UTF-8 ranges/snippets, output size and schema before atomic persistence. Treat source text as data. Unavailable inference or missing consent blocks without fallback.

**End-to-end contract.** Positive synthetic corpus: plan says review changes; later decision narrows an exception; incident shows a missed check. Dossier links all three and the goal; operator edits via a superseding claim, rejects another, approves a third, then selects claims in an exact Company plan, approves, builds and exports; edited/rejected revisions are absent from target files (`lib/harness_forge/company.ex:71-169,234-261`; `lib/harness_forge/harnesses.ex:8-25,122-159`). Negative: fabricated offsets, off-scope source, or unconsented provider yields no claim/decision/artifact. Edge: revision change or revocation blocks stale results and export; conflict stays flagged for resolution. A deterministic fake-provider test proves this path, **not** real-company reasoning quality.

**Ownership/trade-off.** One author owns multi-source model schema/validation, another the review UI, root shared integration; roughly 3–5 engineer days. More input raises token cost and conflict-review load, bounded by 4 revisions. Exact-excerpt-only citation improves review but cannot analyse relationships; milestone coverage enforces accounting but cannot discover them. **Falsifier:** an off-scope/stale citation reaches an approved export, or the test corpus cannot pass through human decisions to a company-specific package.
