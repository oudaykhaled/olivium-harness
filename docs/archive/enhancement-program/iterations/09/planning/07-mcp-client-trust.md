# Candidate: source-bound cross-document analysis drafts

**User benefit.** An operator selects captured documents/history, receives cross-source proposed rules with visible support and disagreement, edits/rejects/approves in Evidence, then uses Company plan/build/export for a company-specific harness. Current `Models.propose/2` analyzes one latest revision (`lib/harness_forge/models.ex:150`); citations, approval and export exist (`lib/harness_forge/models/proposal.ex:49`, `lib/harness_forge/company.ex:110`, `lib/harness_forge/harnesses.ex:122`).

**Decision (bounded ADR).** Add a cross-source proposal operation over 2–4 selected eligible revisions, with an aggregate byte cap inside the inference budget. Show selected scope, source links, revision freshness and missing coverage. Server-owned instructions/schema keep imported text as data (`lib/harness_forge/models/profile.ex:1`). Output: proposed rule/check, exact citations, `supported`/`conflicted`/`uncertain` status and reason. Discussion cannot become a decision without supporting evidence. Changed/outdated guidance and disagreement stay visible; future goals are labeled intent. Validate citations against selected immutable bytes and current eligibility; reject the whole malformed, fabricated or stale response before persistence. Supported proposals cite support; conflicts cite both sides. Persist proposals only. Preserve per-source cloud consent, budgets, privacy fence and no host fallback (`lib/harness_forge/models.ex:165`, `lib/harness_forge/evidence.ex:289`).

**Acceptance.** Positive: synthetic mixed history plus future intent yields cross-source citations and visible conflict/uncertainty; a human edits one proposal, rejects another, approves a third, and exports a target whose files include only the approved recommendation. Negative: injected instructions, forged range, unconsented source, unavailable model or over-budget output creates no approval/artifact. Edge: source change/purge during inference persists nothing; errors/audit reveal no private excerpt. Unsupported goal stays intent. Test portal journey and export bytes; fixtures establish contract, not model quality.

**Effort/risk.** Roughly 2–3 author-days across model validation, portal review and integration tests, within three authors. Falsifier: unsupported rule enters an approved/exported package without explicit human decision, conflicting guidance disappears, or a stale/unconsented source reaches inference. A deterministic keyword summary is cheaper but cannot establish semantic practice or authority. Independently revocable MCP clients remain a separate local-access gap (archived proposal); they do not deliver this company-analysis outcome. Real-company accuracy, managed clients and portable recipient authority remain unproven.
