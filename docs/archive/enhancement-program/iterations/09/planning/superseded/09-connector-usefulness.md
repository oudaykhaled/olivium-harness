# 09 — Connector usefulness: cite the exact passage

**User trigger.** After syncing a selected connector scope or importing an approved directory, an owner finds an obligation in a captured document and proposes a rule. Today the Evidence form binds the **whole body** as its citation (`lib/harness_forge_web/live/portal_live.ex:344-353,1592-1614`), potentially 1 MiB (`lib/harness_forge/evidence/local_import.ex:3-5`). A reviewer must find the sentence again. The domain already stores immutable byte offsets and verifies UTF-8 boundaries, current revision, active source and connection (`lib/harness_forge/evidence.ex:271-286,429-450,561-600`); connector tests verify selected-scope provenance and revocation (`test/harness_forge/connectors_test.exs:58-112,360-385`). Live account metadata remains separate from source import (`lib/harness_forge/accounts.ex:1-7,252-264`).

**Decision candidate.** Add one “Exact supporting passage” field to the existing sourced-claim form. The owner copies a verbatim passage from the selected captured snapshot (1–4096 UTF-8 bytes). At submission, a bounded Evidence operation finds **exactly one** binary occurrence in that pinned, currently eligible revision, computes exclusive byte offsets, creates its citation and proposed claim in one transaction, and returns the existing claim review card showing that passage and offsets. No normalization, model inference, new connector, credential handling or automatic approval. Preserve the current explicit approval, consent, immutable revision and source revocation boundaries.

**Acceptance.** Positive: a unique passage in a synced synthetic source yields one proposed claim with matching snippet/hash/offsets; approval remains a separate exact-revision decision. Negative: absent, repeated, empty, oversized or malformed passage returns a fixed safe error and creates neither citation, claim nor audit entry. Edge: a source update/revocation or cross-workspace snapshot between selection and submission refuses without old-body fallback; a multibyte passage starts/ends on valid UTF-8 boundaries. Test the domain transaction and LiveView with local synthetic fixtures; no connector HTTP call is needed.

**Ownership/effort.** Elixir author owns `Evidence` and sourced-form/card tests; root integrates Portal LiveView. Estimated 1–2 engineer days. Paste accuracy costs an extra action; whole-document citation is easier but weak review evidence. This proposal competes with milestone coverage (broader company accounting) and MCP client revocation (access isolation). **Falsifier:** any accepted claim whose displayed passage cannot be reproduced from its eligible pinned revision, or any failed submission leaving a partial write. Even a passing fixture cannot establish real-company policy completeness or live connector credentials.
