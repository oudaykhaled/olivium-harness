# 09 proposal — continue bounded MCP plan discovery

**User benefit.** An MCP client can currently see only the oldest 20 company plans: `harnessforge_company_plans` returns `truncated: true` without a continuation argument (`lib/harness_forge/mcp/tools.ex:48`, `lib/harness_forge/mcp/tools.ex:148`). The 25-plan test confirms the cutoff (`test/harness_forge/mcp_tools_test.exs:160`); the guide explicitly says pagination is absent (`docs/mcp.md:65`). Add optional `after_plan_id` to the **list mode** of this existing read-only tool. Resolve that UUID within the current workspace, seek by `(inserted_at, id)` after the anchor, retain `limit` 1–20, and return `next_after_plan_id` only when another page exists. Existing `{}` and `{"limit": n}` calls retain their response shape and first-page order. Exact `plan_id` inspection remains separate.

**Contract.** Positive: 25 synthetic scoped plans, `limit: 10`, three successive calls yield exactly 25 unique IDs in ascending `(inserted_at, id)` order; the final page has no continuation. Negative: malformed/non-UUID anchor, `plan_id` mixed with `after_plan_id`, and foreign-workspace anchor produce fixed invalid/unavailable responses without exposing an ID or plan data. Edge: same-timestamp IDs remain deterministic; a newly inserted later plan may appear on a later page, while a deleted/purged anchor fails closed and asks the client to restart from page one. Pagination is a traversal, not a point-in-time snapshot. All pages retain projected summaries, `no-store`, body cap, privacy fence, exact local host/origin, default-off and bearer checks (`lib/harness_forge_web/plugs/mcp.ex:17`, `lib/harness_forge_web/plugs/mcp.ex:151`, `lib/harness_forge/mcp/auth.ex:10`).

**Evidence and choice.** Root should run scoped tool/HTTP regression tests, then an official MCP SDK client traversing >20 plans against a separately built native candidate; fixtures alone establish neither current SDK interoperability nor real-company usefulness. Compare all observed IDs to a same-workspace database oracle, assert no decision/build/export/audit writes, and verify 401/403/404/privacy failures and no secret/body reflection. A missing, duplicated, leaked or reordered plan falsifies this benefit. Ownership: `tools.ex`, `mcp_tools_test.exs`, `mcp_test.exs`, `docs/mcp.md`; approximately 1–2 engineer-days including native evidence. This is narrower than independent per-client revocation, which needs persistent credential lifecycle and operator controls; selected-goal approval coverage from `docs/enhancement-program/iterations/08/handoff-to-09.md` has higher direct company-completeness value. No qualification or portable authority claim follows from pagination.
