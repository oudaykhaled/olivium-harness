# 11 — Reproducible evaluation comparison

**Proposed user benefit:** Evaluation comparison should distinguish task evidence from diagnostics or interrupted attempts. Today `Evaluations.compare/2` checks recorded identity fields and returns `comparable: true`, `sample_count: 1` even for two static integrity passes or matching blocked runs; `qualified` does not condition that label (`lib/harness_forge/evaluations.ex:227-245`; `test/harness_forge/evaluations_test.exs:69-78`). The two built-in tasks are synthetic Go fixtures with evaluator-owned expectations (`lib/harness_forge/evaluation/task_suite.ex:1-6,47-75`). Readiness says those results do not establish company fitness (`lib/harness_forge/readiness.ex:29-35`).

**Decision candidate:** Add a task-evidence comparison mode to the existing `Evaluations.compare/2` contract. Return `comparable: true` in that mode only when both persisted runs are `kind: task`, completed, passed, runtime-qualified, cleanup-complete, and share the existing suite/grader/fixture/runtime/model/environment/scope identities. Otherwise return a bounded reason plus the two historical outcomes; never substitute another run or silently start one. Keep static/smoke comparison available as explicitly labelled diagnostics, without a task-evidence claim. This is a functional admission decision, not a new report page or evaluation engine. Principal Elixir owns `Evaluations` and focused tests; Portal/API presentation, if needed, follows the existing comparison response. Estimated effort: one focused implementation day plus root's checks.

**Acceptance oracle:** Positive: two independently persisted, completed qualified task runs with equal required identities yield task-comparable evidence and `sample_count: 1`; the owner sees that one pair is finite evidence, not productivity or company-policy proof. Negative: a static pass paired with another static pass, or a blocked task paired with a blocked task, never yields task-comparable evidence. Edge: interrupted/cleanup-failed or changed fixture/model/environment identity refuses comparison, without mutating runs, choosing a previous pass, or reporting success. When Docker, pinned image, isolated OpenCode, or selected local model is unavailable, retain its exact blocked/unavailable reason; no synthetic pass or host execution substitutes for the missing runtime (`test/harness_forge/evaluations_test.exs:29-49`; `docs/execution.md:123-129`). Falsifier: any unqualified or incomplete pair receives a task-comparable verdict.

**Trade-off:** This sharpens the meaning of existing evidence with low blast radius, but leaves representative company tasks untested. Selected-goal coverage addresses declared obligations; MCP revocation addresses client isolation; coherence addresses conflicting instructions. Those may yield greater company value, and none is supplied by this comparison gate.
