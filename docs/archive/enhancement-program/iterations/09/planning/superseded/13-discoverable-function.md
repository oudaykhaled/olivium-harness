# 13 — Resume a built company plan after reopening Company

**User trigger.** An owner builds an approved plan, closes the portal, and returns to export or evaluate. The Company guide recognizes a completed build only while `built_artifact` remains in session (`lib/harness_forge_web/components/company/guide.ex:194-208`); remount clears it (`lib/harness_forge_web/components/company_panel.ex:50-75`). Package and plan binding persist (`lib/harness_forge/harnesses.ex:30-65`), but reopened Company cannot identify its exact package. CLI offers plans, build, and generic export without plan-to-package lookup (`lib/harness_forge/cli.ex:34-65,184`). Tests cover build-to-export in one view (`test/harness_forge_web/company_builder_test.exs:156-215`).

**Proposal.** Add a read-only `Harnesses.list_plan_artifacts(plan_id, expected_revision_hash)` contract returning only persisted bindings for that exact workspace plan revision, joined to existing artifacts and sorted by digest. Company reload/selection uses it to show an exact digest and the existing Packages/Evaluations actions after remount; CLI exposes `company artifacts PLAN_ID REVISION_HASH` for the same lookup. This is one resumption capability, not automatic build/export/evaluation. Retain the current `Harnesses.export/2` and evaluation eligibility checks; a historical binding is provenance, never fresh authority. No schema or new panel is needed.

**Acceptance.** Positive: build plan P at hash H, remount, select P, and find its bound digest in Company and CLI; the owner can use the existing export path. Negative: another plan's artifact with the same name/version is absent, and a mismatched hash returns `:stale_plan_revision` without a digest. Edge: if selected evidence is later revoked, the historical digest may be identified as unavailable for handoff, while export remains blocked; a purged plan returns unavailable and cannot reveal another workspace's binding. Zero bindings yields an explicit empty result, never a prompt to rebuild automatically.

**Ownership and tradeoff.** Principal Elixir engineer owns the `Harnesses` read contract and integration tests; Portal/CLI owner wires the two consumers. Estimated 1–2 implementation days. The persisted lookup adds a bounded query and preserves a truthful interrupted workflow. A session-only shortcut is cheaper but repeats the failure on every reload; a new dashboard broadens scope. **Falsifier:** a fresh session cannot recover the exact bound digest, or displays a digest from a different plan/revision/workspace. Real-company/model outcomes and managed runtime qualification remain unproven.
