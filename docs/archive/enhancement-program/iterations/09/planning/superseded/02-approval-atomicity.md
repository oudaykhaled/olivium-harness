# Approval-time selected-goal coverage

**Context.** `Validation.plan/1` accepts zero milestones and validates each present milestone's selected goal IDs and nonblank acceptance/evaluation text ([validation.ex:37–93](../../../../lib/harness_forge/company/validation.ex)); the current fixture approves a selected-goal plan with none ([company_test.exs:400–405](../../../../test/harness_forge/company_test.exs)). This lets an approved package declare goals without any accountable milestone. It does not measure whether the company's real obligations were identified or met.

**Decision proposed.** Add a coverage check inside `Company.approval_eligible/2`, after existing supersession and `eligible/1` checks, for `"approve"` only ([company.ex:110–136,328–346](../../../../lib/harness_forge/company.ex)). Compute `selected goal_ids − union(milestone.goal_ids)` from the stored, validated immutable payload; return `{:error, {:uncovered_goals, sorted_ids}}` (at most 100 IDs). Extend the result and Company panel error rendering for that shape; never interpolate goal text. A zero-goal plan remains eligible under existing policy. `"reject"` stays available without coverage. Creation still accepts incomplete drafts, and historical approved plans retain their bytes and existing `build_inputs/1` behavior.

**Atomicity and precedence.** Keep the new check before `PlanDecision` insert. `mutate/1` uses `Store.transaction/1`; an error rolls back the decision and audit together ([company.ex:400–403](../../../../lib/harness_forge/company.ex), [store.ex:52–58](../../../../lib/harness_forge/evidence/store.ex)). Invalid input, unknown plan, wrong expected hash, prior decision, supersession and stale evidence retain their current errors before coverage. The unique `(workspace_id, plan_id)` index is the final concurrent-decision guard ([migration:33–43](../../../../priv/repo/migrations/20261031000700_company_builder.exs)); normalize a losing insert/SQLite contention into a controlled retry or already-decided outcome, with zero second audit. Do not claim application prechecks alone serialize callers.

**Acceptance.** Positive: two selected goals covered across valid milestones approve the exact revision. Negative: one uncovered goal returns only its ID, with unchanged decision/audit/artifact counts. Edge: duplicate references to goal A cannot cover B; stale/superseded/unknown IDs preserve existing refusal; rejection of an incomplete plan succeeds. A concurrent two-approver test must yield one decision and one audit, never an exception. These cases falsify the contract if violated.

**Trade-off/owner.** Principal Elixir owns Company, validation-facing error mapping and focused ExUnit tests; about one engineer-day, no migration. Creation-time coverage gives a stronger draft invariant but prevents staged authoring. A UI warning is cheaper but leaves direct callers able to approve gaps. This is declared accounting, not policy completeness or outcome quality.
