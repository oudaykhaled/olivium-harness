# Cross-source proposal admission as one reviewable set

**Context.** `Models.propose/2` captures one revision and persists inferred claims (`lib/harness_forge/models.ex:150–185`). `Proposal` permits text/citations from only that source (`lib/harness_forge/models/proposal.ex:18–47,109–122`). It cannot relate practices, failures, decisions versus discussion, exceptions, outdated guidance and goals across documents. Portal review and Company plan approval/build/export remain distinct (`lib/harness_forge_web/live/portal_live.ex:344–365`; `lib/harness_forge_web/components/company_panel.ex:330–345,411–421`; `lib/harness_forge/harnesses.ex:1–27,122–155`).

**Decision proposed.** Add bounded `analyze_company` over explicitly selected current revisions and goal snapshots. Each candidate has a typed finding (`practice`, `failure`, `decision`, `exception`, `conflict`), uncertainty, validated goal references, proposed rule/check/evaluation text and exact, possibly cross-source citations. Validate schema, UTF-8 spans, source/revision IDs and current status before atomically persisting all as *proposed* claims (`lib/harness_forge/models/proposal.ex:49–98`; `lib/harness_forge/evidence.ex:271–325`). Retain a bounded run receipt of revision hashes, goal links and claim IDs, without bodies or credentials. Model output grants no approval.

**Review boundary.** Portal exposes spans, uncertainty and rationale. Operators edit via successor, reject or approve exact revisions (`lib/harness_forge/decisions.ex:7–48`). Only approved current claims enter an operator-composed plan; decision, `build_plan/2` and export retain rechecks (`lib/harness_forge/company.ex:110–169,328–346`; `lib/harness_forge/harnesses.ex:70–90,122–155`). Partial review approves nothing else. Conflicting guidance stays visible, not silently flattened.

**Acceptance/falsifier.** Positive: synthetic recurring practice, later exception and future goal produce cited candidates; edit/approve one, reject another, approve a linked composed plan, export only accepted exact revisions. Negative: fabricated span, stale source, malformed candidate or model error yields zero claims/decisions/artifacts. Edge: source changes during inference; final revision-set recheck refuses the *entire* set. Partial persistence or rejected text in export falsifies atomicity. Synthetic provider proves wiring, not real-company quality.

**Trade-off/owner.** Principal Elixir owns schema/admission/tests; portal/Company author owns review; root owns migration. Estimate 2–3 engineer-days. Per-source proposals reuse more code but miss cross-document conflict; automatic plans remove human authority.
