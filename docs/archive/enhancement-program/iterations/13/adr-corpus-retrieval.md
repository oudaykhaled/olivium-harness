# ADR 13 — bounded corpus runs and versioned retrieval authority

**DRAFT — requires root interface/ownership acceptance.** Scope is the single connected slice selected in `selection-decision.md`; no backend/server contract was inherited or executed by Astra.

## Context

Frozen source `tmp/enhancement-program/13/source-before/lib/harness_forge/company/analysis.ex:169` and `evidence/origin.ex:84` independently enforce 2–4 whole sources. `evidence/local_import.ex` accumulates the directory before a 500-file/16-MiB import; `models/configuration.ex` has singleton settings and ≤100-ID consent. Existing claim/plan approvals, deterministic exports, SQLite/FTS and the 25-row/4,096-byte inspector are reusable authority. The actual pinned Graphiti source has native Jev runtime composition, but empty search groups become unfiltered and failed removal-summary rebuild restores old text. These findings require adapter/control work, not new graph algorithms.

## Decision

### 1. One application-owned CorpusRun boundary

Reuse Elixir/Phoenix, revisioned SQLite, existing jobs/privacy/ledger/approval/export. Add relational `corpora`, `corpus_members`, `capture_runs`, `capture_items`, `passages`, `retrieval_runs`, `origin_dependencies`, `stage_configs`, `stage_consents`, `graph_episode_bindings` and job/attempt records by extending existing records where their semantics fit. These are logical entities, not an instruction to create eleven unrelated services/tables; root resolves exact migration composition. Unique keys include workspace/corpus/source, capture-run/path, revision/chunker/start/end, origin/dependency and episode binding identity. Index scope/current eligibility before keyset/rank. All wire maps use string keys; reject unknown keys/types, oversized values and client-forged authority.

Primary UI action selects corpus + saved project/goal; no 2–4 source form is required. Profile/project references a corpus explicitly; old source arrays and v1 records keep their original validation, with deliberate idempotent migration rather than silent reinterpretation. Corpus selection and provider consent remain separate actions. A client cannot submit membership as authority or authorize future source bodies implicitly.

`start_capture(corpus_id, approved_connection_id, expected_generation)` returns run ID/status; `capture_status(run_id, cursor)` returns body-free counts and ≤25 outcomes; `resume/cancel(run_id, expected_revision)` are idempotent. One active capture/workspace, one SQLite writer, ≤100 accepted files or 8 MiB per commit, ≤1 MiB/file, ≤2 queued batches. Persist a disk-backed bounded traversal frontier and per-directory enumeration progress; do not materialize all paths or bodies. Preserve inode/symlink/contained-root checks; if stable native enumeration cannot be guaranteed, mark a directory changed/incomplete and rescan it with deduplicated outcomes rather than claim a snapshot.

Atomic commits bind file outcome, source revision, corpus member, passage/index intent and checkpoint. Replaying unchanged hash is idempotent; changed bytes create a new revision. Outcomes: captured/unchanged/excluded/failed/stale. Run states: queued/running/paused/cancelled/failed/scan_complete; separate FTS ready/partial and graph unavailable/indexing/ready/stale/denied. Graph readiness never masquerades as capture completeness. Only successful complete traversal can reconcile unseen members in bounded pages; interruption/unreadable entries cannot delete unseen evidence. Persist counts/lag and preserve partial coverage.

### 2. Passage retrieval DTO and limits

`retrieve({corpus_id, project_id, goal_id, goal_hash, expected_generation, question, mode})` admits only server-derived nonempty active authorized scope; mode is explicit `fts` or `graphiti_hybrid`, never a hidden fallback. Return an immutable run ID/digest with coverage/control state. `read_run(id,digest,cursor)` returns ≤25 body-free passage/dependency summaries; `open_passage` retains existing ≤4,096-byte inspection checks. Browser preview tokens never authorize analysis.

Version `query_plan_v1` uses four deterministic lanes: goal/question support; exception/negation/changed guidance; decision/incident chronology; missing-goal obligations. At most four initial searches plus one targeted follow-up; union ≤100 permitted candidate IDs, final ≤24 passages including reserved contrary/unknown slots. Pack original passage plus parent context into ≤32,768 aggregate evidence bytes and ≤49,152 encoded analysis prompt bytes; each original window ≤4,096 bytes. Candidate rank output may expose @20/@50 diagnostics, but the final packed set and its misses must also be measured. Bounds are ceilings, not obligations to fill every slot. If an indispensable parent qualification cannot fit, preserve omission and abstain rather than clip meaning.

Passage DTO: source_id/revision_id/body_hash/start_byte/end_byte/snippet_hash, parent window bounds/hash, source link/title, document_status, event_at/effective_at/captured_at (unknown allowed), provisional relation support/contrary/unknown, retrieval lane, selection/exclusion reason. Offsets are half-open original UTF-8 bytes, validated before prompt/display. Metadata status is documentary evidence, not automatic human approval. FTS indexes bounded passages, not full-source DTO hydration. Graph returns candidate IDs only; Elixir resolves and rechecks exact original bytes and current authority.

Coverage DTO distinguishes enumerated/captured/indexed/eligible/failed/excluded counts, queried lanes/time/status families, missing fields, truncation and unsearched coverage. No finite top-k establishes company-wide completeness. Incomplete scan/index/closure and unresolved critical evidence produce abstain/refresh_required; no universal policy claim is permitted. Unresolved critical conflicts require explicit human resolution before exact claim approval.

### 3. Authoritative origin v2 and invalidation

Persist server-owned immutable `origin_v2` with workspace/project/corpus identity; corpus semantic/authorization generation; saved goal hash; scan checkpoint/completeness; FTS/graph/chunker/parser versions and selected lane; query plan/question/limits; ordered evidence/parent envelopes; stage/model/prompt/config fingerprints; complete dependency-manifest ID/digest. The retrieval/dependency origin excludes editable guidance and human resolution. A separate immutable analysis record references this origin and the initial report hash; each successor claim binds its own exact guidance/resolution payload hash and that unchanged origin. There is no self-referential origin mutation. Dependency rows include every cited and uncited prompt input, previous extraction episode, edge support, summary/context/metadata influence and recursively resolved source revision/hash. Cycles, unknown ancestry or unfinished closure make a derivative ineligible. Dependencies are pageable server records, never a whole-corpus browser array.

Advance corpus semantic generation transactionally for source addition/removal/recapture, membership/status/date/scope change and newly published index content; record generation once per bounded publication transaction. Authorization/consent changes are checked independently even if content is unchanged. A retrieval result built against an older generation cannot publish as current. An active incomplete rescan is visible and prevents a completeness claim. Index version rebuilds invalidate lane-dependent snapshots; optional graph availability alone does not silently rebind an FTS snapshot.

Initially **every** semantic change to a selected corpus invalidates all dependent v2 run/claim/plan/artifact eligibility, including a newly added contrary document when all cited hashes stay unchanged. This is lazy equality/eligibility checking plus durable fence, not rewriting immutable approval records. Revalidate at retrieval, each dispatch, post-response admission, display/review, exact claim approval, plan approval, build, export and MCP readiness. Human text edit creates a successor preserving origin; refreshing evidence creates a new origin/proposal and new exact claim and separate plan approvals. Old immutable artifacts remain historical, cannot be freshly exported as eligible; external existing copies cannot be recalled.

### 4. Actual Graphiti reuse and qualification candidate

Pin Graphiti 0.31.2 commit `d72407dcedac911e1be9fc15b55e8c05a3efcc36`, Apache-2.0 notices, Python/dependency wheel hashes (including explicit httpx0.28.1 compatibility correction), and worker image. Reuse actual `Graphiti.add_episode`, temporal records, hybrid search and `remove_episode`; compose upstream `JevClient`, `LLMRuntime`, `LLMTransport`, `PromptRoutes`, `jev_prompt_overrides`. New immutable episode identity per revision/chunker/window; supplied existing UUID is checked against body binding before replay, never reused for changed bytes. Explicit bounded prior episode IDs and their complete closure prevent hidden recent-context influence. Disable community/global summaries in this slice; entity summaries still need tracked ancestry and cleanup.

Select built-in **Neo4j driver** for first backend qualification. Root must resolve and record a supported exact server version, image digest, architecture and its own license/notices before installing/starting it; client `neo4j>=5.26` is not a server compatibility or license proof. No moving tag can become acceptance evidence. FalkorDB remains an alternative with parameter-value logging and transaction behavior to resolve; deprecated Kuzu is rejected. This conditional server resolution is technical qualification, not a new user approval request. If unavailable, preserve the unresolved backend gate and continue independent work; no silent substituted backend or completion by relabeling.

Use one root-supervised bounded Python worker over framed local IPC (private inherited pipe or Unix socket, no public service). Ops: health/ingest/search/remove/cancel. Request envelope ≤131,072 bytes: protocol_version, operation, request/job IDs, nonempty opaque scope binding, expected generations, bounded passage/episode IDs, stage-config IDs, deadline and idempotency key. Response contains bounded candidate IDs/status/attempt receipts/dependency digests; no approval or trusted citation. Max one ingest operation per corpus, bounded semaphore and explicit close/cancel/restart. Set `GRAPHITI_TELEMETRY_ENABLED=false` before import, prohibit ambient credential discovery/default clients, and expose only permitted local backend/model channels. No graph Cypher, source text or secrets in logs.

Backend qualification must exercise actual upstream ingestion, temporal/hybrid retrieval, persisted search after restart and shared-source removal against the selected real backend. Scripted model/embedding/Jev HTTP responses may prove mechanics with real classes/backend, clearly labeled; they establish no semantic quality. Also test actual native Jev two-route call composition and unsupported-prompt refusal. Missing authorized generative/embedding/Jev stages are explicitly unavailable, never filled by production fake clients. Returning imported fake graph edges is not Graphiti ingestion proof.

### 5. Stage admission, privacy and recovery

Immutable stage pins cover extraction/summary, dedupe_nodes, dedupe_edges, embedder, optional reranker and synthesis: provider/model/endpoint, credential reference only, config/prompt/schema versions, consent revision, limits/rates. Existing singleton settings can seed one explicit snapshot, never be mutated between stages. Jev only serves its two dedupe routes. No calibrated confidence escalation is included. Each actual call resolves full dependency closure and paged source/category/endpoint consent; adding corpus members does not silently consent them.

Preserve ≤131,072 request bytes, ≤4,096 output tokens, ≤60-second attempt timeout (or tighter remaining job deadline). One default attempt; maximum three explicitly admitted orchestration attempts per stage and bounded total run calls/cost. Jev `max_retries=1`; injected metered httpx transport must intercept every post including split/shrink. All generative/embedding/reranker/removal-summary clients likewise cross the gateway. Admit/reserve before egress, recheck cancellation/consent/generation, return actual attempt ID and usage/unknown, then revalidate after response. Replays cannot double-commit results; ambiguous billed attempts retain reservation and another retry consumes new budget. Shrunk context must be recorded and cannot silently pass unchanged completeness. No long SQL transaction across worker/provider call; no exactly-once billing claim.

Extend existing Privacy.Purge prepare/resume/ready and backup quarantine across every new logical entity. In a local transaction tombstone source/corpus dependencies, invalidate serving and cancel queued dispatch before upstream removal. If closure is incomplete, fence the selected corpus. A normal `remove_episode` return does not clear this fence: verify surviving-source dependency summaries, passage/index/cache removals and old-text absence, plus database/files cleanup. Missing model for rebuild leaves denied status. Persist cleanup checkpoints and retain denial through crash/restart/restore; stale responses are discarded. Restored state gets fresh identity, quarantined graph and no inherited consent/approval. External export/provider/backup limits persist.

## Consequences

This connects the user outcome while keeping bounded contexts and immutable approval authority. Coarse generations cause re-review on irrelevant additions; graph adds dependency/IPC/privacy cost; one scan/writer limits throughput but makes restart and SQLite consistency tractable. Exact per-attempt transport instrumentation and inherited graph-summary closure are the highest-risk seams. If either cannot be enforced, deny that graph operation and escalate the concrete failure to root; do not lower the gate. Local qualification is not production deployment.

## Alternatives considered

FTS-only delivery is simpler and remains an explicit useful lane, but cannot fulfill required source reuse by itself. Graph-platform-first delays reviewed exports and broadens state. Relevance-watermark invalidation reduces recomputation but lacks proven critical-miss safety. FalkorDB may reduce footprint but needs separate license/pinning/log-redaction qualification. Default deprecated Kuzu, bespoke graph/Jev HTTP engines, multiple frameworks and higher global caps are rejected. Preserve these alternatives and unknown server/model availability in acceptance evidence.
