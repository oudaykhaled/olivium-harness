# Packages export recovery (UI/UX proposal)

**Benefit.** After a failed export, the operator can correct the destination and retry from the same package without interpreting unrelated provider advice or a stale success notice. The actual filesystem contract already rejects missing/unsafe parents (`unsafe_artifact_path`) and occupied destinations (`export_conflict`): [Artifacts.ex:61–68](../../../../../../lib/harness_forge/artifacts.ex#L61), [Artifacts.ex:260–277](../../../../../../lib/harness_forge/artifacts.ex#L260), [Artifacts.ex:324–328](../../../../../../lib/harness_forge/artifacts.ex#L324). [PortalLive.ex:393–404](../../../../../../lib/harness_forge_web/live/portal_live.ex#L393) retains `export_path` on failure and does not clear the error flash on success; [PortalLive.ex:1060–1083](../../../../../../lib/harness_forge_web/live/portal_live.ex#L1060) sends other contract errors to “provider page could not be imported.” The current form has a labeled target field but no local recovery message ([PortalLive.ex:1767–1785](../../../../../../lib/harness_forge_web/live/portal_live.ex#L1767)). Iteration03 quality and UX independently observed this gap ([retro/05](../../03/retro/05-quality.md), [retro/02](../../03/retro/02-ux.md)).

**Acceptance.** For the selected digest, submit a missing-parent absolute path: show a Packages-specific alert explaining that the parent must already exist and be a real directory, preserve the attempted target in its field, and focus the alert or target. Submit an occupied destination: explain that a fresh directory name is required. For an invalid/symlink path, give the safe general path remedy without claiming which subcase occurred. A failed attempt clears any earlier export success; a successful retry to a fresh destination clears the superseded error, shows the verified destination, and leaves bytes identical to the package. Error copy never exposes filesystem internals. Existing auth, privacy reset, stale-event and revoked-eligibility refusals remain authoritative.

**Checks.** LiveView tests exercise the two real filesystem failures, focus/retained input, error→success and success→error; artifact tests verify exact bytes and no overwrite. Native keyboard/narrow/200% evidence checks reading order and alert prominence. No production command, model call or imported code is needed.

**Alternative.** Static-only cleanup explanation is smaller and avoids export form state, but its benefit is clearer qualification wording, not recovery from a failed action. Export recovery has a concrete retry outcome; risk is error-code conflation, so copy stays conservative. Likely files: `portal_live.ex`, focused web tests, perhaps local styles. Estimated 1–2 engineer days including verification. OpenCode task preflight remains **NOT ASSESSED**.
