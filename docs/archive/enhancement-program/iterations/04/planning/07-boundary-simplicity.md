# 07 — Explain static cleanup without changing admission

**Benefit.** An operator selecting a passing static integrity evaluation can tell that no runtime task or cleanup ran, and a qualified task is still required. The summary prioritizes `cleanup:not_started` as “incomplete,” resembling a cleanup incident ([03 UX validation, lines 49–56](../../03/review/ux-validation.md); [component, lines 210–237](../../../../../../lib/harness_forge_web/components/package_readiness.ex)).

**Boundary and smallest change.** Keep `Readiness.for_artifact/2` and its seven stages, statuses, reason codes, blockers and `next_action` authoritative. Its `cleanup_stage/1` currently maps any status other than `complete` to blocked, and static/smoke admission still calls the existing applicability and release gate ([readiness, lines 198–218 and 255–264](../../../../../../lib/harness_forge/readiness.ex)). In the stateless `PackageReadiness` component only, add a tightly guarded contextual explanation for a selected `static_integrity` pass with recorded `cleanup_status == "not_started"` and release reason `qualified_task_evaluation_required`. Show it beside the existing summary/cleanup row: “Static integrity passed. No model-backed task or runtime cleanup was attempted. Release review still requires a qualified model-backed task evaluation.” Retain the exact cleanup badge, recorded status, release refusal and existing action. If integrity, eligibility, evaluation or runtime backend is blocked, preserve its earlier warning priority. Do not infer any current OpenCode task identity: task applicability and admission remain **Not assessed** ([03 amendment, lines 40–48](../../03/decision-amendment.md)).

**Acceptance.** A real persisted static pass shows the contextual explanation while all seven domain stage values and action remain identical before/after the presentation change. A failed task and a task with `cleanup_failed` keep their distinct failure copy; no run and malformed selection gain no favorable wording. Exercise keyboard reading order at 320 CSS pixels and 200% zoom. In five blinded synthetic walkthroughs, at least four operators distinguish “never attempted” from “failed” and identify the qualified-task requirement; any false qualification interpretation rejects the copy. Preserve auth/reset/privacy invalidation and immutable package bytes.

**Alternatives and risk.** Export recovery is a separate filesystem flow with stale alert issues ([handoff, lines 49–53](../../03/handoff-to-04.md)); general summary compression has a wider regression surface. Main risk is hiding a real earlier blocker, controlled by the narrow guard and contrasting cases. Likely files: `package_readiness.ex`, its web test, and native UX evidence. Estimated implementation: 0.5–1 day.
