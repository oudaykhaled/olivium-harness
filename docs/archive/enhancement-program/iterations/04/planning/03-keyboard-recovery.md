# Iteration 04 proposal — keyboard recovery for package export

**Benefit.** After a failed package export, a keyboard operator should land on the same package's editable destination, with the failure explained there. Today each package has a labeled destination and submit button ([PortalLive](../../../../../../lib/harness_forge_web/live/portal_live.ex:1767)); errors go through the generic top-of-page alert and `reload/1` ([PortalLive](../../../../../../lib/harness_forge_web/live/portal_live.ex:393), [finish](../../../../../../lib/harness_forge_web/live/portal_live.ex:697), [alert](../../../../../../lib/harness_forge_web/live/portal_live.ex:1189)). This is a source-level recovery concern, not an observed keyboard failure. The existing focus event uses an explicit target allowlist ([app.js](../../../../../../assets/js/app.js:111)); preserve that discipline.

**Bounded decision.** On an export failure, retain the attempted package and destination in transient LiveView state, render a per-form error linked with `aria-describedby`, then focus that form's destination input after the patch. Scope the target to a digest that is still present in `@artifacts`; if it disappeared, focus `package-panel` and show the existing alert. A successful retry clears the export error and previous `@export_path`, then announces the new result. No export API, filesystem, package identity or permission change. Use the existing new-directory/no-overwrite contract; do not retry automatically.

**Acceptance.** With two saved packages, submit an occupied destination on the second using Enter: the visible error names the directory remedy, focus returns to the second input, its value and digest remain, and the next Tab reaches its Export button. Repeat with a missing parent path, then retry to a fresh directory and verify the exported bytes and cleared failure. Check 320 CSS pixels and actual 200% zoom. Server tests cover wrong/stale digests and reset/remount clearing transient state; browser evidence records `activeElement`, Tab order and alerts. An AX tree supports semantics only; no screen-reader speech or novice success is claimed.

**Trade-off.** Static `cleanup:not_started` wording has broader, already observed comprehension value ([UX review](../../03/review/ux-validation.md)); select it first if only one unit fits. Export recovery is the stronger action-specific alternative to generic focus styling, but needs careful multi-package targeting. Likely files: `portal_live.ex`, `assets/js/app.js`, package LiveView tests. Estimate: 0.5–1 author day plus native verification.
