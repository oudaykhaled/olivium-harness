# One readable decision for one selected package

**Benefit.** An operator inspecting a saved package sees one answer and safe next step before diagnostic detail. Keep seven gate rows available in order, but make the first reading path a compact decision block: selected package and evaluation, one status sentence, primary navigation action, and known blocker or `Not assessed` reason. Put the full digest, timestamp, gate explanations and identity tables behind named disclosure controls. Preserve a copyable exact digest and accessible labels connecting the decision to its selected pair.

**Evidence.** The inspector prints the digest under the selector, again above the report, and the same `announcement/1` in the live status and report summary ([component lines 78–79, 105–119](../../../../../../lib/harness_forge_web/components/package_readiness.ex)). Seven stage rows follow the action ([lines 120–155](../../../../../../lib/harness_forge_web/components/package_readiness.ex)); identities already use `<details>` ([lines 156–186](../../../../../../lib/harness_forge_web/components/package_readiness.ex)). The [UX retrospective](../../03/retro/02-ux.md) identifies repeated identities/summaries as reading burden; the [handoff](../../03/handoff-to-04.md) retains static-cleanup and export-recovery as alternatives. No novice timing has been measured.

**Acceptance.** For no run, static pass with cleanup `not_started`, genuine task cleanup failure, and OpenCode task abstention, one visible decision sentence names the exact situation and next step without claiming task qualification. The seven independent statuses and recorded cleanup remain available by keyboard and screen reader; opening detail changes no report, event generation, authority or action. Switching package/run, privacy reset, remount and revocation clear the old decision and focused controls as before. At 320/390 CSS pixels and 200% zoom, the action and status remain readable without horizontal overflow. LiveView assertions cover single visible summary, exact selected pair and negative states; native keyboard/AX checks verify disclosure and reset. Existing release/export validation remains authoritative.

**Trade-off and scope.** This changes hierarchy in `package_readiness.ex` and focused web tests, with little domain risk, but hidden detail can conceal a secondary warning. Keep visible cautions for cleanup failure and `runtime_identity_check_required`; label the disclosure “All seven checks and identities.” Static cleanup wording and filesystem export recovery remain separate alternatives with stronger immediate corrective value. Estimated effort: 1–2 author days plus independent browser review.
