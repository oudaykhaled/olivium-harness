# Proposal 12 — make static cleanup understandable

**User benefit.** For a passed static-integrity evaluation, explain in the summary and cleanup stage that no runtime task ran, so cleanup was not attempted. Keep **Not started** and blocked release admission visible. Point to the qualified model-backed task requirement. This removes a false incident cue before the operator chooses a next action.

**Evidence.** `lib/harness_forge/evaluations.ex` records `static_integrity` as an integrity-only pass with `cleanup_status: not_started`; its branch does not call `Coding.run`. `lib/harness_forge/readiness.ex` maps non-complete cleanup to `evaluation_cleanup_incomplete`. `lib/harness_forge_web/components/package_readiness.ex` prioritizes cleanup in `announcement/1`, displaying “Recorded evaluation cleanup is incomplete” before the qualified-task reason. Four original iteration03 retrospectives identified this gap; the fifth favored export recovery. Iteration03 verification reports 453 registered, 438 passed, zero failed, 15 Docker skips and two unchanged Dialyzer opacity findings. Comprehension and flake rate remain unmeasured.

**Acceptance and observation.** Select a persisted static pass in Packages: summary and cleanup row say runtime cleanup was not attempted, retain `not_started`, and retain release refusal. A task with `cleanup_failed` still announces an actual cleanup problem; unknown metadata remains unavailable. Package/run change, privacy reset and revoked session still clear the report. Extend `test/harness_forge_web/package_readiness_test.exs` LiveView assertions for these contrasts; independently observe keyboard order at 320 CSS pixels and actual 200% zoom. Record screenshots/AX observations and exact test results, without claiming screen-reader speech or novice success. OpenCode current task identity, applicability and admission remain **Not assessed**.

**Boundary and effort.** Change only `lib/harness_forge_web/components/package_readiness.ex` and its focused web test; preserve domain stages, actions, authentication, privacy, reset and admission gates. Estimate 0.5–1 day including focused tests and native review. Export recovery alternatively fixes stale error and filesystem guidance, but touches form state and focus. The chief risk is wording that hides a true cleanup failure; the contrasting task case gates acceptance.
