# 16 — Prioritize recoverable package export

**Context / challenge.** Static `cleanup:not_started` is the better *observed* native defect: a genuine static pass led with “cleanup incomplete” although no task ran ([03 UX validation](../../03/review/ux-validation.md), [Readiness](../../../../../../lib/harness_forge/readiness.ex)). Four retrospectives recommend clarifying it; those are judgments, not measured user outcomes. A favorable headline could conceal an earlier integrity, eligibility, runtime or real cleanup failure. The inspector still exposes exact cleanup, admission refusal and next action ([component](../../../../../../lib/harness_forge_web/components/package_readiness.ex)).

**Decision — one UI benefit.** Prefer **Packages export recovery**. A failed export stops delivery of an already-built package. Source sends filesystem failures to “provider page could not be imported”; a successful retry can leave the old error flash while showing success ([PortalLive](../../../../../../lib/harness_forge_web/live/portal_live.ex)). `Artifacts.export/3` distinguishes unsafe or missing parents from occupied destinations and enforces no-overwrite output ([Artifacts](../../../../../../lib/harness_forge/artifacts.ex)). This is source-supported, **not a measured frequency or novice outcome**.

**Acceptance.** For one digest, real missing-parent and occupied-destination submissions retain the entered path and show a Packages-specific remedy at the form; keyboard focus reaches alert or input. Unsafe/symlink paths get conservative guidance. Retry to a fresh destination clears superseded notices, names the verified destination and exports byte-identical content. Failure clears prior success. Package switching, reset, lock, remount, stale submit and revoked eligibility cannot carry stale results or bypass authority. LiveView tests cover both failures and both transition directions; root records native keyboard, 320px and real 200% observations.

**Consequences / alternative.** Scope `portal_live.ex`, focused web tests and necessary styles; preserve artifact API, gates, auth, privacy, reset and immutable bytes. Estimate 1–2 engineer days plus native review. Risk: misclassifying a security refusal as a fixable path; use fixed error-code mapping and a safe fallback. Static cleanup copy is smaller (0.5–1 day) and should win if exact-package alert lifecycle expands scope. OpenCode task identity, applicability and admission remain **Not assessed** under the [accepted amendment](../../03/decision-amendment.md); historical results provide no current authority.
