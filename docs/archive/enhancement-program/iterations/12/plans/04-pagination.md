# Proposal 04 — bounded corpus scope and metadata pages

**User benefit.** A reviewer chooses a project and goal, sees a stable metadata page, and inspects relevant passages before deciding whether evidence supports or conflicts with a recommendation. The page reports included, stale, blocked and unscanned counts and scan checkpoint. A million-file corpus never becomes a million-item form.

**Observed constraint.** Frozen `evidence.ex:51–59,681–689` loads every workspace source and runs a latest-revision lookup per source; revision DTO includes its body (`evidence/records.ex:34–47`). `portal_live.ex:939–987,1967–1998,2273–2283` reloads that list for unrelated events, renders source bodies, and repeats it as a cloud-consent checklist. `company/records.ex:1–35` stores assignments inside profile/project payloads; `company/validation.ex:7–31,159–162` limits source IDs to 100. The analysis UI requests 2–4 source checkboxes (`components/company/analysis.ex:195–265`). Local import walks up to 500 files/16 MiB and imports them in one transaction (`evidence/local_import.ex:21–42,54–85`; `evidence.ex:61–90`). The 101-ID refusal is covered in `company_test.exs:307–312`. Latency is unmeasured.

**Decision and ownership.** Add a workspace/project/corpus membership relation with one row per source, effective scope status, revision pointer and indexed `(workspace, corpus, status, source_id)` key. Root owns migration and contract; Evidence/Company owners own keyset metadata pages and server-side membership mutation; PortalLive/component owner owns project-plus-goal selector, scope summary and page controls. Page API returns at most 50 metadata rows, an opaque continuation bound to workspace, corpus generation and filters, plus counts computed separately. Fetch exact revision body or UTF-8 passage only on inspection, after rechecking scope, connection, tombstone and generation. A changed cursor returns a refresh action. Save selection as corpus identity and generation, never a client-submitted ID array. Preserve small-list APIs until callers migrate. Follow with bounded capture checkpoints, FTS5 passage baseline and pinned Graphiti 0.31.2 adapter feeding existing review → exact claim/plan approval → corrected export → assessment; exercise this UI slice with a public synthetic corpus and saved goal.

**Migration and failure.** Expand with a new table/index and backfill memberships in small idempotent batches while legacy payloads remain readable. New writes update both forms during transition; only switch readers after count/scope reconciliation. Rollback selects legacy readers, retaining the new table for retry. Estimate a brief SQLite schema-write lock, then batch backfill outside that lock; measure lock and p95 page latency under concurrent reads before rollout. Tombstone first and deny stale derivatives even if graph summary rebuild fails. No wider access or consent follows from membership.

**Acceptance.** Positive: next/previous pages have no duplicates, a saved goal and authorised corpus lead to bounded supporting/contrary excerpts, deliberate correction/rejection, exact approvals and corrected export bytes. Negative: empty/foreign scope, revoked revision, tampered cursor and unconsented provider dispatch fail closed; no full body appears in list payloads. Recovery: interruption resumes checkpoint without duplicate membership, changed generation invalidates a page, and failed purge keeps results unservable. Measure loaded rows, bytes, p95, critical evidence misses and reviewer completion. Alternative: increase array and import caps; it changes limits while preserving whole-list hydration and transaction cost, so reject it. Alternative: page existing source rows without membership; useful as a temporary read improvement, but it cannot represent durable project scope or scan coverage.
