# 15 — Bounded company scope and evidence view

**Recommendation.** Give the operator a saved project/corpus and goal selector, a 25-row cursor-paged source summary, and a bounded evidence pane that opens a passage with parent context. Show included/excluded/stale counts and unfinished capture/index coverage. The user reaches supporting and conflicting excerpts, edits or rejects a recommendation, and separately approves its exact claim and plan. Use authorised server results and retain corrected export and representative evaluation as the connected acceptance path.

**Observed baseline, not a speed claim.** Frozen `PortalLive` reloads `Evidence.list_sources/0` into `@sources` (`portal_live.ex:939–979`) and renders each source's latest body, even inside closed `<details>` (`:1970–1998`). `Evidence.list_sources/0` materialises all source DTOs (`evidence.ex:51–59`), whose `source_dto/1` loads each latest revision (`:680–690`); search limits IDs to 50 but then loads full DTOs (`:236–269`). Company analysis renders every assigned source checkbox and goal option (`components/company/analysis.ex:179–185,242–299`) while accepting only 2–4 sources (`:53–65`); backend repeats that bound (`company/analysis.ex:174–188`). `Chat.Retrieval` obtains full bodies to score and excerpt candidates (`chat/retrieval.ex:35–58,92–146`). These are structural risks, not measured latency. CSS bounds `<pre>` height but cannot remove its body payload (`assets/css/app.css:28,105–118`). Current UI tests cover small synthetic scope, recapture and revocation (`company_analysis_test.exs:50–80,214–285`), not large-corpus latency.

**Smallest seams and ownership.** Backend owner adds a scoped, stable cursor query returning source ID, title, status, revision ID/hash and dates, without body; count/coverage uses bounded aggregates. A separately authorised passage endpoint returns exact UTF-8 span, original revision/hash, status/dates and enough parent context to avoid meaning reversal. Access and nonempty group scope are checked before retrieval and hydration; stale/revoked records fail closed. UI owner replaces the source array/checkbox path in `PortalLive`, `CompanyPanel` and `Company.Analysis` with paged summaries and selected passage state; reset/reload clears inaccessible bodies. Keep FTS5 as measured baseline; the following functionality slice can use pinned Graphiti 0.31.2 through its bounded adapter without moving identity, consent or decisions from Elixir/SQLite.

**Acceptance and measurement.** First record current p50/p95 reload time, rendered HTML/LiveView diff bytes and interaction latency on the same public synthetic 500- and 5,000-source corpora; no result is asserted here. Target 25 summaries/page, zero source bodies in list DTOs, at most one 4 KiB passage/context response per explicit open, p95 page/reload below 1,000 ms and p75 interaction below 200 ms on the stated test environment. Positive: page/cursor and saved goal lead to conflicting evidence, correction and approved exported bytes. Negative: foreign, revoked or stale revision cannot hydrate or dispatch. Recovery: changed source or interrupted capture invalidates the pane, preserves deliberate draft safely, and resumes from a checkpoint with honest incomplete coverage. Verify keyboard focus and narrow viewport as well as server payload. Estimated effort: 4–6 engineer-days plus measured synthetic validation.

**Dissent.** Client virtualization alone reduces DOM nodes but still transfers every body and leaves N+1 DTO reads. Raising source limits or adding Graphiti first does not fix the initial LiveView payload. Cursor pagination plus lazy passage hydration is the narrower first move; consider virtualization only after measured residual rendering cost.
