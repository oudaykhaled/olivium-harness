# Retrieval passages at the company review seam

**Recommendation.** Replace the analysis step’s source-checkbox wall with an authorised corpus scope plus one saved goal. Show a bounded page of candidate passages divided into **supports**, **conflicts**, and **needs review**, with captured/pending/excluded counts and “coverage unknown” for incomplete scans. A reviewer opens parent context and pinned details, corrects or rejects a recommendation, approves its exact revision, separately approves the plan, and inspects corrected export and assessment. Relevance never grants policy authority. This UI round should demonstrate review beyond four sources; the following functionality slice supplies company-scale integration.

**Observed baseline.** `Chat.Retrieval` scores title/body substrings and builds at most 12 snippets inside a 24,576-byte prompt (`source-before/lib/harness_forge/chat/retrieval.ex:10–23,31–54,94–137`). `Evidence.search/1` uses FTS5 but returns up to 50 hydrated sources (`source-before/lib/harness_forge/evidence.ex:235–269`). `Chat.Snapshot` validates citation bytes and revision hashes, limiting context to 12 refs (`source-before/lib/harness_forge/chat/snapshot.ex:95–152,192–195`). Company analysis requires 2–4 manually pinned sources and 32,768 body bytes; its prompt sends full bodies (`source-before/lib/harness_forge/company/analysis.ex:169–213,257–274`). The UI renders every assigned checkbox and only structural citation coverage (`source-before/lib/harness_forge_web/components/company/analysis.ex:178–285,453–525`).

**Seams and ownership.** UI owner: `Company.Analysis` presentation plus PortalLive events, with paged metadata, accessible passage cards, visible conflict/unknown status and lazy parent context. Root owns shared PortalLive and migrations. Domain owner: server-derived nonempty scope; relational membership, resumable capture, metadata pagination, exact UTF-8 passage/revision/hash/date/status mapping, FTS5 baseline and versioned retrieval origin. A bounded Python adapter reuses pinned Graphiti 0.31.2 extraction, Jev/runtime and hybrid search. Graphiti converts empty groups to `None` (`search.py:98–110,155–156`), so Elixir must refuse empty scope before search and dispatch. Preserve uncited/new-contradiction dependencies, stage consent/attempt budgets, tombstone-first revocation through failed rebuild, and claim/plan approvals. No new graph engine or default deprecated Kuzu.

**Acceptance.** Positive: on a public synthetic corpus above four files, a saved goal surfaces a relevant policy passage and contradictory dated incident; reviewer opens parent context, corrects/rejects unsafe text, approves exact successors, and verifies corrected bytes in actual exported targets plus a representative rubric. Negative: foreign scope, revoked source, stale revision, misleading isolated quote and incomplete scan never appear as current authoritative support; insufficient evidence permits abstention. Recovery: interruption resumes capture without duplicate membership; changed source or newly conflicting passage invalidates the old origin, retains review history and prompts fresh retrieval; failed graph-summary rebuild keeps derivatives unservable. Compare the same expected passages and task outcomes against FTS5, recording critical misses, citation accuracy, p95 and review time. The 51 offline mocked research passes do not qualify integration, semantics or million-file scale.

**Effort and dissent.** Estimate one bounded UI round plus a following multi-owner functionality slice; the backend work is larger than a cosmetic UI change. A pure FTS5 passage UI ships sooner and gives a measurable lexical baseline, but misses temporal/entity recall. Wiring Graphiti directly to the UI offers richer candidates sooner but risks unscoped queries and unverifiable provenance. Start with the bounded FTS5 review path and design the adapter contract now; admit Graphiti candidates only after its required authority seams are tested.
