# 06 — Goal-scoped evidence review with visible dissent

**User benefit.** An operator selects an authorised corpus and saved goal, then reviews a bounded evidence packet. It shows passages that may support or conflict with a recommendation, plus unknowns. It states what was searched, skipped, stale or blocked, with an “insufficient evidence” outcome. The operator can inspect context, correct or reject guidance, approve the exact claim and plan separately, and see corrected guidance in an actual export.

**Observed baseline.** The frozen validator already accepts `conflict`/`unknown` findings, exact UTF-8 citation spans and `recommendation: null`; its two-source rule is structural coverage only (`models/company_analysis.ex:3–64,70–150`). Admission still takes 2–4 manually chosen sources, at most 32,768 body bytes, and snapshots all selected inputs (`company/analysis.ex:172–275`). The UI renders a whole assigned-source checkbox list, a citation count and findings in one sequence; it warns that completeness is unknown (`components/company/analysis.ex:175–325,425–545`). A conflict requires human resolution before approval; editing creates an unapproved successor (`company/analysis.ex:48–77,358–365`; `components/company/analysis.ex:343–417`). Frozen tests establish exact-citation refusal, valid abstention, scoped selection, correction and export mechanics with synthetic provider output (`company_analysis_output_test.exs:51–119`; `company_analysis_test.exs:25–47,105–135`; `company_analysis_test.exs` under `test/harness_forge_web:51–200`). They do not establish detection recall or real-model judgment.

**Proposed seam and ownership.** Add server-owned, nonempty corpus membership and paginated metadata to the Company/Evidence boundary; select scope and goal once, then fetch a bounded FTS5 passage packet with exact source/revision/hash/span, parent context, date and document status. Keep a versioned origin containing all examined and prompt-influencing passages, including uncited and newly contrary inputs. The UI team owns `components/company/analysis.ex` and its presentation tests: three labelled evidence sections, a compact coverage ledger with counts and unknown denominator, lazy passage expansion, and an abstention state that offers new capture/scope review. Domain owners extend `company/analysis.ex`, origin validation and integration tests. Root owns shared schema/routes/Portal wiring. Graphiti 0.31.2 hybrid retrieval can later feed the same packet through the bounded Python adapter, with server scope and Elixir authority unchanged; graph similarity and Jev probabilities remain candidate relevance, never approval or policy status.

**Acceptance.** Positive: a larger synthetic corpus plus saved goal yields bounded supporting and contrary passages; a reviewer resolves conflict, rejects unsafe text, approves an exact corrected successor and plan, and finds corrected bytes in exported target files. Negative: empty/foreign scope, stale citation, missing parent context or unreviewed contradiction refuses dispatch/approval; zero retrieved passages cannot display “complete.” Recovery: interrupted page fetch resumes without duplicating membership, changed/revoked source invalidates the packet, and abstention leads to an explicit renewed scoped attempt. Test keyboard focus and labels on the new controls. Estimate: medium, roughly one UI iteration with a narrow backend seam; measure critical-source recall, citation accuracy and review time against the present workflow.

**Dissent.** Citation regrouping would improve reading, but leave the four-source bottleneck and hidden contrary evidence. A full graph console adds backend and model qualification cost. Preserve WEB-11-01/02 and CODE-11-02; the 51 offline mocked Graphiti passes and owner assessments do not prove semantic quality, million-file performance or task success.
