# Company operator journey: scoped corpus to deliberate review

**User and job.** A company operator must select authorised history and a saved goal, see evidence examined or missed, and correct recommendations before approval. Success is unassisted scope → conflict inspection → correction/rejection → exact claim and plan decisions on a larger public synthetic corpus, without manual file selection or missed seeded critical conflict. This fails if operators still select files or cannot identify the conflict and excluded coverage.

**Observed gap.** The current UI renders a checkbox for each assigned source and demands 2–4 (`company/analysis.ex:241–310`). The panel pins those revisions (`company_panel.ex:389–429`), while the domain sends their whole bodies under a 32,768-byte ceiling (`company/analysis.ex:170–212,258–275`). The report labels citation count as structural and shows exact excerpts; context hashes are behind a disclosure (`company/analysis.ex:435–559`). A web test proves the unchecked start and corrected export for the small Mercury fixture (`company_analysis_test.exs:50–81,84–206`), not corpus-scale retrieval or semantic quality.

**Bounded UI benefit.** Select an authorised saved *corpus scope* and goal. A compact scope card displays membership, captured/indexed/stale/blocked/incomplete counts and the last checkpoint. Paginate metadata on demand; keep IDs and bodies off the full LiveView render. Beside each recommendation, show bounded supporting and conflicting passages with document status, effective versus capture date, exact revision/UTF-8 span and parent context. State unknown coverage or insufficient evidence explicitly; rank and graph confidence grant no policy authority. Preserve edit/reject/approve and separate plan approval, then link the reviewed guidance to actual export and representative assessment. Measure completion, critical-conflict recognition, recovery and p95 response on a public corpus beyond existing limits; this round cannot claim million-file qualification.

**Seams and ownership.** Root owns schema/router/shared state. The domain lane supplies server-owned nonempty access scope, relational membership, cursor metadata, resumable scan status, bounded passage handles and versioned origins with uncited prompt influences and new contradictions. The UI lane owns `company/analysis.ex` and `company_panel.ex`; QA owns focused web/domain journey tests. Reuse authoritative Elixir/SQLite/FTS5 and pinned Graphiti 0.31.2/Jev through a bounded Python adapter. Upstream normalises empty groups to unfiltered search (`search.py:98–165`); Jev accepts only dedupe routes (`jev_client.py:125–153`); failed removal-summary rebuild can restore stale text (`graphiti.py:2174–2255`). Refuse empty scope before retrieval/dispatch, meter consented stage attempts, and tombstone derivatives until cleanup succeeds. Existing exact approval/export controls remain binding.

**Acceptance.** Given a corpus beyond four sources and a saved goal, when analysis opens, then counts and paginated metadata reveal included/incomplete material without rendering every file. Given seeded support and contradiction, when reviewing, then both bounded passages show provenance/status before decision. Given empty/foreign scope or a revoked source, when opening or dispatching, then no passage or model request is served and a blocked reason appears. Given an interrupted scan or changed revision, when resuming, then checkpointing is idempotent and stale review requires a fresh origin while prior decisions remain immutable.

**Alternative and effort.** A dashboard is faster but leaves manual selection at dispatch. This slice needs 5–8 engineer-days across two lanes plus root integration. If seams cannot work, deliver a truthful saved-scope preview with tested refusal, never a decorative control.
