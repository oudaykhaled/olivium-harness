# ADR12 — Inspect a captured corpus beside a saved goal and exact review

## Context

Select one working even-round UI benefit: **an authenticated operator can inspect a saved captured corpus and goal through bounded metadata and exact passages, compare that evidence with an existing recommendation's supporting/conflicting findings, then continue deliberate correction/rejection and exact approval.** This is a corpus evidence inspection and review surface, not activation of corpus-wide model analysis.

After conductor `PLANS_RELEASED`, all sixteen original proposals were read in full, independently of the conductor rollup. Their exact hashes and semantic read scopes are in `tmp/enhancement-program/12/astra-read-audit.json`. Sealed set: `planning-originals-manifest-01.json`, SHA256 `318c52a2a90dd958af685270272c5a23ea7efb6c3625c9e1c618783bfb7fcc46`. Sixteen originals contain 62,454 bytes. No product execution or implementation was performed by this decisionmaker.

Frozen source supplies decisive constraints:

- `company/analysis.ex:169–275` requires 2–4 source refs and 32 KiB of whole bodies. `evidence/origin.ex:53–99` makes this a strict version-1 authority contract, also checked before dispatch in `models.ex:200–280`. Replacing only a checkbox does not replace analysis.
- `evidence.ex:51–59,235–269,680–689` hydrates full revision DTOs for lists and search. `portal_live.ex:939–970` eagerly reloads these. Pagination after these calls is ineffective.
- `components/company/analysis.ex:430–640` already renders immutable finding kinds, exact excerpts and careful metadata correspondence. Reuse these semantics; lexical matches cannot supply supporting/conflicting classifications.
- `evidence/records.ex:1–47` already represents a saved connection and its captured sources relationally, with sync state and immutable revisions. Use this existing corpus identity for **inspection** rather than introduce another corpus store or extend membership arrays.
- `company.ex:257–330` separately constrains company/project plan eligibility. Inspecting a workspace connection must not add its sources to project membership or claim origins.
- Upstream Graphiti `search.py:98–160` normalizes empty groups to unfiltered search; `graphiti.py:2174–2255` can restore a prior summary after removal-rebuild failure. Neither behavior is an acceptable application authorization/privacy boundary.

Product and quality dissent remains decisive: successful screens, scripted outputs and owner receipts do not establish complete obligations, truth, novice independence or improved work. Architecture/security dissent requires current authority and uncited-dependency preservation. UI/UX dissent requires readable conflict inspection and recovery, not just another administrative form.

## Decision: precise shipped behavior

1. Add an authenticated Company-linked **Corpus evidence review** surface using the existing operator-session boundary. A dedicated LiveView owns the inspection state, with a direct authenticated route and a normal link from Company. **Normal Portal mount, Company navigation and reload must also use bounded metadata, never eagerly hydrate all source bodies.** The dedicated route is not an exemption from this normal-entry requirement. This is one surface in the company journey, not a new search product.
2. Select one existing active source connection, explicitly labelled **captured corpus**, one saved project and one assigned saved goal. A connection is already a workspace-readable corpus; this choice grants no new connector access and does not assign all its sources to the project. Show “Inspection scope” separately from “Sources assigned to this project.” Connection/project/goal choices are bounded server-paged metadata, not entire-workspace arrays. No selection or remote query occurs automatically.
3. Show captured/current/unavailable counts computed from actual local records, connection sync state/last timestamp when meaningful, and unknown discovery/semantic coverage. Local-directory import has no durable resume checkpoint: say coverage unknown, display no resume control. Do not relabel `sync_complete` as all-company capture, indexing progress or analyzed coverage. No invented `indexed`, `stale`, `failed` denominator is allowed.
4. Browse at most 25 metadata rows per page; optionally run bounded literal FTS5 search inside the selected connection. Seed the editable query from the saved goal title only after explicit selection; name matches **candidate evidence / needs review**. Do not classify search hits as support/conflict. Use existing FTS5 indexing and literal-token behavior, with scope predicates in SQL before LIMIT; never retrieve globally then filter, and never call `Chat.Retrieval.retrieve(..., :all)`.
5. Open one exact passage with surrounding context, total text ≤4,096 UTF-8 bytes. List rows contain no source body. Show exact source/revision/hash and exclusive byte offsets, captured/source-updated date, safe stored link, and documentary/effective/event metadata only where explicitly captured with known semantics; otherwise show unknown. A truncated parent context is clearly marked and can be paged through bounded windows; absence of full context cannot be presented as verified meaning.
6. Select an existing company-analysis recommendation for the same project and goal from a bounded list. Render its validated original support/conflict/unknown findings and human-resolution requirement beside the exploratory evidence; use original `finding.kind`, never keyword inference. Explicitly distinguish **Original analyzed evidence** from **Additional inspected corpus evidence — not part of this recommendation's model input**. Show original 2–4-source scope and current eligibility. A report that includes sources outside the selected inspection corpus says so; it is not represented as coverage of that corpus. Reuse existing exact-review navigation to correction/rejection/claim decision, separate plan decision, build/export and assessment.
7. No model request, citation insert, claim revision, project membership, approval or plan mutation occurs on search/page/open. Continue-review revalidates claim ID/hash and existing authority at the destination; it never serializes candidate passages into the old analysis input. Existing guidance correction may record human judgment, but the UI must not claim the additional preview has become a machine-tracked dependency. Any attempt to make preview evidence an authoritative input belongs to the following origin implementation, not an undocumented shortcut.

The UI says plainly: **“Browse captured evidence across this corpus. Model analysis still uses 2–4 explicitly selected sources; this preview has not analyzed the whole corpus.”** No disabled coming-soon buttons for Graphiti, resume or corpus analysis. Existing model-unavailable behavior remains. A useful result with no existing recommendation is evidence inspection plus an honest route to current analysis; it is not a fabricated recommendation.

### Mandatory normal-entry source-load boundary

Root replaces the `{:sources, Evidence, :list_sources}` eager loader in `PortalLive.reload/1` with a bounded metadata read and removes hidden full bodies from source cards. The first Portal page, Company navigation, ordinary refresh and return from inspection must not call whole-workspace `Evidence.list_sources/0` or `Evidence.search/1`'s hydrated path. New `CorpusReview.source_page/1` (or a thin Evidence facade) takes a server-owned workspace and optional validated connection, literal query and signed cursor; it returns≤25 safe source summaries. Workspace-wide legacy source browsing is allowed only under existing operator authority and is not a corpus-analysis scope token. Both APIs share the bounded SQL/projection implementation, not a new retrieval framework.

`summary_refs/1` accepts only server-derived selected refs: hydrate **metadata**, never bodies, for the currently edited profile/project's existing≤100 assignments each, current legacy analysis≤4 pins and opened recommendation refs. Do not enumerate assignments for every project. Preserve exact selected IDs across page changes; saving a catalog/consent form must not silently drop off-page selections or add visible but unchecked rows. Legacy cloud consent remains≤100 IDs; page metadata with its selected-set summary, no broadened consent and no cap increase. Bounded source summaries include revision ID/hash, captured dates, active eligibility and `body_bytes`; `Analysis.current_source?/1` must use validated summary eligibility/body length instead of requiring a body in UI assigns. Actual legacy `Company.Analysis.analyze/2` still reloads and validates its≤4 full bodies server-side at dispatch. Do not change its strict v1 authority contract.

An explicit source-open event uses the same exact passage API; it revalidates session/workspace/source/connection before reading and renders one bounded window. A closed disclosure must not contain preloaded bodies. Existing model-propose buttons pass only an exact revalidated source identity to the existing domain action; they do not need full browser bodies. Portal search returns bounded summaries; support current source-selection, catalogue, consent, chat and review semantics with meaningful regression checks. If a caller truly needs one full source for an existing authorized operation, load it inside that operation rather than into the global socket. Existing non-UI list APIs can remain compatible; this decision does not authorize a blanket API-breaking replacement.

This prerequisite is part of the selected slice, not deferred debt. Block release if only the direct inspector route passes boundedness while normal entry still loads5000 bodies. Counts of claims/goals and other legacy record lists are not newly scale-qualified, but they cannot be used as an excuse to retain corpus-sized source hydration.

No new product tables or new dependency are required this round. Existing `source_connections`, `evidence_sources`, `evidence_revisions`, `evidence_search`, saved company/project/goal and claim records are authority. Root may add the measured query's missing composite index on `(workspace_id, connection_id, id)` in an additive migration; do not preemptively rebuild storage. No backfill or dual membership writes now. Break implementation into reviewable domain, presentation and integration patches, ideally ≤400 net lines each; correctness may justify larger tests, and an arbitrary line cap must not conceal missing seams.

`Company.CorpusReview` uses strict string-keyed inputs and returns DTOs only:

- `choices(kind, cursor)` → ≤25 safe connection/project/assigned-goal/recommendation summaries; no connection config, directory, credentials or source body. Goal choices require selected current project/profile assignment.
- `open_scope(%{"connection_id", "project_id", "goal_id", "goal_content_hash"})` → a server-owned token and safe scope DTO after workspace, active connection, profile/project and goal checks. Token binds workspace, operator session fingerprint, view/reset generation, profile/project content hashes, goal hash and connection identity/config digest/status. Never accept client group IDs or `:all`.
- `page(token, %{"query", "cursor"})` → `{scope, counts, rows, next_cursor}`; max 25 rows, query max256 Unicode characters/1,024 bytes, ≤8 literal tokens; stable source-ID keyset ordering, scope/query-bound signed cursor and short expiry. Fetch26 metadata rows to determine continuation. Page counts and rows share a read transaction. Cursor is a **live keyset page**, not a corpus snapshot: new data may require explicit refresh; no immutable whole-corpus completeness claim. Recheck current source pins when opened.
- `passage(token, %{"source_id", "revision_id", "body_hash", "start_byte"})` → one ≤4,096-byte valid UTF-8 window with exact quote/context boundaries. Deny invalid offsets, mismatched hashes, foreign connection/workspace, inactive/deleted source, revoked connection, changed document scope or privacy fence. Never repair a stale pin silently. Use bounded SQLite text/blob slicing rather than hydrate the whole revision into LiveView; validate boundaries with small extra bytes as needed. A lexical hit supplies a bounded offset, not semantic evidence authority.
- `recommendation(token, %{"claim_id", "revision_hash"})` → exact current eligible original report for matching project/goal and bounded metadata for its existing refs, after existing `Analysis.validate_origin/2`; refuse foreign/stale claims. No new origin version is written. Historical unavailable reports do not expose revoked snippets.

`CorpusReviewLive` state: `scope=nil | pinned`, `query`, `page`, `cursor_stack`, `opened_passage=nil | pinned`, `selected_claim=nil | pinned`, `generation`, `error`, `notice`. Events: `corpus_scope_change`, `corpus_scope_open`, `corpus_search`, `corpus_page_next`, `corpus_page_previous`, `corpus_passage_open`, `corpus_passage_next`, `corpus_passage_close`, `corpus_recommendation_open`, `corpus_continue_review`, `corpus_refresh`. All events check session and view generation before domain reads. Async results additionally bind request ID and scope/query digest; late events after reset/navigation refuse. Clear body/report state on privacy reset, session revocation, scope change and failed freshness validation. Preserve a safe query/goal choice after recoverable failure; never retain a removed passage as a draft. New surface has no persistent editor draft to lose; destination review retains its existing dirty-draft guard. Explicit refresh creates fresh handles; it never approves or repins an existing claim.

Root must inspect existing router/session and exact-review destination code before wiring; reuse the actual authenticated LiveView pipeline. Direct URL query parameters are untrusted hints, not scope authority. Existing authenticated local QA sign-in is authorized; no new credential extraction or access expansion follows.

## Consequences and release-ready PLAN REVIEW notes

This selection reduces corpus discovery and inspection effort without a whole-corpus form, reuses existing relational captures/FTS and keeps a measurable path to current review/export. It adds one read-model surface and bounded query contract. Its cost is an explicit split between exploratory corpus evidence and legacy analyzed evidence; labels and preserved dissent prevent that split being mistaken for completed corpus analysis. The shared Portal source-loader migration is necessary blast radius: source/consent/catalog consumers must use bounded metadata and preserve off-page selections. Other legacy lists and overall application scalability remain unqualified.

Estimated effort: roughly4–7 engineer-days across root plus two principals, including focused tests, then independent verification; not a delivery guarantee or a majority of planner estimates. Stop and return to root if the chosen route cannot enforce bounded reads, the inspected corpus would broaden access, current-report rendering leaks removed content, or the only way to connect review is to falsify v1 provenance. Do not quietly widen into the multiweek option or release inert controls.
