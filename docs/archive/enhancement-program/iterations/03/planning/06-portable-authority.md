# Portable approval receipt for one exact package

**Evidence.** `Compiler.verify/1` compares artifact bytes (`lib/harness_forge/compiler.ex:35`), but denies approval authority. `Company.decide_plan/2` persists an exact local decision (`company.ex:111`); `Company.build_inputs/1` rechecks approval and scope (`:139`); `Harnesses` stores a local binding and rechecks it at export (`harnesses.ex:8,120,141`). The company contract says exported v1alpha1 cannot independently prove approval (`docs/company-builder-contract.md:199–205`).

**Functionality.** Add a versioned canonical JSON approval receipt sidecar, issued only from an eligible bound artifact. Bind receipt version, issuer key ID, workspace, plan ID/revision, decision identity/time, snapshot digest, artifact digest, manifest/spec digests, issue time and expiry. Sign with Ed25519 using an operator-provisioned key; never export the private key. An offline verifier accepts package, receipt and explicitly installed trusted public keys. Check bounded decoding, exact bindings, signature, key scope/expiry and revoked-key list; return distinct `valid_at_issue`, `untrusted`, `expired`, `revoked`, `mismatch` and `invalid` states. A valid receipt attests issuer-observed approval at issuance, not current source eligibility or independently verified human identity. Preserve v1alpha1 bytes; unsigned legacy packages remain unauthenticated.

**Falsifiers.** Positive: an approved exact plan exported to a clean workspace verifies under a deliberately trusted issuer key, with identical digest and decision lineage. Negative: altered file, receipt, plan hash or workspace; substituted unknown/revoked key; expired receipt; rejected/stale/quarantined plan; and unbound legacy artifact all fail authority verification. Restore must not reactivate signing authority. Test these without executing generated code or claiming live model fitness.

**Trade-off and prerequisites.** This is a distinct receiving-maintainer benefit. Readiness projection is cheaper and immediately actionable for the author, but cannot authenticate transferred approval. Goal-origin policy and conflict decisions improve completeness, but leave transfer trust unresolved. This scope requires an ADR for issuer ownership, key rotation/revocation distribution and expiry policy before implementation; offline verification cannot promise post-issuance revocation freshness. If key governance is not ready, ship a clearly unauthenticated export authority report as the smaller trust unit, never a purported signed approval.
