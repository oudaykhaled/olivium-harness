# Exact-package qualification readiness

**User benefit.** A company owner selecting a built package can see whether *that package* has an applicable, qualified task result and what must change before release approval. Export success must not imply runtime or company-task fitness. This is a bounded functionality addition: a read-only readiness projection, not a new approval or evaluation engine.

**Evidence.** [Artifacts.read/1](../../../../../../lib/harness_forge/artifacts.ex#L30) verifies stored metadata, digest and payload; [ArtifactBinding](../../../../../../lib/harness_forge/harnesses/artifact_binding.ex#L6) records workspace, plan, revision hash and artifact digest. [Harnesses.eligible/1](../../../../../../lib/harness_forge/harnesses.ex#L133) rechecks approved claims and exact plan inputs, including rebuilt artifact equality. [Evaluations.applicability/2](../../../../../../lib/harness_forge/evaluations.ex#L61) compares artifact, suite/grader/fixture, runtime image/version/config, model/context, scope and policy identities. [Releases.Validation.check/3](../../../../../../lib/harness_forge/releases/validation.ex#L8) additionally requires a passed qualified task, complete cleanup, successful checks, supported required controls and current eligibility. Existing [release tests](../../../../../../test/harness_forge/releases_test.exs#L118) reject material mismatches; the missing user benefit is an attributable preapproval answer.

**Proposed interface.** `Readiness.for_artifact(digest, evaluation_id \\ nil)` returns a string-keyed map with `artifact_digest`, verified plan binding/revision when present, `evaluation_id`, distinct `integrity`, `eligibility`, `runtime_availability`, `task_result`, `release_admission`, ordered blocker codes and next action. Resolve only workspace-scoped persisted runs; never accept a caller-supplied result map. Reuse `Artifacts.read`, `Harnesses.eligible`, `Evaluations.applicability`, and release validation. If no run is selected, show the latest *applicable* run and its ID, or explicitly `no_applicable_run`; do not select a pass from another digest. Keep the underlying release approval gate authoritative.

**Acceptance.** A matching, completed, qualified task with complete cleanup and all controls yields `ready_for_release_review`, tied to the exact digest/run/plan. Changed artifact, plan approval, suite, grader, runtime image/config, model/context, policy, scope or environment yields a specific blocked or stale reason; failed, cancelled, smoke-only, missing-model and incomplete-cleanup runs never appear ready. Tests exercise current and stale transitions with synthetic fixtures and assert no new release approval is created.

**Risk and alternative.** Current applicability identities are calculated against local runtime configuration, so a changed installation can invalidate an old run; surface that difference instead of silently substituting another runtime. Goal-origin policy admission and portable approval remain separate priorities. This proposal offers immediate diagnostic value but cannot claim real-company fitness without an authorized representative pilot.
