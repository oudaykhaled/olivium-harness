# Bounded architecture recommendation: exact-artifact readiness

**Decision rubric.** Goal-origin rules and declared conflicts have high policy-completeness value: today `Evidence.create_claim/1` requires citations, while `Harnesses.specification/3` writes `goal_id: nil`. Credible admission would require versioned claim/decision records, conflict resolution, snapshot hashing, migration, purge/restore, compiler and UI changes. Reliability risk is high if any old approval silently gains new authority. Portable authenticated approval also has high trust value, but `Company.decide_plan/2` stores a local actor and `Compiler.verify/1` proves deterministic bytes, not signer identity. A useful receipt needs signer enrollment, key rotation/revocation, scope, clean-import verification and versioned export. Both exceed one bounded functionality unit.

Choose **readiness for one exact artifact**. Evidence is immediate: iteration 02 verified build/export and 417 unique synthetic tests, while every retrospective says company outcome remains unproven. Value is an honest answer to “what blocks qualification now?” Scope is a read-only projection across existing gates; reliability is strongest because it grants no approval or qualification. This is a decision on evidence, value, scope and failure risk, not a tally of retrospective preferences.

Add `HarnessForge.Readiness.for_artifact/1` in `lib/harness_forge/readiness.ex`, returning a string-keyed map with artifact digest, plan binding identity when present, ordered gate states, exact blocker codes and next actions. Read through `Harnesses.get/1`; evaluate `Compiler.verify/1`, `Harnesses.eligible/1`, `Evaluations.capabilities/0`, `Evaluations.applicability/2`, and `Releases.Validation.check/3` only when an existing task run is supplied. Keep integrity, current approval eligibility, runtime/model availability, task outcome and release qualification distinct. Expose the projection through the existing Packages LiveView in `lib/harness_forge_web/live/portal_live.ex`; render unavailable as unavailable.

**Acceptance.** Given a valid exported artifact with no qualifying run, show its digest, eligible status and blocked qualification with a specific next action. Given stale plan/evidence, changed artifact/model/suite identity, failed or cancelled evaluation, or incomplete cleanup, show the correct failing gate and never a qualified label. Given a matching passed task run, report release readiness only if `Releases.Validation.check/3` succeeds. Tests cover those transitions and prove projection calls do not mutate approvals, runs or artifacts.

**Risk:** gate drift if UI duplicates domain checks; make the projection the single read model and retain domain enforcement at build/export/release. Defer representative real-model company qualification, goal-origin/conflict authority and portable signatures as separate decisions. Synthetic success remains synthetic.
