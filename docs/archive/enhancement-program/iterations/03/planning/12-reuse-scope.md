# Iteration 03 proposal: exact-package readiness

**Decision:** Add a read-only readiness projection for a selected Company plan and immutable package. It answers “What can I do next with these exact bytes?” without creating another approval, evaluation, or release authority. This is the smallest useful functionality across the five iteration 02 retrospectives: UX, trust, and quality prioritize qualification readiness; product and architecture prioritize policy completeness. Preserve that disagreement and show policy completeness as an unresolved limitation, not a passing gate.

**Interface:** `HarnessForge.Readiness.inspect(plan_id, artifact_digest, evaluation_id \\ nil)` returns `{:ok, %{"plan_revision_hash" => ..., "artifact_digest" => ..., "stages" => [...], "next_action" => ...}}` or a typed lookup error. Each stage has `"status"` (`"ready"`, `"blocked"`, or `"unavailable"`), `"reason"`, and `"action"`. Stages are exact-plan approval/current inputs, artifact integrity/current eligibility, runtime/model availability, applicable task outcome and cleanup, then release eligibility. A selected run is identified by ID; never choose the newest run implicitly. The Company guide or Packages panel can render this projection for the selected plan/package, showing one primary correction and the exact digest and plan revision.

**Reuse evidence:** `Company.build_inputs/1` already checks approved, scoped, current plan inputs. Existing `ArtifactBinding` records connect plan revision and digest; `Harnesses.get/1`, `Compiler.verify/1`, and `Harnesses.eligible/1` cover bytes and current evidence. `Evaluations.get/1` and `applicability/2` bind suite, grader, runtime, model, configuration, environment, scope, and artifact identities. `Releases.Validation.check/3` remains the only release-qualification predicate. The projection calls these gates; it does not copy their admission logic or persist a receipt.

**Acceptance:** Tests cover approved/current, proposed, stale, cross-plan, tampered, missing-run, mismatched-run, failed, cancelled, incomplete-cleanup, unsupported runtime/model, and qualified synthetic fixtures. Each refusal names the failed stage and safe next action. A successful static check or export must still say qualification is blocked. No fixture result claims company fitness; that requires an authorized representative pilot. Portable authenticated approval and goal-origin/conflict policy remain separate alternatives. Main risk is a stale display during concurrent changes: recompute on every request and re-run domain admission for all mutations. No migration or external service is required.
