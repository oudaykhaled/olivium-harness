# Policy architecture: exact goal-origin rule authority

**Recommendation.** Add a versioned, local policy-basis path so an operator can approve an intended rule against an immutable goal revision, then build only that approved revision. Today `Evidence.create_claim/1` requires citations, `Decisions.decide/2` revalidates them, and `Harnesses.specification/3` emits `goal_id: nil`, although the harness contract permits a goal-only rule ([Evidence](../../../../../../lib/harness_forge/evidence.ex), [Decisions](../../../../../../lib/harness_forge/decisions.ex), [Harnesses](../../../../../../lib/harness_forge/harnesses.ex), [Contracts](../../../../../../lib/harness_forge/contracts.ex)). Goals alone remain future intent, never authority.

**Contract.** Extend `Evidence.create_claim(%{"text" => ..., "rationale_kind" => "future_goal", "goal_id" => id, "expected_goal_hash" => hash, "citations" => []})`; retain the existing historical call as `historical_evidence` with one or more citations and `goal_id: nil`. Reject mixed, empty, cross-workspace, or changed bases. Persist basis and goal hash within the immutable claim revision hash. `Decisions.decide/2` rechecks the pinned basis before exact approval. `Company.create_plan/1` and `build_inputs/1` pin each selected claim's basis and selected goal hash; `Harnesses.build_plan/2` emits the approved goal ID, while `eligible/1` rechecks current authority at export. Add `Policies.declare_conflict(rule_ref_a, rule_ref_b)` and `Policies.resolve_conflict(conflict_id, %{"selected_rule_ref" => ref, "actor" => actor, "expected_hash" => hash})`: append-only, workspace-scoped records referencing exact rule hashes. Plan approval/build/export refuse a selected pair with an unresolved or stale declaration; semantic conflicts outside declarations remain unverified. This extends the dormant `rationale_kind`/`conflict_ids` record shape ([records schema](../../../../../../priv/schemas/records-v1alpha1.json)).

**Compatibility and acceptance.** Version the new persisted shape; decode absent basis as historical without rewriting old claim hashes, v1alpha1 specs, compiler identity, provenance, or artifact digests. Positive: approve a goal-backed claim, resolve a declared pair, build deterministically, and export with exact goal lineage. Negative: reject fabricated historical citations, goal mutation/hash mismatch, cross-scope goal, superseded rule, unresolved/stale conflict, and stale plan after changed acceptance. Add migration, purge dependency, restore/quarantine, and old-backup regression cases before admission ([Company](../../../../../../lib/harness_forge/company.ex), [privacy snapshot](../../../../../../lib/harness_forge/privacy/snapshot.ex)). Keep goal text and conflict notes within the existing privacy boundary; audit IDs/hashes, not content.

**Alternatives.** Exact-artifact readiness offers faster value using current evaluation/release gates, but leaves intended policy unexpressible. Portable signed authority helps recipients verify approval, but requires signer trust and revocation design and cannot repair local policy completeness. Both remain separate priorities from the five [iteration-02 retrospectives](../handoff-to-03.md); this proposal makes no qualification or portable-authentication claim.
