# 05 proposal 12 — identify the stale company input

**Observed journey.** A company operator can select exact approved claims, approve a plan, build a deterministic package and export it to a fresh directory. `Company.build_inputs/1` checks exact plan approval and re-resolves pinned context (`lib/harness_forge/company.ex:138-169,318-327`). `Harnesses.build_plan/2` rechecks before publication; `Harnesses.export/2` rechecks evidence and every plan binding (`lib/harness_forge/harnesses.ex:8-25,120-165`). The same boundary serves CLI company build/export (`lib/harness_forge/cli.ex:52-63,184`) and Company LiveView. Existing preflight converts a failed check to one message (`lib/harness_forge_web/components/company_panel.ex:698-719`). A changed selected repository currently returns `:stale_plan` at build and `:stale_or_revoked_plan` at export (`test/harness_forge/company_harnesses_test.exs:125-145`). The operator cannot tell which pinned input changed. Synthetic three-runtime export checks prove deterministic bytes and refusal, not representative company fitness (`test/harness_forge/company_acceptance_test.exs:99-153`). Current OpenCode task applicability remains Not assessed under the accepted 03 amendment.

**One bounded functionality proposal.** Add a read-only, typed *selected-plan drift report* owned by Company, comparing stored snapshot with current scoped inputs. Report only changed categories and local IDs: profile, project, repository, selected source revision, claim revision, or goal. Show this report in the existing Company build preflight and expose the same bounded result through one CLI command. Keep `build_inputs/1` and export admission authoritative; the report grants no approval, does not auto-create a successor and never exports private bodies. A withdrawn or foreign reference is reported as unavailable without disclosing cross-workspace details. This makes a blocked build repairable while preserving exact approval and package identity.

**Acceptance.** Selected repository, source, claim, goal and project drift each identify the affected local input; unrelated changes report eligible. Proposed/rejected plans, wrong workspace, purge and quarantined restore never show stale authority as eligible. Existing build/export still refuse and create no target on failure; a separately approved successor succeeds to a fresh directory with exact files. CLI and LiveView agree on categories. Tests cover negative cases and no extra I/O on preflight. Root owns shared wiring; Company/domain and dedicated tests have one implementation owner, with independent QA validating the journey. Risk: a report can race a later change, so label it a snapshot and repeat authoritative checks at build/export. This improves recovery, not policy completeness, qualified runtime outcomes or portable approval.
