# 05 proposal: one validated task-route snapshot

**Benefit.** A supported OpenCode task records its actual route, allowing later applicability to reject drift. This enables representative qualification without proving company fitness. The [04 handoff](../../04/handoff-to-05.md) preserves the [03 abstention amendment](../../03/decision-amendment.md) and disagreement among five retrospectives about identity, policy origin and conflicts. Select by acceptance value and scope, not counts.

**Observed defect boundary.** `Coding.profile/0` calls `transport/0` three times; `run/2`, `start_proxy/2` and `verify_container/6` resolve it again. `transport/0` maps failed, malformed or unexpected Docker-info results to Unix. `Evaluations.applicability_identity/2` computes task profile before run creation and on comparison. The stored digest may describe another route. [Coding](../../../../../lib/harness_forge/execution/coding.ex), [Evaluations](../../../../../lib/harness_forge/evaluations.ex). [Readiness](../../../../../lib/harness_forge/readiness.ex) correctly abstains from OpenCode task comparison.

**Bounded change.** Resolve one validated route at task admission, accepting only exact Desktop and Unix responses; derive profile, proxy config, network/mount expectations and stored identity from that run snapshot. Unknown output, timeout and command failure refuse task start. An explicit release command performs authoritative revalidation. Preserve historical bytes; version identity so old task digests cannot silently pass. Inspect/Refresh remain command-free and abstain on task applicability.

**Falsification/acceptance.** Hermetic command-boundary cases prove distinct Desktop/Unix profile digests, one route resolution per task, matching executed proxy/network and recorded identity, and refusal before start for malformed/failed/timeout discovery. Flip route or model configuration: authoritative applicability rejects; unchanged input matches. Failure never persists qualified identity. Repeat calibrated, process-scoped Inspect/Refresh traces with delivery barrier and descendants: `Command.docker/1,2,3`, private `local_endpoint/1` and `invoke/4`, `Port.open/2`, `:erlang.open_port/2`, `System.cmd/2,3` and Coding profile/transport show zero prohibited calls across no-run, static, smoke and task-abstention paths. Exclude setup/mount explicitly. Preserve approvals, purge/restore quarantine, consent and release validation.

**Ownership/risk.** Root owns shared evaluation/admission; execution engineer owns Coding/Command; QA owns route matrix/traces; security reviews host-command and identity lifetime. Docker integration remains opt-in. Route drift after resolution must refuse or mark unqualified, never silently substitute.
