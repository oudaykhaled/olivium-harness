# LiveView draft preservation and section transitions

**Finding.** `PortalLive` keeps the same `CompanyPanel` component mounted while changing tabs (`portal_live.ex:40,993`); the panel hides with `hidden={!@active}` (`company_panel.ex:523`). Its plan already has a component-held `plan_draft`, updated by `company_plan_change`, retained by `update/2` and `reload/1`, and cleared only after successful creation (`company_panel.ex:10,34,143-150,184-195,364-377`). `company_builder_test.exs:191-209` proves a plan name survives a trip to Evidence. Browser-shaped `_unused_*` inputs, project selection and milestone fields have a separate regression (`company_builder_test.exs:211-270`); retain `strip_unused_markers/1` and strict shape validation (`company_panel.ex:267-333`). Profile, repository and project forms instead render saved payload or selected edit record and have submit events only (`catalog.ex:18-24,32-37,143-148,315-320`). Their unsaved values lack equivalent server draft state.

**Decision.** Keep the mounted Phoenix LiveComponent. Add bounded component assigns for the three catalogue form drafts and `phx-change` handlers using existing string-keyed field/array validation; update form values from those assigns. Preserve each draft across tab navigation, section open/close, parent `reload/1` and validation failure. Reset only the successfully saved form or an explicit New action; switching an edit record must show that record and must not silently overwrite another dirty draft. Keep inactive sections mounted, using `hidden` and `aria-expanded`/`aria-controls`, so disclosure never destroys plan milestone inputs. Before closing an active section, move focus to its disclosure control; opening through the next-action control focuses its heading or first field. On a rejected submit, retain values and focus the visible error summary (`company_panel.ex:534-538`). Treat browser reload/reconnect as an unsaved-draft boundary and label it plainly; do not store sensitive inputs in local storage.

**Verification.** Extend `company_builder_test.exs` with unsaved profile/repository/project edits across section and Evidence navigation, failed submit retention, explicit reset, and plan milestones/project selections across disclosure and parent reload. Preserve the existing browser-shaped marker regression and revoked-session test (`company_builder_test.exs:313-321`). In real Chrome on synthetic data, test keyboard open/close/focus and narrow width, including an unsaved plan and one catalogue form; record comparable before/after DOM and screenshots.

**Risk.** LiveView reconnect still loses unsaved values; say so. `phx-change` on large forms increases events, so debounce text inputs and keep current 100-milestone/501-reference bounds. No draft may become an approved claim or plan through a UI transition.
