# Iteration 02 proposal: truthful Company readiness

**Evidence.** `portal_live.ex:980` labels a claim-only count “AWAITING A DECISION,” hiding proposed plans; `:987` always marks “Connect sources” complete. `company_panel.ex:543` renders setup and build together. `company/plan.ex:258-260` separates build, export, evaluation and release. `Company.build_inputs/1` (`company.ex:139-153`) requires exact plan approval and rechecks eligibility. `Evaluations.capabilities/0` (`evaluations.ex:19-39`) separates task readiness from qualification; `Releases.Validation.check/3` (`releases/validation.ex:8-60`) requires an applicable passed task run, complete cleanup and artifact eligibility. Iteration 01 retros `02-ux` and `04-trust` corroborate the misleading summary and authority boundary.

**Recommendation.** Put a concise readiness panel at the start of Company. Show one primary next action from persisted prerequisites and separate counts: “Claims awaiting review” and “Plans awaiting review.” Use “Source snapshots captured” only when records exist; a configured connector is neither captured evidence nor authorized source access. Show six independent facts for the selected exact revision/digest: **claim/plan decisions**, **buildability**, **package integrity**, **current eligibility**, **runtime availability**, and **task-evaluation qualification**. Use “not checked,” “blocked,” or “unavailable” where appropriate, with a reason and destination. Reserve “qualified for release” for release validation of a matching task result; static integrity, configuration smoke, exported files, or MCP enablement cannot earn that label. Keep approval controls attached to exact revision review, without implying Company navigation delegates authority.

**Acceptance.** Empty workspace shows no completed source step and leads to profile/source setup. Proposed or rejected claim and plan states have separate review/revision actions; approved but stale plan leads to a new proposal. A current approved plan may say “buildable,” never “built” until the digest exists. A built digest gets integrity and eligibility results separately; missing local runtime/model/isolation shows an explicit blocker, with no inferred connection. A passed static check remains unqualified; only an applicable passed isolated task run with complete cleanup can support release readiness. Keyboard and narrow-screen journeys preserve draft inputs and announce status changes. Browser evidence covers these states without asserting live-model success.

**Risk.** Cached counts can lag or mask storage errors. Refresh on mutations, surface loader failures, and let Company/Release admission recheck authority. Never expose credential values.
