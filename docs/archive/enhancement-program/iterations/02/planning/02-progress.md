# Proposal 02 — saved-state Company progress

**Evidence.** `PortalLive` renders “Connect sources” with unconditional `complete` styling and counts only proposed claims under “AWAITING A DECISION” (`lib/harness_forge_web/live/portal_live.ex:978-992`). Company actually presents seven steps (`components/company/catalog.ex:27,100,285`; `components/company/plan.ex:47,65,226,257`). `CompanyPanel.reload/1` loads saved profile, repositories, projects and plans (`company_panel.ex:357-380`); the parent loads sources, claims, approved claims and artifacts (`portal_live.ex:629-648`). Plan DTOs expose proposed/approved/rejected and superseded status, while `Company.eligible/1` detects changed pinned context (`lib/harness_forge/company.ex:317-335,352-361`).

**Decision.** Add Company progress derived on each Phoenix LiveView refresh from persisted records, with one primary action focusing the earliest unmet prerequisite: saved profile → repository → project membership → active captured source plus current approved sourced claim in scope → exact current plan approval → built package. Display *pending claim decisions* and *pending plan decisions* separately. Treat goals and milestones as optional context. Distinguish “source captured” from an account merely configured; mark a plan current through the eligibility rules used for approval/build. Keep historical approved packages visible without implying current eligibility. Never derive progress from a draft, active tab or optimistic client state. Preserve draft values when navigating.

**Acceptance.** Empty workspace: 0 completed, next action saves a profile; “Connect sources” is not complete. Partial workspace: only saved, valid prerequisites show complete; next action targets the earliest missing control, including source capture or claim review. Proposed plan: pending-plan count increments independently of pending claims; action opens its exact revision for decision. Rejected plan: no approval completion; action proposes a successor. Approved current plan: action builds/selects it. Stale or superseded plan: no current-plan completion, explicit reason and successor/review action. Built package: show digest and separate current eligibility, integrity, runtime availability, evaluation and release states; never claim qualification from build alone. Verify refresh/reconnect, keyboard focus and narrow viewport in a synthetic native browser journey.

**Risks/non-goals.** An aggregate must not hide multiple project/plan branches; label the selected plan and scope, and show ambiguity before choosing a next action. Storage load failure yields “unavailable,” not zero. No new approval authority, automatic source import, model invocation or runtime fallback. This is a UI proposal; it establishes no real-company outcome.
