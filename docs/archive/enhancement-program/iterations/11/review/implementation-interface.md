## 2. Strict payloads and bounds

All external/domain data maps use string keys; reject structs, atom keys, unknown keys and missing required fields at **every** nested level. Never convert input strings to atoms/modules. UUIDs use lowercase canonical 36-byte UUID syntax; digests use lowercase 64-hex SHA256. A JSON decoding boundary must use `Contracts.decode_json/1` to reject duplicate JSON keys before maps lose them. LiveView form indices are parsed by the component into lists; repeated obligation IDs are independently rejected by the domain. Reject malformed UTF-8/NUL. Preserve submitted text bytes; no Unicode normalization or silent trimming/truncation. Nonblank means `String.trim(text) != ""`.

`freeze_rubric` requires exactly `plan_id`, `expected_plan_revision_hash`, `artifact_digest`, `goal_id`, `goal_content_hash`, `task`, `obligations`; additionally allows `supersedes_id` and `expected_predecessor_hash`, both null/absent for a first revision, both valid and exact for a successor. Re-resolve context server-side; supplied pins never authorize themselves. A successor's predecessor must be scoped, canonical, and have no successor; inherit its family ID. Restored historical predecessors may be explicitly linked, but the new revision must resolve a newly eligible exact package under current workspace authority. It never inherits approval.

Every obligation has **exactly** `id`, `kind`, `text`, `mandatory`, `claim_refs`. IDs match `[a-z][a-z0-9_-]{0,63}`, unique within the revision. Kinds are `goal_acceptance`, `approved_analysis_guidance`, `owner_authored`. `mandatory` must be literal true: this bounded feature has no optional obligations. Exactly one goal_acceptance row has empty claim_refs. Each approved_analysis_guidance row has one or more exact `{id, revision_hash}` refs from `required_claim_refs`, without duplicates; every required ref must appear at least once across those rows. A recommendation can map to multiple obligations; one obligation can explicitly map multiple recommendations. Owner-authored rows have empty claim_refs. Require at least one analysis recommendation and one mapped row; no extra or other-goal claim reference is allowed. IDs are stable within each frozen revision; a successor reusing an ID must preserve that obligation's kind/text/mandatory/claim_refs exactly. Changed meaning gets a new ID. Old results are always interpreted through their own rubric/hash.

Bounds: 1–20 total mandatory obligations (the required kinds imply at least two); each task, obligation text and observation at most1000 `String.length` characters **and**4000 UTF-8 bytes. Obligation/task text must be nonblank; unobserved results may have empty observation. Each claim_refs list is bounded by the plan's existing500-ref maximum. Optional attribution/person name is deliberately absent. Complete canonical rubric hash input and complete canonical assessment hash input must each be ≤131072 bytes; check before hashing/insertion and reject excess. Input normalization never truncates. Maximum100 rubric rows and1000 assessment rows per current workspace, including history/restored rows; count and insert in the same serialized transaction. Identical assessment replay is checked before the assessment cap. No eviction.

`record_assessment` allows **exactly** required `rubric_id`, `expected_rubric_hash`, `attempt_id`, `attempt_token`, `task_status`, `critical_status`, `judgment`, `results`. Statuses: task `completed|interrupted`; critical `none|present|unobserved`; judgment `accepted|not_accepted`. No successful defaults. Each result has exactly `obligation_id`, `status`, `observation`; status is `met|unmet|unobserved`. Results must contain every frozen obligation ID exactly once, with no missing/extra/duplicate ID, for unsuccessful as well as successful attempts. A not-observed obligation is represented explicitly as unobserved. `accepted` requires completed, all met with nonblank observations, critical none, current exact authority and no rubric successor. Otherwise return `:acceptance_requirements_unmet` without inserting a row/audit; do not silently downgrade judgment. A complete-shaped not_accepted attempt may record unmet, unobserved, interrupted or stale outcomes; every pin is checked and stale applicability is captured explicitly. Restored rubrics cannot receive any new assessment; freeze a new eligible successor first.

## 4. Server attempts, transaction and replay order

Required trusted server_opts have exactly four unique keyword keys: `:authorize` zero-arity function, `:session_fingerprint`64hex, `:view_generation`32hex, `:reset_token` nonnegative integer. They are server embedding options, never accepted from form/JSON. Root PortalLive constructs authorize from its **server** OperatorSession auth assign, using `OperatorSession.valid?/1` (workspace, epoch, age<43200s); computes fingerprint as Contracts.digest of that server auth map; and passes its current server assessment generation and Company reset value. A missing/false/raising authorization callback refuses. No default permissive callback. Root's direct integration tests may use controlled embedding options; native evidence must use real authenticated events. This is local session authority, not per-client corporate attestation.

`new_attempt/3` checks real authorization, privacy readiness, canonical scoped rubric and original/current workspace equality, then server-mints UUID and signed token. It need not renew stale upstream authority; only not_accepted remains recordable when stale. Return exactly `attempt_id`, `attempt_token`, `rubric_id`, `rubric_revision_hash`. Sign with existing `Phoenix.Token.sign(secret_key_base, "company-assessment-attempt-v1", token_payload, max_age: 43200)`, where secret_key_base is the existing configured endpoint key, never returned or read by advisers. Token payload is exactly version1, workspace_id, session_fingerprint, view_generation, reset_token, rubric_id, rubric_revision_hash, attempt_id. Verify with the same salt/key and max_age43200; token input at most2048 bytes. No new secret, table or provider. The signature is server integrity, not an owner signature.

Mutation order is binding:

1. Validate bounded shape/options; enter `Purge.synchronize`, call `Workspaces.ensure_writable`, then `Store.transaction`. Recheck authorize inside the transaction; session/privacy checks apply even to retries.
2. Load scoped rubric, recompute canonical hash, match expected hash and ensure `payload.origin_workspace_id == outer workspace_id == Store.workspace()`. Historical restore mismatch refuses before any replay. Validate token signature/age and **all** token fields against trusted server options and the submitted exact rubric/attempt.
3. Canonicalize the strict request, check unique scoped attempt. Existing row with matching rubric, request_digest and valid stored assessment hash returns **that same receipt ID/payload/hash** and recalculated applicability, with no insert/audit and before mutable upstream eligibility. Changed request with the same attempt returns `:conflicting_attempt_replay`. An invalid/expired/revoked/reset token cannot retrieve a receipt by replay; use authenticated history reads instead.
4. For a new attempt, check cap, reload exact package/goal/selected recommendation/context pins and compare with captured payload; check current rubric successor. Derive current/stale applicability. `accepted` requires current; not_accepted can capture stale status with a fixed reason. All mandatory result accounting is validated independently. Recheck authorize immediately before the row/audit writes. Freeze always requires current exact eligibility and its own cap/lineage checks within the same fence/transaction.
5. Insert immutable assessment and append exactly one safe audit in that transaction. Audit failure/constraint failure/injected failure rolls back both; no success returned before commit. Serialized fence plus unique attempt constraint makes concurrent duplicates converge on one row/audit; conflict handling must re-read/compare the winning committed row, never overwrite it.

No attempt is consumed on validation/transaction failure: corrected new content can use that uncommitted token until first commit. After commit, changing any canonical request field needs a freshly minted attempt. Corrections to task/rubric/binding need an explicit rubric successor and new assessment. Previous attempts remain distinct; do not update an earlier result or infer acceptance from it.

Audit actions: `company.task_rubric_frozen` with rubric_id/plan_id/revision_hash; `company.assessment_recorded` with assessment_id/rubric_id/attempt_id/assessment_hash/status and server actor. Root extends Audit.@allowed only for `rubric_id`, `assessment_id`, `attempt_id`, `revision_hash`, `assessment_hash`. Existing `plan_id/status/actor` suffice for the rest. Audit carries no task, obligation/observation, goal acceptance, source body, name, token or request object. No inference, claims/decisions, artifact publication, trusted evaluation or release write accompanies an assessment.

## 5. Fixed error codes and safe presentation

New domain errors are `:invalid_input` (unknown/missing/type/enum/UTF-8/ID errors), `:input_too_large`, `:rubric_limit`, `:assessment_limit`, `:not_found` (including foreign IDs), `:stale_plan_revision`, `:superseded_plan`, `:plan_not_approved`, `:package_not_bound`, `:invalid_package`, `:goal_not_selected`, `:stale_goal`, `:analysis_recommendation_required`, `:incomplete_obligation_mapping`, `:stale_authority`, `:stale_rubric`, `:already_superseded`, `:invalid_record_hash`, `:restored_historical`, `:operator_session_revoked`, `:invalid_attempt_token`, `:conflicting_attempt_replay`, `:invalid_obligation_results`, `:acceptance_requirements_unmet`, `:assessment_storage_failed`, `:audit_failed`. Existing privacy fence returns `:privacy_operation_incomplete` or `:privacy_state_unavailable`. A current helper mismatch from existing source/claim/catalog/context eligibility normalizes to `:stale_authority`; malformed stored artifact/loading/verification failures normalize to `:invalid_package`; unexpected storage exceptions become assessment_storage_failed. No arbitrary existing exception text or variable provider reason is echoed. Shape/length errors precede missing/mapping/results errors; valid accepted shape with stale pins yields stale_authority/stale_rubric, not acceptance_requirements_unmet. All refusal paths insert zero assessment/audit rows.

UI maps codes to fixed actionable copy: limits→reduce text/obligations or explain workspace cap; missing mappings/results→identify required frozen IDs from trusted state; stale→manual review/reanalysis/new exact approvals/package/rubric; session→login; restore→new eligible rubric and assessment; privacy→finish removal; conflicting retry→view existing receipt or start a new attempt. Do not send unrelated storage/model failures to reanalysis, auto-repin, approve, select or build. `context` unavailable is visibly blocked; it cannot make Guide completion true.
