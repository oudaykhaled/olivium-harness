## Forms, copy and outcome truth

Task/obligation/observation fields expose the 1,000 Unicode-character / 4,000 UTF-8-byte limit; reject over-limit input with its entered value retained, never silently truncate. Show 1–20 mandatory obligations. Report the 128KiB canonical-input, 100-rubric-revision and 1,000-assessment workspace limits as actionable server errors when reached. No uploads, person-name input, URL input or hidden instruction execution.

Result/status/judgment selects start at **Choose…**, without inferred success. Values are exact: obligation `met|unmet|unobserved`; task `completed|interrupted`; critical `none|present|unobserved`; judgment `accepted|not_accepted`. Give each control a distinct label, e.g. **Result for obligation named-review** and **Observation for obligation named-review**. Nonblank observation is required for each mandatory `met` result in an accepted assessment. Unobserved/nonaccepted rows may retain explicitly blank observations where domain validation permits; never manufacture observations or statuses to save.

Use **Owner accepted this task assessment** only when the server persisted `accepted` after completed work, every mandatory obligation `met` with nonblank observation, explicit critical `none` and current exact scoped authority. Otherwise use **Recorded — not accepted**. A critical violation with an accepted judgment says: **Cannot accept: a critical violation is present. Choose Not accepted to record this attempt.** Missing/blank results identify the exact obligation and preserve input. An interrupted attempt says: **Interrupted work can be recorded as Not accepted.**

Every visible receipt/result includes: **Owner-reported assessment; not independently verified; no runtime or release qualification.** Show **Recorded by local-operator (local workspace access; corporate ownership and personal identity are not attested).** Never call this a trusted run, corporate sign-off, complete company harness or evidence of time/cost improvement. No acceptance value, observation or synthetic oracle text is prefilled as an actual result.

## Drafts, departures and privacy

Source links retain the existing safe `target="_blank"`, `rel="noopener noreferrer"` and announced new-tab copy. Returning to the still-mounted original tab keeps rubric/results text, dirty state and originating link focus. It performs no navigation event, inference or approval. Browser remount/reload reconstructs committed frozen records only; unsaved text is not durably saved.

Intercept an ordinary departure while this assessment is dirty **before** Portal's existing `change_tab/2` rotates/reset state. Use an inline confirmation region, not a global navigation redesign: **This assessment has unsaved changes**; **Keep editing**, **Discard and leave**, and a stage-specific **Freeze rubric and leave** or **Record not accepted and leave**. Saving uses the normal strict transaction and leaves only after its receipt returns. If required explicit statuses/mappings are absent, keep the draft and focus the errors; never fill missing statuses or silently change an accepted judgment. For result-save departure, the button itself is an explicit Not accepted choice; preserve prior entered observations. No extra mutable draft table. Focus the confirmation heading; Keep editing restores the originating control; successful discard/save focuses the requested destination. Clean departure needs no prompt.

Privacy/auth reset takes precedence over departure confirmation: erase sensitive DOM controls and server assigns, rotate generation/attempt state, clear queued intents and close disclosures/receipts as appropriate. Auth loss redirects to login without echoing prior text. Portal-initiated successful purge resets two mounted assessment views through the existing workspace mechanism. A queued old form submit or response cannot restore erased text or create a receipt. Parent tab handlers and component events both revalidate auth; component handlers do not inherit the parent's hook.

Stale context refusal says **Inputs changed. This attempt was not recorded. Review the current evidence and create a new eligible rubric.** Keep the mounted observation draft until deliberate discard or privacy/auth reset; do not auto-copy it into a new attempt. A genuine validation/storage error retains its own remedy. No automatic repinning, inference, plan/claim selection or approval. Supported domain purge is verified after reload; immediate mounted freshness for arbitrary external writers remains deferred.

History shows two separate labels, e.g. **Captured judgment: Accepted** and **Current applicability: Stale — evidence changed**. A restored record says **Restored history — a new rubric and assessment are required**; historical judgment stays visible but acceptance/new-attempt controls are withheld. Purged records show a generic unavailable state with no observation/body echo. Missing assessment means **Unassessed**. Successors preserve old task/observation/judgment bytes and require fresh explicit outcomes.

## Keyboard, reflow and root verification

Native buttons/disclosures, labeled controls and fieldsets give a linear keyboard order: scope → context → task/rubric → freeze → results → submit → receipt/history. Use semantic headings and unique IDs; `aria-expanded`/`aria-controls` on custom disclosure buttons; native summaries remain keyboard-operable. Success uses `role="status"`; validation uses a focusable `role="alert"` summary with links to each field, `aria-invalid` and `aria-describedby`. Do not move focus on typing or disclosure redraw. Avoid color-only statuses and disabled-only explanations.

Use one-column obligation cards, `min-width:0`, wrapping hashes/text, full-width narrow actions and inherited Company target/focus tokens. Avoid a result table, horizontal code scrollers, fixed-height observation panes or sticky elements that cover focus. Source details can collapse, but scope, uncertainty warning, outcome conditions and qualification stay readable.

Root must observe 320 and 390 CSS-pixel widths at actual browser 100% and 200% zoom; record both CSS viewport and actual zoom, rather than simulating zoom with a resized viewport. Check the real Guide/built-package keyboard entry, freeze failure, result failure, accepted receipt, stale/restored history, departure choice and long literal pins/text. Verify no horizontal page overflow/clipped action, visible focus, and keyboard source-link return retaining dirty work. Exercise missing-obligation and critical-violation refusal plus a fully completed accepted attempt, and inspect persisted rows/audits rather than only disabled controls.
