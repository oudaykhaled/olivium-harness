# Portal flow: judge one built package against real company work

**Recommend a Company outcome checkpoint.** The portal carries pinned 2–4 source analysis and one goal into Evidence review, separate exact plan approval, and a built package (`lib/harness_forge_web/components/company/analysis.ex:195–200,343–415`; `components/company/plan.ex:315–397`). Its next action sends the owner to fixed trusted evaluations (`plan.ex:442–457`; `live/portal_live.ex:272–278,2399–2417`); `Evaluations` fixes `synthetic-go-v1` and reserves runs for trusted checks (`lib/harness_forge/evaluations.ex:3–15`). No portal step asks whether this package helped with representative work.

From **Company → built package**, record a task, exact package digest, goal content hash, and an edited rubric of mandatory obligations suggested by the approved plan/goal. Show recommendation evidence and conflicts beside rubric editing; suggested obligations may be incomplete. Record each obligation’s result, evidence/notes, critical violation and interruption/recovery outcome. Explicit owner judgment creates an immutable, workspace-scoped receipt only after every mandatory obligation has a result; a critical violation or missing result cannot be marked successful. A changed package, goal or rubric requires a new receipt; retain its predecessor. Display “owner assessment; runtime unverified” beside trusted runs, never feed this into release applicability. Add bounded retention, source-purge invalidation, backup/restore quarantine and cross-workspace rules before persistence (`lib/harness_forge/privacy/snapshot.ex:7–8,286–345`). At most three product authors including root; root owns migration/router integration and corrections.

**Strongest alternative:** mounted purge invalidation removes stale affected views immediately across tabs, with lower review cost and stronger privacy freshness; it does not measure package usefulness. Preserve this as a distinct candidate, not a vote (`live/portal_live.ex:575–581,865–899`).

**Acceptance:** Native keyboard path from analysed sources/goal → edited or rejected recommendation → exact Evidence and plan approvals → built digest → task receipt; show package, goal, rubric, evidence and owner status together. Negative: incomplete obligation, critical violation, stale identity, foreign workspace, revoked source and forged/late event refuse successful receipt; dirty draft requires explicit save/discard, ordinary departure resets, auth/purge resets and queued analysis stays fenced (`live/portal_live.ex:520–647,960–979`; `components/company_panel.ex:193–245`). Mutation: independently alter one obligation/result, digest, goal hash, decision, purge state or generation and assert refusal; predecessor bytes remain exact. Root runs focused/native/canonical checks. Synthetic task/owner judgment establishes workflow mechanics, not semantic completeness, real-model quality, trusted runtime qualification or measured productivity.
