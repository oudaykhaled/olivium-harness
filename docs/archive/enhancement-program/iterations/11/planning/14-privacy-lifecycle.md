# Privacy lifecycle for an owner task assessment

**Recommend one immutable, owner-reviewed representative-task assessment** tied to an exact package digest, task, selected goal revisions, rubric revision, every mandatory obligation result, and an explicit judgment. Label it **owner asserted**, never trusted runtime qualification. The evaluator accepts only `synthetic-go-v1` and trusted run provenance (`lib/harness_forge/evaluations.ex:1–7,15,82–95,790–805`); it must not consume this assessment for release applicability.

The privacy cost is material: task observations and rubric comments can quote company evidence. Store them in a workspace-scoped assessment table with bounded text, immutable revisions and separate accepted decisions. Keep predecessor assessments for successor packages/rubrics. On supported source purge, delete every affected assessment body, decision and derived artifact/export, including indirect plan and claim lineage; retain at most an opaque receipt ID, workspace ID, purge-operation ID, timestamp and deletion reason. Never retain task text, rubric text, source excerpts, goal labels or reference lists in that tombstone. A workspace purge deletes even tombstones. Extend the purge inventory and dependency graph (`privacy/purge.ex:7–8,128–170,341–410,462–499`; `privacy/company.ex:7–49`).

Backup must include the new table and its owned files, with manifest hashes. Restore must remap workspace identity and quarantine every assessment as historical/unaccepted, clearing decisions and any live execution authority; old bytes remain auditable only inside the quarantined workspace (`privacy/snapshot.ex:7–8,55–86,270–349`). Normal exports may include a consented, bounded outcome summary and immutable IDs, never assessment free text or evidence bodies. External exports cannot be withdrawn.

**Acceptance:** Native synthetic multi-source + future-goal task lets the owner assess every mandatory obligation, record critical violations, and explicitly accept only a complete, violation-free result. Missing result, interrupted assessment, critical violation, forged or foreign-workspace package/task/goal/rubric ID refuses accepted success without mutation. A successor preserves the predecessor byte-for-byte. Source and workspace purge, backup/restore quarantine, stale export refusal and two mounted views verify the retained-byte limits and no authority revival; repeated purge is idempotent. Root plus at most two product authors own integration and corrections.

**Strongest alternative:** mounted invalidation after completed supported source purge (`10/retro/03-security.md`). It closes an immediate stale-view disclosure gap with less persistence and review burden, but supplies no representative-work evidence. Either scope retains external-export limits and requires actual browser verification.
