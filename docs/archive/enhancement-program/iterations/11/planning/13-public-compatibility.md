# Public contract and backward compatibility

**Recommend an owner-reviewed task assessment linked to exact package, goal revisions and frozen rubric.** Approved plans reach deterministic export, but CLI `evaluate`/`runs`/`compare` use trusted synthetic-suite evaluations; `Evaluations` owns immutable run applicability (`lib/harness_forge/cli.ex:184–203`; `lib/harness_forge/evaluations.ex:1–7,63–95,790–802`). Add a separate workspace assessment and portal review with per-obligation results, critical-violation result, actor/judgment, exact task/rubric/package/goal pins and immutable successor history. Owner testimony never becomes `Evaluation.Run`, `runtime_qualified`, release approval or compiler input.

**Compatibility contract.** Preserve CLI commands, JSON envelopes, error exits and `evaluate` kinds. Add distinct `company assessments`/`company assess`; old records render **unassessed**, never pass. Preserve three read-only MCP tools and schemas; if exposing assessments, add a bounded read-only workspace-scoped tool with `owner_reported` authority, truncation and no task text. Existing package readiness, eligibility, qualification and legacy responses retain meaning (`mcp/tools.ex:1–7,31–83,248–290`). Keep spec, provenance, manifest files, compiler identity and digest unchanged (`compiler.ex:15–20,78–140`). Receipts are workspace data, absent from export. Successors retain historical receipts without remapping or inherited success.

**Acceptance.** A synthetic multi-source recommendation reaches a package; the owner assesses every mandatory obligation and critical check for one task; accepted judgment persists after reload. Missing result, critical violation marked successful, stale pin, foreign workspace, duplicate acceptance, malformed/oversize input or interrupted write cannot create accepted success. Direct goal/profile/project/source mutation preserves receipt bytes and marks current applicability stale; purge/restore cannot resurrect eligibility. CLI, portal and MCP agree; assessments cannot change `Harnesses.eligible`, export, trusted runs/compare, release qualification or artifact digest (`company.ex:138–171,345–355`; `harnesses.ex:122–170`).

**Strongest alternative:** approval-time goal/milestone completeness gating prevents incoherent packages earlier, at lower storage/privacy cost; it postpones actual task-outcome evidence. Mounted purge invalidation has the stronger immediate disclosure benefit and remains independent. Scope ownership: one domain/persistence author, one portal/API author, root for shared migration/CLI/MCP integration and verification; at most three product authors including corrections.
