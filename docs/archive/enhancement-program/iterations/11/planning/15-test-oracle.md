# Falsifiable independent oracle: one owner-reviewed company task

**Benefit.** An owner can judge whether one task using an approved company package met its future goal and mandatory obligations. The synthetic path proves review, deterministic build and export (`test/harness_forge/company_analysis_integration_test.exs:32–71`); static integrity cannot authorize release (`test/harness_forge/company_acceptance_test.exs:103–149`). The fixed `synthetic-go-v1` grader and trusted evaluation provenance are separate (`lib/harness_forge/evaluations.ex:3–15,82–89`; `test/harness_forge/evaluations_test.exs:29–74`). Neither proves company-task success.

**Recommend** an immutable, workspace-scoped owner assessment for one task, binding package digest, approved plan revision, selected goal and a frozen rubric revision containing enumerated mandatory obligations and critical violations. Capture each obligation’s observed result, evidence reference and owner judgment; accepted success requires complete assessed obligations and zero critical violations. A rubric is proposed/reviewed with the task, never inferred from package prose. Keep the receipt explicitly labelled **owner assertion; runtime unqualified**. A package or rubric successor needs a fresh assessment. This is a bounded outcome loop with review cost, not a release-qualification shortcut. Root owns schema/privacy integration; one domain author owns validation/persistence; one portal author owns review UI, including corrections.

**Independent root oracle:** use a separately authored public two-source/future-goal fixture and a frozen obligation manifest, not counts derived from implementation output. Positive: complete observations plus owner acceptance persist exact identities; native UI review retrieves the same bytes, and export remains coherent. Negative: omit one mandatory result or mark one critical violation and verify no accepted-success row; interrupted draft also has no success. Mutation: change one obligation ID, goal, plan revision, package digest or rubric hash and verify refusal; successor leaves predecessor unchanged. Authority: forged/cross-workspace IDs, stale/revoked evidence and replayed acceptance cannot create or relabel success. Purge: source/workspace deletion removes affected receipt bytes and mounted canaries; backup/restore quarantines old authority, with no accepted success in the restored workspace. Inspect stored tables and normal APIs, not only rendered labels. Any accepted omission, forged identity or retained purged canary falsifies the slice.

**Alternative:** mounted purge invalidation addresses stale disclosure with less domain data, but defers outcome evidence. Preserve security dissent. Synthetic tests establish mechanics only; real semantic completeness, runtime qualification and time/cost gains require separate evidence.
