# Own MCP: one company journey read

**Recommended benefit.** Add one read-only `harnessforge_company_journey` tool keyed by an exact, workspace-scoped plan ID. Show selected analysis/goal revision identities, recommendation review state, plan approval/readiness, eligible package digest and recorded representative outcome. Return bounded counts, exact references, blocker codes and a human next action; never source bodies, guidance, bearer values or inferred success. MCP offers repository search, plan readiness and package metadata, but no connected review context (`lib/harness_forge/mcp/tools.ex:31–82,200–290`). Company already binds approved claims and selected goals to plans (`lib/harness_forge/company.ex:139–163,223–262`). Reuse scoped eligibility checks; absent assessment says “outcome unassessed.” This gives agents a navigable analysis → review → package → outcome read without approval authority.

**Strongest alternative.** Build an immutable owner-reviewed task/rubric receipt first, bound to exact task/package/goal/rubric revisions. It advances measurement more directly, but adds persisted authority, purge/restore and incomplete-obligation semantics. Security's mounted purge notification is a distinct disclosure fix, not outvoted by receipts. Coherence and goal/milestone coverage at creation versus exact approval remain unresolved.

**Acceptance.** Positive: a synthetic multi-source analysis with future goal, rejected original, edited exact-approved successor, separately approved plan and deterministic package yields linked IDs/hashes, current eligibility and `outcome_unassessed`; a recorded owner assessment appears explicitly as owner asserted, separate from trusted Evaluation.Run. Negative: unapproved/stale/revoked/foreign/unknown IDs and purge/quarantine yield safe bounded failures or redaction, with no stale detail; changed uncited context blocks readiness. Native: root exercises an actual local MCP client through `initialize`, `tools/list`, `tools/call` and matches portal status after supported reload. Mutation: all success/failure calls leave Company, Evidence, Evaluation, audit and artifact inventories unchanged; no build, approval, inference or task execution occurs. Authority: existing opt-in local bearer and send-time purge fence remain; a shared bearer confers no per-client isolation, scope or independent revocation (`mcp/auth.ex:9–66`; `plugs/mcp.ex:151–170`). Keep package provenance local and portable approval verification unavailable. Public compatibility: extend `mcp_protocol_test.exs`, `mcp_tools_test.exs`, `mcp_test.exs`; retain strict schemas, 64 KiB response cap and existing three contracts. At most two product authors plus root corrections. Synthetic client mechanics cannot qualify a real model, live connector, runtime or company outcome.
