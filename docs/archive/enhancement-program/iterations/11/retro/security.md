# Iteration 11 retrospective — security

“Was this tool really helpful and reliable to build a complete harness for a company? What is missing to make it reliable?”

It helped establish a disciplined, locally verified workflow, but the evidence does not establish a complete, reliable company harness. The synthetic Mercury journey rejected unsafe guidance, retained a human correction and exported corrected target files. Immutable owner assessments now expose incomplete reports and stale authority. Those are useful safeguards. Scripted provider responses and a deliberately false, structurally accepted observation establish workflow mechanics and the testimony boundary; they do not establish truthful work, company ownership, semantic quality or productivity. Candidate03 installation and canonical 792 registered/777 PASS/0 FAIL/15 existing Docker SKIP do not close those gaps. Two existing Dialyzer diagnostics and full-style Credo debt remain. [verification.md](../verification.md) records these limits.

The assessment authority is materially stronger. Freeze03 `company/assessment_attempts.ex:8–62` binds signed attempts to workspace, session fingerprint, view generation, reset token, rubric/hash and attempt ID, with 12-hour expiry. `company/assessments.ex:121–138,363–428,582–595` authorizes before replay, rejects conflicting requests and rechecks authorization before transactional receipt/audit writes. The authenticated operator remains `local-operator`: this is operator-session authentication, **not externally verified owner identity or semantic truth**. Source hashes detect changed records; they cannot authenticate an owner's account of events.

The family correction matters beyond cosmetic consistency. `assessments.ex:283–325` retains omitted ancestor obligation definitions and rejects changed-meaning reuse during both creation and stored reads. Workspace scope, canonical hashes, family checks and cycle/depth bounds remain. Reviewed regression assertions at `company_assessments_test.exs:421–507,600–647` include an otherwise hash-valid adversarial history. Restored ancestors can constrain definitions for an explicitly eligible successor; they confer no inherited approval or accepted outcome. CODE-11-01 is closed; CODE-11-02's quadratic list/ancestor reads and unmeasured latency remain.

Privacy handling is substantive but bounded. `privacy/company.ex:110–204` follows uncited analysis contexts, whole families and descendants before leaf-first deletion. `privacy/purge.ex:10–118,244–350` retains durable incomplete-operation fences. `Privacy.Snapshot:55–94,288–350` quarantines restore, withdraws approvals/configuration and changes outer workspace identity; assessment payloads remain historical, and old mutation/replay refuses. Portal purge resets cached assessment generations, but direct supported domain writes do not immediately clear mounted views; supported reload is still required (`portal_live.ex:894–1058`; security QA addendum). Independent exports and unencrypted backups survive source purge. MCP's opt-in loopback/shared-bearer authentication lacks per-client revocation (`mcp/auth.ex:9–66`); actual client isolation remains unqualified.

My top three recommendations are:

1. **Make company corpus access a server-owned boundary.** Remove manual 2–4-document selection through bounded corpus membership and resumable retrieval. Reuse pinned Graphiti **0.31.2@d72407dcedac911e1be9fc15b55e8c05a3efcc36**, real Jev/runtime/extraction/hybrid components and a bounded Python adapter; keep Elixir and revisioned SQLite/FTS5 authoritative. Require nonempty group scope before retrieval and every dispatch. Treat company documents as untrusted data, including embedded instructions; retain exact revision/hash/UTF-8 spans, parent context, dates/status, contrary evidence, coverage gaps and abstention. Graph facts remain proposals.
2. **Carry privacy and spending authority through every derivative.** Pin independently consented provider stages; meter retries, cancellation, ambiguous usage and shared budgets. Record transitive prompt dependencies, including uncited sources and summaries. Tombstone affected results before removal and keep them unservable through failed rebuilds: the frozen reuse decision reports Graphiti can restore an old summary after rebuild failure. Extend restore quarantine and mounted-view invalidation, and test interrupted cleanup before increasing corpus limits.
3. **Prove useful output against independent expectations.** Evaluate representative company tasks and supporting/conflicting source sets, including malicious corpus text, revocation, changed evidence and recovery. Measure missed critical obligations, citation accuracy, cost and latency; add per-client MCP revocation where machine access is used. The separate 51-test offline mock spike proves neither installed integration, real backend behavior, model quality nor million-file qualification.

My dissent is against treating owner “accepted,” graph confidence or passing mechanics as reliable-company certification. Next UI priorities can expose corpus/goal scope, progress, conflicts and current versus historical authority while addressing WEB-11-01/02. Following functionality should connect retrieval → human edit/reject/approve → corrected actual export → representative evaluation. Fresh planning must choose the bounded scope; this retrospective does not.
