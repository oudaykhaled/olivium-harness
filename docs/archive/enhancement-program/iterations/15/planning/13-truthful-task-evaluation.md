# Proposal 13 — Truthful evidence-to-task evaluation

**Scope.** Add a web-visible, versioned assessment of the *same authorised corpus, saved goal, retrieval question, reviewed claim, separately approved plan and exported artifact*. It should expose where evidence was lost before the user trusts the harness, then report actual representative-task outcomes only when the configured model and qualified isolation permit a dispatch. This is one vertical slice of iteration 15’s critical-obligation priority, not a new evaluation engine.

**Why now.** The public nine-content-term question selected three passages and omitted `policy.md`; the focused question selected four including its two-reviewer obligation. The frozen `Retrieval.tokens/1` retains first four and last four terms above eight, dropping middle “policy.” Existing structural readiness correctly says semantic coverage is unknown. The scripted synthesis, exact claim approval, separate plan approval and eight-file export demonstrate mechanics, while static integrity passed and task evaluation remained `BLOCKED model_not_selected / not_dispatched`. A convincing export can therefore preserve a missing obligation perfectly.

**Reuse and seam.** Keep `Company.Retrieval.query_plan/2`, FTS5, its bounded lanes/packing and immutable run diagnostics; `Passages.envelope` and `OriginV2` for checked byte pins and transitive dependencies; `AnalysisV2` for goal-plus-evidence synthesis; existing claim/plan decisions, compiler/export and `Evaluations` records. Extend the browser review/evaluation presentation only enough to show a per-question evidence ledger: expected public source identities and applicability, retrieved/selected/omitted identities, critical supporting and contrary misses, unresolved uncertainty, and the exact exported revision. `Evaluations.compare/2` already refuses mismatched suite/runtime/environment/grader/model identities; preserve that rule. Graphiti 0.31.2/native Jev remains the existing optional graph route, with Elixir authority.

**Checkable acceptance.** Independently author PUBLIC development cases before selecting a retrieval correction: long/focused and reordered questions; general policy plus later scoped exception and failure; distractor; no-answer. Run baseline and each bounded candidate on identical cases and declared caps. Record source-level critical/contrary recall, irrelevant inclusion, byte/citation validity, context omission and answerable-versus-abstain outcomes. A middle-position obligation must appear in selected checked passages where the public case requires it; no-answer cases must state insufficiency. All-abstention fails answerable cases. Through the browser, inspect and correct one recommendation against the saved goal, reject a canary, approve the exact successor claim and **separately** the exact plan, then verify applicable guidance and absence of rejected text in actual export bytes. With an authorised selected model, assess paired baseline/candidate tasks under the same immutable identities for correctness, critical violations, recovery and measured time/cost. Otherwise show the precise `BLOCKED` reason and no benefit claim.

**Alternatives.** A retrieval-only recall score is cheaper but misses unsupported guidance and export drift. Static artifact integrity is necessary but cannot demonstrate task usefulness. A new task runner or graph engine adds authority and operational risk; existing evaluation and retrieval seams suffice for this slice. Preserve scope, consent, revocation, currentness, budget/cancellation, and provenance checks; do not infer policy status from capture time or treat provisional relation labels as entailment.
