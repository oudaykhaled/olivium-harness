# Versioned retrieval origin and old-run currentness

**Scope.** The public nine-content-term question omitted `policy.md`; the focused question included it. `Retrieval.tokens/1` currently retains the first and last four terms, so a middle obligation can disappear. This proposal addresses how a bounded retrieval correction reaches review without changing the meaning of saved runs or weakening source authority. It does not select the correction algorithm.

**Proposal.** Give each new retrieval run an explicit query-plan and packing version in its immutable envelope and digest, recording the effective bounded terms/queries, lane limits, selected passage identities and omitted-candidate diagnostics. Compare bounded full-question terms, bounded multi-query decomposition and packing changes on independently authored public cases before selecting one. Preserve historical envelopes and their stored diagnostics: old runs must not be re-ranked, silently rehydrated as a new strategy, or displayed as if they had new lane scores. Missing historical diagnostics remain `unknown`/`nil`, as `read_run/4` already does. A corrected search creates a new run and a new origin; no in-place migration of reviewed claims.

Reuse `Company.Retrieval`/SQLite FTS5, `Passages.envelope/1`, `OriginV2.seal_retrieval/4`, `AnalysisV2`, current claim and separate plan decisions, compiler/export and evaluations. `OriginV2` already pins corpus semantic/authorization generations, checked passage byte spans, goal/project/profile hashes, stage pin and uncited source dependencies; graph certificates, when present, remain transitive. Keep these checks at retrieval read, synthesis dispatch, claim eligibility and build/export. A current display title or capture time cannot grant policy authority. On changed/revoked source, generation, goal, stage or incomplete graph ancestry, reject serving or reuse; retain an immutable historical record labelled unavailable, and require a fresh reviewed successor before export. A new query version must not retroactively cure an old unsupported claim.

**Connected acceptance.** Through the browser, compare the retained long/focused questions with independent reordered, later-exception, contrary, distractor and no-answer public cases. Record expected critical-source and contrary recall, irrelevant inclusion, citation byte correctness, abstention and declared search/byte caps for each candidate; all-abstention fails answerable cases. Reopen an old run and verify its original digest/selected identities and `unknown` historical diagnostics. Change or revoke a contributing source and verify old run/manifest denial and no new provider dispatch, approval or export from stale authority. For a current run, show the saved goal, support and conflict; correct and approve the exact claim, separately approve the exact plan, and inspect actual export bytes for the scoped rule and rejected-content absence. Static integrity is distinct from representative task benefit; absent an authorised configured model, task evaluation remains `BLOCKED`.

**Trade-off.** Full-question terms are simpler but may dilute ranking. Multi-query decomposition can recover middle obligations but increases searches and fusion complexity. Packing alone cannot recover a candidate never retrieved. Select against the same public cases and measured limits; retain the existing Graphiti 0.31.2/Jev adapter without adding an engine.
