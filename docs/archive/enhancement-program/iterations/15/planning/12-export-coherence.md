# Proposal 12 — Preserve applicability and check meaning into exported files

**Outcome.** A company owner can inspect whether the proposed rule, workflow, check and evaluation criterion cover the same applicable cases before approving the exact claim; the exported files retain that reviewed wording and its evidence/future-goal lineage. This is a WEB-only review and supporting Elixir compilation slice, subordinate to fixing the demonstrated long-question retrieval miss. The review cannot compensate for missing policy evidence.

**Why.** The public iteration-14 export has a rule requiring **two** reviewers for ordinary changes and allowing **one** for a documented emergency exception, but its check asks for “a reviewer.” That is a concrete ambiguity in the exported text, not an observed task failure. The scripted report records a conflict, abandoned discussion, future-goal rationale and uncertainty. The existing browser review displays those alongside human resolution, while the compiler’s provenance projection carries rule revision/evidence/goal identities. Those identities establish traceability, not semantic consistency.

**Proposed seam.** Reuse `Company.Analysis`/`AnalysisV2` guidance fields (`rule`, `workflow`, `check`, `evaluation_criterion`), the existing report and `review_resolution`, `CorpusReview` and Evidence claim review, separate exact claim/plan decisions, `Company.build_inputs`, `Compiler`, `Artifacts`, and evaluations. At the existing review step, show a bounded applicability comparison: each material ordinary/exception/changed-policy condition drawn from **checked, selected** findings, the saved goal as future intent, the current four guidance fields, and an explicit unresolved/unknown lane. Let the human correct or reject the claim using existing successor revision semantics. Surface a deterministic preview of the exact target guidance and goal/evidence provenance before the same claim decision; require the reviewer to resolve any identified mismatch in those existing fields or reject/abstain. Preserve the original report, citations, uncertainty and human resolution as immutable basis/lineage. Keep source dates/status visible; never elevate a goal, search label, newer capture time or uncited passage into policy authority. Do not auto-infer semantic approval or add a new approval stage.

**Connected acceptance.** Independently authored PUBLIC cases include general policy, later scoped exception, abandoned discussion, historical failure, future goal, changed/unknown authority, distractor and no-answer variants. The original long/short question pair remains in the retrieval comparison. For answerable cases, reviewers can see indispensable and contrary checked passages, correct the underspecified check to distinguish ordinary two-reviewer and emergency one-reviewer conditions, approve an exact successor and a **separate** exact plan, and verify the same applicability/check meaning in every actual exported guidance file; rejected/superseded text stays absent. Unresolved authority remains qualified or abstained. Record source-level misses, unsupported claims, semantic disagreements, exported byte assertions and representative task obligation violations. Static integrity alone cannot pass semantic acceptance; without an authorised selected model, task evaluation remains `BLOCKED`, `not_dispatched`.

**Options for Astra.** A review-only comparison using existing fields is smallest and keeps authority human, but leaves free-text consistency dependent on reviewers. A structured applicability matrix could enable stronger machine checks, but changes claim/spec/compiler contracts and requires migration/currentness analysis. Select only after bounded public evidence shows the extra structure improves missed obligations without misleading confidence. Keep FTS5, checked passages, versioned origins, consent/budget/cancellation and pinned Graphiti 0.31.2/Jev seams intact; no new retrieval engine or provider fallback.
