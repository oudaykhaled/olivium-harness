# Critical plan-compaction decision 03

**Decision: release only a bounded, lossless stored-plan representation correction to existing A/Root ownership. Stage 2 is not accepted.** Preserve all question terms, actual queries, five executions, limits, selected evidence, packing and digest authority. No engine, schema, fallback, term/candidate reduction or cap increase is selected. Reports/audits 01 and 02 remain frozen.

**Context / Blocking evidence.** The authorized `dense-resource02.json` records 37 public sources, an admitted 255-character/511-byte question with 128 distinct CJK terms, and an attempted 24-passage envelope of **20,742 bytes**, exceeding 16,384 by 4,358. Root's per-test trace captures the actual canonical-serialization input; this is not an inference from `:invalid_passage`. Run count remains 0→0 and no model dispatch occurred. The exact probe source was read; its test expects successful bounded publication, so the reported RED is meaningful. Retrieval:476 stores the expanded plan and :494 rejects the oversized envelope. The minimal corrective target is repeated plan serialization, not evidence validity or packing. Source pins and inert calculations are in audit03.

**Selected representation.** Keep runtime `query_plan/2` and its five fully expanded lane maps unchanged. At the new-run serialization boundary encode a separate, explicitly tagged stored representation:

- Preserve `version: query_plan_v3`, original `question`, complete ordered `question_terms`, `base_source` and exact `limits`.
- Add `storage_encoding: query-plan-terms-v1`, `lane_recipe: five-lane-lexical-v1`, and the exact already-selected ordered `goal_terms` (at most eight).
- Replace stored expanded `lanes` with that pinned recipe. It defines the existing ordered support/contrary/chronology/obligations/followup lanes, each limit 20; the current OR quoting, AND parentheses, generic contrary/history words, and empty-base handling are immutable parts of recipe v1. Future semantic changes require a new recipe/version.

Derive storage from the exact executed plan. Before publication establish that decoding the proposed representation reproduces that plan, including every expression byte, order and limit. If they disagree, fail explicitly; never silently map an unfamiliar plan to the current recipe. Goal selection must be recorded from the already-frozen plan, not recomputed from a later mutable goal. Keep the codec local to Retrieval. One reusable pure `@doc false` internal decode API is permitted for Root/B mechanical inspection and codec tests; it adds no HTTP/MCP surface or authority. Reject ambiguous mixed plain/encoded maps. No generic expression language, dynamic code/atoms, SQL generator framework or new production dependency.

**Size evidence and alternatives.** Inert UTF-8 compact JSON sizing reproduces the original 20,742 bytes exactly. The selected proposal is a 1,629-byte plan and **16,078-byte envelope**, retaining every other envelope field and all 24 identities: 306 bytes headroom. A reconstructed plan is exactly equal to the observed executed plan. These are inert calculations, not an Elixir implementation or runtime PASS.

A readable literal-fragment example retaining five lane maps, base-term references and literal generic suffixes measures 16,763 bytes and still fails. More aggressive abbreviations could reduce that, but add a grammar/parser without benefit over this fixed recipe. A gzip/base64 JSON proposal measures 16,184 bytes in Python, with exact round-trip; OTP bytes were not measured. Reject gzip: opaque stored provenance, decompression bounds and another decoding path are unnecessary when the transparent fixed recipe is smaller in this sample. Retaining explicit failure is safe but leaves the agreed resource case unresolved.

**Compatibility / parser constraints.** Treat storage encoding and query semantics as distinct versions. New compact records use an exact recognized tag and recipe; reject malformed/unknown encodings or invalid references where decoded, with bounded validation of question bytes, term lists and fixed limits. No decoded stored plan may become authority to rerun SQL, dispatch a provider or alter approval. Do not renormalize original questions when decoding: stored terms and pinned rendering establish historical semantics.

Preserve old plain v2 and plain v3 envelopes byte-for-byte. Existing digest validation must hash the stored envelope plus coverage as stored, before any presentation decode; never hash a decoded substitute, migrate historical rows or regenerate missing diagnostics. If a consumer needs expanded lane inspection, decode into a separate read value without changing immutable storage. Root/A must identify any exact-path consumer requiring this adjustment before edits; do not infer unused fields or use broad source discovery.

The previously reviewed Retrieval read/resolve paths consume scope, identities and coverage without reconstructing queries; OriginV2 seals run digest and uncited/transitive dependencies; AnalysisV2 consumes the checked pack and revalidates before publication. Those interfaces stay intact. Graph StageAuthority must still receive the unchanged original runtime plan/question; graph certificates, consent, deadline/cancellation and budget/currentness checks are untouched. Historical plain records remain interpretable by old semantics; no downgrade claim for new encoded records is made without checking the actual reader.

**Verification / completion of this narrow release.** Existing A authors Retrieval and focused codec tests; Root/B may adjust mechanical inspection assertions within existing ownership. Frozen semantic cases and expectations remain unchanged. Root executes:

1. Exact plan round-trip for ordinary, repeated/reordered, stopword-only, termless goal fallback, Unicode and maximal inputs; malformed/unknown encoding rejection. Pin recipe output so later normalization/constants cannot reinterpret historical plans.
2. Original dense probe, now publishing all 24 selected passages within 16,384 bytes, with identical effective query expressions and unchanged selection behavior. Retain the original RED. The 306-byte headroom does not prove every admitted question/goal combination fits; exercise the already-required maximal-byte boundary and report any remaining limit rather than reducing evidence or inflating caps.
3. Historical plain v2/v3 read/resolve and unchanged digests, new digest-bound diagnostics, existing authority regressions, frozen candidate comparison and historical recovery. Adjust reporting to distinguish stored encoding from expanded executed plan.

Actual full provider-prompt measurement remains connected-proof work. The scope/passages proxy is not that prompt. A remains responsible for source correctness; Root remains sole executor/integrator and final acceptance owner. This decision resolves only which correction may be attempted for the observed cap failure; it does not qualify the eventual implementation, Stage 2, UI or iteration completion.
