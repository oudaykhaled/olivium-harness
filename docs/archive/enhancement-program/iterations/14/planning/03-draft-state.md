# 03 — Question and search-mode draft state

**Recommendation.** Give the corpus question form a bounded LiveView draft, owned by `CorpusReviewLive` and keyed to the currently opened workspace/project/goal/corpus scope. Bind textarea and select values from that draft. Add a form-change event that validates and records only the question (maximum 256 characters) and the two existing mode values. On submit, preserve the attempted draft before starting retrieval. Keep the existing immediate clearing of `run`, `page`, `passage`, `stage`, and `claim`; draft retention must never revive or imply eligibility of old evidence.

**Direct source observations.** `CorpusReviewLive.reset/1` creates `state.query` for the separate legacy inspector, but no corpus question/mode draft (`live/corpus_review_live.ex:67-97`). `corpus_retrieve` accepts submitted values and immediately clears all evidence handles, without assigning those values back to form state (`:343-380`). The form has `for={%{}}`, no value/selected bindings, and `phx-auto-recover="ignore"` (`components/company/corpus_review.ex:578-600`). New mount and cache/privacy reset call `reset/1` (`live/corpus_review_live.ex:20-52`); scope change rotates generation and clears evidence (`:620-674`). The existing replacement regression asserts handles clear after a failed graph attempt (`test/harness_forge_web/corpus_review_flow_test.exs:391-433`). Its guarantee must remain.

**Root-reported evidence, not my execution.** Iteration 13's native browser journey reached separate exact claim and plan approvals and eight exported files. Native02 observed previous evidence controls disappear after a failed replacement. Static integrity passed; representative task evaluation was blocked by `model_not_selected`. These records do not establish uncoached form recovery.

**Design boundary.** Retain the draft across validation errors, async completion, ordinary rerenders, and same-session reconnect while the exact scope remains current. A privacy/cache reset, logout, workspace switch, or changed project/goal must discard it. Treat a fresh mount as a new scope unless the server can revalidate a carried scope identity; never put question text into a URL or durable browser store. A controlled form-recovery event is possible, but must pass the current generation and scope checks; the current `ignore` setting and generation envelope prevent assuming automatic recovery works. Socket-only state is the smaller first implementation; cross-mount recovery needs a separate, privacy-reviewed seam.

**Acceptance.** A focused question and graph mode remain visible after a failed graph retrieval, with old evidence/synthesis controls absent; correcting mode to keyword can submit the retained text. Validation failure preserves edited text. Changed scope/privacy reset clears both draft and evidence. A reconnect in the same valid scope preserves draft or visibly explains why recovery was refused. Test keyboard editing and selected option in rendered HTML. No claim/plan approval changes, implicit retry, provider dispatch, or ranking changes. Defer semantic relevance and task benefit to iteration 15.

**Trade-off.** Socket ownership avoids new storage and privacy retention but cannot guarantee full reload recovery. A client store could survive reload, at the cost of sensitive-text lifetime and scope leakage; reject it for this slice.
