## Decision and bounded scope

Choose **existing-route progression with a bounded evidence presentation extension**. Reuse Phoenix/LiveView, current capture/retrieval/Passages authority and the existing Company/Evidence/Plan/Package flow. Retain pinned Graphiti0.31.2 and its established JevClient/LLMRuntime/PromptRoutes integration; do not alter its engine, ranking, qualification or configuration in14.

1. **Primary journey and prerequisites.** Promote “Build from company evidence” on Company. Order Corpus as scope/preparation → capture and index status → question → named evidence → synthesis/review handoff. Keep supplementary inspection/original-report comparison reachable as secondary material with its outside-model-input boundary intact. Link missing profile/project/assigned-goal/connection prerequisites to existing setup. Explain goal assignment; do not auto-create/assign records. Preserve Company dirty-draft refusal. Show local-directory capture capability honestly; a remote connector may remain inspectable but must not present a working directory-capture action. Backend admission remains authoritative.
2. **Draft and recovery.** Bind question and the existing `fts`/`graphiti_hybrid` choice to bounded socket state for the exact opened scope. Retain attempted text/mode across validation errors, ordinary rerenders and failed requests. Discard on changed project/goal/connection, privacy reset, logout or workspace change. A new mount has no persistence promise; explain re-selection when recovery is refused. No question text in URLs or durable browser storage. Before replacement, clear all prior run/page/passage/stage/claim handles. Fence delayed success and exit callbacks against current generation/session; do not let an obsolete error replace the current status. Map actual supported reason codes to capture/index, queue-busy, graph unavailable, model unavailable or stale-scope guidance; unknown errors remain unknown. No automatic retry, FTS fallback, consent or provider dispatch. Switching to keyword search is an explicit operator action.
3. **Named, inspectable evidence.** Enrich only the displayed existing page with authorised source title, current display identity, exact revision, available status/event/effective/captured dates and a checked bounded excerpt. Label missing metadata unknown and retrieval relations provisional; distinguish included analysis passages from additional candidates. Preserve exact-context opening and make its button source-specific. Never substitute current metadata as a historical fact about a sealed recommendation. Full identities remain available in disclosure. Reuse checked passage authority instead of duplicating connector/privacy SQL. Applying its existing maximum4KiB window to at most25 displayed rows is a permissible simple first implementation: at most100KiB of parent-window bytes, not a full-source or whole-corpus load. Drop parent text from the list DTO when unnecessary, do not hydrate the26th pagination sentinel, and record measured page behavior. A batch projection is justified only if it preserves the same checks and is simpler or fixes a measured problem; it is not a new framework requirement.
4. **Truthful progress and deliberate handoff.** Present existing capture checkpoint/state/completion/error and observed-entry counts; label indexing as indexed / active captured members. Discovery and semantic coverage are separate, and a complete local scan is not complete company coverage. Translate raw readiness into evidence gathered for review, distinguish incomplete search, no candidates, model abstention and setup failure. Keep goal rationale, uncertainty, human resolution and current guidance visible at the existing review handoff. State separately what synthesis consent, exact claim approval, exact plan approval, export, static integrity and representative task outcome mean. Reuse current guide/next actions and readiness views; no second persisted workflow state or new outcome dashboard.

Keyboard names, predictable focus on result/error/exact passage and return, concise live status, narrow-width wrapping and visible primary actions are part of these controls, not a separate redesign. Retain pagination and all existing caps.

## Alternatives and consequences

**Copy/CSS-only reorder:** cheapest and reversible, but cannot supply missing source identities or retain submitted drafts. Rejected as insufficient for the connected review task.

**One new wizard or merged Company/Corpus LiveView:** could reduce page transitions, but duplicates scope/progress state, broadens stale-authority and dirty-draft risks, and requires more cross-surface changes. Rejected for14. Existing transitions are accepted if clear and exact-revision checked.

**Comprehensive recovery/outcome console:** resume management, latest-run restoration, paginated capture outcomes, sealed-manifest browser and joined export receipt are useful, but add lifecycle and identity seams beyond this small UI improvement. Deferred.14 displays paused/incomplete states honestly and does not claim cross-session resumability was added.

The selected option adds bounded DTO work and presentation/state coupling. Main risks are stale metadata, UI authority surviving scope changes, additional per-page queries, inaccurate setup diagnoses and layout hiding a conflict. Mitigations are shared checked reads, no persistent draft store, generation-aware callbacks, exact reason mapping, and the acceptance below. No migration, new dependency, storage, provider configuration or approval policy is required. Rollback is a source/release rollback of these additive UI/DTO changes; Root owns any packaged install/rollback and must preserve immutable existing records.
