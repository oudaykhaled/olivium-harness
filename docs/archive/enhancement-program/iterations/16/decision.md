## Decision

Select **one Company start-and-return journey**: make the existing corpus route and saved-state next action clear, then allow the operator to recover a separate-plan naming error without losing valid reviewed context. Reuse existing corpus review, exact-context access, original findings/human resolution, claim decisions, plan decisions, build/export and evaluation screens as the connected path. This is a bounded navigation/presentation and recovery slice, not a new dashboard or review authority.

1. Put the saved-state next action and its reason before optional setup detail. Keep the corpus entry prominent and clearly state that per-document assignments are unnecessary for corpus analysis. Retain explicit project choice for multiple projects and unavailable-state messaging. Put the full saved-setup/plan checklist behind an accessible disclosure; do not label all company setup “manual.” Label the existing selected-source analysis disclosure as the **manual alternative, 2–4 sources**, and localize assigned-source counts and checked-source exclusions to that alternative. Do not hide an active error, pending attempt or unsaved draft merely to simplify presentation.
2. At the plan handoff, explain that only current, eligible, exact approved claims for the selected project/goal are selectable, including corpus claims without manual assignments. Keep the selected goal, exact claim revision and separate plan lifecycle explicit. Reuse existing next actions into plan review, build, Package export and Evaluations; navigation does not select a different revision, approve anything or dispatch a model.
3. Align Package name with the existing64-character slug rule. Give a concrete example, an associated inline error and focused recovery. A space, uppercase initial, invalid punctuation or65-character name is rejected without silently slugifying/trimming it into a different approved payload. After an in-scope rejection, retain project, repositories, exact claim references, goal, preset, target, execution settings and milestones. Correcting only the name can save a **proposed** plan; claim approval never approves it. Changed project/scope/currentness takes precedence over draft preservation.
4. Preserve evidence inspection and human judgment along the journey. Governing policy, scoped exception, abandoned discussion, unknown currentness, saved future intent, original conflicts and resolution remain inspectable before exact claim approval. Question/background counts remain submitted-run diagnostics; do not group individual passages as “question-derived” from their packing lane because lane and candidate membership are not equivalent. No new sufficiency checkbox, automatic applicability badge or semantic-confidence score is introduced.
