# Iteration 16 proposal — company context and own MCP boundary

**Observed problem.** The WEB journey carries a selected corpus and saved goal through human correction, separate exact claim and plan approvals, eight exports, and static PASS. The representative task remains BLOCKED: no model was selected or dispatched. Main15 has MCP disabled. The [handoff](../../15/handoff-to-16.md) and [architecture retrospective](../../15/retro/architecture-astra.md) identify company-context debt: MCP cannot provide the same bounded, current evidence. This does not make the MCP active or the harness task-qualified.

The curated [`MCP.Tools` snapshot](../../../../../../tmp/enhancement-program/16/source-safe/lib/harness_forge/mcp/tools.ex) defines four read-only tools: run readiness, repository search, plan readiness, and package inspection. Run readiness returns identity, selected count, currentness and blocker, without passages or goal text (lines 31–136). Package inspection labels qualification `not_assessed_by_this_tool` and portable approval verification `unavailable` (lines 299–342). [`Readiness`](../../../../../../tmp/enhancement-program/16/source-safe/lib/harness_forge/readiness.ex) separates integrity, eligibility, runtime, evaluation, applicability, cleanup and release admission; it disclaims approval and live runtime checks (lines 1–49, 280–357). The curated [`Protocol` snapshot](../../../../../../tmp/enhancement-program/16/source-safe/lib/harness_forge/mcp/protocol.ex) serializes tool results as structured content and text (lines 119–146).

**Bounded reuse options.** (A) Reuse existing WEB review data for a compact context/status summary. It works while MCP is disabled, but leaves external context debt. (B) Later extend read-only MCP tools with scoped evidence and goal references. This addresses the debt, but adds disclosure, authorization, currentness, bounds and revocation work beyond this WEB slice. A small supporting seam could reuse existing readiness codes for consistent WEB and future MCP wording, without duplicating domain decisions.

**Recommended slice.** Choose A, adding the vocabulary seam only if needed. In existing company review, show corpus/goal identities, captured-versus-unknown coverage, current/refresh-required run, exact claim and separate plan decisions, artifact digest, and static-versus-task status. An “MCP context” line should state disabled on Main and “metadata/readiness only”; offer no activation or external evidence claim. Keep source text behind existing exact-context controls.

**Falsifiable acceptance and Root verification.** In the authorised public journey, changed/revoked source requires refresh; rejected claim never appears approved; plan never inherits claim approval. Without a selected model, static PASS coexists visibly with task BLOCKED/not dispatched. Keyboard and narrow WEB navigation expose each status and next action without color alone or full-source payload. Root can inspect the public WEB flow and existing readiness outputs. Any wrong identity, authority or status rejects the slice. Company completeness, real-model quality, novice success, task benefit and external-context safety remain unproved.
