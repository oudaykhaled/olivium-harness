# Lens 09 — Show the actual export and its exact lineage

The connected WEB demonstration reached eight fresh files, but the last handoff is spread across Company, Package and Evaluations. Company shows the selected approved plan revision, a build button and the resulting package digest; Package’s recorded completion supplies a destination and digest; Evaluations separately reports static PASS and task BLOCKED because no model was selected. The actual browser records identify plan `1538481d-f092-4f1e-986e-910863f754e5` at revision `2c2f0286…`, corrected claim `a41fb86c-d09c-4fa4-8dee-7f0118cd7899` at `a762ce50…`, and artifact `eecb9274…` ([plan approval](../../../../../../tmp/enhancement-program/15/browser-evidence/21-separate-exact-plan-approved.txt), [fresh export](../../../../../../tmp/enhancement-program/15/browser-evidence/24-actual-fresh-export.txt), [task state](../../../../../../tmp/enhancement-program/15/browser-evidence/29-task-blocked-no-model-no-dispatch.txt)). The [compiler snapshot](../../../../../../tmp/enhancement-program/16/source-safe/lib/harness_forge/compiler.ex) constructs deterministic file hashes, provenance and an explicitly unverified native preview; [Artifacts](../../../../../../tmp/enhancement-program/16/source-safe/lib/harness_forge/artifacts.ex) verifies payloads and exports only into a fresh destination. A digest alone cannot tell an operator whether these files were exported, where, or whether any task worked.

Two bounded reuse options merit comparison. **A:** extend the existing Company “Built” receipt with plan/claim pins and a link to the Package export control. This keeps the smallest UI change and preserves existing authority, but leaves export and evaluation states on separate pages. **B:** add a compact lineage panel at the Company handoff, populated only from existing saved plan, artifact, export receipt and evaluation records. It connects the journey, but needs a server-owned join and explicit unavailable states; a client-composed success badge could misstate freshness. I recommend B only if the existing records can be matched without a new schema. Otherwise ship A and retain the missing export-receipt link as an explicit limitation.

Acceptance is falsifiable: after separate exact claim and plan approvals, Company displays the selected hashes and artifact digest, then distinguishes **built preview**, **fresh export completed at this destination**, **static integrity passed** and **task blocked/no dispatch**. An export failure or an export for another digest cannot show completion. A changed/revoked source or superseded plan clears actionable lineage and requires review; no UI control confers approval or execution authority. Root can verify with a public synthetic WEB journey, inspect the actual exported file bytes and manifest against the saved artifact, and read persisted evaluation state. Keyboard users must reach each next action in order; status changes need labelled text and live-region announcement, with long digests wrapping at 390 px.

This slice improves honest handoff, not semantic evidence sufficiency, company-scale coverage, runtime enforcement or task benefit. One scripted synthesis and blocked task cannot qualify those claims. Own MCP company-context debt remains separate.
