- `Plugs.MCP.fenced_dispatch/2` enters the existing `Purge.synchronize/1`; `dispatch_authorized/2` rechecks authentication and `Privacy.ready/0`, invokes the protocol, and calls `send_json/3`/`send_resp` before leaving the callback. Plan lists are SQL-limited projections rather than whole snapshots; package data passes verified storage read and existing admission. Ineligible intact packages return only fixed minimal readiness fields. No generic dispatch, mutation, model call, export or code execution was found.
- Approved predecessor admission is delegated to `Company.build_inputs/1`/`Harnesses.eligible/1`, so a successor does not silently withdraw existing approved eligibility. Explicit local/unbound provenance and unassessed qualification labels preserve that distinction.
- Root's LocalOrigin wrapper branches only on exact `conn.request_path == "/mcp"`; other paths retain the prior guard and normal endpoint pipeline. Runtime enablement is exact `"true"` and stores only the env reference.

### Resolved finding S01 — exceptional responses could omit no-store (P2)

`lib/harness_forge_web/plugs/mcp.ex:17-39,190-193`: the ordinary body rebinds `conn` after setting `Cache-Control: no-store`, but the function-level rescue/catch uses the original argument binding. `failure/5` itself sets content type only. An unexpected error before/during the privacy admission path can therefore return the safe fixed 500 without the frozen no-store header. No company bytes or exception terms are reflected; this is a failure-header contract gap, not an observed authority or content leak.

Correction verified in source: `failure/5` now unconditionally sets `Cache-Control: no-store` before serializing/sending. The new `RaisingBodyAdapter` regression raises a sentinel-bearing error during raw body read; its test asserts fixed HTTP 500, no-store, and absence of the exception sentinel, private path and bearer. The focused run including this regression passed. This reviewer made no source edit or test run.
