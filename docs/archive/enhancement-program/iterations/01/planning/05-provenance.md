# Planner 05 — company plan provenance and portability

**Priority: P1, bounded first fix.** Add a local, read-only artifact provenance inspection operation and show its result beside company package export. The useful answer is: “Which exact plan(s) produced this digest, and can this workspace still export it?” An operator currently sees `harnessforge.provenance.json`, but that file only lists rule revision/evidence references and goal IDs; it has no plan ID, plan revision hash, approval or binding ([compiler.ex:78–98](../../../../../../lib/harness_forge/compiler.ex)). The binding lives in `company_artifact_bindings` ([artifact_binding.ex:5–11](../../../../../../lib/harness_forge/harnesses/artifact_binding.ex)); `build_plan` persists it before publishing files ([harnesses.ex:16–24](../../../../../../lib/harness_forge/harnesses.ex), [harnesses.ex:30–68](../../../../../../lib/harness_forge/harnesses.ex)).

## Proposed scope

Expose one domain operation, e.g. `Harnesses.provenance(digest)`, which reads the verified stored artifact, fetches all workspace-scoped bindings for that digest, and returns a finite string-keyed summary: digest, package name/version, `provenance_scope: "local_workspace"`, each bound plan ID/revision hash, current plan approval status, and one of `eligible`, `blocked`, or `unbound_legacy` with a reason code. Its eligibility result must call the existing `Harnesses.eligible/1` gate rather than reimplement claim/source/plan authority ([harnesses.ex:132–165](../../../../../../lib/harness_forge/harnesses.ex)). Multiple plans may produce identical bytes, and any currently valid binding can authorize the bound artifact; no binding means the existing legacy path. Show this summary in the company package preview/export UI and make the portable limitation explicit: exported v1alpha1 files do not prove company plan approval. Return IDs/hashes/status only, never source bodies, plan descriptions, actor identities or credential material.

This improves a concrete workflow: before exporting or handing off a company package, the owner can see whether the digest is linked to the approved plan they intended, and why it is blocked after source revocation or restore. Keep the existing export gate intact ([harnesses.ex:120–129](../../../../../../lib/harness_forge/harnesses.ex)). Backups preserve bindings, while restore withdraws plan/claim decisions and source authority ([snapshot.ex:55–86](../../../../../../lib/harness_forge/privacy/snapshot.ex), [snapshot.ex:245–255](../../../../../../lib/harness_forge/privacy/snapshot.ex)); the summary must say `blocked` there.

## Portability decision and MCP exposure

Do **not** insert plan fields into v1alpha1 `harnessforge.provenance.json` in this iteration. `Compiler.verify/1` recompiles and compares every byte ([compiler.ex:33–43](../../../../../../lib/harness_forge/compiler.ex)), so changing the compiler output or identity would break historical immutable artifacts. Export writes runtime files only ([artifacts.ex:61–69](../../../../../../lib/harness_forge/artifacts.ex), [artifacts.ex:104–116](../../../../../../lib/harness_forge/artifacts.ex)). The contract explicitly reserves complete portable plan provenance for a versioned schema decision ([company-builder-contract.md:194–206](../../../../../company-builder-contract.md)). A future v1alpha2 design needs an independent verifier and a clear rule for multiple valid bindings, revoked approvals, purge, restore and foreign workspaces; a JSON sidecar alone cannot supply live approval authority.

For HarnessForge’s planned MCP server, expose the same read-only summary as a bounded `artifact_provenance` tool, keyed by digest and scoped to the active workspace. Return `portable_approval_verification: "unavailable"`; no build/export/approval action, arbitrary file path or source text through this tool. There is no current HarnessForge MCP server in the application paths inspected; existing `mcp: %{}` entries are runtime confinement settings ([coding.ex:83](../../../../../../lib/harness_forge/execution/coding.ex), [docker.ex:193](../../../../../../lib/harness_forge/execution/docker.ex)). MCP exposure may follow the local operation, but must not be described as shipped by this first fix.

## Acceptance and negatives

- Synthetic approved plan → built artifact → inspection returns exact binding and `eligible`; two plans with identical digest list both bindings without duplicating artifacts.
- Revoked/stale source, withdrawn plan approval, purged dependent artifact or quarantined restore returns a blocked or absent result; no legacy fallback for an artifact that still has invalid bindings ([harnesses.ex:146–165](../../../../../../lib/harness_forge/harnesses.ex)).
- Legacy unbound artifact is labeled `unbound_legacy`, never “company approved.” Unknown/tampered digest fails through artifact verification.
- Exported bytes and manifest digests remain unchanged. Any MCP test must separately prove local scope, bounded arguments, no secret/body leakage and read-only behavior; fixture success is not live client compatibility.
