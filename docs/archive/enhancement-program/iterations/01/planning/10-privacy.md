# Privacy, purge, and workspace races for own MCP

## Recommendation (P0)

Expose a small **read-only company catalogue** through the own MCP server: profile, repositories, projects, plans, capability search, and repository consumers. Keep source bodies, claims, model settings, credentials, backup/restore, and purge tools outside this first surface. Existing catalogue descriptions are explicitly data rather than policy authority ([`lib/harness_forge/company.ex:3-7`](../../../../../../lib/harness_forge/company.ex)); repository/project reads are already workspace scoped through `Store.scoped/1` ([`company.ex:33-36`](../../../../../../lib/harness_forge/company.ex), [`evidence/store.ex:15-23`](../../../../../../lib/harness_forge/evidence/store.ex)). Do not present catalogue records as approved instructions or a complete company truth.

**One admission boundary for every MCP read:** authenticate the current operator and workspace, acquire `Privacy.Purge.synchronize/1`, check `Privacy.ready/0`, perform the scoped read, and serialize/dispatch the response before releasing the fence. A check outside the lock leaves a gap where purge can prepare after the check and before data is read. `Purge.prepare/2` revokes connections and commits a durable prepared operation under this same lock; incomplete operations make `ready/0` fail ([`privacy/purge.ex:10-18`](../../../../../../lib/harness_forge/privacy/purge.ex), [`privacy/purge.ex:73-114`](../../../../../../lib/harness_forge/privacy/purge.ex), [`privacy/purge.ex:542`](../../../../../../lib/harness_forge/privacy/purge.ex)). Most current catalogue reads call `Repo` directly without a privacy check or lock ([`company.ex:17-22`](../../../../../../lib/harness_forge/company.ex), [`company.ex:98-107`](../../../../../../lib/harness_forge/company.ex), [`company.ex:173-174`](../../../../../../lib/harness_forge/company.ex)); do not assume their direct use is safe during purge. Keep the fence in a single MCP dispatch wrapper so adding a read tool cannot bypass it.

Authenticate each request against the *current* workspace identity and session epoch. The local workspace lock excludes a second OS process, but does not serialize concurrent requests in this process ([`workspaces.ex:40-53`](../../../../../../lib/harness_forge/workspaces.ex)). Browser operator sessions bind workspace ID and epoch, and logout rotates that epoch ([`plugs/operator_session.ex:20-36`](../../../../../../lib/harness_forge_web/plugs/operator_session.ex), [`controllers/session_controller.ex:31-35`](../../../../../../lib/harness_forge_web/controllers/session_controller.ex)). A persistent `access-token` value alone would survive logout and content purge ([`workspaces.ex:64-80`](../../../../../../lib/harness_forge/workspaces.ex), [`privacy/purge.ex:121-125`](../../../../../../lib/harness_forge/privacy/purge.ex)); do not treat it as a revocable MCP session. Apply the existing exact local Host/Origin guard to the MCP route ([`plugs/local_origin.ex:7-29`](../../../../../../lib/harness_forge_web/plugs/local_origin.ex)). Return `no-store`; never echo auth material in tool output, errors, audit, or logs.

## Strict negative acceptance, in priority order

1. **P0 — purge race:** Hold a catalogue response in progress, start source or workspace purge, and prove purge waits until response dispatch finishes. Then prove requests admitted after the prepared fence return an unavailable/privacy error and reveal no catalogue bytes. A failed cleanup leaves the fence active until reconciliation ([`privacy/purge.ex:224-249`](../../../../../../lib/harness_forge/privacy/purge.ex)).
2. **P0 — authorization:** Anonymous, wrong-workspace, expired, logged-out, and stale-epoch clients receive no catalogue records. Reject hostile Host/Origin values. A restored workspace has a new identity and quarantined prior authority ([`privacy.ex:5-11`](../../../../../../lib/harness_forge/privacy.ex)).
3. **P0 — scope and minimization:** A guessed ID from another workspace, purged source, or removed plan yields no data. Responses exclude source bodies, credential references/values, session files, and arbitrary file paths. No MCP method mutates catalogue, approves a claim/plan, starts inference, exports, backs up, or purges.
4. **P1 — recovery:** During an incomplete purge and immediately after restart, MCP reads remain unavailable until startup reconciliation finishes; startup already runs reconciliation before jobs and endpoint ([`startup_gate.ex:1-16`](../../../../../../lib/harness_forge/startup_gate.ex)).

Use synthetic fixtures and local requests only. These tests establish the local privacy contract, not remote client compatibility or physical erasure; content purge explicitly retains identity/login files and excludes external copies ([`docs/privacy.md:9-11`](../../../../../privacy.md)).
