# Iteration 01 decision: local MCP company and package readiness

**Decision:** implement a first-party, opt-in, read-only MCP endpoint in the
existing workspace-owning Phoenix process. Ship three useful tools: find reusable
repositories, inspect company-plan readiness, and inspect an exact built package's
integrity and current eligibility. This is a functionality iteration.

**Status:** scope frozen for authoring after root accepts this decision and the
[guardrail brief](review/guardrail-brief.md). No implementation, passing check or
iteration completion is claimed by this document.

Decision maker `/root/i01_decision_astra` (`gpt-6-astra`) read all 16 `gpt-6-sol`
planner artifacts. All 16 reported ready and were observed running concurrently
at the final planning review barrier; see [the concurrency record](concurrency-evidence.json)
and root's authoritative dispatch roster. Root-authorized release messages were
sent to all 16 after that observation. Some planners were reactivated for review;
the record does not claim continuous simultaneous investigation.

## Context, choice and alternatives

The existing company workflow builds approved exact plans and deterministic
packages, but external local agents cannot query its trusted state. Reuse
`Company.search_capabilities/1`, plan admission `Company.build_inputs/1`, verified
artifact reads `Harnesses.get/1`, and current artifact admission
`Harnesses.eligible/1`. Do not duplicate approvals, catalogue storage, provenance
authority or runtime qualification logic.

The rubric in [the draft](decision-draft.md) weights immediate usefulness 30%,
trust/reliability 25%, bounded feasibility 20%, reuse 15% and verification 10%.
After all reports, the narrower MCP readiness slice scores 5/5/4/5/5 = **96/100**:
the existing exact admission APIs and a real installed client remove two draft
uncertainties. Portal-only readiness remains **94/100** and is the preferred next
UI focus. Portable provenance stays **82/100** and requires a separate versioned
format decision. Managed execution fails the external/isolation hard gate; it
cannot be manufactured by this iteration. These are engineering estimates, not
measurements or planner votes.

Choose in-process HTTP because a separate CLI/stdin server would conflict with
`Workspaces.acquire/1` while the portal owns the database. A stdio proxy adds a
second transport without improving this bounded acceptance journey. Do not
modify the workspace lock. Do not change v1alpha1 generated bytes or manifests.

Pin **MCP 2025-11-25**. Root/impediment inspection reports an installed official
Node MCP SDK **1.29.0** supporting it, with Node **26**. Independent QA must record
the actual package path/version it runs. This is deliberately a legacy profile:
official [2026-07-28 versioning](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning)
uses per-request metadata and `server/discover`; this iteration does not implement
or claim that newer profile. Supporting one proved useful profile is preferable
to untested dual-era breadth.

## Frozen transport and credential contract

- Endpoint: exact `/mcp`, inside the current Phoenix process and loopback listener.
  Root integrates an exact path branch before the existing global LocalOrigin
  wrapper and generic JSON parser. All other paths retain their current guards.
  The dedicated plug itself checks actual loopback peer, exact allowed Host and
  every supplied Origin; invalid supplied Origin is always rejected. An absent
  Origin is permitted only on the independently authenticated machine route.
- Enablement: `HARNESSFORGE_MCP_ENABLED=true` plus
  `HARNESSFORGE_MCP_TOKEN_ENV=NAME_OF_OPERATOR_SECRET_ENV`. Disabled by default.
  Resolve that environment reference on each request; missing, malformed or empty
  configuration denies access. Require an operator-generated bearer from at least
  32 random bytes, represented as 43–256 URL-safe characters. Validate reference
  syntax with a bounded environment-name grammar. Never use or read the browser
  access-token file for MCP. Require exactly one bounded Authorization bearer
  header and constant-time comparison. Do not put credential values in app config
  dumps, URLs, responses, archives, logs, screenshots or client config examples.
- This is an **independent machine credential**, not a browser session. It survives
  browser logout and epoch rotation intentionally. Explicit revocation/rotation:
  stop the owning app, unset/replace the referenced value or disable MCP, then
  restart. Old credentials fail after rotation. Environment changes in another
  shell do not alter a running process. Backups/restores never carry this credential;
  enabling a restored/new workspace requires explicit launch configuration.
  No claim of per-client revocation or automatic browser-logout invalidation.
- Guardrail reviewer explicitly accepted this lifecycle and the bounded three-tool
  scope in the decision follow-up. No new capability registry, persistent session
  store or token UI is required for iteration 01.
- JSON POST responses; implement `initialize`, `notifications/initialized`, `ping`,
  `tools/list`, `tools/call`. Advertise only tools with `listChanged: false`. GET
  returns authenticated 405 (no SSE); DELETE authenticated 405. No MCP session ID,
  server requests, resources, prompts, subscriptions or remote OAuth service.
  Use the official [2025-11-25 transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)
  and [lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle):
  initialization negotiates the supported version, accepted initialized
  notifications return 202 with no body, subsequent requests carry the pinned
  version header, and unsupported version headers return 400. Explicitly require
  the version header on subsequent calls because no connection session is stored.
  Stateless HTTP does not maintain a per-client initialization registry.
- Raw body maximum **65,536 bytes**, decoded by `Contracts.decode_json/1` before
  ordinary Jason parsing; reject duplicate keys, batches, excessive nesting,
  malformed IDs and non-object shapes. IDs: integer within the safe JSON integer
  range or UTF-8 string at most 128 bytes; reject null/bool/float/compound IDs.
  Tool arguments have exact string-keyed schemas and reject unknown keys.
  Encoded response ceiling **65,536 bytes**; overflow returns a fixed safe error,
  never partial JSON. No response compression/cache of company data in this slice.
  Set `Cache-Control: no-store`; do not enable permissive CORS.
- Every data-bearing read uses one admission wrapper: authenticate, acquire
  `Privacy.Purge.synchronize/1`, recheck enabled/credential and `Privacy.ready/0`,
  perform scoped reads and current admission, encode/send before releasing fence.
  Never cache returned content. The fence orders dispatch against purge; it does
  not erase copies already received by a client. All errors are fixed codes and
  messages, not exception/request/body/path reflections.

## Exact tool surface

Frozen module boundary (no new supervision child or persistent protocol session):

```elixir
HarnessForge.MCP.Auth.authorize(conn)
# :ok | {:error, :disabled | :unauthorized | :forbidden}
# Reads explicit enablement/env-ref config; no browser-token access.

HarnessForge.MCP.Protocol.version()
# "2025-11-25"

HarnessForge.MCP.Protocol.handle(decoded_request)
# {:reply, json_rpc_map} | :accepted_notification |
# {:reject, http_status_integer, safe_json_rpc_error_map}
# Runs only inside the plug's privacy fence for data-bearing calls.

HarnessForge.MCP.Tools.list()
# [fixed_string_keyed_tool_definition]

HarnessForge.MCP.Tools.call(tool_name, arguments)
# {:ok, string_keyed_result_map} | {:error, safe_atom}

HarnessForgeWeb.Plugs.MCP.init(options)
HarnessForgeWeb.Plugs.MCP.call(conn, options)
# Dedicated raw HTTP/auth/fence-through-send boundary, always halts handled /mcp.
```

Root configuration exposes application keys `:mcp_enabled` (boolean) and
`:mcp_token_env` (the reference name only), populated from the startup variables
above. Tests may set those keys and a synthetic environment value, restoring them
afterward. The auth module resolves the reference on each call. Lane A owns all
protocol shape/error translation; lane B returns only the declared domain tuple.
Shared changes require an explicit coordinator message, not silent divergence.

Tool definitions set `readOnlyHint: true`, `destructiveHint: false`,
`idempotentHint: true`, `openWorldHint: false`; these annotations describe the
implemented boundary, not an authorization mechanism. Return a structured JSON
object and matching text JSON for compatibility; never create dynamic schemas or
instructions from company content. Fixed tool descriptions label catalogue text
as operator-authored data and readiness as a current observation.

### `harnessforge_search_repositories`

Arguments: `{ "query": string, "limit"?: integer }`; query is valid UTF-8,
maximum 256 characters / 1,024 bytes, at most 20 whitespace tokens; limit defaults
to 10 and permits 1–20. Empty/whitespace query returns an empty result.

Reuse current lexical all-token capability matching, deterministic ordering and
workspace scope. Output exactly `repositories`, `returned_count`, `truncated`,
`authority: "operator_authored_catalogue"`. Each row: `id`, `identity`, `name`,
`owner`, `content_hash`. No purpose/examples/full capability arrays, source/goal
assignments or credential fields. Existing catalogue is capped at 100 records;
measure that fixture and avoid a new index/migration. Response limits apply even
to unusual maximum-length catalogue values. Do not claim large-fleet scale.

### `harnessforge_company_plans`

Arguments are either `{ "limit"?: integer }` (default 10, max 20), or exactly
`{ "plan_id": UUID }`. No caller workspace, actor, hash or approval input.

List: stable oldest-first `(inserted_at,id)` order, fetch `limit+1` projected rows
in a workspace-scoped query; return `plans`, `returned_count`, `truncated`. Each
summary contains `id`, `name`, `revision_hash`, `status`, `superseded`. Do not load
every plan/snapshot merely to return a bounded list. This first list is explicitly
truncated without pagination; exact known IDs remain inspectable. Pagination is a
documented limitation and follow-up, not a promise of complete discovery.

Inspect: use `Company.get_plan/1` and `Company.build_inputs/1`; project the same
summary plus `buildable`, `blocker_code`, `next_action`, and up to 20 directly bound
`artifact_digests` with `artifacts_truncated`. Decisions and current readiness are
distinct: proposed/rejected plans are not buildable; approved but stale plans
report blocked; an eligible approved predecessor stays buildable after a successor.
Bounded fixed next actions include `review_plan`, `review_current_inputs`,
`build_in_portal`, `inspect_package`. Do not return build-input text or snapshots.
Current buildability never reserves or authorizes a future build.

### `harnessforge_inspect_package`

Arguments exactly `{ "digest": string }`, lowercase 64-character hex.
Use `Harnesses.get/1` for verified bytes and `Harnesses.eligible/1` for current
admission **inside the same privacy fence**. Unknown/tampered artifacts return
a safe tool error. No caller paths; no arbitrary files or root overrides.

Output allowlist: `digest`, `name`, `version`, `runtime`, `runtime_version`,
`integrity: "verified"`, `eligible`, `blocker_code`, `next_action`, `rule_count`,
`file_count`, `provenance_scope: "local_workspace"`, up to 20 `plan_bindings`
(`plan_id`, `plan_revision_hash`) and `bindings_truncated`, plus
`qualification: "not_assessed_by_this_tool"` and
`portable_approval_verification: "unavailable"`.

For an ineligible but intact artifact return only digest, integrity, eligible=false,
fixed blocker/next action and qualification labels; suppress company/package
descriptive fields and bindings. An unbound legacy artifact can retain existing
eligibility semantics but must be labeled `provenance_scope: "unbound_legacy"`,
never company-plan approved. Fixed next-action guidance points to existing portal
inspection/export/evaluation controls; MCP performs none of those actions.

**Deliberate content boundary:** package guidance means readiness and next-action
guidance here. No native AGENTS.md/CLAUDE.md bytes, rule/claim text, citations,
source provenance text, plan prose, arbitrary manifest-file reads or full spec.
Wider content serving requires its own consent/minimization decision. No tool
imports, calls models/providers, executes code, approves, builds, exports,
mutates or grants any runtime/release authority.

## Risks + mitigations

- **Risk**: auth reused as browser privilege → **Mitigation**: distinct configured secret, no browser token access, explicit independent lifetime and rotation proof.
- **Risk**: purge or stale inputs race a read → **Mitigation**: current admission and dispatch inside existing privacy fence, controlled concurrency regression.
- **Risk**: protocol-only success hides useless output → **Mitigation**: real company search → plan → exact package journey is the countable outcome.
- **Risk**: native or SDK mismatch → **Mitigation**: run the exact packaged endpoint with SDK1.29.0; preserve legacy-version limitation.
- **Risk**: large catalogue/plan outputs → **Mitigation**: fixed projections, SQL-limited plan list, entry/body/output bounds and maximum-size fixture checks.

## Escalation path

- If a frozen API or security condition cannot be implemented within this slice → `staff-tech-lead` receives failing evidence, exact invariant and smallest two alternatives; root/Astra explicitly amend decision before authors expand scope.
- If review is unresolved after three author/reviewer rounds → `staff-tech-lead` receives diff and outstanding failure; do not count the iteration or lower the check.
