## Smallest safe contract

1. Extend strict retrieval input with **one optional `declaration_ref` object containing exactly `id` and `digest`** (bounded UUID/digest validation); keep all existing mandatory keys and unknown-key rejection. The WEB server supplies its explicitly selected reference. No client-supplied complete/optional/status/member arrays and no implicit latest declaration. A present invalid/stale ref fails closed; it must never use the no-ref fallback.
2. Inside the existing caller/privacy/transaction fences, resolve the exact declaration and match workspace, corpus, project, goal/hash, profile/project hashes and semantic/access generations to retrieval scope. Use `Requirements.summary`'s existing eligibility, active-member, connection configuration and exact receipt validation; do not duplicate a reduced checker. Its required_status complete already excludes missing required coverage, undeclared members and incomplete optional active members. A valid noncomplete declaration may produce an inspectable abstained run; invalid currentness must reject or invalidate it explicitly.
3. Persist a compact versioned coverage binding in the run's existing digest-bound coverage/envelope JSON: exact declaration ID/revision/digest, checked capture-completeness result and named omission provenance. The immutable declaration already pins its connection/receipt set. Keep metadata bounded and preserve envelope/prompt limits. Avoid adding fields to every historical `pins(scope)` shape or graph certificate merely to carry this optional binding; a conditional digest-bound coverage field plus explicit validation is sufficient and reduces compatibility risk. No table migration is inherently needed.
4. For this explicit branch only, derive the capture-complete operand from the checked declaration. Retain indexed==expected, nonempty selected passages, omitted/packing budget, complete parent windows, source membership/currentness and graph certificate checks. `ready` continues to mean a mechanically admissible evidence pack, never understanding/semantic truth. Keep semantic_coverage unknown and expose optional omissions to the downstream prompt/coverage readback.
5. Recheck the same exact declaration after search at publish and in the common checked-run path used by `read_run`, `read_summary`, `validate_current` and `resolve_for_analysis`. Receipt revisions, configuration changes or declaration supersession can happen without a corpus-generation change. A publication-only check would grant stale continuation authority later. Do not recompute a ready state using a different declaration or mutate an old run to make it current.
6. Preserve the no-reference/historical contract and its honest abstention behavior in this bounded change. Do not reinterpret existing run digests. Adding explicit declaration validation must not silently widen legacy completeness or change unrelated approved-ancestor rebuild compatibility.
