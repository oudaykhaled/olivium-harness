# Native command approval decision02

**Decision: implement the existing native app-server approval path using `approval_policy="untrusted"`, with managed one-shot function `exec_command`.** No generic permission question is needed. This is a stricter, separately pinned runtime overlay preserving the export's bash-ask intent; exported bytes remain unchanged.

At Codex commit `fe74a774532af67b5a4a3dec03ce9469e17f89af`, `UnlessTrusted` prompts for **every unmatched command**, including ordinary workspace commands. The upstream `git_status_obeys_approval_policy_and_explicit_rules` test demonstrates both the prompt and the explicit-allow-rule bypass. `on-request` and granular policy allow ordinary sandbox commands. [Policy:815–850](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/exec_policy.rs#L815), [test:1010–1052](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/exec_policy_tests.rs#L1010).

Do not use a catchall prefix: empty patterns are invalid; `*` is literal. PreToolUse `permissionDecision="ask"` is unsupported and fails open. [Parser:171–209](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/execpolicy/src/parser.rs#L171), [matcher:21–55](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/execpolicy/src/rule.rs#L21), [hook test:556–583](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/hooks/src/events/pre_tool_use.rs#L556).

**Fixed native profile:** read-only `/etc/codex/requirements.toml` pins `allowed_approval_policies=["untrusted"]`, `allowed_approvals_reviewers=["user"]`, and `[features] unified_exec=false; shell_tool=true`. Those feature entries are separate TOML assignments. Only managed requirements can retain unified-exec disabled; registration then chooses completion-only `exec_command`, omitting `write_stdin`. The upstream app-server integration test proves this native function/approval/result sequence. [Normalization:153–167](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/config/managed_features.rs#L153), [integration test](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/app-server/tests/suite/v2/config_requirements_exec_tests.rs).

Use a fresh thread/home; pin all loaded system/user/project/environment rule roots empty and immutable. Disable hooks, auto-review, login shells, TTY, permission grants, shell snapshots, search/plugins/MCP and other execution tools. Preserve the model provider/catalog pins and existing nonroot Docker boundaries. Select a source-owned named permission profile with candidate-only writes, network disabled and explicit denied reads for protected paths; allow only that profile. Denied-read restrictions prevent native unsandboxed fallback. Without them, native retry can inherit approval and drop its inner sandbox. [Sandbox enforcement:270–279](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/tools/sandboxing.rs#L270), [retry:396–420](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/tools/orchestrator.rs#L396).

**Bridge:** trusted container driver initializes app-server over stdio, starts the pinned thread (`approvalPolicy:"untrusted"`, `approvalsReviewer:"user"`, selected `permissions` profile), then starts the task turn. For `item/commandExecution/requestApproval`, bind JSON-RPC request ID, thread/turn/item/approval/environment IDs, exact command/cwd, run/artifact/profile hashes, deadline and scope. Add a bounded private approval endpoint to existing Relay/RelayPlug and proxy allowlist; this endpoint does not exist today. Reuse WEB authorization/currentness for the exact decision; never send approvals to Ollama or block Relay's GenServer awaiting a human. Return only `{"decision":"accept"}` for an applicable exact authorization; otherwise decline/cancel. Never return session acceptance or policy amendments: only session acceptance populates native approval cache. [Wire contract:1544–1622](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/app-server-protocol/src/protocol/v2/item.rs#L1544), [cache:71–116](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/tools/sandboxing.rs#L71).

Approval covers the complete submitted command, including its children, not independent approval of every OS execve. Native `exec_command` can intercept patch syntax into file-change approval; initially decline that unsupported callback, never auto-accept it. Under untrusted, interception still asks. [Interception:378–405](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/tools/handlers/unified_exec/exec_command.rs#L378), [patch safety:43–51](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/safety.rs#L43).

**Gates:** observe the exact catalog/config first; prove safe commands, writes, compound commands and repeated identical calls each wait; denial/timeout/disconnect/revocation cause zero execution. Reject rule injection, stale approvals, amendments, escalation and unexpected callbacks. Prove timeout/cancel cleanup, protected-path denial and no fallback. Then execute the actual metered local task and protected grader before paired baseline. Source establishes feasibility, not installed execution success.
