# R01 positive-current context addendum 02

This supersedes decision01 only for migration name, authentication propagation and listed ownership. Five tables, explicit policy action, bounded processing, immutable legacy identities and all guardrails remain. No implementation release.

**Migration:** use unused 20261104000200_local_use_policies.exs. 20261104000100 already belongs to setup_analysis_runs. Root rechecks absence at edit time. capture_ref.id is CaptureRun.id; capture_ref.digest is SetupCaptureBinding.digest resolved by capture_id/workspace/owner, never an invented CaptureRun.digest. Capture.Writer emits initial lifecycle provenance inside its already-verified binding/lease transaction, before any positive policy exists.

**One explicit context.** Add Evidence.SourceUseContext with fields kind, operator_auth, caller, operation_ref, authorization_ref. Only kind=interactive or setup_analysis is supported. interactive(auth,caller) checks genuine existing workspace/epoch/12-hour OperatorSession rules through Workspaces.authenticate_operator/1 plus the unchanged four-key caller validator/callback. It returns a struct, never a serialized token. Revalidate both at every owning boundary; a struct/map/owner string or callback alone proves nothing. Reject arbitrary maps/extra fields. Browser input never supplies context; WEB creates it from socket operator_auth and carries it explicitly into async closures. No process dictionary, global context, widened caller keys or persisted auth epoch/callback.

**Interactive propagation.** Append context as a separate argument to Retrieval.retrieve_evidence/3, read_evidence_summary/4, read_evidence/5, open_evidence_passage/5 and resolve_for_analysis/4. Setup’s existing retrieve path gets retrieve/3 with identical legacy output. Passages.envelope/3 takes (id,purpose,context); OriginV2.seal_retrieval/5 takes (id,digest,caller,stage_id,context), preserving existing /3 and /4 signatures. Add StageAuthority.prepare_synthesis/4, prepare_setup_synthesis/4, new/6 and new_for_run/6; add RunAuthorization.prepare_setup_synthesis/4. AnalysisV2.analyze/3 permits one separate :source_context option; its :caller remains exactly four keys. Add analyze_prepared/3 and SetupRuns.command/3, threading context through private execution/preparation/publication helpers. Old arities pass nil, never infer context from a callback; managed content denies, unenrolled legacy unknown behavior remains. JSON enumerates remaining body/currentness/compile overloads.

**Bound worker context.** SourceUseContext.setup_analysis(interactive,operation_ref,authorization_ref) validates genuine live interactive credentials, then RunAuthorization.source_use_binding/3 resolves the exact persisted analysis operation, accepted command, owner/workspace/run/session/config/preparation/authorization and disclosure. It factors current/3’s metadata authority checks (no payload hydration or policy recursion): exact reference digests, authorization not revoked, 300-second deadline, live setup phase/current operation, descriptor/consent/budget and prepared references. Existing full prepared-payload validation still runs after policy admission. The returned struct retains the genuine auth and caller plus ONLY the two refs; no worker-asserted owner. Every validation reloads those facts. StageAuthority carries source_context in its existing in-memory struct; final admission/publication also checks StageControl.current, cancellation/deadline and exact manifest/stage equality. No independent unattended principal is introduced: lost/expired session context fails closed and needs fresh authenticated admission; restart does not resurrect it or erase the grant. References alone cannot authorize work.

**Shared SQL.** LocalUsePolicies.not_denied_sql(alias,purpose,context) returns {:ok,{sql,params}} or {:error,code}. Alias allowlist is exactly [r]; purpose is the four fixed values. Validate nonnil context before query; all values use placeholders. Nil context returns a central NOT EXISTS enrollment predicate, so old getters and MCP cannot disclose managed content. Valid context adds the exact active-set/item/owner/purpose checks; setup context additionally restricts references to its checked manifest. Keep other source/currentness/hold predicates. Do not catch errors into allow-all SQL. Passage hydration and legacy body getters call this same owner before selecting text, then recheck before return.

**Ownership/testing.** Add core-owned source_use_context.ex; consumer additionally owns analysis_v2.ex/stage_control.ex/decisions.ex; Root owns setup, PortalLive, CompanyPanel and HarnessDelivery callers, including existing preview/download. JSON assigns exact overloads. Test every old/new arity, fake struct/auth/callback, mismatched caller, expired/revoked run, forged refs, nil-context SQL/MCP/body getter, and async propagation. 

**Exact refresh, superseding permanent freeze.** prepare_refresh/3 records explicit permission to retain bounded updates for review, no use grant. A fresh acquire command consumes its reference once and binds the actual capture. Writer allows changes only to that active set’s existing source identities at the same verified root. New revisions deny all uses until a fresh exact manifest is authorized. Activation atomically CAS-switches every enrollment to the new set, increments generation, supersedes the old set and emits an event. Withdrawal/holds win; stale or withdrawn sets cannot refresh. No automatic rights for future revisions/new sources. Failed capture/review retains disclosed staged bytes without claiming erasure; operator may delete through Purge. Purge preserves a minimal namespace-denial digest; reimport under the same workspace/connection/provider/external identity cannot regain legacy fallback through a new source UUID.
