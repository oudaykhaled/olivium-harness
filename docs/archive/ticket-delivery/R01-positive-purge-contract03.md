# R01 purge/provenance contract 03

**Decision:** detach immutable authorization provenance from deletable acquisition records. Preserve the existing conservative SetupHistory purge of all prepared prompts/configs/commands; do not retain those rows or tombstone every policy. Root adjudicates this correction before integration; this report makes no product edits.

**Schema.** Remove policy-set FKs to capture_runs/setup_run_configs and policy-item FKs to evidence source/revision rows. Remove event source FK. Keep their frozen IDs/digests as non-content historical references, with existing live ownership validation on INSERT/activation. Retain policy-internal set/item/event/checkpoint FKs. Add immutable sets.origin_workspace_id and enrollments.original_source_id, allowing target tombstones to remain attributable after source_id becomes NULL. Add sets.quarantined=false, set true only by offline restore. No sixth table, new grant or permission backfill.

Frozen basis remains the bounded allowlist already produced by capture_basis: capture/config/acquire IDs and hashes, connection/root hashes, capture counters/state, refresh provenance and exact revision manifest. No setup payload, query, prompt, body, source text, arbitrary metadata, full configuration or credentials may be copied. Retained source identifiers/path keys/hashes are restricted authorization metadata, not a claim of total metadata erasure. Live source existence/currentness is checked separately. Historical config/binding digest pins attest what was verified when the grant was created; they do not prove a deleted setup still exists or historical eligibility.

**Source purge order.** Under the existing durable Purge fence and one SQL transaction, call Privacy.LocalUse.before_source_purge(source_id,purge_id) before SetupHistory.purge. Validate frozen policy integrity; tombstone ONLY the target’s enrollment, preserving original_source_id/namespace/generation. Delete unactivated preparations whose setup evidence is being erased; cancel outstanding refresh intents through a non-content privacy-barrier event. Preserve active/withdrawn/superseded sets and immutable manifest metadata. Then run unchanged SetupHistory deletion/cancellation and ordinary corpus/source cleanup. Policy dependencies no longer block those deletes. No unrelated positive grant is revoked. Workspace purge tombstones all namespaces and removes grant detail in FK-safe order, preserving existing workspace-identity restrictions.

**Useful survivors.** Replace active_enrollments’ equality to original item_count with exact classification: each original item has either its matching bound enrollment or its matching original_source_id tombstone. Unexplained missing/mismatched enrollment fails closed. Current grants for surviving exact revisions remain usable after fresh genuine admission; existing setup/model cancellation still applies. Refresh freezes the effective bound-source set only. Its digest/CAS rechecks that same set at activation; it cannot reinclude the purged namespace. Original manifest and policy digests remain unchanged during source purge. A survivor’s new capture has new live binding/config evidence; it need not resurrect the deleted setup.

**Restore.** Privacy.LocalUse.quarantine(query,old_workspace,new_workspace) runs on Snapshot’s copied connection with captured policy triggers temporarily removed and restored. Remap all five tables, recompute namespace identities and workspace-bound preparation/policy digests in predecessor order, retaining old acquisition pins as historical origin facts. Do not rewrite frozen basis to pretend it references newly rehashed setup authority. Set quarantined=true on retained sets; preserve states, generations, tombstones and holds. All managed reads deny until a fresh explicit same-root capture/regrant through the existing refresh action; only previously active sets may be predecessors, never withdrawn sets. Prepared sets and unconsumed refresh intents become unusable. Restore itself grants nothing. Unknown legacy history stays unknown.

**Owners/tests.** Root owns migration, privacy/local_use.ex, SetupHistory/Purge/Snapshot integration and tests. Existing policy owner adjusts integrity/effective-enrollment/refresh checks; consumer owner only honors quarantine. Test A/B independent sets and one shared A+B set: purge A removes all setup copied payloads, preserves B grant/hash, denies A reimport, and permits explicit B refresh. Test crash/replay, corrupt orphan refs, pending cleanup, workspace purge and copied restore: no FK failure, unchanged denial/generation, no restored positive access. Full R01/provider/history/erasure qualification remains open.
