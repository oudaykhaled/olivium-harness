# A04-02 decision 01: Bind setup operations to one authorized run

**Boundary.** Extend Company setup orchestration, Evidence acquisition/manifests, and Models admission/Ledger. Implement one saved project/repository/goal, one approved local connection, FTS retrieval and local synthesis, with durable usage/recovery. Claims remain proposed; claim and plan decisions remain separate. Assistant, critic, diagnostics, cloud, historical acquisition, native execution and subsequent wizard capabilities remain unavailable. Establish reusable shared-budget binding now; do not claim all A04-02 acceptance. Implementation waits for Root’s existing canonical baseline repair, not another approval stage.

**Profile.** Propose `setup-local-synthesis.v1`: current snapshot only; no inferred history/availability; one explicitly selected local connection/root; UTF-8 `.md/.markdown/.txt`; symlinks/unsupported files excluded or fail under existing rules. Proposed maxima: 500 files, 16 MiB aggregate bodies, 1 MiB/file, 10,000 enumerated entries, capture deadline 600 seconds; FTS’s existing 5 searches/100 candidates/24 passages/32,768 evidence bytes/49,152 prompt bytes. Model descriptor comes from configured Ollama loopback destination, with exact model/endpoint/route/credential-reference/prompt/schema/rates, output≤4096 and timeout≤60,000 ms. Inference proposal: two actual sends total, 100,000 tokens, zero estimated cloud microusd, 300-second authorization lifetime. Defaults grant nothing. Fixed profile only initially; policy may narrow, never silently enlarge. Missing/incompatible model remains blocked; no configuration change or cloud fallback.

Capture’s 100-entry/8-MiB batches **do not** enforce aggregate limits (`capture.ex:270–397`; `capture/writer.ex:7–34`). Bind existing CaptureRun to immutable profile and durable counters; check enumeration before frontier insertion and body/file allowance before read/commit, counting duplicate replay once. Resume cannot reset allowances/deadline. Exhaustion is incomplete capture, never successful truncation. Do not substitute `LocalImport.read_all` or build another scanner.

**Public contract.** Keep `SetupSessions.command/2` v1 navigation compatible. Add `SetupRuns.command(envelope,caller)` with exact `{version:1,id,expected_version,command_id,action,payload}`. IDs are UUIDs; caller workspace/operator/session resolved server-side. Actions: `prepare` payload `{profile_version,connection_id}`; `acquire`, `retrieve`, `authorize`, `analyze`, `retry`, `cancel` payload `{config_id,config_digest}`. Retrieval question derives from the pinned saved goal/outcome, bounded to existing query limits; no browser evidence array. `prepare` only proposes/preflights. `acquire` explicitly authorizes the displayed bounded capture; `authorize` explicitly confirms displayed exact disclosure and run limits. Replay `(workspace,owner,session,command_id)` requires identical canonical request digest and returns its stored receipt; conflicts/future/stale versions cause no side effects.

`SetupRuns.get(id,caller)` returns versioned DTO `{version:1,session_version,run_ref,state,blocker,next_action,profile,acquisition,disclosure,usage,operation_refs}`; references are IDs/digests, never control tokens. States: `proposed|acquiring|retrieving|needs_input|ready|running|completed|blocked|cancelled`. Writes/readbacks enforce owner, configuration digest and current context. Ordinary reload never captures, grants or dispatches.

For v2, scope→understanding requires current exact disclosure **and** run authorization; a ready flag alone is insufficient. Selection/configuration changes revoke pending run admission, preserve usage/history and require new preparation. Existing v1 placeholder navigation gains no execution capability. Queries exceeding existing bounds return needs_input rather than silently changing the outcome.

**Persistence.** SQLite migration rebuilds SetupSessions constraint to accept schema 1/2; existing v1 payload/empty refs remain valid. Explicit prepare CAS-upgrades only its owned row to v2, adding nullable `{id,digest}` run_ref; typed operation/decision references are server-written, bounded, never browser-save fields. Add immutable `setup_run_configs` (workspace/owner/session, profile version, canonical effective profile, stable scope hash, digest) and `setup_run_commands` (identity/digest/receipt), plus mutable `setup_run_states` (CAS version, phase, exact capture/declaration/retrieval/manifest/stage/consent/authorization refs). Stable scope hashes include catalog/goal hashes, connection fingerprint and acquisition bounds; postcapture corpus generations belong to refreshed evidence references, not the immutable intent hash. Reject unknown versions/fields. Preserve 16-KiB session bound. Restore remaps references but withdraws authorizations; downgrade refuses v2/authorization data.

Command receipts are immutable accepted-operation references; completion lives in run state. Authorization receipts also preserve exact consent/pin/manifest/context-hash bindings, enabling scoped reuse without treating arbitrary existing consent as context coverage. Capture reference reuse additionally requires the identical profile binding.

**Acquisition and closure.** Preflight verifies saved relationships, bound corpus, active approved directory, current operator and requested bounds; repository selection alone grants no source access. The operator explicitly associates that connection with this outcome. No general acquisition-grant system is asserted. Capture creation, immutable scope binding and command receipt commit together through existing Capture/Oban seams. Workers recheck the binding, cancellation, directory fingerprint and current source restrictions. After complete capture/index readiness, use Requirements and Retrieval to derive the whole authorized connection scope server-side. Reject other active connection memberships; never silently include them. Reseal exact revisions/windows through OriginV2, including R01 holds. Step 2 remains awaiting final consent until this closure exists; metadata preflight cannot pass disclosure admission.

**Consent.** Models exposes `StageAuthority.prepare_setup_synthesis(config_ref,retrieval_ref,prior_stage_ref,caller)` returning persisted stage/manifest references and `reusable|consent_required`. Prior references come only from owned state. Reuse the SAME compatible pin and active consent via `authorize_consent/3`; compare every model descriptor/context field and current source coverage. Initial/mismatched pins are prepared once. Uncovered evidence requires an explicitly reviewed fresh pin and first consent; do not repeatedly grant an immutable revision-1 pin (`stage_authority.ex:137–195,520–539`). Run-budget authorization and disclosure are separate: reuse satisfied consent, authorize only missing limits/disclosure. Changed context/destination cannot reuse a grant merely because source bytes match. Analysis must consume the persisted reviewed manifest, not silently reseal another one; add `AnalysisV2.analyze_prepared(binding_ref,caller)` sharing its existing prompt/dispatch/persist implementation.

Preparation resolves the pin before final `OriginV2.seal_retrieval/4`; only that stage-bound manifest is displayed, granted and consumed. Never authorize an intermediate stage-free closure.

**One budget owner.** Add Models-owned immutable `model_run_authorizations`: workspace/owner/session/config+scope digest, allowed stage descriptors, server-generated budget_id, exact caps, authorized_at/deadline; separate mutable revocation state. Pin IDs can change after new disclosure consent only when descriptors/context remain authorized. `Models.RunAuthorization.authorize(config_ref,caller)` executes only the explicit command and atomically creates this binding plus existing Ledger budget. Allow zero **cost** cap in Ledger; request/token limits stay positive. Never accept budget IDs/caps from browser execution payloads.

Unique `(workspace,owner,session,config_id)` prevents repeated authorization commands from minting another budget. Preparing the same active config reuses its identity. Cancel revokes the run before signalling child operations; it never refunds unknown usage.

Add `StageAuthority.new_for_run(operation_id,manifest_ref,stage_ids,authorization_ref,caller)`; distinct operations persist authorization/budget identity in StageControl and recheck it at admission, mark-dispatching, final HTTP guard and publication. `Ledger.reserve_stage_attempt` resolves that trusted budget, preserving existing settlement/uncertainty. Legacy `new/5` remains outside setup; reject its use for registered setup operations. No reopening operation IDs, per-step fresh budgets, fingerprint padding or automatic retries. New caps require an explicitly authorized new run; no top-up in this slice. Uncertain calls retain reservations across reload/cancel/restart.

**Transactions/recovery.** Purge fence precedes short SQL/CAS transactions. Commit operation intent before releasing locks; perform capture filesystem work, availability probes and HTTP outside SQL/privacy locks, then revalidate before publication. Persist command identity and dispatched operation identity so crash/retry cannot resend. Use existing StageControl restart reconciliation; resumable capture retains its limits. Timeouts/deadlines constrain admission/work checkpoints, not a hard database or end-to-end latency SLO. Usage comes only from Ledger: reported totals, pending/uncertain reservations, remaining caps clamped at zero, overrun separately; local unpriced/cloud estimated are never billing claims.

**Ownership/confirmation.** Models engineer owns RunAuthorization, StageAuthority/Control, Ledger, AnalysisV2 and admission tests. Setup engineer owns SetupSessions/SetupRuns, SetupLive and WEB tests. Root owns migrations/schema records, Capture/Writer limits, Privacy, router/Portal integration and execution. Verify zero unauthorized sends; same-pin reuse without duplicate grant; context/destination/cap changes; two distinct operations exhausting one budget; concurrent/replayed commands; capture replay/limits; R01 hold/revocation between approval and dispatch; restore, unknown usage and local-unavailable recovery. Actual WEB uses public synthetic evidence and real server actions; transport fixtures are tests only. Actual-provider qualification remains separate; no paid/private calls are authorized here.
