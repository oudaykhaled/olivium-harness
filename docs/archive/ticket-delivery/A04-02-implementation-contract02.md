# A04-02 implementation contract 02

**Status/scope.** Frozen proposal replacing decision01’s ambiguous interfaces; independent recheck precedes authors. Deliver one saved repository/outcome, explicitly approved local acquisition, existing FTS, exact prepared local synthesis, and usage/recovery. No assistant/critic/native execution, cloud, historical acquisition, later wizard gates or scale qualification. No new graph, consent or model-budget engine. Claims and plans retain separate approvals. Root controls baseline readiness and execution.

**Types.** All boundary objects use exact string-key allowlists. `Ref={"id":UUID,"digest":lowercase_SHA256}`; versions are positive integers, times server UTC. Unknown fields/versions fail. Canonical digests use `Contracts.canonical_json/digest`; no browser JSON supplies authority. The paired contract-audit02 freezes field inventories, record names and signatures.

**Command.** `SetupRuns.command/2` accepts `{version:1,id,expected_session_version,expected_run_version,run_ref,command_id,action,payload}`; `id` is setup-session ID. Run reference/version are both null only before the first run. Actions/payloads:

| Action | Exact payload |
|---|---|
| prepare | `{profile_version:"setup-local-synthesis.v1",connection_id}` |
| acquire, retrieve, cancel | `{}` |
| authorize, analyze, retry | `{prepared_ref}` |
| new_run | `{predecessor_run_ref}` |

Every action checks current owned run and BOTH versions. Authenticate first; matching stored command ID+request digest returns its original accepted receipt before stale-version rejection. Changed reuse returns `command_conflict`. Receipt is `{version:1,command_ref,action,run_ref,operation_ref,prepared_ref,session_version,run_version}`; optional refs are null. Success is `{:ok,receipt}`. Errors are `{:error,{"code":code,"current":null|{session_version,run_version}}}`; unauthorized/foreign reads reveal no current versions. `get(id,caller)` returns the exact public projection specified in the audit; reads never run work.

`prepare` reuses identical active intent. `new_run` requires the current predecessor in expired/cancelled state, creates a fresh immutable run incarnation and empty preparation/authorization state, preserving predecessor usage/uncertainty. It creates **no budget or grant**. Fixed caps cannot increase; navigation/retry/reload cannot create an incarnation. A completed/exhausted run can be explicitly cancelled before replacement. Selection changes revoke active admission and require preparation, without deleting usage.

First slice permits one capture and one retrieval/preparation per incarnation; analysis retry reuses that preparation. Refresh/expansion requires explicit replacement. `new_run` recomputes the current proposal from saved selection/connection/configured local destination, reusing identical config content when possible, and displays it before confirmation. No operation owns authority merely because its predecessor did.

**Fixed profile.** One current local connection/root, current snapshot only, UTF-8 `.md/.markdown/.txt`, existing symlink/unsupported-file rules. Limits: 500 body files, 16,777,216 body bytes, 1,048,576/file, 10,000 admitted enumeration entries (`max_admitted_entries`), 600 seconds from acquisition acceptance. Existing FTS packing bounds remain. Model: configured non-cloud Ollama loopback only; exact descriptor, zero rates, output≤4096, request timeout≤60 seconds. Authorized model limits: two reservations, 100,000 tokens, zero estimated microusd, 300 seconds from explicit authorization. Two reservations do not promise two successful sends. Missing model is recoverably blocked; no fallback/configuration changes.

**Prepared disclosure.** `StageAuthority.prepare_setup_synthesis(operation_ref,retrieval_ref,caller)` accepts only a registered retrieval operation. Resolve prior pin from owned receipts. Persist immutable preparation containing run/config/retrieval/stage/manifest refs, compatibility context digest, exact checked pack, prompt bytes and request-body bytes/hashes. Resolve/reuse pin first, then seal final stage-bound OriginV2 manifest. Preparation publishes through run-version CAS; it cannot silently replace a displayed preparation. No grant is created.

Compatibility projection is exactly `{version:1,scope:{profile_ref,project_ref,repository_ref,goal_ref,outcome_hash,connection_id,root_fingerprint,history:"current_snapshot_only"},purpose:"company_synthesis_v2",descriptor}`. Descriptor includes stage/provider/model/endpoint/route/credential reference/prompt/schema hashes/rates/output/timeout; excludes generated pin ID and consent revision. Reuse requires equal projection, the SAME owned pin, its active pinned consent revision, and existing `authorize_consent/3` coverage against the new current manifest. Corpus generations and source membership are revalidated separately, never inferred from compatibility. Uncovered scope gets a fresh reviewed pin/first grant; arbitrary legacy grants are not adopted.

`authorize` submits the displayed preparation Ref. Atomically compare it with current run preparation, config/run identity, both versions, current origin, descriptor and limits. A mismatch creates neither consent nor budget. Persist immutable disclosure binding to exact preparation/pin/consent/context. Reuse valid consent without granting again. Scope→understanding requires this current binding plus active run authorization, not a stored ready flag.

**Registration and transactions.** Setup owns `setup_run_operations`. For capture/retrieval/analysis, command identity, immutable operation registration and session/run CAS commit together **before execution**. Operation records bind kind, command, run/config, expected publication version, applicable preparation/authorization and corpus generations. Workers cannot replace refs. `SetupRuns.operation_binding(operation_id,caller)` resolves trusted identity; `publish_operation(operation_ref,expected_run_version,result_ref,caller)` CAS-checks registration/current run and advances run version. Cancellation makes late publication fail. Command replay never re-executes work.

For authorize, insert unique command receipt and perform both CAS writes first inside the transaction; invoke trusted `RunAuthorization.authorize(config_ref,prepared_ref,caller)` only against that accepted command. Consent/disclosure binding, authorization/Ledger creation and ready-state update join the **same** transaction: any failure rolls everything back. No authority escapes before commit. Acquire follows the same atomic pattern using `Capture.start_for_setup/3` below. Observe filesystem/model availability outside transactions; lock ordering is always Purge→SQL. No scan, provider call or worker wait while holding these locks; checkpoints/timeouts are not a hard SQL/end-to-end SLO.

**Models.** Immutable authorization binds workspace/owner/session/run/config/scope, allowed descriptor, server-generated `budget_id` (Ledger `run_id`), exact caps and expiry. Unique `(workspace,run_id)` prevents fresh budgets on reconfirmation. Existing-budget caps must match exactly; never coerce zero request/token caps to defaults. Ledger permits nonnegative cost only; local-only descriptor validation remains independent.

`AnalysisV2.analyze_prepared(operation_ref,caller)` consumes registered stored pack/prompt/body and reviewed manifest—no reseal. `StageAuthority.new_for_run(operation_id,manifest_ref,stage_ids,authorization_ref,caller)` verifies registration before opening StageControl and never calls `Ledger.start_run`. `RunAuthorization.current(authorization_ref,operation_ref,caller)` resolves the sole trusted budget/descriptor. StageControl stores/checks authorization ID, budget ID and operation binding digest. Ledger resolves registered operations to that budget; missing/broken bindings deny, never fall back to operation ID. New retry operations share authorization/deadline/budget and exact body; no fingerprint padding.

Legacy analyze/new reject registered setup operation IDs **or setup-owned pins**, before sealing/budget creation. This closes fresh-ID bypass while preserving unrelated legacy APIs. Admission, final HTTP guard and publication recheck authorization/revocation, exact consent and OriginV2/R01 currentness. Claim/stage completion and Setup publication CAS join one Purge-fenced transaction. Settlement survives denial/cancellation; uncertain reservations remain charged. No automatic resend after restart or ambiguous send. Explicit retry is permitted only after a known settled outcome and remaining capacity; otherwise recovery stays blocked.

**Capture contract.** Root’s `Capture.start_for_setup(config_ref,command_ref,caller)` requires an already-open Setup command transaction and registered capture operation; it joins that transaction, never opens independent work or commits. Create CaptureRun using registered operation ID, immutable profile/fingerprint/deadline binding, counters, frontier and Oban intent atomically with command/CAS. Existing unbound captures cannot be adopted. Workers recheck run cancellation/lease/profile on each page/read/commit.

Acquisition checks active approved connection and selected project’s bound corpus; other active connection memberships block this slice. Complete capture plus index readiness feeds the existing Requirements declaration and FTS path; no manual document shortlist or early disclosure gate. Query text is derived and displayed from the pinned outcome, with overflow requiring input rather than silent truncation.

Unique entry/body charge rows prevent checkpoint upserts from resetting accounting. Reserve new enumeration entries before inserting frontier rows. Before body I/O, stat safely and reserve one file plus the bounded read allowance; Root extends LocalImport’s existing checked-descriptor reader to respect that allowance and recorded file identity. Commit actual bytes, charge state and source publication together under the same live lease. Committed identical replay returns stored evidence without rereading/recharging; changed identity is stale/incomplete, not a free reread. Expired/crashed unresolved reads retain allowances and block that item; this first slice requires explicit new-run recovery, not speculative replay. Resume never renews the original deadline. Exceeding limits produces incomplete capture; retrieval cannot treat it as complete. Existing scanner batches may observe up to 100 entries before admission; rejected entries are not persisted. This is neither a physical enumeration cap nor a filesystem latency promise.
