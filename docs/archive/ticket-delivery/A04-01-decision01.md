# A04-01 bounded implementation contract

**Decision:** Approve two persisted steps—outcome and scope—plus seven-step navigation with honest unavailable capabilities. This is partial AC5 delivery, not seven-step AC1 completion. A02-01’s versioned measurement producer is not established by the inspected code: existing saved goals may be pinned, but measurement status stays unknown; do not invent a contract revision or claim measurable benefit.

**Identity/storage.** Introduce `HarnessForge.Company.SetupSessions` and `SetupSession`, using existing SQLite/Repo/Store, validation conventions, audit and workspace privacy fence. Persist UUID, server workspace, server owner, schema_version1, lock_version1+, step, bounded JSON payload and timestamps. Owner is `Workspaces.operator()` = `"local-operator"`, only after validating the existing server caller authorization callback. This is workspace-local operator ownership, not named-user isolation. Never persist auth epoch/digest/view generation as owner; fresh authentication can reopen the same record. Capture workspace once; check caller/workspace again inside the transaction and before returning. URLs confer no authority.

**Exact public API (proposed, not existing).** `create(%{}, caller)`, `get(%{"id"=>uuid}, caller)`, `list(%{}, caller)` (latest20 metadata-only), `command(envelope, caller)`. Create is explicit, never a mount side effect. Caller uses the existing four server-built keys, never browser input. All external envelopes/DTOs are string-keyed. Envelope exact keys: `"id"`, `"expected_version"` (positive integer), `"command"`, `"payload"`. Commands:

- `"save"`: payload exactly `{"draft": map}`; persists a bounded working draft, without approving or creating domain records.
- `"change"`: payload exactly `{"selection": map}`; replaces acknowledged selection after validation; clears dependent session references, never domain records.
- `"back"`, `"continue"`: payload `{}`; move one fixed step, requiring current applicable prerequisites for forward movement. Never save an unsent form implicitly.

Selection allowlist: `profile`, `project`, `repository`, `goal` (each null or exact `{"id","content_hash"}`), `corpus_id` (null/UUID), `declaration` (null or `{"id","digest"}`). Null explicitly clears. Validate present references on change; incomplete selections remain needs_input. Draft allowlist: `outcome_note`≤2048 UTF-8 bytes, `scope_note`≤2048; total encoded payload≤16KiB. Reject unknown/non-string keys, malformed IDs/hashes, forged completion/approval/owner/operation fields; never create atoms. Operation/decision references are server-only reserved empty lists in this increment, not client-writable authority.

Return `{:ok, dto}` or `{:error, %{"code"=>fixed_string,"fields"=>map}}`; conflict additionally contains `"current"=>authorized_dto`. DTO exact keys: `id,version,step,selection,draft,steps,next_action,reference_status,updated_at`. Codes: invalid_input,not_found,unauthorized,conflict,stale_reference,unavailable,capability_unavailable. No foreign-record existence disclosure. Commit before saved acknowledgement. Use Ecto3.14.2 optimistic_lock or equivalent SQL workspace/owner/id/version CAS; translate stale writes after rollback, reread authorized current state, preserve local edits visibly. Duplicate stale navigation conflicts, never advances twice.

**Validation/navigation.** Fixed steps: `outcome,scope,understanding,review,candidate,evaluation,release`. Validate repository membership, assigned goal and exact profile/project/goal hashes; corpus/declaration through existing scoped APIs and `Requirements.context/summary`. Revalidate access, semantic/authorization generations and declaration revision on reads/commands. Preserve historical pins as stale; never silently rebind. Revoked references are redacted/unavailable; DB failure is unavailable, never empty success. Scope changes invalidate dependent references. Purge fence precedes DB transaction; no worker/provider waits inside it.

Outcome→scope requires current profile/project/repository/goal pins; unknown measurement remains explicitly draft. Scope→understanding requires a current selected corpus/declaration; it opens the unavailable shell, never analysis. Back remains possible from stale state to repair selections. Other forward transitions reject capability_unavailable. Persisted step is navigation only. Derive next_action `{code,reason,bound_ids,focus}` from existing Guide/readiness, preserving independent claim/plan decisions. Shell steps3–7 show capability_unavailable until integrated, regardless of saved artifacts; existing qualified workflows remain separate links. No consent, capture, synthesis, build or approval from navigation. A04-02 retains exact-manifest grants/destination/budget admission ownership.

**WEB/ownership.** Service author: new setup_sessions.ex/schema and domain tests. WEB author: new setup_live.ex and LiveView tests; seven allowlisted `/setup/:id/:step` views, first two editable. Root: migration, router, CompanyPanel/Portal entry/restore integration, Privacy.Purge deletion list, Privacy.inventory table entry and Privacy.Snapshot quarantine remapping. No overlapping edits. Resolve scope from authoritative get, never route claims; GET cannot advance state. Restore selections after refresh/reauthentication without replaying commands. Preserve Guide and existing dirty/stale guards.

**Verification/open limits.** Test real DB restart/remount/reauth restore, two-tab CAS/replay, forged owner/workspace/keys/references, changed generations/access, failure rollback, purge/snapshot quarantine, and zero dispatch. Test actual early clicks/loading behavior; waiting for connected DOM does not fix the open A03 interaction bug. Keep that defect explicit until repaired. Root owns integration/runtime verification. No implementation or acceptance is claimed here.

## Addendum: saved coverage choice

Accepted: Root owns additive `Requirements.saved_choice(corpus_id,project_id,goal_id,goal_hash,caller)`, exposed as `Corpora.requirements_saved_choice/5`, plus focused tests. Run within existing `Corpora.guard`, current_context and privacy-fence/transaction ordering. Query exact server workspace/corpus/project/goal/current expected revision, explicit LIMIT1; validate the candidate with existing checked_summary(id,digest). Return `{:ok, []}` only for a valid context with no saved declaration, otherwise `{:ok, [metadata]}` where metadata has exactly string keys id,digest,revision,inserted_at. Preserve stale/unavailable/auth errors; never flatten failures into empty choices.

Existing checked_summary reads declaration payload internally for validation; this is not a payload-free validation promise. Return no declaration entries, source bodies or authority. UI starts blank, labels “Saved coverage revision N,” and requires explicit selection; missing choices link to existing corpus review. Saving still revalidates exact pins; no automatic successor selection or rebinding.

Allow internal `scope_pin` from server-returned Requirements.context(scope+expected): server-only persisted metadata, not exposed as a DTO field; `reference_status` conveys currentness. Reject it in client command keys; stale pins remain historical, never permission. No consent/dispatch or policy subsystem added. Tests cover absent/current/stale/wrong-scope/revoked/DB-failure outcomes. Root also integrates Privacy inventory and existing snapshot quarantine; do not duplicate revocation machinery.
