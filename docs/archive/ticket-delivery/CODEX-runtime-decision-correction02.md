# Correction02: meter native Ollama Responses

**Decision:** Supersede the proposed Responses-to-Chat codec. Forward validated native Responses through existing Relay → Runtime → Ledger to the pinned local Ollama `/v1/responses`; preserve OpenCode's Chat path.

Ollama v0.40.14, commit `9a3e8177767245acc62b735eba7d5d8a553606d0`, already converts function calls/results, handles namespaces, emits function-argument SSE events and terminal token usage. Its request schema does not implement arbitrary `tool_choice`. [Pinned implementation](https://github.com/ollama/ollama/blob/9a3e8177767245acc62b735eba7d5d8a553606d0/openai/responses.go). Middleware emits `response.failed` after in-band generation errors. [Middleware](https://github.com/ollama/ollama/blob/9a3e8177767245acc62b735eba7d5d8a553606d0/middleware/openai.go). The route also includes cloud passthrough; compatibility is not local-only authority. [Route](https://github.com/ollama/ollama/blob/9a3e8177767245acc62b735eba7d5d8a553606d0/server/routes.go).

**Smallest seam:** add `Runtime.responses(scope, body)` and a Responses validator/usage parser, not a semantic tool translator. Extend the bounded raw HTTP collector to retain status/content-type and SSE bytes. Buffer within fixed byte/event/count/deadline limits; validate the complete event sequence, reconcile, recheck source/currentness, then return original validated bytes. No reconstructed successful response. This avoids publishing tool calls before validation; latency is an explicit tradeoff.

Allow only exact POST route, selected immutable local model, bounded text/history and preflight-approved client function tools/namespaces. Validate call/result correlation. Pin `stream=true`, `store=false`, output/context limits and supported defaults. Deny nondefault unsupported tool choice, server tools/search, remote models/continuation, background/conversation state, compaction, arbitrary media/URLs, unknown fields and redirects. Strip inbound authorization; relay capability never reaches upstream. Exact Codex 0.156.0 requests remain the compatibility gate.

Reserve before each actual attempt; disable HTTP retries, separately charge client retries. Reconcile failures and disconnects conservatively. Require one consistent terminal completion, integer usage, valid offered tool names and ordered IDs; missing usage, malformed/truncated/error streams or ambiguous output-limit exhaustion never qualify. Cancel/revoke stops publication and retains uncertain accounting.

Test full tool round-trip, namespaces, malformed SSE, HTTP-200 errors, unknown usage, budget/limit exhaustion, revocation and retry accounting. Root's ≤3GB download/6GB disk-reserve bounds remain; Qwen metadata establishes a candidate, not installed availability or task success. Real isolated execution and matched benefit remain unverified.
