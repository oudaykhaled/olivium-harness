# Native shell startup facts 06

**Decision: reject a SHELL-only fix. Separating the unmodified CLI package from private controller files addresses the observed /opt collision, but is not yet a complete startup fix: the pinned source also exposes a CODEX_HOME helper conflict. Task argv remains blocked.**

Root136’s retained zero-turn diagnostic rejects the bundled zsh path against managed filesystem restrictions before initialization. This is not evidence that a model selected zsh.

At pinned commit `fe74a774532af67b5a4a3dec03ce9469e17f89af`, core selects `default_zsh_path.or_else(InstallContext::current().bundled_zsh_path())` independently of shell-tool/fork flags. It then adds this helper path as readable and validates the resulting profile against managed deny-read constraints. Hence disabled zsh-fork does not prevent the collision. [Selection:3975–3977](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/config/mod.rs#L3975), [helper roots:514–539](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/config/permissions.rs#L514), [validation:4072–4173](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/config/mod.rs#L4072).

`default_zsh_path` is an internal Rust ConfigOverrides field, not a demonstrated TOML or thread/start setting. The public ConfigToml has shell-environment policy and allow-login-shell, but no zsh-path selector. Do not invent `zsh_path`, substitute bash as patched zsh, or rely on a retired feature. Bundled resource discovery returns an existing file from the native package layout. [Internal field:2600](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/core/src/config/mod.rs#L2600), [resource lookup:208–237](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/install-context/src/lib.rs#L208).

On Unix, ordinary default-shell detection reads the current UID’s passwd entry through getpwuid_r, then searches supported shells/PATH; Linux falls back to bash before zsh. It does not read SHELL here. Existing child `shell_environment_policy.set.SHELL="/bin/bash"` does not govern bundled-helper discovery. If exact /bin/bash selection later requires it, a source-owned image passwd entry is a separate verifiable image choice; environment/info must confirm the result. [Detection:61–119,192–212,346–368](https://github.com/openai/codex/blob/fe74a774532af67b5a4a3dec03ce9469e17f89af/codex-rs/shell-command/src/shell_detect.rs#L61).

Root’s proposed layout is appropriate for the observed collision: install the same integrity-pinned npm CLI under `/usr/local/lib/harnessforge-codex-cli`; retain trusted controller/preflight files under denied `/opt/harnessforge-codex`; pin native executable/PATH, image receipt and source hashes. Keep all managed denied paths, nonroot/read-only container settings and native sandbox requirements. No Codex fork or second runner is needed for that separation.
