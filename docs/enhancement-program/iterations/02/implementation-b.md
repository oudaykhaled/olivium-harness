## Focused-control privacy reset correction

Independent review found that a changing outer wrapper ID does not guarantee erasure: installed LiveView 1.2.13 reuses keyed descendants and protects focused inputs. That wrapper alone is not accepted evidence.

The minimal correction threads a server reset generation into all nine fixed Company forms. `LiveSocket.dom.onBeforeElUpdated` acts only on an increasing valid generation for a compiled form ID. Before descendant morphing, it synchronizes live values and defaults, checkbox checked/defaultChecked and select selected/defaultSelected from the incoming server form. Controls absent from that incoming form are cleared while awaiting removal. It synchronizes both the supplied form (which can be a private locked clone) and the connected fixed-ID form if different, including their generation attribute. Same-generation refresh and typing are untouched. No per-input selector, new dependency, browser storage or debounce infrastructure was added. Forms absent from the authoritative reset DOM are removed; this is not physical browser-memory erasure.

Static inventory passed for nine fixed form IDs, all eight B form generation attrs, private-clone/connected synchronization and increasing-generation guard. No Mix/browser was run by B. Guardrail accepted this mechanism before code, with final acceptance dependent on runtime evidence.
