# Proposal 06 — Company guidance at narrow widths

**Evidence.** The saved desktop screenshot shows the first Company form below the heading, four metrics and workflow banner; the DOM lists seven full setup sections ([baseline](../../../../../tmp/enhancement-program/01/browser/company-dom.txt), [screenshot](../../../../../tmp/enhancement-program/01/browser/company-before-ux.png)). At ≤650 px, `app.css:122` hides `.workflow` and makes the sidebar a horizontally scrolling row; `app.css:196` stacks Company fields. The four metrics remain in two columns. `CompanyPanel.render/1` (`company_panel.ex:543`) mounts catalogue and plan forms together. The workflow marks “Connect sources” complete unconditionally and “Awaiting a decision” counts only claims (`portal_live.ex:980-991`); the baseline has a proposed plan but displays zero. The five retrospectives recommend guidance while retaining policy, qualification and authority gaps.

**Decision.** Put a saved-state Company summary before the forms: one primary next action linked to its section/control, separate pending claim and plan counts, and a short blocker. At narrow width, show the current task first; use accessible disclosures for the other sections. Preserve the seven-section sequence and exact-revision decisions. Keep goals and milestones optional. On error, open the affected section and focus its error summary without clearing drafts. Never infer buildability, runtime readiness or qualification from package presence.

**Acceptance.** In native Chrome at 320, 375 and 650 CSS px, empty, partial, proposed, rejected, approved and stale synthetic states show one usable next action, accurate counts and no horizontal document overflow. Keyboard navigation reaches the next control and every disclosure; focus remains visible after LiveView updates. At 200% zoom, text and controls remain usable. Expansion and status updates avoid visible layout jumps; compare screenshots at each width. Establish baseline measurements before performance claims; target field p75 CLS <0.10 and INP <200 ms if available. No browser or field measurement was run for this proposal.

**Risks.** Collapsing forms can hide errors or disrupt focus and drafts; error expansion and state-preserving LiveView updates are required. Keep the action in normal flow so it cannot obscure controls. Disclosure alone is simpler but leaves the misleading summary unresolved.
