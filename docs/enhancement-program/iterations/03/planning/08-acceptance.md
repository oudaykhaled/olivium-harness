# Acceptance proposal: exact-artifact qualification readiness

**Recommendation.** Deliver a read-only readiness projection for one selected company artifact, with ordered blockers and evidence identities. It answers “what prevents qualification of these exact bytes?” without treating export, static integrity or a synthetic run as company fitness. [Company.build_inputs/1](../../../../../lib/harness_forge/company.ex), [Harnesses.eligible/1](../../../../../lib/harness_forge/harnesses.ex), [Evaluations.applicability/2](../../../../../lib/harness_forge/evaluations.ex) and [Releases.Validation.check/3](../../../../../lib/harness_forge/releases/validation.ex) already encode the gates. Report each independently; never mutate approval or release state.

**Falsifiable contract.** Given a valid approved plan and built artifact, readiness names its digest, plan revision, scope, runtime/model, suite/grader/environment identities, most relevant run ID, observed outcome and cleanup status. Static integrity passing with `runtime_qualified: false` remains “integrity passed; qualification blocked”; [company acceptance](../../../../../test/harness_forge/company_acceptance_test.exs) already proves `Releases.approve/1` refuses that run. A missing model, unsupported managed runtime, unavailable Docker, failed protected check, cancelled run, incomplete cleanup, changed runtime image/model/suite/config, stale plan or revoked source each yields a specific blocker and safe next action. A current passed qualified task with complete cleanup may report “release-admissible” only if the same validation used by `Releases.approve/1` succeeds; it must not claim representative company success. Requery after any identity or authority change must replace the prior status. No caller-supplied outcome may influence the projection, consistent with [evaluation option rejection](../../../../../test/harness_forge/evaluations_test.exs).

**Negative controls and verification.** Assert isolation across two packages and workspaces; A’s passed run cannot ready B. Static/smoke passes, synthetic blocked task, altered run identity, failed grade, pending cleanup and stale plan cannot advance. Preserve an eligible predecessor when a successor is merely proposed. Compare projection against direct `Validation.check/3` errors and the persisted run. Run focused Company/evaluation/release tests, then canonical `mix test`; iteration 02’s **417 unique passes** are historical baseline, not a new result. Run the 15 Docker fixtures only if isolation, execution or cleanup code changes; Docker was available and exercised in iteration 02.

**Scope decision.** Goal-origin policy and declared conflict resolution offer higher policy completeness but require versioned authority, migration, purge/restore and immutable-export compatibility. Portable signed approval also needs trust/revocation and clean-import semantics. Both deserve later dedicated acceptance. This readiness slice does not solve either, and live company/model qualification remains unproven.
