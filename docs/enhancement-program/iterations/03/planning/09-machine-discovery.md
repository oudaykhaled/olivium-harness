# Proposal 09 — Exact evaluation readiness in MCP package inspection

**Recommendation:** extend the existing read-only `harnessforge_inspect_package` call with an optional exact `evaluation_id`, after the domain readiness projection is defined. This gives a machine client a useful answer to “what blocks this package from qualification?” without creating another authority path. It is a bounded companion to the iteration-03 qualification-readiness candidates, not a reason to choose MCP work ahead of the shared domain gate. UX, trust and quality retros prioritize exact-artifact readiness; product and architecture prioritize missing policy authority instead ([handoff](../../02/handoff-to-03.md), [UX](../../02/retro/02-ux.md), [trust](../../02/retro/04-trust.md), [quality](../../02/retro/05-quality.md), [product](../../02/retro/01-product.md), [architecture](../../02/retro/03-architecture.md)).

**Observed gap.** The MCP endpoint already authenticates a local bearer, holds the privacy fence and exposes three fixed read-only tools ([auth](../../../../../lib/harness_forge/mcp/auth.ex), [transport](../../../../../lib/harness_forge_web/plugs/mcp.ex), [tools](../../../../../lib/harness_forge/mcp/tools.ex)). Package inspection verifies bytes and current eligibility but always says `qualification: "not_assessed_by_this_tool"`. Existing evaluation applicability binds artifact, runtime, model, suite and environment identities; release validation requires a passed qualified task run and complete cleanup ([evaluations](../../../../../lib/harness_forge/evaluations.ex), [release gate](../../../../../lib/harness_forge/releases/validation.ex)).

**Interface.** Accept `{"digest":"<64 lowercase hex>","evaluation_id":"<UUID>"}`; `evaluation_id` is optional. Preserve the current response when omitted. When supplied, append `evaluation_readiness: {evaluation_id, status, blocker_code, next_action}` with `status` one of `qualified_for_release_gate`, `blocked`, or `unavailable`. The status is an observation of existing gates, never approval or promotion. `next_action` is a fixed portal destination, not free-form evidence text. A nonexistent, foreign-workspace or revoked run returns the same generic `unavailable` response. Do not disclose run payloads, task bodies, model prompts, source text, credentials or actor identity.

**Acceptance:** exact matching passed/qualified/clean runs report gate-ready; missing, failed, cancelled, stale-identity, ineligible-package and incomplete-cleanup cases stay blocked or unavailable with stable codes. Recheck eligibility and applicability on every call under the privacy fence; a later build/release still repeats admission. Assert no database/artifact mutation and no private sentinel in JSON or logs. Keep request/response caps and the existing MCP `2025-11-25` client contract. Synthetic fixtures prove projection behavior only; real company fitness and portable approval remain unproven ([MCP guide](../../../../../docs/mcp.md)).
