# Product intent: admit goal-origin company rules

**User job.** A company engineering owner needs to turn a desired change into reviewed instructions without pretending the change was observed in historical source material. Today [Goals.add_goal](../../../../../lib/harness_forge/goals.ex) saves an owner and acceptance statement, and [Company.resolve](../../../../../lib/harness_forge/company.ex) scopes selected goals into an immutable plan snapshot. Yet [Evidence.create_claim](../../../../../lib/harness_forge/evidence.ex) requires citations, [Decisions.decide](../../../../../lib/harness_forge/decisions.ex) validates them again, and [Harnesses.specification](../../../../../lib/harness_forge/harnesses.ex) emits every rule with `goal_id: nil`. A goal can influence roadmap data, but cannot become an approved normative rule through the current authority path. The [harness contract](../../../../../lib/harness_forge/contracts.ex) already allows a rule supported by a goal rather than evidence; the application does not yet supply that path.

**Bounded change.** Add an explicit `future_goal` claim basis alongside existing `historical_evidence`, pinned to one workspace goal's immutable content digest. Keep exact claim revision approval and exact plan approval. Let an owner declare conflict pairs between proposed rules and record an exact resolution before either can enter an approved plan. Expose basis, goal acceptance, conflict and resolution status at proposal and decision points. Extend the existing claim, decision, plan-admission and compiler interfaces with versioned fields; preserve historical claim/artifact bytes and existing eligible predecessors. The schema already names `rationale_kind`, `goal_id` and `conflict_ids` in [records-v1alpha1](../../../../../priv/schemas/records-v1alpha1.json), but persistence and admission must make their authority real.

**Acceptance.** Given a scoped goal and a separately approved goal-origin claim, an exact approved plan builds a rule bearing that goal ID with no fabricated citation. A historical claim still requires valid citations. An undeclared conflict is outside semantic detection; a declared unresolved pair, cross-workspace goal, stale goal digest, rejected claim, or changed resolution blocks plan approval/build/export with a specific reason. Resolving a pair and renewing exact approvals permits only the selected rule. Existing approved artifacts remain byte-verifiable and do not acquire new authority.

**Risk and priority.** Versioned persistence, purge/restore, stale revision handling and immutable output need focused regression evidence. This proposal does not establish real-model company fitness or portable authenticated approval. Qualification-first and portable-authority-first remain credible alternatives in the [iteration 02 handoff](../../02/handoff-to-03.md); select among them using user value, scope and testability, rather than retrospective vote count.
