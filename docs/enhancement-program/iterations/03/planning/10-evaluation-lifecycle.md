# Proposal 10 — exact-artifact qualification readiness

**User benefit.** An engineering owner selecting a Company package should see why it cannot enter a pilot release, without interpreting passed integrity as model qualification. This is a functionality improvement, not a company-fit verdict.

**Evidence.** `Harnesses.get/1` verifies stored package bytes; `Harnesses.eligible/1` rechecks the approved plan and current source authority. `Evaluations.run/2` persists `pending`, `running`, `blocked`, `failed`, `cancelled`, `interrupted` and passed outcomes; `cancel/1` and `reconcile/0` preserve separate `cleanup_status`. `Evaluations.applicability/2` compares current suite, grader, fixture, image, version, environment, config, capability, policy, scope and model identities. `Releases.Validation.check/3` admits only an applicable, completed, qualified passed task with complete cleanup and supported required controls. `Releases.approve/1` rechecks that gate transactionally. The current `synthetic-go-v1` suite and Docker fixtures do not prove real company outcomes; the live model route is unselected in ordinary tests.

**Change.** Add read-only `HarnessForge.Evaluations.readiness(artifact_digest, evaluation_id \ nil)` returning `{:ok, %{artifact_digest, evaluation_id, stage, blockers, next_action, identities}}` or a typed lookup error. Resolve only workspace-owned records. Show separate stages for artifact integrity, current Company eligibility, runtime/model availability, task observation, cleanup and release admission. Derive blockers from existing domain checks; never accept caller-supplied outcome or qualification. Expose the projection beside the exact artifact/evaluation selectors in Evaluations and Releases. A passed static or smoke run can advance its named stage only. No release approval is written by this query; approval continues through `Releases.approve/1` with fresh validation.

**Falsifiable acceptance.** For one eligible digest, static pass, blocked task (`model_not_selected`), failed task, cancelled task, interrupted/`cleanup_failed` task and mismatched suite/model digest each return a distinct truthful blocker and safe next action. A stale or revoked plan blocks regardless of old passed evidence. A deliberately privileged qualified fixture may show release readiness, but the UI labels its provenance as fixture-only in tests; `Releases.approve/1` remains the authority. Change artifact digest or runtime identity and readiness falls back to blocked. Check read-only behavior by comparing run/release counts before and after projection.

**Risk.** A cached readiness display could become stale between viewing and approval. Compute on demand, include inspected identities, and retain transaction-time release validation. Keep readiness wording separate from representative company-task success, which still requires an authorized live pilot.
