# Runtime truth for an exact harness

**Functionality proposal.** Add an exact-artifact eligibility report that answers “What can I run now, why, and what evidence would change this?” for a selected package digest. The read path should combine saved artifact/plan identity, current `Harnesses.eligible/1`, `Compiler.verify/1`, `Adapters.Registry.list/0`, and persisted evaluation runs; it must not start a model, Docker container, or probe on page render. Return separate `export`, `integrity`, `current_eligibility`, `managed_runtime`, `task_evidence`, and `release` states with stable reason codes and one corrective action each. A dedicated operator-initiated refresh may call `Evaluations.capabilities/0` once and record timestamp/result; bound concurrent refreshes and show “not checked” when absent or expired. Do not translate an unresponsive probe into “qualified.”

The registry advertises export for OpenCode, Codex and Claude, but sets `runtime_qualified: false`; only OpenCode has `opencode_docker` and other managed backends are `unavailable` ([registry](../../../../../lib/harness_forge/adapters/registry.ex)). Each adapter’s `probe/1` reports unavailable, including OpenCode’s preview probe ([OpenCode](../../../../../lib/harness_forge/adapters/opencode.ex), [Codex](../../../../../lib/harness_forge/adapters/codex.ex), [Claude](../../../../../lib/harness_forge/adapters/claude_code.ex)). Actual OpenCode task availability requires selected local Ollama model, authorization, service and pinned Docker images ([Coding.availability/0](../../../../../lib/harness_forge/execution/coding.ex)). `Evaluations.run/2` blocks non-OpenCode task execution; applicability binds artifact, runtime, model, suite, configuration and environment identities ([Evaluations](../../../../../lib/harness_forge/evaluations.ex)). Release admission additionally requires a passed qualified task, complete cleanup and matching controls ([validation](../../../../../lib/harness_forge/releases/validation.ex)).

**Acceptance.** Positive: an exact OpenCode package with current approval, verified bytes and an applicable completed qualified task displays the run ID and release eligibility. Negative: stale plan, altered digest, missing model/image, Codex/Claude preview, cancelled or failed task, incomplete cleanup and changed suite/model/profile each produce a distinct blocked state and safe next action. Static integrity and offline smoke remain explicitly insufficient. A short runtime root must keep the Unix relay socket below **104 bytes**; an overlong path is a visible blocker, never host execution or another provider ([relay](../../../../../lib/harness_forge/execution/relay.ex)).

**Trade-off.** Policy-first work could complete goal authority and conflicts; portable signed approval could support import trust. Both matter, but neither tells an operator whether this exact artifact has an executable, evidenced path today. Risk: stale cached readiness; mitigate by pinning digest/identity inputs, timestamping observations and repeating domain admission at evaluation/release actions. This report makes eligibility actionable without claiming real-company outcome qualification ([handoff](../../02/handoff-to-03.md)).
