# Iteration 14 proposal 02 — contextual prerequisites

**User/job/hypothesis.** A company operator entering corpus review needs to establish an authorised captured connection, saved project and assigned future goal, then ask a question without hunting through unrelated tabs. Success is uncoached completion of the public corpus-to-reviewed-export journey with no manual per-document assignments; the hypothesis fails if operators still stall at an empty selector or mistake a saved goal for analysis authority. This is an iteration 14 UI candidate, not a claim that novices or model effectiveness have been measured.

**Direct frozen-source observations.** `lib/harness_forge_web/components/company/corpus_review.ex:39-97` leads with “Choose what to inspect” and renders empty-choice text without prerequisite actions; the capture/question pipeline is conditional after scope opening (`:551-599`, `lib/harness_forge_web/live/corpus_review_live.ex:779-789`). `CorpusReviewLive` loads connection/project choices at mount and goal choices after project change (`:20-34`, `:675-748`); changing scope clears large evidence state and rotates generation (`:665-710`). `lib/harness_forge/company/corpus_review.ex:156-177,392-410` requires an active connection, saved project and assigned goal with exact goal hash. Existing creation/navigation seams are `CompanyPanel` project save/new and `company_navigate` (`lib/harness_forge_web/components/company_panel.ex:297-307,402-429`), `Goals.add_goal/1` (`lib/harness_forge/goals.ex:13-33`), and the portal goal form/tab and corpus route (`lib/harness_forge_web/live/portal_live.ex:590,721-750,2834-2860`). A Company profile already links to Connections and Goals when empty (`lib/harness_forge_web/components/company/catalog.ex:84-117`). These are bounded reads, not a whole-codebase review.

**Root-reported runtime evidence.** The iteration 13 handoff reports a public synthetic eight-file export with separate claim/plan approvals and static integrity PASS; representative task evaluation was BLOCKED `model_not_selected`. Saved Main screenshots reviewed by the usability retrospective reportedly lacked a contextual project-creation action. I did not reproduce browser behavior.

**Inference and smallest scope.** Put a compact “Prepare this scope” section before inspection: state which prerequisite is absent, link to the existing Connections, Company project and Goals entry points, and explain that a goal must be assigned to the saved project/profile before it appears. Preserve the selected context where safe on return, but require fresh scope opening; no implicit creation, assignment, approval or provider dispatch. Reuse the existing empty-choice DTOs and portal navigation. This helps discovery without introducing workflow authority. An alternative is a new wizard (more guidance, more state and stale-context risk); static help text is cheaper but leaves the operator to find the action.

**Acceptance checks.**

- Given no project, when corpus review opens, then an action reaches existing Company project creation and return shows the newly saved choice after refresh.
- Given a saved goal not assigned to the selected project/profile, when scope is opened, then it remains unavailable and the UI explains the assignment step; no scope token or analysis is created.
- Given multiple projects and paginated choices, when a different project is selected, then goal choice clears, only its assigned goals appear, and old run/passage/synthesis controls stay cleared.
- Given an unsaved Company draft, when navigating to corpus review, then the existing save/discard refusal remains visible; a retry after resolving the draft succeeds.

**Ownership/risk.** UI owner for corpus component and LiveView; portal/Company routing needs Root integration. Verify focus, keyboard path and stale generation in packaged browser. Defer relevance ranking, Graphiti, scale and model-backed evaluation to functionality 15.
