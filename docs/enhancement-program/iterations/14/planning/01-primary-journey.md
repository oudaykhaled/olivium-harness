# Primary Company → corpus journey proposal

**User/job/hypothesis.** A company operator with an authorised directory, saved project and future goal needs to turn corpus evidence into reviewed, exported guidance without guessing which Company route to take. Success: in a five-person first-use study, at least four complete the existing public synthetic capture → question → evidence → correction/claim approval → separate plan approval → export path without coaching or manual per-document assignments, and all five distinguish static integrity from representative task success. Falsifier: route choice or prerequisite recovery prevents completion, or an operator calls a blocked task evaluation successful. This is a proposed gate, not measured usability.

**Direct frozen-source observations.** Company opens with a secondary “Browse captured corpus evidence beside a saved goal” button, then renders the saved-record guide and legacy setup/analysis before plan and assessment (`components/company_panel.ex:1313–1404`). The guide's next action is derived from profile → repository → project → approved claim → plan, and its evidence instruction points to manual assigned sources (`components/company/guide.ex:146–225`); it does recognise v2 claims without legacy source assignments (`:113–120`). Corpus renders inspection first and the actual capture/question pipeline below it (`live/corpus_review_live.ex:786–792`; `components/company/corpus_review.ex:25–100,551–601`). Candidate rows expose lane/relation and an identical “Inspect exact passage” action; the source title appears only in the opened passage (`corpus_review.ex:609–634`). The question/mode form has no displayed draft binding (`:578–599`). Failed replacement clears prior evidence handles (`corpus_review_live.ex:343–380`).

**Root-reported evidence.** Iteration 13's browser record, as described in the handoff, reached eight actual exported files after separate claim and plan approvals. Static integrity passed; representative task evaluation was blocked by `model_not_selected`. No uncoached novice or real-company effectiveness was measured.

**Inference and options.** The competing inspection-first and saved-record routes plausibly make the corpus builder hard to discover. Option A, preferred: on Company, present one prominent “Build from company evidence” entry with a short saved-state journey and contextual actions for missing connection/project/goal; order corpus capture → question → candidate review before the existing inspection/original-report material. Reuse `Guide.project`, `CorpusUI.pipeline`, existing route and approval controls; keep the legacy workflow accessible for existing packages. Advantage: smallest connected information-architecture change; risk: route handoff and draft preservation need careful checking. Option B: merge the entire corpus pipeline into Company. Advantage: fewer page transitions; cost: substantially larger LiveView state and regression surface. Do not alter retrieval ranking or claim semantic completeness in this UI round.

**Acceptance examples.** Given valid saved prerequisites, when the operator opens Company, then the corpus path leads to capture, question and named provisional evidence with a visible route to exact claim review, separate plan approval, export and evaluation. Given a missing project or goal, when they enter the path, then a contextual action identifies the missing saved record and returns to their work without implying approval. Given a failed replacement question or unavailable graph/model, when the attempt ends, then old evidence/claim controls stay cleared, the entered question and mode remain available for correction, and the recovery message names the relevant setup step. Given a completed export with blocked task execution, then the interface presents “exported/static PASS” and “task BLOCKED” distinctly.
