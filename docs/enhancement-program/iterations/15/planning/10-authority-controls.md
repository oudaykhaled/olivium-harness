# Authority controls for dependable web retrieval

**Proposal.** Correct the demonstrated nine-content-term question failure within the existing browser corpus-to-harness journey. Treat retrieval as evidence selection, never as authority to change source access, provider/model, consent, budget, cancellation, claim approval, or plan approval. The current `Retrieval.query_plan/2` keeps the first four and last four distinct content terms after eight, dropping a middle “policy” term. Public browser records show the long question returned three passages without policy; a focused question returned four including policy. This is one reproduced miss, not a population recall estimate.

**Bounded selection.** Compare three candidate corrections on independently authored public development cases before choosing one: (A) retain all question terms within an explicit query-byte/term bound; (B) split the question into capped subqueries with deterministic deduplication and a fixed total search cap; (C) keep the query but adjust existing lane packing to reserve indispensable policy/contrary material. A is simplest but may dilute FTS5 rank; B may recover dispersed terms but increases searches and fusion complexity; C cannot recover a source absent from all candidate sets. Keep SQLite FTS5 as baseline and current `Retrieval`, checked `Passages`, and versioned `OriginV2` seams. The pinned Graphiti 0.31.2 native Jev integration remains optional under its existing authority path; no new engine or silent mode fallback.

**Authority invariant.** Apply `Corpora` scope and current-generation guards before each candidate query and publication; keep connector document scope before FTS `MATCH`. Every selected passage must pass exact current source/revision/hash/UTF-8-window checks. Seal the retrieval run and all prompt-influencing dependencies before synthesis. `AnalysisV2` must continue through the configured stage pin, exact consent, per-attempt reserve/dispatch/settlement, deadline and cancellation checks. A changed source, revoke, unknown derivative loss or stale generation blocks serving and dispatch; neither a wider query nor a retry may create new authority. Show insufficient/unknown coverage rather than silently treating an omitted obligation as absent. Preserve exact immutable claim decision and a separate exact plan decision before deterministic export.

**Connected acceptance.** On the same public corpus, compare baseline and candidate for the retained long/short questions plus reordered policy terms, later exception, contrary failure, distractor and no-answer cases. Record expected-source and critical-obligation recall, contrary recall, irrelevant inclusions, byte/candidate/search caps, p95 latency, context omission, citation validity, unsupported claims and abstention. Answerable cases cannot all abstain. In the web flow, review and correct one goal-linked recommendation, reject a canary, approve its exact successor and separately approve the plan, then verify corrected bytes and exclusions in actual export files. Revoke/change a selected source and cancel an in-flight attempt to verify stale controls deny use and attempt accounting remains accurate. Compare representative tasks only with an already authorised configured model; otherwise report `BLOCKED model_not_selected / not_dispatched`, without a benefit claim.

**Limits.** The iteration 14 synthesis was scripted and static integrity passed, while task evaluation was blocked. Semantic correctness, real-company benefit and physical million-file scale remain unproved. The 13/14 publisher-retirement and unknown-worker-loss caveats require explicit failure evidence before closure.
