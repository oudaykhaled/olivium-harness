# Web evidence recovery for the company question

**Proposal.** Keep the browser’s existing corpus question → named passage inspection → synthesis scope flow, but make decisive term loss observable and recoverable before synthesis. The public long question selected three passages and omitted policy; the focused question selected four including policy. `Company.Retrieval.tokens/1` retains only the first and last four content terms beyond eight. This is one reproduced omission, not an estimated recall rate.

**Selection before implementation.** Compare three bounded variants against the current FTS5 baseline on independently authored public development corpora: (A) a full-question expression with explicit term/byte limits, (B) several bounded overlapping or intent-based queries with deterministic fusion, and (C) unchanged query plus different lane/packing allocation. Include middle-position policy terms, reordered/paraphrased questions, later exceptions, failures, distractors and no-answer cases. Report critical and contrary source misses, irrelevant inclusion, context truncation, abstention, p95 latency and query count under declared corpus/hardware/caps. Pick the least complex variant that improves decisive evidence retention without unacceptable noise or cost; do not preselect A, B or C. All-abstention fails answerable cases.

**Web seam.** Reuse `CorpusReviewLive`’s draft, async retrieval, stale-run reset, paged checked results and `CorpusReview`’s named passage/context panel. Surface the immutable run’s actual search limits and selected-versus-additional-candidate distinction beside “Review synthesis scope”; offer a focused-question retry using the existing form while retaining project, goal and corpus selection. The reviewer must see which evidence enters synthesis and may inspect original byte-pinned context. This is a compact recovery affordance, not a new workflow or separate search store.

**Connected acceptance.** From one authorised corpus and saved goal, equivalent long and focused questions show policy plus applicable contrary/exception evidence within the declared caps; a changed/revoked source invalidates old controls. A reviewer corrects or rejects unsupported guidance, approves one exact claim and a separate exact plan, then verifies corrected applicability and checks in actual exported bytes with rejected material absent. Preserve versioned origin, transitive dependencies, consent, budgets and cancellation. Static integrity and scripted synthesis prove mechanics only; representative task evaluation stays `BLOCKED` when no authorised selected model is available.

**Limits.** The UI can reveal omitted terms/candidates and support retry, but it cannot certify semantic coverage. Do not add graph/RAG/Jev engines: reuse SQLite FTS5, Passages, OriginV2, AnalysisV2, existing decisions/plans/compiler/evaluations and pinned Graphiti 0.31.2 native Jev integration. No new desktop, mobile or standalone CLI feature.
