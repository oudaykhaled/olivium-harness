# Proposal 02 — Goals to Evidence handoff

**User/job.** An operator who saved intended practice needs to find the separate rule proposal and make deliberate approval decisions. Success: a native synthetic keyboard journey reaches the rule form in Evidence, then its unselected “Saved goal” control, and proposes/reviews a rule without accidental authority. Navigation creating authority, stale private details after reset, or unreachable controls falsifies the hypothesis. First-time-operator comprehension remains unmeasured.

**Facts.** Goal save calls `Goals.add_goal` and reports a flash ([Portal](../../../../../lib/harness_forge_web/live/portal_live.ex#L420)); saved cards lack a return action ([cards](../../../../../lib/harness_forge_web/live/portal_live.ex#L1856)). Evidence has a separate goal-rule form, blank “Saved goal” option, and copy distinguishing selection from approval ([form](../../../../../lib/harness_forge_web/live/portal_live.ex#L1446)). Generic tab changes lack focus ([handler](../../../../../lib/harness_forge_web/live/portal_live.ex#L58)); allowlisted focus targets visible elements ([JS](../../../../../assets/js/app.js#L115)). Tests use sidebar navigation and assert blank selection/claim absence ([test](../../../../../test/harness_forge_web/goal_claims_test.exs#L28)). Native05 observed BODY focus after save, then Tab to Goal ([verification](../../05/verification.md#L55)).

**Recommendation.** Add “Continue to rule proposal in Evidence” beside saved goals. Activation changes tab and focuses the fixed rule-form container (make it programmatically focusable); next Tab reaches the blank **Saved goal** select. Reuse Portal and the `company-focus` allowlist without targeting a stale generated control ID. Proposal, exact claim approval and separate Company plan approval remain distinct. Per-card preselection is faster but weakens explicit choice; automatic navigation removes review of the saved card. Export recovery is a distinct alternative.

**Checks.** Given a saved goal, when activated by keyboard, then the rule-form container receives focus and next Tab reaches the blank select; the operator can choose, author and separately review an exact rule revision. Given save or handoff alone, when claims/plans are inspected, then no proposal, selection, approval or binding exists. Given unavailable/purged goals or a queued old view after reset/lock, when retried, then stale details/form state stay absent and generation/authentication refusal holds. Verify keyboard sequence, controls and no horizontal clipping at 320/390 CSS pixels and actual 200% zoom. These checks establish neither screen-reader speech nor WCAG conformance.
