# Authority and adversarial security — unselected proposal

**Recommend:** after a *completed* supported domain-source purge, invalidate affected mounted Company analysis/review and package state across the workspace. The owner should not keep reading a removed source's recommendation while deciding what to approve or export. `Privacy.Purge.source/2` serializes, revokes the connection, removes dependent claim families, plans and artifacts, and returns completion (`lib/harness_forge/privacy/purge.ex:21-26,128-170,341-404`). The portal currently broadcasts `:company_cache_reset` only from its own successful privacy handler (`lib/harness_forge_web/live/portal_live.ex:866-899`); a supported service caller has no equivalent notification. Reuse the existing reset and late-event fences, with a completion-scoped, workspace-bound notification. This is useful disclosure control within the connected analysis-to-human-review journey, though it does not prove semantic completeness.

**Acceptance:** two authorised mounted tabs reviewing a synthetic multi-source recommendation and an approved package lose affected report/package state promptly after an actual source purge, without manual reload. Unrelated goal policy and an independent unsaved edit survive where their authority remains; a queued old analysis result cannot revive removed content. A duplicate completion notification creates no inference, claim, approval or export. Failed/prepared purge sends no completed notification. Forged workspace/source IDs, foreign-workspace subscriptions, stale package links and direct profile/project/goal mutation cannot turn a reset into cross-workspace disclosure or fresh approval. Read paths must still recheck scoped DB authority, exact context, and operator session (`lib/harness_forge/evidence/store.ex:15-23`; `lib/harness_forge/company/analysis.ex:78-115,188-255`). Test portal and supported service entry points plus own-MCP reads with their separate bearer authority (`lib/harness_forge/mcp/auth.ex:9-26,51-66`); no generic client-supplied broadcast should authorize state change.

**Strongest alternative:** immutable owner-reviewed task/package/goal/rubric receipt, with every mandatory obligation assessed and critical violations blocking successful judgment. It better begins measuring representative work, but adds durable sensitive history: exact workspace scoping, successor semantics, source-purge deletion, backup inclusion, quarantine approval withdrawal and retained-byte limits must be designed together (`lib/harness_forge/privacy/snapshot.ex:7-8,286-350`; `lib/harness_forge/evaluations.ex:1-7,82-95`). Owner assertions remain separate from trusted `Evaluation.Run` and fixed `synthetic-go-v1` release applicability (`evaluations.ex:15,790-802`). Neither proposal qualifies real model reasoning, portable signer/revocation authority, per-client MCP revocation or runtime isolation.

At most three product authors including root; root owns shared PubSub/portal integration and corrections. Existing main 8865 and historical MCP stay untouched until root's controlled verification.
