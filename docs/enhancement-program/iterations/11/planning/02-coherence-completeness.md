# Proposal 02 — exact-plan coherence review

**Context.** Company analysis supports human-edited recommendations and exact Evidence/plan approvals. Yet `Validation.plan/1` accepts empty milestone `goal_ids`; `Company.resolve/1` checks goal scope and claim selection, not goal-to-milestone coverage (`lib/harness_forge/company/validation.ex:37–55,79–94`; `lib/harness_forge/company.ex:234–260,281–289`). A report can label a conflict, but approval does not detect contradictions **between** approved claims (`lib/harness_forge/company/analysis.ex:160–165,356–359`). Exact citations prove quotation, not policy truth (`lib/harness_forge/models/company_analysis.ex:57–66`).

**Decision candidate.** Add an exact-plan coherence worksheet at **plan approval**. For each selected goal, show its pinned revision, approved recommendations, supporting/conflicting findings and milestones. Require goal-to-milestone-to-claim association and owner disposition: addressed with acceptance/evaluation method, or deferred with reason and excluded from the package's claimed goal scope. Let the owner flag competing selected claims and record precedence/exclusion; unresolved flagged pairs block approval. Bind the worksheet to the immutable plan; recheck on approval, build and export. Export only retained eligible revisions and disclose deferrals. This is an owner assertion, not automatic semantic completeness.

**Acceptance.** Synthetic native journey: four authorised sources including uncited context, two goals, competing recommendations, human edit/reject/exact Evidence approval, pair resolution, coverage/deferral, plan approval, deterministic build and byte-checked export. Refuse an unassociated selected goal, empty goal milestone, unresolved flagged conflict, stale claim/goal/source or forged/foreign worksheet; failure creates no approval/build/export. Excluded guidance stays out. Own MCP reads scoped status only; it cannot approve. Test supersession and purge/reload invalidation without remapping old decisions. Scripted inference proves workflow only; semantic discovery, runtime and portable authority remain unqualified.

**Tradeoff / alternative.** Creation-time refusal catches gaps earlier but prevents incomplete drafts. Approval-time validation preserves iterative review. An owner-task/rubric receipt offers outcome evidence; mounted purge invalidation offers faster disclosure control. Both remain alternatives. Ownership: Elixir domain author for validation/persistence, UI author for review, root for migration/integration; target ≤400 net LoC per PR. Blast radius: plan, approval, export.
