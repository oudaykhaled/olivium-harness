# Domain and persistence contract: representative work

**Recommend one owner-reviewed task assessment** attached to an exported package. The owner defines a task and bounded rubric of mandatory obligations traced to selected goals and plan milestones, records each result, then accepts or rejects the outcome. This connects approved guidance to work without implying automated quality. The milestone validator permits empty `goal_ids` and does not demand selected-goal coverage (`lib/harness_forge/company/validation.ex:37–55,79–93`); the plan snapshots goal hashes and binds builds to plan revision and artifact digest (`lib/harness_forge/company.ex:139–166,250–260`; `priv/repo/migrations/20261031000700_company_builder.exs:45–58`).

Persist an append-only assessment revision containing workspace ID, task/rubric canonical hash, ordered obligation IDs and goal/milestone references, package digest, plan ID/revision hash, captured goal ID/content hashes, per-obligation observation/status, critical-violation flag, actor, decision and time. Validate every reference through scoped loads in one transaction; a digest alone cannot authorize a foreign package. A correction creates a successor; historical receipts never repoint to a newer package, rubric or goal. A successful owner judgment requires every mandatory obligation assessed and no critical violation. Interrupted or incomplete work remains a draft or unsuccessful receipt. Keep it outside `evaluation_runs`, whose result and execution context describe trusted-check provenance (`lib/harness_forge/evaluation/run.ex:1–11`).

**Acceptance:** positive: synthetic four-source approved package and selected goal produce a native task receipt showing evidence, all obligation results and exact identities after reopen. Negative: missing result, critical violation, foreign-workspace reference, changed rubric/package, duplicate acceptance and forged success refuse atomically. Mutation: a new plan/package/rubric retains old assessment bytes and demands separate review. Authority: only an authenticated workspace owner can submit; owner testimony never changes trusted run status or release qualification.

**Compatibility:** additive table and scoped index; immutable update/delete triggers. Add it to `Privacy.Snapshot` workspace and immutable inventories, with explicit quarantine behavior: rekey retained history, clear acceptance authority, and label restored assessments requiring reassessment (`lib/harness_forge/privacy/snapshot.ex:7–8,270–348`). Verify backup/restore, purge, foreign-workspace reads and predecessor history. No claim of real-company semantic completeness or runtime enforcement.

**Strongest alternative:** mounted purge invalidation immediately reduces stale disclosure, with less schema work; it leaves representative outcome measurement open. Ownership: root owns migration/snapshot integration, Elixir author owns assessment context/validation, UI author owns native review. Three authors total, including corrections.
