# Candidate: independently revocable local MCP clients

**User benefit.** An operator can stop one retired assistant's future local reads without disconnecting another. Today `MCP.Auth` accepts one environment-referenced bearer (`lib/harness_forge/mcp/auth.ex:51`); rotation revokes every client, while browser logout is separate (`test/harness_forge_web/mcp_test.exs:230`).

**Decision (bounded ADR).** Extend auth with a finite startup registry, `HARNESSFORGE_MCP_CLIENT_TOKEN_ENVS`, of `client_id:ENV_REFERENCE` entries. Bound IDs, entry count and config bytes. References follow the existing uppercase grammar; values retain the 43–256 URL-safe bearer contract (`lib/harness_forge/mcp/auth.ex:6`). Tokens stay in referenced environment values. Compare bearer digests in constant time. Preserve legacy single-token mode when registry is absent. Mixed modes, malformed/missing entries, duplicate IDs/references/values and overflow disable MCP authentication with generic 401. Preserve default-off 404, peer/Host/Origin 403, and three read-only tools (`lib/harness_forge/mcp/auth.ex:10`, `lib/harness_forge/mcp/tools.ex:1`).

**Revocation contract.** Remove A's entry from the launch configuration and restart the owning app, retaining B. A's next request returns 401; B continues. Another shell's environment edit does not change the running app (`docs/mcp.md:90`). Preserve reauthentication behind the privacy fence and 503 refusal (`lib/harness_forge_web/plugs/mcp.ex:152`). Prior reads cannot be recalled. Responses and application/audit logs must exclude token values, references and Authorization headers; any audit records only bounded client ID/result category.

**Acceptance.** Positive: A/B distinct tokens initialize and read; after restart without A, A=401/B=200. Negative: unknown/malformed/repeated Authorization, duplicate ID/reference/value, missing reference and mixed modes yield generic 401 without secret disclosure. Edge: revoked A remains denied after restart; foreign peer/Host/Origin=403, disabled=404, prepared privacy=503. Queued A cannot dispatch after in-process credential change (`test/harness_forge_web/mcp_test.exs:300`).

**Scope and falsifier.** Four files: `config/runtime.exs`, auth, MCP docs and HTTP tests; about one engineer-day. Any A read after revocation, B outage, credential leak or weakened fence falsifies delivery. Shared-token rotation is simpler but interrupts B; selected-goal coverage addresses company completeness more directly. Fixture tests do not qualify fresh SDKs, managed clients, Linux or portable authority.
