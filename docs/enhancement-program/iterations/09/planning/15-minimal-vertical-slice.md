# 15 — Smallest connected company-analysis slice

**Recommend one analysis session:** select two to four captured sources and one saved goal; use the configured provider under existing consent/budget controls to propose a synthesis card, then let the operator edit, reject, or approve its successor before exporting a company plan. Distinguish recurring practice/failure, discussion versus decision, exceptions/changed guidance, goal relevance, proposed rule/check, and uncertainty. Each assertion needs exact UTF-8 spans. A controlled synthetic provider response exercises mechanics without proving semantic quality; unavailable live inference stays visible.

**Critical contract:** freeze all input source ID/revision/body hashes and goal ID/content hash in a durable manifest, including examined sources omitted from the card. Bind cards and successors to its digest. Validate citations against pinned revisions and recheck source/goal eligibility at decision, build, and export. Edits create proposed revisions; approval never transfers. Show cited spans, dates/status, omitted sources, and uncertainty; inferred policy status requires human approval.

The existing seam is real: `Models.propose/2` supplies only one revision (`lib/harness_forge/models.ex:150`), while `Models.infer/2` accepts multiple authorized source IDs (`:89-103`). `Models.Proposal` validates exact byte spans but checks every citation against one source (`lib/harness_forge/models/proposal.ex:49-54,109-121`). Evidence already accepts multi-source citation lists and immutable successors (`lib/harness_forge/evidence.ex:289-325,429-452`); Company/Harnesses recheck selected evidence and export eligibility (`lib/harness_forge/company.ex:234-261,287-313`; `lib/harness_forge/harnesses.ex:134-190`). Existing single-source and withdrawal tests are regression anchors (`test/harness_forge/models_test.exs:70-129`; `test/harness_forge/company_harnesses_test.exs:147-188`).

**Acceptance:** positive: synthetic meeting, incident, and updated policy produce cited practice/failure/exception synthesis tied to a goal; operator edits, approves, and finds its rule/check in target files. Negative: rejected proposal is excluded; uncited assertion, foreign citation, or stale input blocks approval/export without artifact. Edge: changed *examined but uncited* source invalidates the session; conflict stays visibly unresolved. Falsifier: exported rule lacks a pinned influencing revision or survives withdrawal.

**Ownership/effort:** root owns manifest schema/integration; domain author owns multi-source validation/successors; portal author owns review/edit/plan path. Estimate 3–5 person-days including tests and native portal journey. Citation-only claims are cheaper but lose examined-source freshness. Isolated coverage, copy, MCP, and export gates remain future work.
