# 09 proposal — cross-source analysis contract through export

**Decision.** Expose one portal action backed by `Models.propose_sources(source_ids, goal_ids, opts)`: analyse 2–4 explicitly selected current captured revisions plus one saved future goal, then return bounded review drafts. This extends the existing single-revision `Models.propose/2` (`lib/harness_forge/models.ex:150`) and reuses source retrieval/consent and exact citation validation (`lib/harness_forge/chat/retrieval.ex:31`, `lib/harness_forge/models/proposal.ex:100`). No MCP tool is necessary: MCP remains read-only while proposal, decisions, build and export stay in the portal (`docs/mcp.md:3`, `lib/harness_forge_web/live/portal_live.ex:407`).

**Response contract.** Return at most six draft recommendations, each `{kind, target, text, rationale, citations, goal_id, uncertainty}`. `kind` is `practice`, `decision`, `exception`, or `conflict`; `target` is `rule`, `skill`, `check`, or `evaluation`. Every factual assertion has 1–4 exact UTF-8 byte-range citations to selected revisions, including two distinct sources for a cross-source conclusion. `uncertainty` marks disagreement or superseded guidance. Bind source/revision hashes, goal hash and model run ID to the response. A recommendation is **not approved evidence**. The operator edits or rejects each draft, explicitly proposes chosen text using existing multi-citation claims (`lib/harness_forge/evidence.ex:289`, `lib/harness_forge/evidence.ex:429`), decides exact claim revisions, selects them into a coherent Company plan, approves its exact revision, builds and exports (`lib/harness_forge/company.ex:71`, `lib/harness_forge/company.ex:110`, `lib/harness_forge/harnesses.ex:8`, `lib/harness_forge/harnesses.ex:122`). Target composition uses accepted content only.

**Falsifiable checks.** Positive synthetic corpus: policy says review changes, later decision adds owner sign-off, exception exempts emergencies; a future goal requests faster releases. Review must show the recurring rule, changed decision, exception and tension with the goal, with separate citations; human editing/rejection, approval and export yield package files matching accepted text only. Negative: forged ranges, unselected IDs, missing consent, stale revision/goal, malformed output or unavailable provider return fixed errors and create zero claims/decisions/packages; no heuristic fallback. Edge: conflicting current documents remain an explicit unresolved review item, never silently one approved rule. Assert package digest/files after real portal export and absence of rejected text. Fixture provider tests prove contract only; real-model quality and representative owner review remain unverified. Root owns runtime/SDK/browser checks. Approximately 2–3 engineer-days across model contract, portal, and tests; broader synthesis risks unsupported policy inference.
