# Browser oracle: company analysis to exported harness

**Recommend one workflow:** analyse consented policy, plan and incident history; present a cited synthesis of practice, failures, exceptions, superseded guidance and goals; let the operator edit/reject/approve proposed rules; compose, build and export a package. Today `Models.propose/2` reads one source revision (`lib/harness_forge/models.ex:150`); Portal exposes citations and separate claim decisions (`lib/harness_forge_web/live/portal_live.ex:1524`); Company pins claims/goals and exact plan revision (`lib/harness_forge_web/components/company/plan.ex:558`); build/export recheck authority (`lib/harness_forge/harnesses.ex:8,122`). Cross-source explanation reaching export is the missing benefit.

**Positive corpus:** synthetic policy P mandates review; incident I records a bypass and failure; newer decision D supersedes an exception; future goal G requires a measurable check. Import through approved local sources. The analysis must cite exact revisions of P/I/D, explain the conflict and effective guidance, distinguish observed history from future intent, propose a rule/check with evaluation rationale, and label uncertainty. Generic advice without cross-source provenance fails. Synthetic expected relationships cannot establish real-company semantic quality.

**Root browser oracle:** Playwright 1.49+ role/label locators, stable IDs where needed. In an authenticated Portal session, select corpus; request analysis; inspect citations/uncertainty; keyboard edit one proposal, reject obsolete guidance, approve the corrected exact claim revision; select it and G in Company; approve the exact plan; build; export to a fresh directory. Assert visible states and focus after each action. Join browser evidence to decision/audit counts, revision hashes, package digest and exported file bytes: corrected rule and target guidance present; rejected text absent. A queued state alone proves nothing. Root captures browser trace, accessibility tree and screenshots as appropriate; this planner runs no browser/HTTP.

**Negative/recovery:** stale source or revoked consent blocks analysis/approval. Missing model is visibly unavailable without fallback; uncertain text never auto-approves. Stale hash, rejected claim or revoked source blocks build/export with no new artifact or overwritten destination. Error retry retains review context, focuses actionable help and never duplicates decisions. Approval remains separate from analysis; release remains separate from export. Scope excludes semantic completeness, managed execution and portable company authority. Ownership: analysis/domain author; Portal/review author; root shared integration and export verification. **Falsifier:** export contains rejected/unsupported guidance, omits approved company-specific guidance, or hides a corpus conflict without operator decision.
