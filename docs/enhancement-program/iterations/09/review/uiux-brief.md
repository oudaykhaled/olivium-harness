## Connected presentation

Extend Company’s existing Claim review section with **Analyse company context** and a focused `Company.Analysis` presentation component. Keep the existing sequence: select context → inspect analysis → edit/save a proposed successor → review/decide its exact revision in Evidence → deliberately select approved guidance and its goal in a Company plan → approve that exact plan → build → open Packages/export. Preserve explicit selection at every step; successful analysis never selects claims, approves decisions or creates a plan.

Require a project selection even when only one exists. Use the existing **union** of profile/project source and goal assignments (`company.ex:239`), pinning both records. List active current captured sources with unchecked choices and a live “2 of 4 selected” count. Show each title, revision, capture date, source-updated date when available, and safe source link. Label missing dates/links “Unknown”/“No source link”; allow only vetted HTTP(S) links and escape all labels/excerpts. “Current captured revision” means current in this workspace, not freshly synchronized remote policy. Explain excluded/unselected coverage and that capture order cannot establish decision chronology. Choose one saved goal explicitly; display title, owner, acceptance and pinned hash. Capture selection pins when chosen; a reload must refuse changed pins, not silently repin them.

Present the persisted result in this order: selected context and goal; **Original model report**; **Current guidance to review**; review continuation. The report shows findings with kind labels, exact supporting/conflicting excerpts, goal rationale, original status, and always-visible uncertainty. Discussion, decision, exception, change and unknown must remain distinguishable without color. Label the two-source finding count **Structural citation coverage**; the recommendation has no separate support-reference field, and this count cannot prove corroboration. Unknown coverage is valid. An abstention shows uncertainty and creates no claim. A controlled synthetic result must say “Synthetic provider and corpus: protocol/workflow demonstration”; it establishes no company/model semantic qualification.

Only `rule`, `workflow`, `check`, `evaluation_criterion` are editable guidance. Display four labelled textareas, each bounded to 1,000 characters, with a preview of deterministic fixed-label claim text. Export only approved guidance; keep report/source bodies out of target files. Workflow/check/evaluation wording is advisory, with no executable grader. Never edit the original report or change its status. Label the action **Save new proposed revision**. Saving creates an unapproved successor and displays its new exact hash; never rewrite earlier approval. For original uncertain/conflicted status, require a nonblank saved human resolution on a successor before approval. Show the existing resolution when reopening or making another successor; omission preserves it, and edits cannot silently clear disagreement. Resolution records human judgment, not model verification. Dirty text disables continuation to exact approval until saved or explicitly discarded.

Evidence must render `company_analysis` explicitly. Today any nonnil basis is labelled goal-only and “has no source citation” (`portal_live.ex:1532`); that branch is incorrect for the new origin. Reuse the report/current-guidance presentation there, including exact context, immutable original status, saved resolution, current eligibility and full revision hash. Reject and Approve remain distinct explicit `decide` actions. Rejected, superseded, stale and unresolved proposals cannot appear as selectable approved guidance. Company Plan and Guide currently reject unknown origins (`plan.ex:675`, `guide.ex:110`); extend their projections with the shared origin helper and selected project/goal/all-context checks. Never infer eligibility from citation count alone.

## Lifecycle, copy and recovery

Use parent LiveView async work; CompanyPanel already owns authentication and its server-generated envelope (`company_panel.ex:101`). Retain a single pending request identity in parent and component. Changing selection while busy must not change the running request’s identity; disable the selection controls until completion or explicit departure. Repeated submits reuse the same identity and never redispatch. No automatic retry. Clear analysis drafts/pending state on tab exit, reset, lock or remount; ignore mismatched late callbacks and late abstentions. Cancellation does not promise erased ledger usage or undo a proposal already committed; persisted records remain discoverable by normal Evidence reload.

Normal no-model copy: “Analysis unavailable. Select an already installed model in Connections.” Unreachable provider: “The configured model is unavailable. Check its connection before a new request.” Add an unchecked cloud consent control: “I also allow selected company/project context and saved goal details to be sent to this provider for company analysis.” It adds `company_context` only with explicit acknowledgement and existing selected-source consent. Display budget refusal without suggesting a free retry. Configuration/consent fingerprint checks apply at dispatch and proposal admission; later approved-plan build/export works offline and does not require current inference consent/model availability. Source, goal, project and profile pins still govern eligibility.

Map domain errors to fixed local copy: stale context → “Selected context changed. Review current sources and goal, then start a new analysis”; resolution required → “Save your resolution in a new proposed revision before approval”; duplicate/unknown request → “This request was already dispatched. Review its recorded outcome before starting another”; malformed output → “The model response could not be admitted. No recommendation was saved.” Refusals preserve valid draft bytes except explicit reset/departure. Never show raw provider responses, exception terms or endpoint secrets.

Use native fieldsets/legends, labels, checkboxes, buttons and details. Announce busy/completion through one polite status region with `aria-busy`; focus a visible error summary with `tabindex=-1`, link field errors via `aria-describedby`/`aria-invalid`, and move completion focus to the result heading. Preserve logical keyboard order and disclosure `aria-expanded`/`aria-controls`; no focus trap. Reuse `--company-space-*`, `--company-target`, existing surface/text tokens and wrapping rules (`app.css:166`). Add only bounded analysis targets/form IDs to current reset/focus registries. Preserve iteration 08 Package-name draft retention, generation rotation, single-refusal focus and exact retry (`package_build_test.exs:76`); analysis reloads must not clear that recovery.
