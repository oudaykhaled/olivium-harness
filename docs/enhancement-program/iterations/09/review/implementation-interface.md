## Clarifications that bind implementation

- Scope is the existing **union** of profile/project source and goal assignments, with the same profile/project pinned (`lib/harness_forge/company.ex:239`). Capture order does not establish policy chronology.
- Model/configuration/consent freshness applies at dispatch and proposal admission, including abstention. Later approval/build/export validates source/goal/profile/project authority and makes no inference; it requires no currently selected/running/unchanged model or inference consent. Stored provider identity is attribution.
- `report` is immutable original validated model output. `guidance` holds separately versioned current instructions; human edits never rewrite original findings/status/uncertainty. Root's explicit post-brief clarification: this new origin requires saved human resolution if original recommendation status is uncertain/conflicted **or any original finding has kind `conflict`**, even with recommendation status supported. This checks declared structure, not semantic contradictions; legacy approval rules stay unchanged.
- The ≥2-source condition counts distinct source IDs across validated finding citations, including discussion/conflict. Call it **structural citation coverage**, never machine-proved corroboration. No new supporting-finding reference field is added.
- Resolve the advisers' citation-order difference as follows: retain original report order; flatten/deduplicate its exact citation spans for persistence, then canonicalize stored citation DTOs by `(revision_id,start_byte,end_byte,id)` for continuity/hash. Never reorder legacy hashing.
- Guidance uses existing Evidence text-trimming semantics (`lib/harness_forge/evidence.ex:300`): validate complete four-field UTF-8 inputs, each ≤1,000 characters and nonblank after trimming; store trimmed values, preserve internal whitespace. Original report/snippet bytes remain unchanged.
