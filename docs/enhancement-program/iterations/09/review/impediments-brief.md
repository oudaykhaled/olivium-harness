## Durable schema and authority

All boundaries use string keys. Input refs are 2–4 distinct `{source_id, revision_id, body_hash}` maps, sorted by source ID. Assignment means the existing **union** of profile and selected-project assignments, not intersection. Capture the same project/profile and current active connection/source revisions, document scope and goal. Profile/project descriptions remain untrusted context.

| Exact basis/context field | Meaning |
|---|---|
| `kind`, `version` | Literal `company_analysis`, integer `1`. |
| `project_id`, `goal_id`, `goal_content_hash` | Selected scoped identities and `Goals.content_hash/1`. |
| `context` | Exactly `profile`, `project`, `sources`; first two exactly `{id, content_hash}`, sources are the complete sorted input refs, including uncited inputs. `context.project.id == project_id`. |
| `context_digest` | `Contracts.digest(context)`; no bodies, prompts or provider endpoint. |
| `report` | Original validated `{findings, recommendation, uncertainty}` including original recommendation status and goal rationale; immutable through all successors. |
| `guidance` | Exactly `rule`, `workflow`, `check`, `evaluation_criterion`; initialized from report, independently versioned human edits. |
| `provider`, `model`, `config_fingerprint`, `run_id`, `request_id` | Actual verified dispatch attribution, immutable after admission. |
| `review_resolution` | Initially null; nonblank human judgment ≤1,000 characters when saved. Omitted successor input preserves it; an existing resolution cannot be cleared, but may be explicitly replaced. |

Enforce ADR limits: 32,768 aggregate source bytes, 49,152 prompt bytes, 4,096 output tokens, 32,768 output bytes, depth ≤12, duplicate-key rejection, exact fields, ≤6 findings, ≤16 distinct citations, exact UTF-8 spans/snippets and ≤1,000-character texts. Flatten findings into unique citations sorted by source/revision/start/end/snippet; persist only those identities. A non-null recommendation needs citations covering ≥2 selected sources. This is structural citation coverage: discussion/conflict citations do not machine-prove corroborating support. The prompt requests evidence-based synthesis; the fixture oracle and human review assess meaning.

Generic callers cannot remove origin, swap citations/context, change report/status or bypass rendered text. `validate_successor` permits only guidance/resolution differences and preserves canonical citation records. For uncertain/conflicted reports, even unchanged guidance needs explicit saved resolution before approval; rejection stays available. Root inserts a distinct analysis hash clause **before** existing generic basis matching: digest `{kind: "company-analysis-claim", version: 1, text, citations, basis}` with string keys; canonical citations project exactly `id`, `revision_id`, `start_byte`, `end_byte`, `snippet_hash` in validated report order. Preserve legacy source/goal hash implementations byte-for-byte. Every successor remains proposed until exact approval.

## Capture, dispatch, admission

Call graph: B → `Analysis.analyze` → capture scoped context/config → `Models.start_run` → `Models.infer` → provider → `HTTP.request` → bounded report validation → privacy fence/transaction → full recheck → citations/claim/audit. Never hold a DB transaction or privacy lock across inference.

For this purpose alone, the exact Models request adds `expected_config_fingerprint` and `company_analysis_context` to existing fields. The latter is exactly `{project_id, goal_id, goal_content_hash, context, context_digest}`. Source IDs must equal manifest IDs; categories require `source_body` and `company_context`. Public infer opts remain timeout-only. Check expected fingerprint and context before credential resolution/reservation. Install a server-owned internal `:dispatch_guard` closure performing both checks, then check immediately before provider generation. `HTTP.request/5` invokes it immediately before **each** `Req.request`; it never becomes a Req option or caller-supplied override. Extend `Ollama.available(config, opts \\ [])` so guarded `/api/tags` and subsequent `/api/generate` both receive it. Other real providers already forward opts. Guard refusal propagates unchanged without HTTP dispatch.

Capture A must never silently dispatch configuration B: the captured, verified config drives authorization, credential reference, provider, schema, body and ledger reconciliation throughout. Infer returns verified `provider`, `model`, `config_fingerprint` alongside existing fields. Admission compares that attribution, current fingerprint and the entire source/goal/project/profile snapshot, including **abstention**. Fail stale rather than return an old abstention. Ledger records may remain after dispatched refusal; no claim/citation/decision/plan/package is admitted.

After admission, provider configuration/consent is historical attribution. Approved build/export performs no inference and requires no selected/running/unchanged model; data pins remain current. This resolves the ADR's “around dispatch and admission” language without adding a later model gate.
