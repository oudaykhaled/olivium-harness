# Corrective navigation after a static pass

**Benefit.** An operator inspecting a passing static check can identify the next screen and why it matters. The action falls back to “Review evaluations” for incomplete cleanup, though a static check never dispatched a task ([Readiness `next_action/action`](../../../../../lib/harness_forge/readiness.ex#L302); [inspector action](../../../../../lib/harness_forge_web/components/package_readiness.ex#L113)). The [03 UX retrospective](../../03/retro/02-ux.md) reports this as a comprehension risk; it records no novice study.

**Proposal.** Only when the exact selected run is `static_integrity`, outcome `passed`, recorded cleanup `not_started`, and the existing next action is `review_evaluation → evaluations`, label the button **“Go to Evaluations for a model-backed task”**. Adjacent help: **“Static checks passed. No task or task cleanup ran. Opening Evaluations does not start a run; a qualified task result is still required for release review.”** Use recorded fields, not a guessed or latest run. Keep the seven stages and current summary visible. This is presentation only: the button still navigates to `evaluations-panel` and focuses it through the existing allowlisted `company-focus` event ([PortalLive](../../../../../lib/harness_forge_web/live/portal_live.ex#L252), [app.js](../../../../../assets/js/app.js#L114)).

**Acceptance.** A genuine selected static pass shows the exact label/help; keyboard activation focuses the Evaluations panel, then Tab reaches its first logical control. No run or approval is created. No selected run, unknown metadata, task cleanup failure, unsupported backend, and OpenCode task abstention do not get this label. Switching package/run, reset, remount and revocation clear stale text/action as current state requires. At 320 CSS px and actual 200% zoom, the action wraps without horizontal overflow; its accessible name and nearby help convey the same distinction. LiveView tests assert each state and unchanged `next_action`; native checks record focus/Tab and visual evidence. No screen-reader or novice result is claimed.

**Alternative and risk.** A general rewrite of every next-action label could improve other routes but multiplies state and regression cases. Static cleanup explanation without navigation is smaller, yet leaves the immediate action vague. Limit this change to `package_readiness.ex` and focused web tests, with an optional local style adjustment; estimate 0.5–1 author day plus browser verification. Preserve authentication nonce, privacy/reset, no-overwrite export, existing admission gates and **OpenCode current task NOT ASSESSED**.
