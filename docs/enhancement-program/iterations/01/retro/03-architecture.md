HarnessForge is helpful and increasingly reliable for composing an explicitly scoped, reviewed company harness locally. It has not demonstrated a complete, operational company harness. Iteration 01 improves discovery and diagnosis through MCP; it does not close policy completeness, portable authority or execution-quality gaps.

The strongest architecture is the separation of authority from descriptive context. `Company.build_inputs/1` requires the exact approved plan and reconstructs its pinned scope; selected claims must remain approved, current and cited to active, permitted sources ([company.ex:139](../../../../../lib/harness_forge/company.ex#L139), [company.ex:234](../../../../../lib/harness_forge/company.ex#L234)). `Harnesses.build_plan/2` rechecks inputs, durably binds the plan before publishing, and export rechecks eligibility ([harnesses.ex:10](../../../../../lib/harness_forge/harnesses.ex#L10), [harnesses.ex:120](../../../../../lib/harness_forge/harnesses.ex#L120)). Tests explicitly cover deterministic exports, stale metadata refusal, publication failure and prevention of fallback from invalid bindings ([company_acceptance_test.exs:99](../../../../../test/harness_forge/company_acceptance_test.exs#L99), [company_harnesses_test.exs:199](../../../../../test/harness_forge/company_harnesses_test.exs#L199)). These establish immutable local composition and admission, not company-wide policy correctness.

The accepted evidence supports a bounded success: 388 passed, zero failed, 15 existing Docker skips; 44 official SDK checks passed for MCP 2025-11-25, with database hashes and artifact bytes unchanged. Coverage is unmeasured and two baseline Dialyzer diagnostics remain ([manifest](../../../../../tmp/enhancement-program/01/accepted-evidence.json), [native summary](../../../../../tmp/enhancement-program/01/qa/validation-summary.json)). MCP correctly delegates readiness to Company/Harnesses and explicitly reports qualification unassessed and portable approval unavailable ([tools.ex:200](../../../../../lib/harness_forge/mcp/tools.ex#L200)). I did not rerun checks, import data or invoke models for this retrospective.

The three concrete gaps, ranked by their effect on a complete company harness, are:

1. **Goal-derived policy and conflict decisions.** Goals currently contain title, owner and acceptance; generated rules always have `goal_id: nil` ([goals.ex:11](../../../../../lib/harness_forge/goals.ex#L11), [harnesses.ex:184](../../../../../lib/harness_forge/harnesses.ex#L184)). Pinning selected goals prevents drift but does not explain which approved rule implements a future goal or resolve contradictory approved rules. Acceptance: support an explicit, versioned goal-origin claim basis without inventing source citations; require exact human approval; represent declared conflicts and their exact-revision resolution. Tests must reject unapproved goal rules and unresolved declared conflicts, prove goal changes invalidate affected plans, and preserve evidence-origin behavior and historical v1alpha1 verification. Do not claim automatic semantic conflict detection.

2. **Observed runtime and company-task evaluation.** Export adapters exist for three targets, but Codex/Claude managed backends are unavailable; evaluation distinguishes integrity from isolated task qualification ([registry.ex:15](../../../../../lib/harness_forge/adapters/registry.ex#L15), [evaluations.ex:1](../../../../../lib/harness_forge/evaluations.ex#L1)). Acceptance: one bounded, consented company pilot must use an installed real local model and supported isolated runtime, exercise representative tasks with protected objective checks, and retain exact artifact/model/environment identities, failures, budgets and verified cleanup. Missing models, runtime or connector scopes must produce explicit blockers and zero unauthorized dispatch. Existing synthetic SDK success cannot satisfy this criterion; selected live connector credentials/scopes remain unverified ([verification](../verification.md)).

3. **Portable approval provenance.** Exported provenance retains rule references and goal IDs, while company approval resides in local bindings ([compiler.ex:78](../../../../../lib/harness_forge/compiler.ex#L78), [contract](../../../../company-builder-contract.md#binding-tradeoff-and-legacy-compatibility)). Acceptance: a versioned provenance envelope must bind the exact plan, decisions, scope and package digest to an explicit verifier trust policy. An independent workspace must distinguish intact bytes, historically verified approval and unknown current revocation; tampering, missing trust and mismatched decisions must fail. Preserve old package bytes and restore quarantine.

UI iteration 02 should guide the existing profile → project → evidence → exact-plan decision → package path with visible blockers and contextual next actions. Validate an empty synthetic workspace through export in a browser, including stale-plan recovery and separate integrity/eligibility/qualification labels; the current long form is the recorded [baseline](../../../../../tmp/enhancement-program/01/browser/company-dom.txt). The next functional iteration should address gap 1 with explicit goal-origin authority and declared conflict resolution, bounded to Company/Evidence/Harnesses and compatibility tests. Expanding MCP mutations would not resolve these underlying reliability gaps.
