# Iteration 01: independent QA and operability retrospective

HarnessForge is helpful for assembling and inspecting a governed company harness, and this iteration provides credible evidence for its narrow read-only MCP contract. Reliability as a complete company solution remains unproven. Finding a repository, observing approval/buildability and verifying package bytes are useful milestones; they do not demonstrate that a company's goals become effective, enforceable guidance during real work.

The [accepted manifest](../../../../../tmp/enhancement-program/01/accepted-evidence.json) matches all 19 recorded source/evidence hashes when independently reread. The [final regression checks](../../../../../tmp/enhancement-program/01/regression/final/checks.json) report 403 registered tests, 388 passed, zero failures and 15 unchanged Docker skips, with coverage unmeasured. Format, warning-gated compilation and the CI Credo warning gate passed. Dialyzer exited 2 with exactly the two existing `releases.ex:47/121` opacity diagnostics; the [reviewer verdict](../../../../../tmp/enhancement-program/01/regression/final/verdict.json) correctly retains that follow-up. This establishes an application regression result, without establishing clean type analysis or exercised container isolation.

The [native result](../../../../../tmp/enhancement-program/01/qa/native-client-result.json) adds stronger transport evidence: the packaged candidate passed 44 checks through official MCP SDK 1.29.0, Node 26.3.1 and protocol 2025-11-25. Authentication, malformed requests, bounds and portal coexistence were exercised. The [validation summary](../../../../../tmp/enhancement-program/01/qa/validation-summary.json) records identical row counts/content hashes across 30 tables and unchanged bytes across ten artifact files, including the failed first attempt. Secret/source-body sentinels were absent from responses/logs. That is persuasive read-only and minimization evidence for this synthetic workspace. It provides no model-driven client, live connector, throughput or complete-company proof; its database contained zero evaluation runs, model requests and workspace goals. The 1.211 ms curl observation is one local smoke sample.

Failure history improves confidence in the reporting discipline. [Verification](../verification.md) preserves the SQLite query and exception-path cache-header defects, four corrected new Dialyzer findings, the overlong QA socket path and duplicate-Host QA construction failure. Successful reruns support those corrections. Neither a single seed nor retained failures establish a measured flake rate.

The next three gaps, ranked by consequence, are:

1. **Company outcome qualification.** No real pilot shows that approved knowledge improves useful work. [Compiler](../../../../../lib/harness_forge/compiler.ex:7) explicitly distinguishes preview from unavailable managed compilation; [MCP projection](../../../../../lib/harness_forge/mcp/tools.ex:253) says qualification is unassessed. Acceptance: an independently authorized pilot predeclares five representative tasks across two repositories, compares baseline versus harness over three runs each with pinned model/runtime identities, and records correctness, policy violations, cost and duration. Require zero unauthorized operations and a declared usefulness threshold; unavailable prerequisites remain blocked.

2. **Operational execution assurance.** The skipped tests include actual confinement, cancellation, timeout, output bounds and cleanup recovery, not cosmetic checks. See [execution tests](../../../../../test/harness_forge/execution_test.exs:25) and [coding tests](../../../../../test/harness_forge/coding_evaluation_test.exs:193). Acceptance: a supported isolated release lane runs all 15 with zero skips, validates resource removal after interruption/restart, measures flake rate over 100 runs against a 1% budget, and either resolves both type diagnostics or retains explicit owners and deadlines. Measure coverage before selecting a justified gate.

3. **Portable, understandable authority.** Package eligibility is local and current; portable approval verification is explicitly unavailable. Acceptance: exported provenance binds exact plan/claim revisions and evaluation identity; a fresh workspace rejects tampering, absent trust and withdrawn authority, and reports an actionable reason without granting approval implicitly.

Bound iteration 02 to the Company screen: show separate approval, buildability, integrity and qualification states, one next action per blocker, and explicit unavailable integrations. Validate proposed, stale, rejected and eligible journeys with keyboard access and screenshots. For the next functionality iteration, implement a bounded qualification-readiness report using existing eligibility and [release validation](../../../../../lib/harness_forge/releases/validation.ex:8), exposing missing prerequisites without asserting pilot success. This makes the eventual real pilot assessable while preserving existing authority boundaries.
