# MCP acceptance: prove the wire and the company boundary

**Priority: P0 for any MCP delivery.** The router currently has no MCP route ([router.ex](../../../../../lib/harness_forge_web/router.ex#L18-L32)); existing `mcp: {}` settings disable servers inside coding runs ([coding.ex](../../../../../lib/harness_forge/execution/coding.ex#L80-L84)). A unit-tested dispatcher would not show that an outside client can connect. Freeze one supported protocol revision and transport before implementation: the sibling plans currently propose different revisions (2025-11-25 and 2026-07-28). Their lifecycles differ: [2025-11-25 Streamable HTTP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) uses initialization and permits sessions; [2026-07-28 versioning](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning) uses per-request metadata and `server/discover`. Test the chosen revision's actual wire contract; advertise only what the endpoint implements. If older clients are unsupported, record the observed failure and the precise supported version.

## Proposed acceptance ladder

1. **In-process HTTP contract:** add `test/harness_forge_web/mcp_test.exs` using `HarnessForgeWeb.ConnCase` (endpoint, `Phoenix.ConnTest`, SQL sandbox already supplied in [conn_case.ex](../../../../../test/support/conn_case.ex#L18-L37)). Send raw JSON-RPC POSTs through the real endpoint, not direct dispatcher calls. Assert content type, HTTP status, `jsonrpc: "2.0"`, request ID correlation, result/error shape, deterministic `tools/list`, schema, and a successful `tools/call` result. For 2025, exercise `initialize` → `notifications/initialized` → list/call and notification HTTP 202. For 2026, exercise discovery, required `_meta`/headers, and version mismatch. Cover GET behavior exactly as selected transport permits; avoid claiming full Streamable HTTP if required GET behavior is absent.
2. **Synthetic company truth:** create a disposable workspace and public synthetic plan fixture, following [company_acceptance_test.exs](../../../../../test/harness_forge/company_acceptance_test.exs#L7-L96). Compare MCP projections with `Company.list_plans/0`, `get_plan/1`, and `build_inputs/1` ([company.ex](../../../../../lib/harness_forge/company.ex#L98-L170)). Show proposed, approved/buildable, and stale or ineligible states. Verify read calls leave plan decisions, audit events, artifacts and evaluations unchanged. A current preflight is advisory; a later build still rechecks eligibility. Assert tool results contain only approved projection fields, with no source body, credential, path, or whole snapshot.
3. **Failure matrix:** missing/wrong credential, foreign Host/Origin, expired workspace capability, malformed/duplicate-key JSON, invalid JSON-RPC ID and shape, unsupported version/method, unlisted tool, bad/extra arguments, oversized body, unknown or foreign-workspace ID, and purge in progress. Assert bounded safe errors, no credential/body reflection, no server crash, and no mutation. The endpoint already limits parsed bodies to 1 MiB ([endpoint.ex](../../../../../lib/harness_forge_web/endpoint.ex#L43-L50)); its general Jason parser is not duplicate-key validation, so test the MCP-specific boundary. Reuse existing Host/Origin regression cases ([portal_test.exs](../../../../../test/harness_forge_web/portal_test.exs#L60-L74)); machine auth must be tested separately from browser session redirects ([operator_session.ex](../../../../../lib/harness_forge_web/plugs/operator_session.ex#L12-L36)).
4. **Real external-client smoke:** start the actual local server with a disposable workspace and use one pinned, independently maintained MCP client supporting the chosen revision to connect, discover/list, and call a read tool. Keep the portal usable during the exchange. Repeat against the native packaged release if packaging is in scope. Record client package/version, server revision, exact command, exit code, sanitized transcript, and unsupported-client behavior under `tmp/enhancement-program/01/`. A hand-written curl exchange is useful wire evidence, but alone does not establish external-client compatibility. Fixture tests do not establish live model quality or private-company compatibility.

Run focused `mix test test/harness_forge_web/mcp_test.exs test/harness_forge/company_acceptance_test.exs`, then canonical `mix test` and format/compiler checks after integration. Report actual counts and any skips; do not convert an unrun client smoke into a compatibility claim.
