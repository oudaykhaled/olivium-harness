# Iteration 01 proposal: install HarnessForge's MCP in real local clients

**Priority: high, after the authenticated read-only MCP endpoint exists.** A company builder should be able to run the packaged app, connect Codex CLI or Claude Code to its own MCP endpoint, and retrieve reviewed company context. This is a distinct capability from exporting Codex/Claude *harness previews*: those exporters deliberately emit no MCP server configuration ([Codex connector](../../../../../docs/codex-connector.md#L3-L25), [Claude connector](../../../../../docs/claude-code-connector.md#L8-L11)).

## Checkout evidence and bounded change

The source/release launcher already supports `serve`, and the release includes `bin/harnessforge` plus bundled BEAM/ERTS ([launcher](../../../../../bin/harnessforge#L6-L22), [packaging](../../../../../packaging/README.md#L3-L24)). `CLI.help` has no MCP or client setup command ([cli.ex](../../../../../lib/harness_forge/cli.ex#L221-L269)); the router has no MCP route ([router.ex](../../../../../lib/harness_forge_web/router.ex#L18-L32)). The package smoke runs offline CLI commands, not a long-lived server or MCP client ([packaging/smoke.sh](../../../../../packaging/smoke.sh#L12-L24)). The workspace lock means a second `bin/harnessforge` invocation cannot inspect a running portal's state ([workspaces.ex](../../../../../lib/harness_forge/workspaces.ex#L40-L53)).

Add a small **client connection card** in the already-running portal, backed by the MCP security/transport work. It displays the exact loopback URL, enablement/health state, tool inventory, and copyable Codex and Claude setup instructions for this workspace. Put an equivalent `mcp-client help` command in the offline CLI for generic syntax and a clear “start `serve` first” instruction; do not make it query a live workspace. Keep credentials out of displayed commands, project files and exported harnesses. If a bearer token is required, show only an environment-variable *name* and a local, explicit token-loading procedure; the user supplies the value outside client configuration. Do not write into `~/.codex`, `~/.claude.json`, `.mcp.json`, or another project automatically. Client configuration belongs to the operator and must be reversible using each client's normal remove command.

Current official docs describe Codex HTTP MCP registration/configuration and listing ([OpenAI MCP docs](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)); Claude documents HTTP installation, local/project scopes and status checks ([Claude MCP docs](https://code.claude.com/docs/en/mcp)). These pages may describe clients newer than the checkout's observed Codex `0.156.0` and Claude `2.1.311` ([target records](../../../../../docs/codex-connector.md#L8-L11), [Claude record](../../../../../docs/claude-code-connector.md#L3-L6)). Probe the **exact installed binaries** before publishing any command or header syntax as supported. If either cannot send the chosen bearer transport, mark that client unavailable for this endpoint instead of weakening authentication or silently switching to stdio/SSE. Never conflate a successful `mcp list` or version print with a tool call.

## Acceptance and negative checks

1. Extract a freshly built local archive into a new directory; run `serve` with a disposable synthetic workspace. Confirm the packaged launcher and HTTP endpoint, then configure each claimed exact client version against loopback. Each real client must initialize and discover the advertised tools; a direct protocol client calls one read-only company tool and checks the expected synthetic reviewed data. Record binary versions, transport, statuses and sanitized traces. Claim client discovery and direct tool behavior separately; model-driven use remains unqualified without an authorized live session.
2. The portal connection card and offline help give the actual URL, setup and removal steps; a second offline CLI process while `serve` owns the workspace reports `workspace_in_use` cleanly. After stop/restart, the documented flow reconnects without a second owner.
3. Missing/wrong token, disabled MCP, foreign Host/Origin, malformed version or unsupported tool yields no company content. Configuration output, archives, logs, error messages and screenshots contain no token bytes or private source bodies; disabling/rotation invalidates an existing connection.

Claim only the OS/architecture archive and client versions actually exercised. The current archive is a macOS arm64 local candidate, not a public release or a Linux compatibility result ([packaging record](../../../../../packaging/VERIFICATION.md#L1-L7), [release limits](../../../../../packaging/README.md#L3-L7)). MCP client interoperability does not qualify managed Codex/Claude coding execution, model quality or release promotion ([status](../../../../../docs/status.md#L58-L69)).
