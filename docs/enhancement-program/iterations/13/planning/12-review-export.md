# Human correction, exact approvals, and corrected target exports

**Observed gap.** Iteration 12 proved a supervised correction path: an unsafe claim was rejected, corrected guidance was saved as a successor, its exact revision was approved, the plan was approved separately, and fresh native03 target files contained the correction; current04 reused that authority without a fresh export. Yet analysis still admits only 2–4 whole sources and 32,768 body bytes, so newly inspected contrary evidence stays outside the saved origin ([handoff-to-13.md:21–25](../../12/handoff-to-13.md); [product.md:5–9](../../12/retro/product.md); [analysis.ex:169–212](../../../../../tmp/enhancement-program/13/source-before/lib/harness_forge/company/analysis.ex)). Exact decisions depend on current origins.

**Connected change.** Admit an analysis from a server-owned, nonempty authorised corpus plus saved goal and bounded support/contrary/unknown passage snapshot. The review DTO must display each proposed guidance field, exact cited UTF-8 spans with parent status and dates, conflicting and uncited prompt inputs, coverage gaps, and an explicit abstain reason. Persist an immutable origin version containing corpus/scope and goal generations, retrieved passage revisions and hashes, citations, uncited and transitive prompt influences, retrieval configuration, and an evidence-discovery watermark. Keep its identity stable through a human text correction: `Analysis.revise/3` already creates a successor while retaining origin and citations ([analysis.ex:47–75,123–157](../../../../../tmp/enhancement-program/13/source-before/lib/harness_forge/company/analysis.ex)). A changed source, changed goal/scope, revocation, or newly indexed relevant contrary passage beyond that watermark marks the proposal stale; refresh produces a new proposed claim requiring a new decision, never silently rebinds old approval.

**Authority and reuse.** Preserve append-only approve/reject against `expected_revision_hash`; conflict resolution remains required before approval ([decisions.ex:7–58](../../../../../tmp/enhancement-program/13/source-before/lib/harness_forge/decisions.ex)). Retain the separate exact plan decision and `build_plan` input recheck, then require current origin closure again at `eligible/1` before export ([harnesses.ex:8–25,211–289](../../../../../tmp/enhancement-program/13/source-before/lib/harness_forge/harnesses.ex)). Elixir/SQLite own these decisions and exports. Reuse pinned Graphiti 0.31.2 for retrieval/lineage and native Jev node/edge dedupe through a bounded adapter, with FTS5 as baseline; neither a graph score nor a model verdict grants approval ([REUSE-DECISION.md:13–42](../../../../../tmp/enhancement-program/11/scale-reuse-steering-01/REUSE-DECISION.md)). Compiler verification and fresh-directory payload verification already provide deterministic byte checks ([compiler.ex:23–42](../../../../../tmp/enhancement-program/13/source-before/lib/harness_forge/compiler.ex); [artifacts.ex:104–117,163–179](../../../../../tmp/enhancement-program/13/source-before/lib/harness_forge/artifacts.ex)).

**Acceptance.** On a larger public synthetic corpus, show retrieved support and a scoped exception, reject unsafe guidance, correct a successor, approve its exact hash, observe build refusal before separate plan approval, then export to a fresh supported Codex target and compare every actual file hash and guidance byte to the compiler manifest. The rejected text must be absent. Negative cases: forged span, uncited drift, new contrary evidence, revoked source, stale plan and changed goal each block approval/build/export. Recovery: refresh snapshot, resolve the conflict, create and approve new exact claim and plan revisions, then export fresh bytes. Compare FTS5 and Graphiti on an independently frozen critical-evidence oracle and paired representative tasks; scripted output proves mechanics only ([STUDY.md:269–311](../../../../../tmp/enhancement-program/11/scale-reuse-steering-01/STUDY.md)).

**Risk, alternatives, effort.** Discovery-watermark invalidation can overblock on irrelevant new passages; a bounded relevance recheck with audit trail may narrow invalidation, while uncertain coverage abstains. Estimate 3–5 engineer-days for origin/review/export integration and 2–3 for adversarial and representative verification, contingent on the selected corpus/backend contract. A broad graph rewrite adds no approval value; retaining the four-source gate leaves the principal user bottleneck intact.
