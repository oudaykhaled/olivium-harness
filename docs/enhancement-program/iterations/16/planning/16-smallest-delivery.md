**Options.** (A) Improve the Company entry, progressively disclose the manual 2–4-source route, and make the existing claim-to-plan handoff explain eligibility and the exact next action. This reuses Phoenix components and existing server decisions; its cost is a small cross-component state/presentation seam. (B) Add a full journey dashboard spanning capture, analysis, approvals, export and evaluation. It could reduce navigation, but duplicates state, expands stale-context risk and exceeds one reviewable UI slice. A name-format hint alone is cheaper, yet leaves the misleading handoff intact.

**Decision recommendation.** Deliver A as one connected WEB slice. Keep corpus/goal selection and evidence review primary; after exact claim approval, show a context-bound next action into separate plan creation, with an explicit explanation when a corpus claim is ineligible under current project membership. Add field-specific package-name guidance and retain valid draft selections on rejection. Keep approval buttons and authority in their current Elixir paths. Product owner: WEB component specialist for Company/Plan presentation; Root owns the LiveView interface, integration and browser verification. Blast radius is Company and corpus navigation plus plan creation; build/export semantics remain governed by existing checks.

**Falsifiable acceptance.** With zero manual assignments, a valid captured corpus/goal can reach evidence review without an implied source-assignment prerequisite. A corrected approved claim either appears as plan-eligible under verified membership or yields a specific, actionable reason; it never silently becomes eligible. A spaced name identifies the name field, focus returns there, and project/claim/goal selections persist; a valid slug can proceed to separate exact plan review. Changed/revoked scope blocks stale decisions. Keyboard and 390×844 checks cover order, focus, wrapping and status announcements. Root should run targeted LiveView tests and one public browser journey through exact claim, separate plan, actual export and static PASS/task BLOCKED, comparing artifact identities; no provider call is needed for UX qualification.

**Limits.** Structural capture counts are not discovery or semantic coverage. Real-model quality, representative task improvement, physical scale, novice success and own MCP company context remain open.
