### P1 API07-1 — original-daemon failure skips local capability revocation during cancellation

[Frozen Coding.cleanup](../../../../../../tmp/enhancement-program/07/source-candidate-02/lib/harness_forge/execution/coding.ex#L861) verifies the original daemon at line864 **before** `CodingSession.stop(id)` at line865. Verification failure or invalid persisted cleanup context short-circuits before local session/relay shutdown. [Evaluations.cancel](../../../../../../tmp/enhancement-program/07/source-candidate-02/lib/harness_forge/evaluations.ex#L197) has already persisted `cancelled`; it then returns `cleanup_failed` with retained context, but has no separate local revocation path.

This is a new ordering regression: [actual-before Coding](../../../../../../tmp/enhancement-program/07/source-before/lib/harness_forge/execution/coding.ex#L807) stopped the session before Docker work. The consequence is source-derived: a still-running owned container may continue using its relay until the execution call returns or the relay expires. [Relay.authorized](../../../../../../tmp/enhancement-program/07/source-candidate-02/lib/harness_forge/execution/relay.ex#L199) checks only its token; [Runtime.chat](../../../../../../tmp/enhancement-program/07/source-candidate-02/lib/harness_forge/models/runtime.ex#L52) does not consult the Run outcome. Finite turn/time/budget limits bound this exposure but do not make cancellation revoke the capability.

**Required root check/fix:** keep external daemon reads/mutations behind validated original authority, while revoking the owned local session independently of daemon availability. Under an actual persisted running v2 row and active relay/session, inject unavailable/mismatched original identity, call cancellation, and assert: cancelled outcome; cleanup_failed; exact context retained; local session absent/relay capability rejected; no subsequent model dispatch; zero daemon mutations or decoy contact. Repeat cleanup after restoring the origin; cancellation must remain cancelled. The existing guarded in-flight cancellation test at `coding_evaluation_test.exs:379` covers a healthy original daemon, not this failure branch. I have not executed this reproduction.
