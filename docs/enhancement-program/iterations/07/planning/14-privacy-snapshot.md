# Privacy and resource ownership: one attempt-owned route observation

**Recommendation (ADR):** Capture one validated, short-lived Docker transport observation before a task attempt creates a relay or container. Pass its fixed route enum through admission, proxy configuration, verification and the recorded environment profile; persist only the credential-free profile digest and existing result fields. Treat timeout, nonzero, malformed and unrecognized discovery as unavailable. Do not persist relay tokens, socket paths, port, environment values or Docker `info` output. The observation is attempt-scoped, not a reusable authority claim.

**Evidence and trust boundary:** `lib/harness_forge/execution/coding.ex` calls `transport/0` separately in `profile/0`, `run/2`, `start_proxy/2` and `verify_container/6`; its fallback maps every non-Desktop response to Unix. `lib/harness_forge/evaluations.ex` computes the profile digest in `create/2` before `Coding.run/2`, so a recorded identity can disagree with launch. This is a source-derived risk, not an observed exploit. `lib/harness_forge/privacy/snapshot.ex` backs up `evaluation_runs` and quarantines them on restore; `docs/privacy.md` says backups include private evidence, exclude run output and credentials, and remain unencrypted. A new persisted route transcript would enlarge backup disclosure without improving proof.

**Minimality and alternatives:** Route consistency is the smallest trust improvement with direct launch/profile evidence. Coherence admission addresses missing or contradictory rules; portable approval addresses recipient signer and revocation; representative qualification addresses actual company outcomes. Each remains necessary but has a broader independent contract. Keep cleanup tied to existing workspace/run/profile labels and names, never rediscover the route to decide what may be removed (`coding.ex` `cleanup/1`, `inspect_owned/2`). A simple live rediscovery at each use retains the mismatch; saving a full runtime snapshot would add privacy and restore obligations.

**Acceptance:** Positive: a single recognized Desktop or Unix observation yields matching dispatch, proxy networks/config digest and persisted profile identity. Negative: failed/unknown discovery blocks before relay/container creation and never asserts Unix. Edge: discovery or model-config drift before qualification makes the attempt inapplicable; cancellation/reconcile still removes only original labeled resources, including after restore quarantine. Synchronous readiness remains command-free and reports Not assessed when current route authority is absent. Verify with deterministic command-injected tests for both routes, failure/drift and cleanup, plus existing privacy backup/restore tests; root owns Mix and native checks.
