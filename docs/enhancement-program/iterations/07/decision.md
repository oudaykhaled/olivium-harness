## Context

An operator needs a task evaluation whose recorded environment describes the transport used by that attempt. Today [Coding.profile](../../../../lib/harness_forge/execution/coding.ex#L28) discovers transport three times; run admission, proxy creation and container verification discover it again. Its `transport/0` at line 427 turns every response except exact Docker Desktop into Unix, including command failures. [Evaluations](../../../../lib/harness_forge/evaluations.ex#L391) records another profile before dispatch. These are source-derived inconsistencies, not an observed exploit or a fresh runtime experiment.

[Command](../../../../lib/harness_forge/execution/command.ex#L6) also resolves the Docker endpoint on every call. Merely passing a route enum cannot bind later commands or cleanup to the original daemon. The existing workspace/run/profile labels in Coding prevent ordinary foreign-resource deletion, but absence on a different daemon cannot prove original cleanup. The shared JSON result in [Run](../../../../lib/harness_forge/evaluation/run.ex) is returned by `Evaluations.get/list_runs`; it is unsuitable for a private endpoint path.

The strongest alternatives are meaningful: [Company.resolve](../../../../lib/harness_forge/company.ex#L234) establishes selected approved snapshots without declared-conflict resolution; [milestone validation](../../../../lib/harness_forge/company/validation.ex#L79) does not require every selected goal to have acceptance coverage; goal-only artifacts are rejected by `Coding.artifact_sources/1`; [MCP authentication](../../../../lib/harness_forge/mcp/auth.ex) uses one bearer. ## Decision

Deliver **one validated, attempt-owned coding transport contract**: each new OpenCode task attempt either uses one recognized local route and original daemon throughout dispatch/profile/cleanup, or records a bounded unqualified refusal. Original endpoint ownership is part of this benefit, not an additional cleanup feature.

1. Discover a bounded local Unix endpoint and structured daemon identity before relay, ledger-backed runtime preparation, network/container creation or candidate files. Validate exact field types, bounded values and an explicit supported route mapping. Desktop requires a positively recognized Desktop observation; native Unix requires a positively recognized, documented native-Linux signature/topology contract. `OSType=linux`, nonempty OS text, or “not Desktop” alone must not select Unix. Unknown/malformed/nonzero/timeout/oversized discovery refuses. Existing endpoint restrictions remain; no remote daemon or caller-supplied command/endpoint is admitted. Discovery classification occurs once per attempt; later daemon-identity checks verify the bound identity rather than choose another route. Root/guardrail must review the exact finite native signature contract before its implementation is called supported; unavailable native topology stays unavailable, with fixture evidence labeled separately.
2. Use a small typed internal observation and pure profile derivation. Pass its route to relay socket choice, proxy configuration, network expectations and verification. Introduce a **v2 coding profile identity**; derive the public environment digest from the same observation, including a versioned digest of daemon/endpoint identity rather than raw paths. Persist identity before resources, then execute from that captured observation. Preserve blocked-run records when discovery fails, with no fabricated Unix identity and no qualified outcome. Static integrity, offline smoke and non-OpenCode contracts remain separate.
3. Persist a nullable private `evaluation_runs.execution_context` map, with exact versioned string keys for route, validated endpoint, daemon ID and original workspace/run ownership. It is internal cleanup authority, outside `result` and all DTOs. No raw discovery output, environment dump, relay token, provider credentials or generated content belongs there. Add no backfill/default. An additive nullable column permits durable atomic run/context storage; a sidecar would add a second commit and separate purge/restore lifetime. Existing unencrypted private backups will contain this non-secret but potentially identifying endpoint path: document that bounded disclosure and keep public outputs free of it.
4. Extend the existing Docker-command boundary with an internal pinned-endpoint form. Every new coding-attempt command uses it, including reads, mutations, cancellation and restart cleanup. Check daemon identity through that endpoint before resource-effect/cleanup boundaries; mismatch/unavailability refuses, never redirects to the current default. Preserve existing resource-label checks and verified-absence rules. Keep context until cleanup has actually been verified; retain it across failed cleanup/retry. A trusted local daemon remains a trust assumption. Identity checks are observations, not atomic protection against a malicious host replacing a socket between check and operation.
5. Current authoritative task applicability obtains a fresh validated observation and compares v2 route/endpoint/daemon/profile and existing model/configuration identities. Unknown, changed or legacy v1 identities refuse qualification. A completion-time identity/configuration mismatch cannot remain qualified. Historical rows remain readable; their bytes are not rewritten. No old saved identity becomes current authority. Preserve existing model/consent guards; this work does not claim to detect every transient configuration ABA change or establish model provenance.
6. Recovery distinguishes new v2 attempts from historical rows. New attempts with missing/corrupt context fail closed; never use the default daemon as an origin guess. Legacy terminal observations remain readable without manufacturing a new cleanup obligation. An unfinished legacy coding attempt without provable original daemon ownership must remain unresolved rather than declaring absence on today's daemon; root must expose this compatibility limit before installation. Offline smoke retains its existing backend contract. Reconciliation must enumerate persisted v2 contexts, not only the current daemon's labels, so a context switch cannot hide an outstanding attempt. This does not add planner11's exhaustive cleanup sweep.
7. Restore retains historical result bytes as already transformed by quarantine, clears private execution context when the column exists, and grants no ability to contact or clean the original workspace's daemon. Old backups without the column remain readable/migratable. Selective/workspace purge must complete pinned owned cleanup before removing its authority record and remain fenced/retryable on failure. Populated rollback must refuse to drop cleanup context; rollback is not permission to forget outstanding resources.

The approved [03 abstention amendment](../03/decision-amendment.md) remains binding: synchronous Readiness/Inspect/Refresh stays command-free and current OpenCode task identity/applicability/release admission remains **Not assessed**. MCP remains three read-only tools and `qualification: not_assessed_by_this_tool`. No new provider, MCP tool, company policy lifecycle, receipt, goal evaluation exception or UI panel is added.

## Consequences and alternatives

The benefit is falsifiable correspondence between a new attempt's recorded transport and its executed/cleaned resources. Explicit unsupported-route and original-daemon-unavailable outcomes may reduce apparent availability. Endpoint persistence, a nullable migration, privacy lifecycle and extra bounded daemon checks make this larger than a route-string patch. That cost is accepted because this ADR promises original-daemon ownership. Keep each implementation slice ideally at or below 400 net lines; exceeding that is a review signal to simplify within this contract, not permission to omit recovery.

**Route-only repair (planner15)** would cheaply remove repeated branch selection and failed-discovery fallback. It is rejected for this selected guarantee because Command still changes daemon per call; it remains a valid smaller alternative if root explicitly revises the claimed benefit. **Private sidecar context (planner14 follow-up)** avoids a schema change but adds file/DB atomicity, selective purge path and restart discovery problems. Prefer the nullable private column (planner03/09 follow-ups); no context in public result JSON. **Do nothing or longer timeout** preserves ambiguous profiles and is rejected.

**Declared conflicts** give direct policy value but need scoped declarations, successor-plan selection, direct-build/export admission and revocation/purge/restore semantics. **Recipient receipts** need an actual trust-policy owner plus keys/freshness/revocation distribution. **Representative company qualification** needs owner-reviewed obligations/tasks and observed real outcomes; synthetic Go checks cannot supply that oracle. **Selected-goal milestone coverage** is smaller and useful, but checks declared accounting rather than runtime identity. **Scoped MCP clients**, **exhaustive cleanup sweep**, and **goal-only task admission** each have distinct benefits; none is bundled. Goal-only admission can reuse the existing synthetic task oracle honestly, so lack of representative company outcomes alone is not a reason to reject it; the current transport inconsistency is the reason to defer expanding evaluation inputs now.
