## Decision and reason

**NO-GO for acceptance/count now. GO for completing the already-authorized current-candidate verification, same-reviewer addenda, protected local installation and retrospectives.** Once every substantive gate below is met, root may accept the bounded corpus-inspection/review benefit with two specifically named **UNVERIFIED** accessibility cells. Root must explicitly accept this addendum and the resulting limited verdict; absence of proof is never a pass.

The original changed-UI matrix requested both320/390 CSS widths at100/200% browser zoom and native keyboard selector completion. Root has actual narrow-CSS-width observations and partial keyboard activation, but has not observed the browser zoom level or completed native selector-only interaction. Root reports that the Chrome extension works while the native Mac app surface remains locked after the user's already-answered “Both done.” This is an observation/control limitation, not evidence of product failure or success. Asking the same unlock question again adds no authority or proof.

**Explicit narrow amendment:** these two unobserved cells may remain open qualification limitations rather than indefinitely block this bounded iteration, provided the current candidate's working normal-entry→inspection→review journey, source/authority controls, failure recovery and actual export continuity are demonstrated and independently dispositioned. This is a conscious change to ADR12's test-qualification requirement, not retroactive satisfaction of the matrix. It does not waive any demonstrated keyboard/reflow defect: if a reviewer identifies inability to perform the core action, lost content, inaccessible required controls or broken focus that blocks completion, correct and verify it with the same owners before acceptance. It grants no full-WCAG, novice or keyboard-only accessibility claim.

Why this trade-off: unchanged browser-control availability cannot be manufactured by more source polish, and the user requires the connected corpus-to-harness outcome. The residual risk is that browser zoom or selector-only operation exposes a real defect that narrow CSS geometry and Enter activation missed. Retain that risk prominently and revisit on the first available supported native control surface or the next change to these controls/CSS, without making it a prerequisite for unrelated iteration13 planning after legitimate12 closure.

Alternatives considered: (1) hold all delivery until native controls unlock—stronger eventual coverage, but no controllable completion date and risks diverting the binding core outcome; (2) count CSS-width observations/protocol tests as zoom/keyboard proof—rejected because it fabricates evidence; (3) narrowly qualified acceptance after all other gates—selected, with unresolved dissent preserved. No majority-vote approval is inferred from five favorable source assessments.
