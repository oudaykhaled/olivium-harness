# 09 — Truthful corpus analysis readiness and stage consent

**User benefit.** Let an operator select one authorised saved corpus and goal, see bounded coverage and supporting/conflicting passages, and start analysis only when every model stage is authorised and budgeted. Explain the available action, transmitted data and any blocking stage without a million-file checklist.

**Observed baseline.** The frozen Company Analysis form selects 2–4 source checkboxes and one goal, displays model status, and offers “Analyse selected context” with no stage readiness check in its disabled expression (`source-before/lib/harness_forge_web/components/company/analysis.ex:195–323`). `Company.Analysis` admits only 2–4 refs and 32 KiB of bodies, starts a one-request run, then sends `source_body` and `company_context` (`source-before/lib/harness_forge/company/analysis.ex:12–45,169–213`). `Models.status/0` describes one configured model; the configuration is one workspace settings row with consent listing at most 100 source IDs (`source-before/lib/harness_forge/models.ex:32–79`; `models/configuration.ex:7–17,31–63,102–150`). The ledger atomically reserves a request before dispatch, retains an uncertain reservation, and does not silently retry (`models/ledger.ex:44–125,128–184`). Tests prove scoped cloud refusal before reservation, changed-configuration refusal, and unknown-outcome retry fencing in synthetic conditions (`test/harness_forge/company_analysis_test.exs:56–103`; `test/harness_forge/models_test.exs:193–220`). They do not prove a Graphiti worker is integrated.

**Smallest connected change.** Extend Company Analysis with a saved corpus/goal summary, paginated metadata, capture/index coverage and exclusions, then stage readiness: extraction/generation, Jev node/edge decisions, embedding/retrieval and synthesis. Each row names the pinned endpoint/model or local component, consented categories, bounded attempts/tokens/estimated cost, used/unknown reservation, and next action. Show “not configured”, “awaiting consent”, “capturing”, “retrieval incomplete”, “ready”, “dispatched”, “usage unknown”, and “review required” from persisted facts. Cancel only future dispatch; explain an in-flight attempt may still be billed. Preserve drafts on recoverable refusal.

The backend owners should add server-derived nonempty group membership and paginated corpus/job state in Evidence/Company; stage-pinned configuration and independently scoped consent in Models.Configuration; per-attempt reservation, retry/cancel and ambiguous usage in Models.Ledger; and a bounded Graphiti Python adapter that routes actual LLM/embedding calls through those controls. PortalLive/CompanyPanel own events and stale-token checks; the Company Analysis component renders state. Capture exact revision/hash/UTF-8 spans, parent context, dates/status, conflicting evidence, coverage gaps and transitive origins before any claim reaches existing exact approval and deterministic export. Tombstone revoked derivatives before removal, including failed graph summary rebuilds. Reuse Graphiti 0.31.2’s actual runtime/Jev routes; extraction still needs an authorised supplied generative model.

**Acceptance.** Positive: a larger public synthetic corpus plus saved goal yields bounded progress, contrary passages and a reviewed correction carried into actual exported files and representative assessment. Negative: empty/foreign groups, unconsented stage, exhausted budget or unavailable model disable dispatch and create no claim. Recovery: interruption preserves checkpoint and uncertain charge, resume skips completed files, changed/revoked source blocks stale results through failed rebuild, and explicit reauthorisation permits a fresh bounded attempt. Test keyboard/status announcement and no false “complete” state. Estimate: 2–3 engineering weeks across UI/backend seams, plus real-backend qualification. A standalone consent wizard is cheaper but leaves the source bottleneck; defer it. No paid pilot, private import or host execution is implied.
