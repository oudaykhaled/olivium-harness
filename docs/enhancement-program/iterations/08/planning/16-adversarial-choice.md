# Proposed ADR08: recover a rejected package build

**Context.** The package form accepts a name but shows no syntax rule ([Portal:2005](../../../../lib/harness_forge_web/live/portal_live.ex#L2005)); the contract requires 1–64 characters matching `^[a-z][a-z0-9_-]*$` ([schema:20](../../../../priv/schemas/harness-v1alpha1.json#L20)). Build sends validation errors through `error_message` ([Portal:425](../../../../lib/harness_forge_web/live/portal_live.ex#L425)), where `invalid_harness` falls into provider-import advice ([Portal:1258](../../../../lib/harness_forge_web/live/portal_live.ex#L1258)). The form renders hardcoded defaults ([Portal:2008](../../../../lib/harness_forge_web/live/portal_live.ex#L2008)). These are source-confirmed recovery defects, not measured user failures.

**Decision and benefit.** Give the operator actionable, package-specific recovery: state the fixed name rule beside the field; on an invalid name, show a fixed correction near that field, retain the bounded submitted package values and focus the error/name; a corrected retry can build. For other `invalid_harness` causes, use safe package-specific guidance without printing validator details. Keep connector remedies specific to connector operations. This addresses a demonstrated wrong turn at a consequential build boundary, with no change to package authority or compilation.

**Confirmation.** Positive: uppercase/space/overlong name gives the fixed rule, retained values and keyboard focus; correcting only the name builds one digest-bound immutable artifact when approved evidence exists. Negative: refusal creates no artifact/audit build event; connector errors keep their own remedy and hostile error details never render. Edge: workspace reset/operator revocation clears retained draft and focus generation; missing approved claims retain their existing explanation. Root verifies focused LiveView regression, canonical Mix gate and native keyboard/320–390 CSS-width at actual 200% zoom, recording source-bound evidence; no human-comprehension rate is inferred.

**Scope and blast radius.** UI author owns `portal_live.ex` and focused `portal_test.exs`/package tests; UI/UX reviewer owns copy/focus review; root alone runs Mix/browser, integrates shared assets if a focus hook is needed, and records evidence/board. No schema, compiler, migration, export or release change. Estimated one focused PR under 400 net lines.

**Alternatives and cost.** Saved-goal continuation is a stronger workflow-reach hypothesis: cards currently stop after acceptance ([Portal:1980](../../../../lib/harness_forge_web/live/portal_live.ex#L1980)), while the rule form requires blank deliberate selection ([Portal:1542](../../../../lib/harness_forge_web/live/portal_live.ex#L1542)). It needs navigation/focus work and a first-time operator study; the prior 4/5 target was unperformed. A generic error-map rewrite covers more operations but widens regression surface. Chosen recovery has narrower reach; it does not qualify company/model fitness, obligation coherence, portable authority, or publication completion.
