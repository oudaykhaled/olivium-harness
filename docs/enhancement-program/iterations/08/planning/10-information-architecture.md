# Information hierarchy: continue from a saved goal

**Problem and evidence.** A saved goal confirms its owner and acceptance criteria, then its card ends without a next action ([PortalLive:421–423](../../../../../lib/harness_forge_web/live/portal_live.ex#L421), [1952–1985](../../../../../lib/harness_forge_web/live/portal_live.ex#L1952)). The separate Evidence rule form asks the operator to choose a saved goal and explicitly says selection is not approval ([1542–1603](../../../../../lib/harness_forge_web/live/portal_live.ex#L1542)). Its reverse empty-state already navigates to Goals ([1550–1557](../../../../../lib/harness_forge_web/live/portal_live.ex#L1550)). The missing forward cue makes the creation sequence harder to discover.

**Recommend one UI benefit.** Add one “Write a rule for this goal” action on each saved-goal card. It changes to Evidence and focuses the goal-rule heading, using the existing tab/focus pattern ([PortalLive:254–266](../../../../../lib/harness_forge_web/live/portal_live.ex#L254), [514–519](../../../../../lib/harness_forge_web/live/portal_live.ex#L514)). Keep the Saved goal selector blank; the operator deliberately chooses the current goal revision. Add no new panel or automatic proposal. This makes the next task visible at the point of success while the form retains its explanation and approval boundary.

**Acceptance.** Positive: keyboard activation from a saved card lands on the rule-form heading; the next Tab reaches the blank Saved goal selector, and the existing help remains readable. Negative: navigation alone creates no claim, decision, plan, package, export or runtime action and selects no goal. Edge: unavailable or removed goals, workspace reset, stale form generations and lost operator access cannot revive a draft or focus a hidden control; the action and explanation remain complete at 320/390 CSS pixels and actual 200% zoom. Root schedules focused LiveView and browser checks, including exact unchanged revision/digest identity and keyboard focus. A proposed four-of-five first-time-operator comprehension target is **unperformed**; technical navigation success cannot satisfy it.

**Files and ownership.** UI implementer: `lib/harness_forge_web/live/portal_live.ex`; UI test owner: focused `test/harness_forge_web/portal_test.exs` coverage; root owns shared assets/integration, native browser execution and evidence. Preserve current privacy, reset, approval and immutable artifact boundaries.

**Tradeoff and limits.** Invalid package names currently fall into provider-import advice ([PortalLive:425–441](../../../../../lib/harness_forge_web/live/portal_live.ex#L425), [1258–1281](../../../../../lib/harness_forge_web/live/portal_live.ex#L1258)); correcting that is a smaller, confirmed recovery repair and should remain a competing candidate. I prefer the goal continuation because it exposes the next creation task without technical overload. Neither change establishes company/model fitness, novice comprehension, full accessibility, or portable authority; prior outcome, coherence and receipt dissent survives.
