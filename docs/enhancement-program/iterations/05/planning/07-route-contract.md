# 05 proposal: trusted task-route snapshot

**Observed gap.** [Coding](../../../../lib/harness_forge/execution/coding.ex) calls `transport/0` three times per profile, then in `run/2` and `start_proxy/2`. Docker-info failure silently chooses `unix_socket_proxy`. [Evaluations](../../../../lib/harness_forge/evaluations.ex) computes task applicability through that live profile; [03’s accepted amendment](../../03/decision-amendment.md) therefore makes [Readiness](../../../../lib/harness_forge/readiness.ex) abstain. [Validation](../../../../lib/harness_forge/releases/validation.ex) remains release authority. The [04 handoff](../../04/handoff-to-05.md) and five original retrospectives keep company outcomes, policy origin, conflicts and portable authority unresolved. Company fitness is unproven.

**One bounded functionality unit.** Introduce a versioned, validated route snapshot owned by `Execution.Coding`: resolve the local Docker endpoint and daemon OS once at each task execution or authoritative release-validation attempt; accept only explicitly recognized Desktop and local Unix cases. Derive profile digest, proxy configuration, relay mode and recorded task environment identity from that same immutable in-memory snapshot. Unknown OS, failed/ambiguous endpoint, timeout or malformed response returns a specific refusal; it never defaults to Unix. Bind snapshot to the observed daemon endpoint and current model configuration digest. Do not persist it as current authority or reuse it across commands. Recheck configuration and daemon identity before qualification; a changed value makes the task inconclusive and triggers cleanup. Historical run bytes remain historical; old records are compared under unchanged authoritative admission, never rewritten. Readiness Inspect/Refresh stays command-free and task `not_assessed`; opening release review grants nothing.

**Acceptance and ownership.** Coding owns snapshot resolution, profile construction and execution plumbing; Evaluations owns recording the exact resolved identity; Validation owns fresh comparison at approval/promotion. Root owns shared integration and board. Test Desktop/Unix profiles are distinct and stable per snapshot; malformed/timeout/changed endpoint/config refuse without asserting a route; actual task setup and stored identity match; failure cleans up. Trace Inspect/Refresh for zero command/port calls. Test actual release attempts repeat authoritative checks; retain static/smoke refusal and legacy artifact verification. Docker-capable qualification and interruption tests must report execution versus skips separately. This enables trusted applicability, not a qualified company pilot.

**Trade-off.** A pure configured route would simplify inspection but could drift from the daemon. Persisting a discovered route would shorten checks but creates stale authority. Fresh validated resolution costs one bounded Docker probe per authoritative attempt and keeps failure explicit.
