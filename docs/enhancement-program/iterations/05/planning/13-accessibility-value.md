# 05 proposal: reviewable goal-origin rule

**Operator benefit.** An owner can turn a saved future goal into a rule, inspect both before approving, and see why a changed goal stops the plan. This is a functionality unit with a small presentation change. [Goals and Evidence](../../../../../lib/harness_forge_web/live/portal_live.ex) currently sit on separate tabs; claim proposal requires a citation, while [Company Plan](../../../../../lib/harness_forge_web/components/company/plan.ex) labels goals as optional intent and exposes only approved sourced claims. [04 handoff](../../04/handoff-to-05.md) and the five original retrospectives leave goal authority, declared conflicts, and current task identity as separate candidates. Complete-company fitness remains unproven.

**Bounded contract.** Reuse exact claim decisions and plan admission. Add a goal-origin claim basis bound to workspace, goal ID/content hash, claim revision, and separate approval. In Evidence, let the operator choose a citation or eligible saved goal. Show origin, goal title/owner, and exact revision next to decision controls. In Company Plan, show origin beside each selectable rule and a specific stale-goal refusal with a route to review. Keep claim and plan approvals separate; selecting a goal alone authorizes nothing. Preserve citation-origin hashes and historical package bytes.

**Acceptance and test ownership.** Domain owner tests successful goal-backed approval → plan → build → export, plus missing/foreign/changed goal, withdrawn/superseded claim, source purge, workspace purge and restore quarantine. Web owner tests the same saved-record journey and stale-goal refusal: keyboard users reach origin choice, inspect the exact rule, decide, then reach the focused error and corrective control after a stale build; accessible names identify both origin options and exact decisions, and status text announces the refusal once. Use semantic locators and a scoped axe scan as defect checks, plus 320px/200% overflow and focus observations. These checks establish observable mechanics, not human comprehension, screen-reader speech or WCAG conformance. Root owns shared schema/route integration and immutable-evidence verification.

**Trade-off.** Declared-conflict admission can prevent known contradictions but needs a separate declaration lifecycle; current-route identity can improve qualification but needs trusted execution provenance under the [03 amendment](../../03/decision-amendment.md). Goal origin supplies traceable intent with less UI surface, while representative model/company outcomes and portable authenticated approval remain open.
