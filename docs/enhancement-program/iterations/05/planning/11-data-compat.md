# 05 proposal: versioned goal-rule basis without historical package drift

**Benefit and code basis.** Let an operator approve a goal-grounded rule without inventing a citation. `Evidence.create_claim/1` requires citations (`lib/harness_forge/evidence.ex:288-315`); `Harnesses.specification/3` emits `goal_id: nil` (`lib/harness_forge/harnesses.ex:180-195`). `Contracts` permits a rule with a goal and empty evidence (`lib/harness_forge/contracts.ex:299-319`). `Company` pins goal hashes (`lib/harness_forge/company.ex:245-260`).

**ADR — decision.** Add a typed, versioned goal basis to *new* immutable claim revisions: `{basis_version: 1, kind: goal, goal_id, goal_content_hash}`; hash the canonical basis and rule text together. Keep existing citation-origin hash calculation and rows exactly as written. Require a separate exact-revision approval, selected goal, matching workspace/hash and explicit plan reference. At plan creation and every build/export/release eligibility check, compare the current approved claim, goal basis, goal scope and pinned plan snapshot. Emit `goal_id` with empty evidence only for admitted goal rules. Do not infer normative authority from goal selection, a historical package, or a recorded task identity.

Use a SQLite side table keyed to claim revision, preserving immutable `evidence_claims` and frozen `v1alpha1` schema. Assert historical `Compiler.verify/1`, digest, manifest and export bytes unchanged. New records use the existing rule shape; retain `template_version`. `Artifacts` stores by digest and refuses overwrite (`lib/harness_forge/artifacts.ex:20-35,104-139`).

**Acceptance and operations.** Test approved goal rule → exact plan → build/export; reject missing/rejected/foreign/stale/superseded basis; recheck after source purge and restore. Keep unrelated legacy packages eligible. Include the side table in inventory, selective purge, immutable triggers and restore ID rewrite; clear restored decisions and retain quarantine (`lib/harness_forge/privacy/{company,purge,snapshot}.ex`). Migration adds a table/index/trigger with a brief SQLite schema-write lock (measure on test data); rollback drops the table only after confirming no goal-basis records. Root owns migration/privacy; feature author owns API/admission tests. Preserve invalid binding evidence until dependent artifact removal, since its loss can grant legacy eligibility (`harnesses.ex:145-169`). Company fitness remains unproven.

**Alternatives.** Reusing nullable `goal_id` without a typed exact basis is smaller but loses approval provenance. A new package schema provides portable provenance but expands compiler compatibility and export contracts beyond this unit. Declared conflicts and current task identity remain separate 05 candidates; choose by acceptance value and code evidence, never report counts.
