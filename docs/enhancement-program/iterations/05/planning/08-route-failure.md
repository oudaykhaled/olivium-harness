# Iteration 05 proposal 08 — task route resolution

**One functionality unit:** make OpenCode task transport stable per execution attempt. `Coding.profile/0` discovers transport three times; `run/2`, proxy creation and verification resolve it again. `transport/0` maps every non-Desktop response—including timeout and Docker failure—to Unix. A recorded profile may differ from the relay/proxy route; failed discovery can attempt the wrong socket ([Coding](../../../../../lib/harness_forge/execution/coding.ex), [Command](../../../../../lib/harness_forge/execution/command.ex)). The accepted [03 amendment](../../03/decision-amendment.md) requires command-free inspection to abstain from current task identity.

**Proposal:** return `{:ok, :desktop | :unix, route_context}` only for validated Docker and local-endpoint responses; otherwise return a typed error. Resolve once before creating task resources; pass the result to profile, relay, proxy, network and verification. Record the resulting profile digest with the run. Route drift fails closed and cleans up owned resources; later attempts resolve anew. Historical route identity cannot establish current applicability. Keep endpoints out of reports.

**Acceptance:** Desktop and Unix fixtures yield distinct profile identities and matching proxy topology. Timeout, missing executable, nonzero exit, unexpected OS text or invalid endpoint create no task/relay/proxy and return a bounded reason, with no Unix fallback. Inject drift before launch/verification and show refusal and owned-resource cleanup. Recorded identity matches the used route; configuration change invalidates later applicability. Inspect/Refresh remain command-free with OpenCode task admission **Not assessed**; release commands retain authoritative checks. Test controlled command boundaries and opt-in Docker route contrast where available. No company-fitness claim follows.

**Ownership/risk:** execution owner changes Coding/Command; root owns shared Evaluations/Validation and persisted identity; QA checks cleanup and command-free inspection. This touches execution and identity, so has greater blast radius than goal-origin or conflict admission. Those choices improve policy authority sooner but leave route ambiguity. Increasing timeout is simpler but preserves fallback. Select by value/reliability/simplicity, never votes; do not bundle policy admission. The [04 quality retrospective](../../04/retro/05-quality.md) identifies this gap; [handoff](../../04/handoff-to-05.md) keeps priorities open.
