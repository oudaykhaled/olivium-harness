Current matching goal title, owner, acceptance and full origin hashes appear before claim approval, with no invented citation. Human details are shown only after `Evidence.validate_claim/1` and matching `Goals.content_hash/1`; changed or unavailable goals suppress those details and disable approval, while the decision boundary remains authoritative.

The new draft, selection, generation and review cache join existing privacy reset/lock clearing. A generation-keyed form subtree and generation-keyed select/textarea IDs with matching labels replace browser inputs on reset and successful proposal. Both change and submit events reject captured generations before reading or writing a draft. Fresh mounts generate independent controls; `phx-auto-recover="ignore"` prevents LiveView's reconnect recovery from repopulating old private inputs. The inherited event authentication rechecks the current operator session before the new events. No shared JavaScript reset allowlist is needed for these new keyed controls.

Company Plan and the pure Guide consume `Evidence.approved_claims/0`, which the domain owner guarantees contains only current shared-validated exact approvals. Their added logic projects source/goal membership only. Goal claims no longer require sources for guidance; their goal must already belong to company/project scope and must be separately selected in the plan. No claim checkbox automatically selects a goal. Known missing/stale/invalid goal errors and the Packages direct-build refusal receive narrow corrective copy.
