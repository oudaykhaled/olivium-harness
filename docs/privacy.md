# Local privacy, retention, backup and restore

HarnessForge retains imported snapshots and derived content until the operator explicitly purges it. `HarnessForge.Privacy.inventory/0` reports scoped record counts, including MCP clients, disclosure grants and their exact members, and owned artifact/run/temporary file counts. It does not read environment credential values. The workspace stores evidence bodies and FTS inside SQLite; source connector credentials and provider credentials are environment references, and local login/session secrets are separate files. Independent MCP client credentials are returned once; SQLite stores only their hashes.

`Privacy.purge_source(source_id, source_id)` requires the exact source ID as typed confirmation. It removes all stored revisions, FTS rows and citations for that source, every revision of affected claim families and their decisions, artifacts whose rules cite those revisions/claims, and associated evaluations and release approval/channel/history rows. Unrelated sources, claims, goals and artifacts remain. A history row referencing the removed release as its previous version is also removed. Source purge revokes and clears the owning connection's directory/configuration/cursor to prevent queued reimport, and withdraws model configuration and cloud consent. Other sources on that connection require a new explicit connection/revalidation. Associated queued sync, proposal and evaluation jobs are cancelled; executing jobs and unverifiable runtime cleanup block completion. Explicitly creating a new connection can import the original material again.

Source purge also removes entire MCP disclosure grants containing that source, including historical members, and grants for affected corpora. All items of each affected grant are removed together; unrelated grants and client registrations remain. Workspace content purge removes all scoped MCP clients, disclosure grants and grant items.

All stored artifacts must pass integrity and lineage inspection before source purge. A corrupt artifact or unattributed artifact stage blocks it. Repair/reconcile the artifact store or separately choose a whole-workspace content purge; the source action does not silently delete unrelated artifacts. Original imported files, provider copies, previously exported packages and backup directories remain under their owners' control.

`Privacy.purge_workspace(workspace_id)` requires the exact active workspace ID. It deletes active evidence, goals, decisions, model configuration/ledgers, evaluations, releases, scoped jobs, audit content and the owned `artifacts`, `runs` and `tmp` trees. It retains minimal privacy-operation tombstones containing identifiers, state and safe error codes. The running database, workspace identity, ownership lock and login/session files remain. This is **content purge**, not full root deletion. Full workspace-root removal must happen offline after the application and its SQLite connections close. Neither operation promises physical erasure of SSD blocks, SQLite journals, filesystem snapshots, backups, exported packages or provider copies.

Purge intent and checkpoints are durable: `prepared → database_purged → completed`. SQL removal and restoration of known immutable-delete triggers commit in one transaction. File deletion never follows symlinks. Failures retain the last checkpoint and a safe error code; `Privacy.ready/0` fences new workflows until `Privacy.reconcile/0` or retry of the original purge verifies cleanup and finishes. Boot recovery must run reconciliation before background jobs and the endpoint become available. If a recorded runtime attempt may own a container, an unavailable Docker backend produces `cleanup_failed`; content is not reported purged. No repository code is executed during privacy operations.

`Privacy.backup(fresh_absolute_directory)` creates a private stage beside a fresh destination. SQLite `VACUUM INTO` produces a consistent committed snapshot, including WAL-visible committed changes; it runs outside application transactions. Verified immutable artifacts are included only when their rule/goal identities exist in that database snapshot. The manifest records every included file's size and SHA-256, plus artifact digests. Publication uses an atomic directory rename. Access tokens, session secrets, environment credential values, run output and temporary files are excluded. Incomplete purge state blocks backup. [SQLite documents snapshot consistency and transaction restrictions for VACUUM INTO](https://sqlite.org/lang_vacuum.html).

The copied SQLite database is scrubbed of MCP client hashes, registrations, disclosure grants and their exact members before its manifest hash is calculated. Restore repeats this scrub for older backups that contain them. Active and revoked MCP authority is removed; a restored workspace requires newly issued client credentials and disclosure grants.

Backups also retain private coding-attempt cleanup context: the non-secret but identifying original local Docker endpoint path and daemon ID. Public run/package/MCP projections exclude those values. Backups **contain private evidence and are not encrypted**. Keep them in operator-controlled encrypted storage; HarnessForge does not manage backup destinations, retention or copies. Hash verification detects accidental corruption and changes relative to a manifest. It does not authenticate a maliciously replaced manifest/backup from an untrusted party.

`Privacy.restore(backup_directory, fresh_absolute_directory)` verifies the exact manifest file set, file hashes, SQLite integrity and foreign keys before copying. Existing targets, traversal, symlinked ancestors, symlinked entries and unexpected files fail closed. Restore changes the workspace UUID so cleanup labels cannot affect the original workspace. Evidence and artifact previews remain available, while source connections are revoked and stripped of paths/configuration, all model consent/credential references and queued jobs are removed, claim decisions and release approvals/history/channels are removed, and evaluations become interrupted/unqualified. A `restore.json` receipt records required reconnect/review/model/re-evaluation steps. Original coding execution context is cleared when present, including in newer backups; older backups without that column remain restorable. Recovery and purge in the restored workspace do not contact the original daemon. Local login and session secrets are generated afresh at the next launch. Restoration never re-enables approval validity or private egress automatically.

The filesystem model assumes the local operator's account is trusted. Path checks prevent user-supplied traversal and symlinks; they cannot protect against a malicious process with the same filesystem permissions swapping entries during an operation. Inventory and backup scanning are bounded to 20,000 files and 1 GiB. Large workspaces fail visibly instead of silently skipping content.

Verification uses synthetic data: selective source canary removal, dependent release invalidation with unrelated release preservation, immutable-trigger restoration, incomplete-cleanup fencing, resumable file failure, outside-file preservation, repeated content purge, committed SQLite backup/restore, fresh restored authority, tamper detection and unsafe-path rejection. These checks do not establish physical media erasure or live Docker compatibility.

For new coding attempts, source purge targets only the planned run IDs and workspace purge targets the active workspace. Each retained v2 context, including completed-clean history, requires verified cleanup on its original daemon before deletion. If that daemon is unavailable or identity/ownership does not match, purge remains fenced and retryable. The context-bearing evaluation rows survive database and file-removal failure phases and are deleted only after owned run files, including `runs/coding-<UUID>`, are removed. Terminal legacy observations remain readable; unfinished legacy coding attempts without original connection proof remain unresolved. These rules trade purge availability for retaining cleanup authority and do not establish physical erasure.
